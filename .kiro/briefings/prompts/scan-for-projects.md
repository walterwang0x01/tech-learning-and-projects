# 简报扫描 → 项目化总结

按项目维度扫描简报内容，输出对每个项目有直接影响的条目和动作建议。

## 输入

- 配置：`.kiro/briefings/scan-config.yaml`
- 简报源：`learning-notes/_briefings/{topic}/YYYY/MM/YYYY-MM-DD.md`

## 流程

### Phase 0：读配置 + 算扫描范围

1. 读 `.kiro/briefings/scan-config.yaml`，提取：
   - `topics` 中 `true` 的主题
   - `last_scanned_date`
   - `projects` 列表
   - `output_dir`
2. 算扫描日期窗口：
   - `last_scanned_date` 为空 → 扫该主题目录下全部历史 md（首次运行）
   - 有值 → 只扫 `(last_scanned_date, today]` 区间
3. 用 `find` / `ls` 列出待扫描的 md 文件清单，给用户报数：
   ```
   扫描范围：YYYY-MM-DD ~ YYYY-MM-DD
   主题：ai-agent (N 篇), global-tech (M 篇)
   ```
4. 如果**没有任何**新文件 → 直接告诉用户"上次扫描后无新简报"并结束。

### Phase 1：逐文件提取候选条目

对每篇简报：

1. 读全文（用 read_file）
2. 提取每条头条 / 快讯 / 项目论文中的：
   - **标题/主语**（一句话能说清是什么）
   - **链接**
   - **日期**（从文件名）
   - **来源主题**（ai-agent / global-tech）
3. 暂存到内存中的"候选池"，**先不做项目匹配**

> 简报数量大时（> 30 篇），用 sub-agent 并行做这步会更快。可调用 `general-task-execution` 把扫描分片。

### Phase 2：按项目分桶

对配置里每个 `project`：

1. 用项目的 `interests` 关键词逐条匹配候选池
   - 标题 / 摘要中命中任一关键词即收录
   - 同一条可被多个项目收录
2. 命中后对每条做"动作建议"：
   - 内容性质（资讯 / 工具 / 安全警报 / 监管 / 经济模型 / 评估基准）
   - 紧迫度（🔴 本周 / 🟡 本月 / 🟢 知道即可）
   - 具体落地动作（基于该项目的栈和已知架构，给出具体建议）

### Phase 3：写总结文件

输出路径：`{output_dir}/YYYY-MM-DD_review.md`（YYYY-MM-DD = 今天）

文件结构：

```markdown
# 简报扫描总结 — YYYY-MM-DD

> Author: Walter Wang
> 扫描范围：[起始日期] ~ [结束日期]
> 覆盖主题：ai-agent / global-tech
> 简报总数：N 篇 / 候选条目：M 条

## 📋 摘要

3-5 句话讲清这次扫描的核心结论：哪些主题在升温、有哪些必须本周处理的事。

---

## 🎯 按项目分组

### {项目名}（{项目描述}）

#### 🔴 本周必做（紧迫）
- **{标题}** ({YYYY-MM-DD}, {topic})
  - 简报原文一句话总结
  - **对该项目的影响**：具体到代码 / 架构 / 流程哪里会被波及
  - **建议动作**：1-2 条可执行的具体步骤
  - → [来源链接]

#### 🟡 本月可考虑
（同结构）

#### 🟢 知道即可
（同结构，可压缩到一行）

---

### {下一个项目}
（同结构）

---

## 🌐 跨项目趋势

不属于单一项目，但值得记的趋势观察（最多 5 条）：

- **{趋势标题}**：1-2 句描述 + 为什么重要 + 可能的下一步信号

---

## 📊 扫描统计

| 指标 | 数值 |
|------|------|
| 简报天数 | N |
| 候选条目 | M |
| 项目相关条目 | 各项目 X / Y / Z |
| 跨项目趋势 | K 条 |
```

### Phase 4：更新游标

把 `scan-config.yaml` 中的 `last_scanned_date` 改写为今天的日期。

用 `str_replace`，只改这一行，其他配置保留。

### Phase 5：通知用户

简短输出：
- 总结文件路径
- 各项目"本周必做"的条数（用户能立刻看出哪个项目最紧迫）
- 是否有跨项目趋势值得当面讨论

## 写作原则

- 项目"建议动作"必须**具体**：不能写"加强安全检查"，要写"在 SceneRouter 的工具调用前加 X"
- 有疑问的地方用 `> ⚠️ 待确认：xxx` 标注，不要硬编
- 同一条简报可被多个项目收录，**不要为了避免重复而漏掉**
- 链接保留原文链接，不要二次封装
- 全程中文，技术术语英文

## 异常处理

- 配置文件缺失 → 告诉用户先建 `scan-config.yaml`
- 简报目录为空 → 提示先跑简报采集 hook
- 文件写入失败 → 追加到 `learning-notes/_briefings/.errors.log`
