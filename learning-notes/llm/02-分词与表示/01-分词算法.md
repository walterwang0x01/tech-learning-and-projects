## 1. 分词粒度的权衡

LLM 处理的是数字序列，分词器（tokenizer）负责把文本切成一个个"词元"（token），再映射成整数 ID。切分粒度怎么选，是个绕不开的权衡：

| 粒度 | 问题 |
| --- | --- |
| 词级（word-level） | 词表爆炸（`run/runs/running` 都占位置）；OOV：未见词变 `<UNK>`；无法处理形态关系（`unhappiness` 与 `happy` 是无关 ID） |
| 字符级（character-level） | 序列长度暴涨（5 字符单词变 5 token）；语义稀释；计算代价：自注意力 `O(n²)`，序列长 5 倍计算量变 25 倍 |

子词分词（subword）是折中方案：**高频词保持完整（`the`、`is`），未见词拆成有意义的子片段（`unhappiness`→`un`+`happi`+`ness`）**，把 OOV 问题降到几乎为零——最差情况都能拆到字符级兜底，同时高频词又能保持紧凑表示。这是 BPE、WordPiece、Unigram LM 等主流分词器的共同出发点。

## 2. BPE：从字节对合并规则说起

BPE（Byte Pair Encoding）最初是数据压缩算法，借用到分词领域。核心思想极简：**统计当前语料中出现频率最高的相邻符号对，把它合并成一个新符号，重复 N 次**。

### 完整训练流程

```
输入：训练语料，目标词表大小 V
第一步：初始化 —— 每个词切成字符序列，词尾加特殊标记（如 </w>），统计词频
  例：语料里 "low" 出现 5 次 → {"l o w </w>": 5, ...}
第二步：迭代合并（重复直到词表达到大小 V 或无法再合并）
  1. 统计所有相邻符号对的出现次数（按词频加权）
  2. 找频率最高的对 (A,B)，把语料中所有 "A B" 替换为新符号 "AB"
  3. 把 (A,B)→AB 记入合并表，按顺序编号
第三步：编码新文本 —— 按训练时记录的合并规则顺序依次应用（顺序必须一致）
```

### 手工走一遍例子

语料：`{"low":5, "lower":2, "newest":6, "widest":3}`（词频），初始化为字符序列（`</w>` 表示词尾）。第 1 轮统计相邻对频次——`(e,s)` 在 "newest" 和 "widest" 中共现 6+3=9 次最高频，合并 `e s→es`；第 2 轮 `(es,t)` 共 9 次，合并为 `est`；第 3 轮 `(est,</w>)` 共 9 次，合并为 `est</w>`；继续下去 `(l,o)` 因 "low"+"lower" 共 7 次被合并成 `lo`，再与 `w` 合并成 `low`……每轮都是贪心合并当前最高频的相邻对。

**关键性质**：合并规则是有顺序的列表，编码新词时必须按训练时产生的顺序依次应用，否则同一个词可能被切出不同结果。

## 3. WordPiece：打分公式差在哪

WordPiece（BERT 使用）表面上和 BPE 做同一件事——迭代合并符号对，但**选择合并哪个对的打分公式不同**：

```
BPE:        score(A,B) = count(A,B)                        —— 单纯看共现频率
WordPiece:  score(A,B) = count(A,B) / (count(A)×count(B))  —— 类似互信息
```

这个分母是关键差异——相当于在问："A、B 相邻出现的频率，是否比它们各自独立出现的期望频率高得多？"假设 `the`、`ing` 都是超高频子词，即便"the ing"共现次数不低，分母也会把分数拉得很低——两个高频词凑在一起本来就"应该"经常共现，不代表该合并；反过来两个各自不那么高频、但只要出现就几乎总相邻的对，会得到很高分数。这个公式和 PMI（点互信息）`log[P(A,B)/(P(A)·P(B))]` 结构一致（没取 log），本质是挑"比随机组合更愿意黏在一起"的对。

效果上，WordPiece 倾向优先合并"强关联但各自频率适中"的片段，BPE 则被超高频片段主导前几轮合并顺序。WordPiece 编码时非词首子词会加前缀标记（BERT 用 `##`），如 `unhappiness` 编码为 `un ##happ ##iness`，用于解码还原哪些子词需拼回原词。

## 4. Unigram LM 分词：反过来做减法

BPE 和 WordPiece 都是自底向上——从字符开始不断合并变大。Unigram LM 分词器（SentencePiece 的一种模式）走**自顶向下**路线：先建远大于目标大小的候选子词集合，再不断删除，直到收敛到目标词表大小。

### 核心思想：概率语言模型

Unigram LM 假设每个子词 `x_i` 独立服从概率分布 `P(x_i)`，句子切分为 `X=(x_1,...,x_n)` 的概率是所有子词概率相乘：`P(X)=Π P(x_i)`（"unigram"——不考虑上下文的独立假设）。训练目标：用 EM 算法迭代估计每个子词的概率，使整个语料的似然最大化。

迭代收缩流程：①初始化远超目标大小的候选子词集合；②EM 估计每个子词概率；③计算"删掉它后语料似然下降多少"（贡献度）；④删除贡献度最低的一批；⑤重复②~④直到收缩到目标词表大小。

### 与 BPE 最大的实用差异：分词不再是唯一的

BPE 编码一个词走它记录的合并规则，结果唯一确定。Unigram LM 分词一个词时理论上存在多种切分方式，模型挑**概率最大的切分**（类似维特比算法），但也可按概率采样出不同切分——这叫**子词正则化**，训练时故意喂多种切分方式的同一个词，提升模型对分词边界扰动的鲁棒性。

## 5. SentencePiece：它是框架，不是算法

一个常见误解：把 SentencePiece 当成"第四种分词算法"。**SentencePiece 是分词器实现框架/工具库，BPE 和 Unigram LM 都可作为它内部的算法后端**（Llama 系列用 BPE 后端，T5/ALBERT 用 Unigram LM 后端）。

SentencePiece 相对裸的 BPE/WordPiece 实现解决了两个工程问题：**语言无关的预处理**——传统 BPE 依赖空格切词，对中文日文这类不用空格分词的语言不适用；SentencePiece 把输入当原始 Unicode 字符流直接处理，空格当普通字符（`▁`）参与训练。**可逆的编码/解码**——保证 `decode(encode(text))==text` 严格可逆，对翻译、代码生成等需精确重建原文的场景很重要。

所以正确表述是"这个模型用 SentencePiece 训练的 BPE 分词器"，而非"用 SentencePiece 分词算法"——后者混淆了框架和算法。

## 6. 字节级 BPE：GPT 系列的选择

普通 BPE 在字符层面操作是有代价的：基础符号表要覆盖所有可能的 Unicode 字符（数万到十万级），否则遇到没见过的字符（生僻字、emoji）仍会 OOV。**字节级 BPE（byte-level BPE）** 的解法：先把文本用 UTF-8 编码成字节序列，在字节（0~255，固定 256 种）上做 BPE 合并——不管输入什么语言，都能先表示成字节再编码，永不 OOV。GPT 系列采用字节级 BPE 正是看重这个保证。代价是：中文汉字在 UTF-8 下往往占 3 字节，没被合并成一个 token 时会被切成 3 个 token。

## 7. 中文分词与多语言公平性

中文分词在两个层面比英语复杂。**没有天然的词边界**——中文没有空格提示词边界；子词分词器直接在字符/字节流上统计频率学出子词边界，绕开了这个传统难题。**字节级 BPE 对中文不友好**——若合并规则没把汉字对应的 3 个字节合并成 token（取决于训练语料中文比例），一个汉字可能被切成 2~3 个碎片 token，同样语义内容中文消耗 token 数远高于英文，按 token 计费场景下体现为更高实际成本。

这个问题不是分词算法本身的缺陷，而是**训练语料的语言分布通过分词器间接传导到下游所有环节**：英语主导的语料下，高频英语词/子词更容易被压缩成单个 token，形态丰富的语言更容易被切碎。这带来三重后果：非英语用户单位信息成本更高；上下文窗口按 token 数计算，非英语用户能塞入的实际内容更少；同样训练预算下，非英语内容覆盖的实际语义信息量更少。缓解手段包括小语种语料过采样、扩大总词表、训练专用分词器，目前没有完美解法。

> ⚠️ 待确认：不同厂商分词器对中文的实际压缩比会随训练语料和词表大小变化，没有通用准确数字。

## 8. 词表大小的权衡

词表大小 `V` 是分词器训练的核心超参数：

| 词表 | 优点 | 代价 |
| --- | --- | --- |
| 小词表 | embedding 参数少、softmax 计算量小 | 每词需要更多 token，序列变长导致 `O(n²)` 计算量增加，单 token 语义稀薄 |
| 大词表 | 常见词/短语紧凑表示为单 token，序列更短 | embedding 矩阵和输出层参数量线性增长，长尾 token 训练信号稀疏 |

这是典型的"序列长度 vs 词表参数量"跷跷板：词表变大缩短序列（减少 Transformer 主体计算），但增大 embedding 层和输出层的参数与计算（生成任务里到词表大小的 softmax 是单独计算瓶颈）。实践中还要考虑训练语料的语言分布——多语言模型词表往往要大得多。

## 9. 最小可运行实现：手写简化版 BPE

用 Python + numpy 实现一个能跑的简化 BPE：训练学出合并规则，再用规则编码新文本。

```python
"""简化版 BPE 训练与编码，标准库 + numpy（合并候选排序）"""
import numpy as np
from collections import Counter, defaultdict


def get_word_freqs(corpus):
    freqs = Counter()
    for line in corpus:
        for word in line.strip().split():
            freqs[tuple(word) + ("</w>",)] += 1  # 词尾标记，区分词中/词尾字符
    return freqs


def apply_merge(symbols, pair):
    """合并 symbols 里所有相邻的 pair（训练合并、编码复用同一逻辑）"""
    merged, out, i = pair[0] + pair[1], [], 0
    while i < len(symbols):
        if i < len(symbols) - 1 and (symbols[i], symbols[i + 1]) == pair:
            out.append(merged)
            i += 2
        else:
            out.append(symbols[i])
            i += 1
    return out


def train_bpe(corpus, num_merges):
    """迭代合并最高频对，返回按顺序记录的合并规则列表"""
    word_freqs, merge_rules = get_word_freqs(corpus), []
    for step in range(num_merges):
        pair_freqs = defaultdict(int)
        for word, freq in word_freqs.items():
            for i in range(len(word) - 1):
                pair_freqs[(word[i], word[i + 1])] += freq
        if not pair_freqs:
            break
        pairs = list(pair_freqs.keys())
        freqs = np.array([pair_freqs[p] for p in pairs])  # numpy 排序找最高频对
        best_pair = pairs[int(np.argmax(freqs))]
        merge_rules.append(best_pair)
        word_freqs = {tuple(apply_merge(list(w), best_pair)): f for w, f in word_freqs.items()}
        print(f"第 {step+1} 轮合并: {best_pair} → '{best_pair[0]}{best_pair[1]}'  (频次={int(freqs.max())})")
    return merge_rules


def encode(word, merge_rules):
    """按训练时产生的顺序依次应用合并规则"""
    symbols = list(word) + ["</w>"]
    for pair in merge_rules:
        symbols = apply_merge(symbols, pair)
    return symbols


if __name__ == "__main__":
    # low/lower、newest/widest 共享子结构，观察合并规则如何抓住共现模式
    corpus = ["low low low low low", "lower lower",
              "newest newest newest newest newest newest", "widest widest widest"]

    print("=== BPE 训练过程 ===")
    rules = train_bpe(corpus, num_merges=10)

    print("\n=== 学到的合并规则（按产生顺序） ===")
    for i, r in enumerate(rules):
        print(f"  规则{i}: {r}")

    print("\n=== 用规则编码新词 ===")
    for test_word in ["lowest", "newer", "wider"]:
        print(f"  '{test_word}' → {encode(test_word, rules)}")
```

实测输出（numpy 2.4.4）：

```
=== BPE 训练过程 ===
第 1 轮合并: ('e', 's') → 'es'  (频次=9)
第 2 轮合并: ('es', 't') → 'est'  (频次=9)
第 3 轮合并: ('est', '</w>') → 'est</w>'  (频次=9)
第 4 轮合并: ('l', 'o') → 'lo'  (频次=7)
第 5 轮合并: ('lo', 'w') → 'low'  (频次=7)
第 6 轮合并: ('n', 'e') → 'ne'  (频次=6)
第 7 轮合并: ('ne', 'w') → 'new'  (频次=6)
第 8 轮合并: ('new', 'est</w>') → 'newest</w>'  (频次=6)
第 9 轮合并: ('low', '</w>') → 'low</w>'  (频次=5)
第 10 轮合并: ('w', 'i') → 'wi'  (频次=3)

=== 学到的合并规则（按产生顺序） ===
  规则0: ('e', 's')
  规则1: ('es', 't')
  规则2: ('est', '</w>')
  规则3: ('l', 'o')
  规则4: ('lo', 'w')
  规则5: ('n', 'e')
  规则6: ('ne', 'w')
  规则7: ('new', 'est</w>')
  规则8: ('low', '</w>')
  规则9: ('w', 'i')

=== 用规则编码新词 ===
  'lowest' → ['low', 'est</w>']
  'newer' → ['new', 'e', 'r', '</w>']
  'wider' → ['wi', 'd', 'e', 'r', '</w>']
```

可以直接验证第 2 节手工推导的合并顺序——`(e,s)` 因在 "newest"（6 次）和 "widest"（3 次）中共现，频次 9 排第一位，与代码输出一致。第 9 轮 `('low','</w>')` 优先于频次 3 的 `('w','i')` 被合并，说明贪心算法每一步的候选集合会随前面合并结果动态变化。

"lowest" 被拆成 `low`+`est</w>` 两个学到的子词，而非退化成未知符号——这正是子词分词解决 OOV 问题的体现。"wider" 因没学到 `wid` 这个合并，被切成 5 个片段，说明子词切分粒度取决于该模式在训练语料中的出现频次。

## 10. 小结

| 方法 | 合并/选择策略 | 特点 |
| --- | --- | --- |
| 词级分词 | 按空格/规则切词 | OOV 严重，词表随词形变化爆炸 |
| 字符级分词 | 每字符一个 token | 无 OOV，但序列长、语义稀释 |
| BPE | 贪心合并当前最高频相邻对 | 简单高效，GPT/Llama 系主流 |
| WordPiece | 合并 `count(A,B)/(count(A)·count(B))` 最高的对 | 类似互信息打分，BERT 采用 |
| Unigram LM | 自顶向下裁剪，EM 估计子词概率 | 支持多切分/子词正则化，T5/ALBERT 采用 |
| SentencePiece | （框架非算法）内置 BPE/Unigram 后端 | 语言无关预处理 + 可逆编解码 |
| 字节级 BPE | 在 UTF-8 字节上做 BPE | 永不 OOV，代价是非拉丁文字易被切碎 |

核心权衡贯穿全篇：**词表大小 vs 序列长度 vs OOV 覆盖率 vs 多语言公平性**，没有免费的最优解，只有场景取舍。
