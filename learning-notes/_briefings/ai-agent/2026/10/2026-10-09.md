## 📌 头条

### LangChain 跑通「会花钱」的 agent：Stripe Link + MPP

LangChain 放出了一个叫 Restock 的示例 agent，跑在 Managed Deep Agents 上、常驻 Slack，能自己找商品、建购物车、走结账——用的是 Stripe 的 Machine Payments Protocol（MPP），一个 Stripe 和 Tempo 合写的开放协议，让 agent 不经过结账 UI 就能程序化付款。关键在于凭证不落到 agent 手里：Stripe Link 给的是一次性卡号或 Shared Payment Token，背后是你钱包里已有的卡，agent 永远拿不到原始卡信息。对做支付编排的你，这正好是「LLM 绝不持有写权限、金额由服务端定」那套设计的一个现成样例，值得对着它的代码读一遍 MPP 的 402 + WWW-Authenticate 握手怎么走。

→ [LangChain 博客](https://www.langchain.com/blog/agents-that-can-pay-with-stripe-link) / [MPP 文档](https://docs.stripe.com/payments/machine/mpp)

### Google 把 Gemini 变成企业 agent，还给它配了公司邮箱

Google 在 Gemini at Work 2026 上发布了面向企业的 Gemini agent：一个 prompt 框里完成知识工作、写文档、分析数据、写代码，关掉电脑后还能在云端继续跑。最反常识的是身份设计——每个 coworker agent 拿到一个真的 Workspace 账号：邮箱、日历、Drive、公司通讯录里的一个席位，同事可以像给人派活一样给它派活。执行任务时它还能派生临时的 sub-agent，各自带独立身份，协作干几天的活。官方只说了形态没给可靠的 benchmark，所以别把它当成能力证明；但「agent 有自己的组织身份 + 可委派子代理」这个方向，和你在做的多调用方编排是同一条路。

→ [TechCrunch](https://techcrunch.com/2026/10/08/google-brings-agentic-ai-to-gemini-starting-with-businesses/) / [Google Cloud 官方](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026/)

## ⚡ 快讯

- **Docker Agent**：Docker 官方开源了 docker-agent（项目名 cagent，Apache-2.0 的 Go 运行时）：用 YAML 声明式定义多 agent 团队，接任意 MCP，agent 能像容器镜像一样推到 OCI 仓库分发。是个 docker CLI 插件，Docker Desktop 4.63+ 装好后 docker agent 直接用，HN 上到了 291 分。 → [GitHub](https://github.com/docker/docker-agent) / [开源中国](https://www.oschina.net/news/502889)

- **Claude Haiku 5.5**：Anthropic 最快的小模型，价格砍到 Haiku 4.5 的约四分之一（输入 $0.10/百万 token、输出 $0.50），首次支持可调 effort。官方称 agent 能力相对 4.5 大幅提升、对齐评测里 misaligned 行为明显更少；同时 Sonnet 5.5 的缓存读价格也减半到 $0.10/百万。 → [开源中国](https://www.oschina.net/news/502894/anthropic-claude-haiku-5-5)

- **字节 Seed**：一篇 9 月底的论文直指 DeepSeek 长上下文「抽风」原因：分块 KV 缓存压缩引入了 token 的「相位」坐标，造成相位敏感性——同一信息在一个相位好检索、在另一个相位难检索，长上下文检索准确度各相位间最高可差 40 个百分点，被平均分数掩盖。 → [IT之家](https://www.ithome.com/1/010/780.htm) / [arXiv](https://arxiv.org/abs/2609.36322)

**Package Hallucination Attacks on Coding Agents** — 攻击者往 AGENTS.md / .cursorrules 这类社区共享规则文件里注入 prompt，诱导 coding agent 把正规依赖换成攻击者控制的包。直接命中「规则文件 = 不可信输入」这条，用社区规则文件前值得警惕。→ [arXiv](https://arxiv.org/abs/2610.09264)

**Not Every Call Needs a Frontier Model** — 一个 agentic 家居系统里 LLM 调用点难度差一个数量级（路由意图、分类动作、grounding、规划、写代码），却普遍用「为最难点选的那个模型」服务所有点。按调用点评测 0.8B 到前沿模型，论证分级选模的空间。→ [arXiv](https://arxiv.org/abs/2610.09021)

**Humanize: Judgement Engineering for Agentic Coding** — 多 agent 编码编排，核心是在 planning/implementation/review/learning 的边界上做显式、可机械执行的判定：人先批准 plan contract，builder agent 再实现。和「写代码的 agent 不是判断是否完成的好裁判」这个痛点正对。→ [arXiv](https://arxiv.org/abs/2610.08900)
