### 一个 MCP 的 SSRF 结构性缺陷，Google、JPMorgan 和两国政府都中招

过去五个月里，Google、摩根大通、法国 DINUM 等五家机构各自爆出同一个 MCP 漏洞：MCP server 从 agent 拿到一个 URL/path 就直接发外部请求，不校验这个地址实际解析到哪里，于是谁能操纵 agent 就能让 server 去访问内部系统——这是经典的服务端请求伪造（SSRF），只是搬到了 agent-to-agent 的场景里。Ars Technica 把它描述成「结构性缺陷」而非单点 bug：恶意指令能从一个被攻陷的 agent 顺着 MCP 调用链扩散到网络里的其他内部 agent。如果你在用 MCP 串联多个内网 agent，别只给工具加鉴权，要在 server 侧对出站地址做解析校验和白名单——鉴权判断「这个 agent 能不能调」，拦不住「这个 agent 被诱导去打内网」。

→ [Ars Technica](https://arstechnica.com/security/2026/10/vulnerability-in-agents-from-google-and-others-exposes-structural-flaw-in-mcp) / [The Next Web 技术拆解](https://thenextweb.com/news/mcp-flaw-ssrf-google-jpmorgan-dinum-protocol-pivoting)

### AWS 把 OpenAI 的 Agents API 搬进 Bedrock 托管运行时

AWS 10 月 5 日的每周汇总正式介绍了 Amazon Bedrock Managed Agents powered by OpenAI 的公开预览（9 月 29 日起进入 preview）。它基于 OpenAI Agents API 的 AWS 定制版，让你用 OpenAI 模型构建的 agent 完全跑在 AWS 内部，复用你已有的身份、权限和治理控制。使用方式是创建一个带模型、指令、工具和执行环境的 session，发消息进去，服务替你跑完整个 agent loop 和模型调用。价格要留意：OpenAI 模型 token 走 Bedrock 的 in-Region 费率、比 OpenAI 官方价高约 10%，另加 AgentCore Runtime 的 CPU/内存，以及示例栈里那个即使空跑也要约 $33/月 的 NAT 网关。想把 agent 托管但又卡在企业合规上的团队，这是继 OpenAI Agents API（9/10 公测）、Google GKE Agent Substrate（9/11）之后的第三个托管运行时选项，值得对照一下各家「替你跑什么、什么留给你」。

→ [AWS 每周汇总](https://aws.amazon.com/blogs/aws/aws-weekly-roundup-amazon-bedrock-managed-agents-powered-by-openai-q3-service-availability-updates-kiro-workflows-and-more-october-5-2026) / [Bedrock 预览公告](https://aws.amazon.com/about-aws/whats-new/2026/09/bedrock-managed-agents-preview/)

## 📈 趋势
