## 📌 头条

### OpenCode 2.0 发布：后台子代理 + Code Mode

终端 AI 编程工具 OpenCode 发了官方称之为「重大更新」的 2.0。核心变化是把一直存在但没真正启用的客户端/服务器架构做实，常驻一个本地共享服务统一终端、Web 和桌面三端。真正值得试的是两点：一是后台子代理 + 异步 shell 命令，可以并行跑编排任务；二是 Code Mode，让模型把 MCP 工具和 OpenAPI 组合进脚本来调度，而不是一次只调一个工具。另外独立出来一个 @opencode/sdk，能把 OpenCode 嵌进自己的服务（Cloudflare 已经通过实验性 OpenCodeHarness 支持跑在 Durable Object 里）。如果你在用 MCP 做工具编排，Code Mode 这套「让模型写脚本调度工具」的思路值得拿一个真实任务跑一遍对比。

→ [开源中国](https://www.oschina.net/news/503031/opencode-2-0) / [2.0 新特性详解](https://www.augmentedswe.com/p/whats-new-in-opencode-2) / [Cloudflare 集成](https://developers.cloudflare.com/changelog/post/2026-10-12-opencode-harness/)

### LangChain 把 agent eval 常见问题讲清楚了

LangChain 博客发了一篇 agent eval 答疑长文，系统回答了「从哪开始评测」这个大多数人卡住的问题：离线 vs 在线评测怎么分工、几类 evaluator 各自管什么、什么时候才该用 LLM-as-judge、多轮对话怎么评、以及怎么把成本压下来（配套 Harbor 跑 benchmark）。对正在给 agent 搭评测体系的人，这是把散落的决策点一次串起来的入门地图。配合他们另一篇用 Deep Agents CLI 让文档代码样例「自己测自己」的实践，可以直接照着搭一套 CI 友好的 eval 流程。

→ [Agent evals 答疑](https://www.langchain.com/blog/common-questions-about-agent-evals) / [让文档自测](https://www.langchain.com/blog/our-docs-test-themselves)

**Evidence-First Agentic Verification (Sauron)** — 长程 agent 任务的评判常依赖打分表，但证据散在环境状态和执行轨迹里，judge 容易漏看或轻信 agent 自报的成功；该工作提出先收集证据再判定，避免把错误奖励强化进 RL。→ [arXiv](https://arxiv.org/abs/2610.17724)

**The Silent Failures in Agentic Data Science** — 指出现有对数据科学 agent 的评测只看下游预测表现和代码正确性，掩盖了过程中的静默失败。→ [arXiv](https://arxiv.org/abs/2610.14115)

## 📈 趋势

- 🔺 编码 agent 从「单工具调用」转向「让模型写脚本编排工具」——OpenCode Code Mode、LangChain Deep Agents CLI 都在往这个方向走

- 🔺 MCP 生态进入「治理与可靠性」阶段：工具元数据质量、选工具准确率、静默失败审计成为新研究热点
