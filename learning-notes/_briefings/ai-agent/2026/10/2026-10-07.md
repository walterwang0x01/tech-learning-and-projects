### OpenAI 一次性放出 722 篇模型自产数学稿

OpenAI 在 GitHub（openai/math 仓库，Apache-2.0）公开了一个未发布内部前沿模型产出的 722 篇数学手稿，归入 372 个相关结果族，官方说这是模型开发评估阶段在公开数学难题上跑出来的产物。重点不只是数量：仓库同时附带了部分证明的 Lean 形式化（可由计算机机械校验），还给了引用与修订的规范协议。按 36氪引述的口径，单份成果平均耗算力约等于 ChatGPT Pro 三小时深度推理；OpenAI 另一篇说明里把这批工作归到下一代模型 Astra 的内部版本，并称找解的 token 成本约 2000 美元。手稿里点名了 Mahler 猜想、π 的无理性指数等经典问题，但官方和多家报道都强调「发布了手稿」不等于「结论已被数学界独立接受」——数学家要花几个月才能判断里面是真·新思路还是已有技巧的拼接。对你这种做 agent 的人，更值得看的是它把「生成-形式化校验」这条链真跑通了：想复用这个模式，先去读 Lean artifact 怎么和自然语言证明对齐。

→ [OpenAI 社区说明](https://community.openai.com/t/first-look-at-mathematics-manuscripts-from-an-internal-frontier-model-at-openai/1403886) / [36氪](https://www.36kr.com/newsflashes/4015136016617345) / [Scientific American](https://www.scientificamerican.com/article/openai-unleashes-hundreds-more-math-results-upon-a-field-already-in-shock/)

### Anthropic 把网络能力测试拆成三档开放

Anthropic 10 月 6 日把原来的 Project Glasswing 并入「Cyber Verification Program」，重构成三档访问层级，让经过审核的安全团队（含部分政府伙伴）申请对应强度的权限，每升一档，网络安全相关的拦截分类器就放宽一点。拿到权限后可以用它最强的模型——Claude Opus 5.5、Sonnet 5.5、Mythos 5.1 以及后续新模型——对电网、银行、航班系统这类关键基础设施做高风险的攻防测试。Anthropic 说这个安全计划今年已帮伙伴发现十万量级的软件漏洞（官方声明口径「超过 10 万」，The Register 引用的是 4 月至 7 月 12.9 万个已验证漏洞，两个口径都来自 Anthropic 自己，采用需谨慎）。放宽攻击性能力的访问本身就是把双刃剑，这条值得持续盯——它基本定义了「前沿模型做攻防」这件事未来一年的监管基调。

→ [Anthropic 官方](https://www.anthropic.com/news/cyber-verification-program) / [The Register](https://www.theregister.com/security/2026/10/07/anthropic-reconfigures-its-cool-kids-security-program/5301509) / [36氪](https://www.36kr.com/newsflashes/4015151743815561)

## ⚡ 快讯

- **Google EmbeddingGemma 2**：DeepMind 10 月 6 日开源 EmbeddingGemma 2，基于 Gemma 4 架构、Apache 2.0，把文本/代码/图像/视频/音频统一映射到同一个 768 维向量空间。总参数 7.4 亿是模块化拆的——纯文本只用 2.7 亿，视觉编码器 1.7 亿、音频编码器 3 亿按需加载；文本任务在 Pixel 11 Pro 上约占 191MB 内存，全模态约 567MB，整个推理不出设备。对本地 RAG/端侧检索是现成的多模态底座，但官方自己说没做安全调优、100 种语言性能不均衡 → [Google 博客](https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/) / [IT之家](https://www.ithome.com/1/010/125.htm)
- **MCP 转向无状态**：InfoQ 的分析点出 MCP 新版把协议本身做成无状态了，但状态并没消失，而是被甩给了应用层自己维护。对接 MCP 的 agent 要重新想清楚会话态存哪、谁来续——无状态协议好扩展，代价是续接会话的复杂度转嫁到了你的应用。MCP 的权重还在往上走：各家运行时（如 LangGraph Agent Server）都在把 MCP endpoint 做成一等公民 → [InfoQ](https://www.infoq.cn/article/MwQyLYzgSiD16x36k9Ef)
- **LangGraph v1**：LangChain 发布 LangGraph v1，定位是「稳定性导向」而非大改——核心图 API 和执行模型不动，主要收紧类型安全（现在可以在建图时声明 interrupt 的类型，严格约束 interrupt 传入传出的值）、补文档、改开发体验。已经在用 LangGraph 的项目升级成本低，但要留意迁移指南里 interrupt 相关的类型变更 → [LangGraph v1 说明](https://docs.langchain.com/oss/javascript/releases/langgraph-v1) / [迁移指南](https://docs.langchain.com/oss/python/migrate/langgraph-v1)
- **Garry Tan 谈 harness 的 token 账**：YC 的 Garry Tan 抛了个观点：大厂实验室出的 agent harness 有「烧 token」的动机，所以创业公司做的 harness 反而有真实价值——像 Grep 那样把 token 消耗自动换成可确定性测试、可复现的代码，只要观察 agent 的使用就能做到。这条和同期一篇讲企业 agentic AI token 经济学的论文（The Harness Effect）正好互为印证：orchestration 层才是对抗 token maxing 的关键杠杆 → [原推](https://x.com/garrytan/status/2107129959550685660) / [The Harness Effect 论文](https://arxiv.org/abs/2607.06906)
- **搜索 agent 的「假完成」**：一篇讲 agentic search 的论文发现：即便 agent 返回了正确答案，在带多个约束的问题上，有高达 48% 的正确答案其实还有约束没被验证就被判「任务完成」了——作者称之为 illusory completion（虚假完成）。换句话说「答对了」可能只是蒙对的。做 search/research agent 的要警惕：别拿「agent 自己说完成了」当终止信号 → [arXiv](https://arxiv.org/abs/2602.07549)
- **代码修复：循环不等于可靠**：另一篇针对 agentic code repair 的研究用五种子跑了 30 个 HumanEval 修复、共 900 条三轮修订轨迹，发现强制多轮修订下，当前轨迹的正确率从一轮后的 0.820 掉到两轮后的 0.673——「反复 generate-test-revise」本身给不了可靠性保证，关键在于能不能把一个正确补丁留住、验证、提交。给写修复类 agent 的提醒：别迷信多轮迭代，要给补丁加状态约束 → [arXiv](https://arxiv.org/abs/2607.24604)

## 📈 趋势

- 🔺 harness / orchestration 层成为焦点 — 从「堆 token 买能力」转向把编排层做成对抗 token 浪费的杠杆，创业公司的确定性 harness 开始有卖点
- 🆕 MCP 转无状态 — 协议本身卸掉状态、甩给应用层，SDK 下载和调用量仍在高速增长，接入方要重新设计会话态管理
- 🔺 agent 安全 / 可靠性论文密集 — 假完成、循环不等于可靠、工具使用削弱拒绝能力、停止权治理，一批研究都在戳「agent 看起来干完了」的可信度
- 🆕 多模态嵌入下沉端侧 — EmbeddingGemma 2 把五种模态塞进 740M、手机内存量级跑，本地 RAG 的多模态底座成熟了一截
