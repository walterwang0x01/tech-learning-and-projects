## 📌 头条

### Figma 联创泼冷水：MCP 不是完美协议

Figma 联合创始人 Dylan Field 公开表示 MCP 并非完美协议，Figma 会尽量支持多种标准、但不会把全部数据都通过 MCP 暴露出去。这话对正在把 MCP 当默认集成层的人是个提醒：协议还在早期，连积极接入的大厂都是「支持但留一手」的态度，别把全部数据访问都押在单一协议上。落到你手上的动作很具体：设计自己的 MCP server 暴露面时默认最小授权、按需开放工具和资源，比一股脑全接更稳，也和今天多篇 Agent 安全论文的方向一致。

→ [TechCrunch](https://techcrunch.com/2026/10/20/figma-co-founder-dylan-field-thinks-mcp-is-not-a-perfect-protocol)

### IBM ALTK-Evolve：不靠前沿模型也能登顶 τ²-bench

IBM Research 的 ALTK-Evolve 在 τ²-bench 客服任务上登顶，关键不是换了更强的模型，而是靠「学到的记忆」（learned memory）——让系统在交互中积累并复用经验，用记忆工程补上模型能力的缺口。这对预算有限、又想把 Agent 做到可用的团队是个明确信号：与其堆更贵的底座，不如在记忆/上下文工程上下功夫。如果你在做客服或多轮任务型 Agent，值得拿 τ²-bench 跑一轮，对照看记忆层能带来多少提升。

→ [Hugging Face](https://huggingface.co/blog/ibm-research/altk-evolve-bc)

## 📦 项目 & 论文

| 项目 | 描述 | 链接 |
|------|------|------|
| EGI-BENCH | 企业级 Agent 评测套件，把 CRM 操作、异构文档检索、多轮规划、工具调用等分散的评测统一到一个 runner | [→](https://arxiv.org/abs/2610.27234) |
| RITE | 专测电商 Agent 对「静默工具错误」的端到端韧性——工具返回貌似合理的错值且无报错，会一路传到最终答案 | [→](https://arxiv.org/abs/2610.27777) |
| PROVISO | 按「内容来自用户还是外部工具输出」做溯源的安全动作选择器，用对比候选动作而非孤立判断来平衡安全与可用 | [→](https://arxiv.org/abs/2610.27115) |
| MAS-Guard | 从单 Agent 到多 Agent 系统的统一护栏，针对分布式授权、异构角色、可能被攻陷的参与方 | [→](https://arxiv.org/abs/2610.28397) |
| Muse Glimmer 30B | 开源 30B 端侧 Agent 模型，把多步推理、工具调用、失败恢复集成进单一模型，消费级硬件本地可跑 | [→](https://arxiv.org/abs/2610.24628) |

**Recoverability and Verifier Strength** — 提出两个可测量指标（verifier 强度 σ、可恢复性），界定 Agent 平台「读执行轨迹→自动改进→自动验证→无人发布」这个自改进闭环里，到底多少能安全脱离人工。对做 Agent 自动化治理的人是个量化框架。→ [arXiv](https://arxiv.org/abs/2610.27465)

**Context-Aware Prompt Injection Detection (nokast-secureRAG)** — 约 0.5B 的小模型当 RAG 检索与生成之间的「语义防火墙」，联合评估查询+检索内容，分成 safe/suspicious/malicious，针对间接 prompt injection 和检索投毒。→ [arXiv](https://arxiv.org/abs/2610.28364)

## 📈 趋势

- 🆕 Agent 安全从单体护栏走向多 Agent、溯源级防护（MAS-Guard、PROVISO、nokast-secureRAG 同日扎堆）
- 🆕 durability / 可持久化基础设施开始外溢到各种 harness（Vercel 开放、arXiv 自改进闭环），长任务可恢复成标配诉求
- 🔺 记忆/上下文工程被当成「不换底座也能提分」的杠杆（IBM ALTK-Evolve 登顶 τ²-bench）
- 🔺 科研湿实验闭环里的 Agent 越来越多（Anthropic 蝎毒蛋白、分子发现、材料/化学多篇），从「生成」走向「迭代实验」
