## 📌 头条

### Anthropic 把 Agent Skills 捐给 AAIF，标准脱离单一公司

Anthropic 在 10 月 22 日 San Jose 的 AGNTCon + MCPCon 上宣布，把 Agent Skills（去年 12 月发布的开放标准，一个带 SKILL.md 说明文件的文件夹，能按需给 agent 加载特定任务知识和脚本）捐给 Linux 基金会旗下的 Agentic AI Foundation（AAIF）。捐的是名称、logo、GitHub 组织和 agentskills.io 域名——继 MCP 之后 Anthropic 第二个交出治理权的标准。同一场发布里 AAIF 一口气新增四个项目：Agent Skills（Anthropic）、Open Responses（OpenAI）、OpenEnv（Hugging Face）、OpenSandbox（阿里），托管项目总数到 10 个。官方说 70+ 平台（ChatGPT、Cursor、GitHub Copilot、VS Code）已集成。对你意味着：你本地 `~/.kiro/crew/skills/` 下写的那套 SKILL.md 现在是跨平台标准格式，值得按官方 spec 核对一遍字段兼容性。

→ [Anthropic 公告](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation) / [Linux 基金会新闻稿](https://www.linuxfoundation.org/press/agentic-ai-foundation-announces-four-new-projects-agent-skills-open-responses-openenv-and-opensandbox) / [IT之家](https://www.ithome.com/1/016/811.htm)

### Claude Duet 发布：主动式 agent，关键操作先问你

Anthropic 10 月 21 日放出 Claude Duet 研究预览——跟「你问我答」的 Claude 主应用不同，Duet 会自己从你连接的 app 里发现待办、提前推提醒，离开设备后还能在自家云电脑上接着干，关键操作才停下等你批准。它建在 Claude Opus 5.5 上，号称接 6000+ 连接器，继承你 Claude 账号里的 memory、skills 和连接的 app。目前只对美区 Pro/Max 用户开放候补，且后台轮询会计入你现有套餐额度。官方自己也承认它「仍可能误判什么事紧急」。这是 Anthropic 对标 ChatGPT、Meta Muse 这类常驻 agent 的回应。对你意味着：主动式 agent 的「判断何时该打断人」正是 Kiro Crew 监控循环的同类问题，可对照它怎么分「需要你 / 可以等 / 先问一下」。

→ [TechCrunch](https://techcrunch.com/2026/10/22/claude-duet-app-is-anthropics-bet-on-agents/) / [开源中国](https://www.oschina.net/news/503159/claude-duet)

## 📦 项目 & 论文

| 项目 / 论文 | 一句话 | 链接 |
|------|------|------|
| Who Verifies the Builder? | 当同一个 agent 既写代码又写测试，通过的测试套件不再是独立的正确性证据——提出对 agent 产物做独立验证 | [→](https://arxiv.org/abs/2610.28667) |
| SUDP：Agent 秘密委托协议 | 今天 agent 运行时「靠暴露授权」——把可复用密钥放进运行时，一次 prompt injection 就变成持久账号沦陷；SUDP 做范围化委托 | [→](https://arxiv.org/abs/2604.24920) |
| PerMIT：持久记忆完整性 | 持久记忆是注入和投毒的无防御面；PerMIT 只信任用户输入和闸门确认过的值，给记忆加可证明的完整性保证 | [→](https://arxiv.org/abs/2610.28987) |
| RegretBench：备份意识 | coding agent 普遍缺「这步会改掉以后可能要用的状态、得先备份」的意识；205 个可执行任务衡量并自动化备份 | [→](https://arxiv.org/abs/2610.28934) |
| Harness Scaling for Agentic RL | agent harness 决定模型怎么用工具、管上下文；只用单一固定 harness 训练会过拟合，提出跨 harness 训练提升泛化 | [→](https://arxiv.org/abs/2610.29458) |

**Behavior Beyond Text: Evaluating Refusal Transfer Failure in LLM Agents** — 文本里会拒绝有害请求的模型，换成工具调用场景就未必拒绝；2304 条跨四领域的 prompt 显示拒绝行为不一定从文本迁移到工具使用。→ [arXiv](https://arxiv.org/abs/2610.28982)
