## 📌 头条

### Claude 动态多 Agent 工作流开始公测

Anthropic 把「Claude Managed Agents 动态工作流」放进了公开测试版:一个主 agent 负责写计划,计划拆成多个阶段跨多个子 agent 运行,最后合并结果——这正是 orchestrator-worker 那套模式的官方托管实现。官方给了个硬对比:在一个 11.6 万行的代码库里埋了问题,动态多 agent 方案比单 agent 更快定位。对你意味着什么:如果你此前在用 LangGraph 或 CrewAI 手搓这类编排,现在有了可直接试的托管基线,值得跑个 benchmark 对比下自己的实现在同类大仓场景下的召回和耗时。具体阶段划分和合并策略官方公告没完全展开,接入前要看清它的计费口径。

→ [原文](https://www.oschina.net/news/502951)

### Anthropic:以后 CLAUDE.md 和 AGENTS.md 都不用了

围绕「agent 上下文该写进 CLAUDE.md 还是社区约定的 AGENTS.md」的争论,Anthropic 给的答案是——以后两个都不用。这触及的是 context engineering 的核心路线之争:到底靠静态配置文件喂上下文,还是让 agent 运行时自己检索组装。报道基于 InfoQ 的转述,Anthropic 的具体替代方案和迁移路径要看一手公告才能确认边界。对你意味着什么:如果你的项目里已经维护了一堆 CLAUDE.md/AGENTS.md,先别急着大改,看清官方新机制落地后再决定要不要迁。

→ [原文](https://www.infoq.cn/article/MAo3KoDWm9FGIcKau9AK)
