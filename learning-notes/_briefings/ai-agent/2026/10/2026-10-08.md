## 📌 头条

### LangChain Managed Deep Agents v0.9：Agent 能自己排期了

LangChain 发布了 Managed Deep Agents v0.9（Public Beta），一次给了三样东西：Agent 能在对话中给自己创建定时/循环任务（新的 Schedules SDK，底层就是 cron 表达式，到点由 LangSmith 起一个新 run，结果回到原来的频道）；一个部署可以 per-run 动态配置——在每次运行开始时读 runtime context，按发起的频道或用户决定这次用哪个 model、哪些 skills、挂哪些 MCP server；以及 Slack reactions（默认 👀，表示 Agent 已经收到正在想）。per-run 配置这条对你最有参考价值：官方明确说这不是靠 prompt 让模型自己选工具，而是在模型跑之前就把工具集定死，既缩小了 context、又顺带当成了访问控制，还能选模型本身（这是模型没法自己做的）。如果你在用 LangGraph/MCP 搭多团队共用的内部 Agent，可以照这个「一个部署、按 context 装配」的思路改，省掉给每个仓库维护一份近似副本。

→ [原文](https://www.langchain.com/blog/managed-deep-agents-schedules-per-run-configuration-slack) / [Skills 改版](https://www.langchain.com/blog/revamping-skills-in-deep-agents)

### Cloudflare 把安全运营拆成一队 Agent

Cloudflare Managed Defense 公开了它的 agentic 安全运营 harness：用一组各司其职的 AI Agent（跑在 Workers 上、吃全球网络遥测数据）来分析安全告警。按官方描述，它的核心设计是把「确定性的证据收集」和「模型推理」分开——先用确定性手段把证据凑齐，再让模型基于这些证据给出有依据（evidence-grounded）的建议交给分析师，而不是让模型凭空判断。这个「证据与推理分离」的分层正是 Agent 落地到高风险场景（安全、支付、运维）时反复出现的正确姿势：模型只做推理，不直接持有写权限和事实判定。想把 Agent 用在你们生产告警/排障流程里的话，这篇是一个来自一手厂商的参考架构。

→ [原文](https://blog.cloudflare.com/agentic-security-operations)

## 📈 趋势

- 🆕 托管 Agent 平台开始卷「运营能力」——自排期、per-run 装配、Slack 原生交互，而不只是比模型强不强
- 🔺 「证据与推理分离」成为 Agent 落地高风险场景（安全/支付/运维）的通用正确姿势：模型只推理，不碰写权限和事实判定
- 🔺 MCP 从「让 Agent 用工具」延伸到「让一个 Agent 操控另一个 Agent」，编排正在往更上一层走
