### 当 prompt 变成 shell：agent 框架把注入升级成 RCE

微软 Defender 安全团队披露 Semantic Kernel 框架两个漏洞（CVE-2026-25592、CVE-2026-26030），把"prompt injection 顶多让 bot 说错话"这个旧认知彻底打破——注入内容可以让 agent 把攻击者控制的值传进真实系统函数，进而触发远程代码执行或任意文件写入，影响 Python / .NET 版本。配合本月安全圈的另一组发现：OX Security 称 MCP 实现存在跨 Python/TypeScript/Java/Rust 的系统性"工具投毒"面，早期研究测到多达约 43% 的 MCP server 含命令注入风险、约三分之一允许不受限网络访问。核心结论是架构性的，不是某个实现的 bug：一旦模型能调工具，工具描述、检索内容、stdout 全都成了可执行攻击面。对你最实在的动作：把 agent 的工具输出和外部检索内容当不可信数据隔离，给能写文件、跑脚本的工具加白名单和最小权限，别让注入有机会落到 shell。

→ [微软安全博客](https://www.microsoft.com/en-us/security/blog/2026/05/07/prompts-become-shells-rce-vulnerabilities-ai-agent-frameworks/) / [MCP 工具投毒分析](https://itecsonline.com/post/mcp-tool-poisoning-enterprise-ai-agent-security-2026) / [MCP server 安全审计](https://beyondscale.tech/blog/mcp-server-security-guide)

## ⚡ 快讯

- **Google I/O 2026 放出 Gemini Omni + 3.5 Flash**：Gemini 3.5 Flash 主打 agentic 场景，官方称输出速度接近 300 token/s、约为同档前沿模型的 4 倍，价格压到对标模型的二分之一到三分之一，agentic 与 coding benchmark 还反超了更大的 3.1 Pro；Omni 则是输入输出双向多模态的视频模型，能用对话指令改场景、换风格、调镜头。低延迟 + 低价正是高频工具调用 agent 的痛点，值得拿 Flash 跑一轮自己的 agent 任务测吞吐和工具调用准确率。 → [Gemini 3.5 官方博客](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-5/) / [Ars Technica](https://arstechnica.com/google/2026/05/google-announces-agent-optimized-gemini-3-5-flash-and-a-do-anything-model-called-omni/)
- **Gemini Spark：Google 的 24/7 个人 AI 助手**：TechCrunch 实测 Google 新推的 Gemini Spark，能自动处理收件箱摘要、本地活动规划这类日常任务，结论是"出乎意料地好用"，但也吐槽不清楚为何要单独做成一个产品而非并进 Gemini 主线。这类常驻型个人 agent 的看点是任务编排和触发机制，可参考它怎么把多步骤日常事务串起来。 → [TechCrunch](https://techcrunch.com/2026/05/30/i-put-googles-24-7-ai-assistant-gemini-spark-to-work-and-its-actually-pretty-useful)
- **CAPTCHA 仍能识破 AI agent**：Roundtable 的研究显示，现有 CAPTCHA 体系对 AI agent 仍有相当检测力，HN 82 分、63 评论。这对"让 agent 自动操作网页"的方向是个现实约束——浏览器 agent 在真实站点上仍会被人机验证拦下。做 web automation agent 的要把验证码识别失败当常态来设计降级和人工接管路径。 → [Roundtable 研究](https://research.roundtable.ai/captchas-detect-ai/)
- **Groq 在英伟达 200 亿美元"非收购"后拟融资 6.5 亿**：据 Axios，AI 推理芯片创业公司 Groq 正寻求 6.5 亿美元内部融资，从硬件转向更聚焦 inference。推理成本是 agent 规模化的硬约束，Groq 这类专攻低延迟推理的玩家如果跑通，对高频调用的 agent 工作负载是实打实的降本机会。 → [TechCrunch](https://techcrunch.com/2026/05/29/after-nvidias-20b-not-acqui-hire-ai-chip-startup-groq-reportedly-raising-650m)
- **某公司单月误烧 5 亿美元 Claude 账单**：Tom's Hardware 报道，一家未具名公司因没给员工 Claude 许可证设用量上限，单月烧掉 5 亿美元。极端归极端，但点中了 agent 工程的真问题：token 成本就是 agent 的运行成本，effort 控制、缓存、模型分级、用量限额不是优化项而是预算底线。接 agent 进生产前，先把每个 license / API key 的用量闸门焊死。 → [Tom's Hardware](https://www.tomshardware.com/tech-industry/artificial-intelligence/mystery-company-accidentally-blew-usd500-million-on-claude-in-a-single-month-failed-to-put-usage-limit-on-licenses-for-employees)
