## 📌 头条

### 企业 IT agent 评估白板填上：ITBench-AA 与阿里云 RCA Benchmark 同周发

5/27 Artificial Analysis 联合 IBM 在 Hugging Face 把 ITBench-AA 的 SRE 部分跑分挂出来：所有前沿模型（GPT/Claude/Gemini）在 Kubernetes 故障根因分析这一项上的得分都低于 50%，是目前最不饱和的 agent benchmark 之一。同期还测出一个反常识的结论：长程 trajectory 跟最终准确率没正相关，turn count 跨近 3 倍变化但分数不变——agent 跑得久不等于跑得对。换到中国侧，阿里云在同一周发布开源 RCA Benchmark（联合信通院、中科院、清华、复旦、南开），目标也是 Agentic Ops 的根因分析能力评估。两边一前一后把「企业 IT 自动化是否真有用」这块评估白板补上：之前业内还在用 Terminal-Bench 这种早已被刷爆的指标，现在做 SRE/AIOps 方向的 agent 应该立刻接 ITBench-AA 重新基线，国内场景再加一个阿里云 RCA Benchmark 验证迁移性。

→ [Hugging Face / Artificial Analysis 结果](https://huggingface.co/blog/ibm-research/itbench-aa) / [ITBench-AA Leaderboard](https://artificialanalysis.ai/evaluations/itbench-aa) / [阿里云 RCA Benchmark](https://my.oschina.net/u/3874284/blog/19681780)

### Interrupt 2026 一周打包：LangSmith Engine 上线 + Sandboxes GA

LangChain 5/27 五月 newsletter 把 Interrupt 2026 两天的发布全部 ship 出来：LangSmith Engine 自动监控生产 trace、把失败聚类成具名 issue、对照源码定位 root cause、生成 PR 等你 review；LangSmith Sandboxes 升 GA，每个沙箱是 hardware-virtualized microVM、跟其他服务和其他沙箱内核级隔离，能安全跑模型生成的不可信代码；同时官宣的 Auth Proxy 在网络层注入凭据，避免 prompt injection 把 API key 从 prompt/log/file/依赖里泄出去；面向自托管 LangSmith on K8s 的 Mission Control 也同期 GA。23 场 Interrupt 2026 talks（来自 LinkedIn / Rippling / Cisco / Lyft 等）已挂 on demand。整周打包看下来，agent 工具链正式从「写出来能跑」进入「跑稳了能恢复」阶段。如果你在跑生产 agent，本周值得做两件事：测试环境挂上 LangSmith Engine 跑一周看它聚类出的 issue 是否覆盖你的痛点；模型生成代码不要再裸跑 docker，迁到 Sandboxes 一行 SDK 就能起。

- **Lyft 自服务 agent 平台**：LangChain 同周发 Lyft 案例：用 LangGraph + LangSmith 把客服 agent 平台做成自服务，子团队从「月」级 build time 压到「周」。LangGraph 在里面负责把司机/乘客请求路由到一组 specialized subagents，安全检查、状态管理、handoff 都内嵌在图里。是 Interrupt 2026 这波 GA 之后第一个上线案例，企业方做内部 agent 平台可以直接拿来对照工程结构。 → [LangChain 案例](https://www.langchain.com/blog/lyft-built-a-self-serve-ai-agent-platform-for-customer-support-with-langgraph-and-langsmith)
- **claude-mem 一天涨 352 星**：GitHub trending 今日新面孔：thedotmack/claude-mem，给 Claude Code 装持久记忆——会话期间自动捕捉 agent 行为、用 agent-sdk 压缩、再注入回未来会话的 context。已支持 Codex、Gemini、Hermes、Copilot、OpenCode 等多家。当前累计 star 已到 7 万级，单日就涨了 352 颗。如果你跟 Claude Code 重度合作但每次都重新解释项目背景，今天值得装一下试试。 → [GitHub](https://github.com/thedotmack/claude-mem) / [OSChina 速览](https://www.oschina.net/news/446641)
- **Apache RocketMQ 5.5.0 LiteTopic**：Apache RocketMQ 5.5.0 正式发布，社区提案 RIP-83 定义的 LiteTopic 进入开源版本，专门面向 AI Agent、异步任务和海量轻量会话场景：单实例支持百万级轻量通道，每个 session 对应一个独立 LiteTopic（推荐命名 `chat/{sessionID}`），消费状态独立持久化、事件驱动分发。多 agent 异步通信、MCP/session state 管理这类原本在 Redis pub-sub 上凑活的场景，现在终于有 production 级的开源方案。 → [OSChina 报道](https://my.oschina.net/u/6179068/blog/19684510) / [Multi-agent 最佳实践](https://rocketmq.apache.org/docs/bestPractice/04multiagent/)
- **MiniMax-M2 论文披露 229.9B/9.8B activated**：5/27 上 arXiv 的 MiniMax-M2 系列论文给了完整数字：旗舰 M2 是 229.9B 总参数 + 9.8B 激活/token 的 MoE 架构，专门为 agentic 部署做端到端设计——三个支柱是 agent-driven data pipeline、agentic coding/工具使用的可验证 trajectory、面向 agent 的 RL 训练。开源权重已在 Hugging Face、Azure AI Foundry 上线，200K context、131K 输出。看推理成本：每 token 只激活 4.3% 的参数，是目前 agentic coding 这一档里压价空间最大的开源选项。 → [arXiv](https://arxiv.org/abs/2605.26494) / [Hugging Face Paper Page](https://huggingface.co/papers/2605.26494)
- **微软 Yusuf Mehdi 把 Windows 推向 Agentic OS**：微软执行副总裁 Yusuf Mehdi 5/26 内部备忘录宣布 2027/6 离职，离职前最后一年主导 Windows 向 Agentic OS 的转型，推动 One Copilot 愿景落地。背景是 PC 装机量持续低迷、Copilot+ PC 渗透不及预期，靠应用层加 agent 已经撑不住，「OS 即 agent runtime」成为下一个赌注。Windows 这件事跟 Apple Intelligence 走过的弯路是同一类：开发者要等很久才能看见底层 API 释放，所以现阶段你的 PC agent 该对准的还是 Claude Code/Codex 这种应用层 harness。 → [OSChina 报道](https://www.oschina.net/news/446402)
- **Snowflake Cortex Code Agent SDK 拆解**：InfoQ 中文 5/26 出了一篇 Snowflake Cortex Code Agent SDK 的技术实践：在 Snowflake 上构建可编程 AI Agent 的完整链路，给的是真实 SDK 调用细节而不是营销稿。对在数据仓库里直接挂 Agent（in-warehouse compute、避免数据外流）的团队是直接的样本——尤其是受合规约束、数据出不了 VPC 的金融/医疗场景。 → [InfoQ 中文](https://www.infoq.cn/article/yB9yJlJADmFBNurNUEaG)
- **AI 订阅制 vs API 价差被拆穿**：OSChina 5/27 转发的长文把当下 AI 厂商的定价模型摆在桌面上：订阅制比 API 便宜 10-40 倍，90 美元订阅 Claude 相当于白嫖几千美元的 API 调用量。补贴在 SaaS 时代很常见，但 agent 时代单 user 调用量随着工具循环线性甚至指数膨胀，「开源本地模型 + 人力外包」正在颠覆前沿实验室的成本逻辑。如果你在评估 long-running agent 的 BOM，本周可以拿这套数据反推一遍：自家 token 用量是不是已经到必须自托管开源模型 + RL 微调的阈值。 → [OSChina 长文](https://www.oschina.net/news/446711)
- **Zara Zhang：一线 coding agent 用法变化**：LangChain 团队的 Zara Zhang 5/26 发推说她近一个月 coding agent 用法的两个变化：一是从 terminal 转去 Codex/Claude Code 桌面 app，Codex Mac app 体验最佳；二是从「全 Claude Code」转成 Codex 和 Claude Code 各 50% ——Codex 像可靠工程师，给定明确任务直接干完；Claude Code 更像一个能沟通的 PM/设计师，前期模糊问题用它聊。这种「按 task 类型分流」是当前 prosumer 群体最稳定的复合用法，比单押一家更有效率。 → [Zara 推文](https://x.com/zarazhangrui/status/2059354487823978586)
