### xAI 推出 Grok Build：Agentic CLI 赛道再添一员

xAI 把 Grok Build 早期测试版放给 SuperGrok Heavy 订阅用户，访问入口是 x.ai/cli。它是一个面向编码、应用构建和工作流自动化的 agentic 命令行助手——按 xAI 的定位，是要直接对标 Claude Code、OpenAI Codex CLI 和 GitHub Copilot CLI。这条线现在已经五家在跑：Anthropic、OpenAI、GitHub、xAI、刚刚被微软力推的 Copilot CLI（昨天微软还在内部砍掉 Claude Code 用量），Grok Build 入场把战线又拉长一截。如果你在 Mac 上用 Claude Code，现在的 reasonable move 是把 Grok Build 排进观察列表，先用一次跑完 SuperGrok Heavy 的免费额度做对比，看输出风格和长任务表现。

→ [开源中国报道](https://www.oschina.net/news/441096)

### LangChain Interrupt 2026 总览：runtime 治理 + 观测层 + 自动 triage 一并落地

昨天我们提了 LangChain Labs 和 Agent Harness 的拆解，今天 LangChain 把整场 Interrupt 2026 发的所有产品打包成《Everything we shipped at Interrupt》。三件最关键：LangSmith **LLM Gateway** 把 spend limits、PII redaction、trace continuity 直接做到 agent 生命周期里——以前需要 Portkey/LiteLLM 加自建治理层，现在可以一行接入 LangSmith；**SmithDB** 是 LangSmith 自研的分布式数据库，专门为 agent 观测设计，比通用 OLAP 快 12 倍且支持完整 portability；**LangSmith Engine** 监听生产 trace、把失败自动聚类成 named issue 并提出修复 + eval 覆盖建议，让你不用再人工 triage agent 故障。三件加上昨天的 Labs / Harness，组合成"agent 全生命周期平台"。Walter 已经在用 LangGraph，今晚可以先把 LangSmith Engine 的 issue 聚类开起来，存量 trace 直接入库就行。

→ [Interrupt 总览](https://www.langchain.com/blog/interrupt-2026-overview) / [LLM Gateway](https://www.langchain.com/blog/introducing-llm-gateway) / [SmithDB](https://www.langchain.com/blog/introducing-smithdb) / [LangSmith Engine](https://www.langchain.com/blog/introducing-langsmith-engine)
