## 📌 头条

### Anthropic Glasswing 累计 10000+ 高危漏洞，苹果首批吃完单

Anthropic 在 5 月 26 日公布 Project Glasswing 阶段进展：让 Claude Mythos 扫描了 1000 多个开源项目，挖出 23019 个问题，其中 6202 个是高危/严重漏洞；自家加六家独立安全公司复核了 1752 条，超过 90% 是真阳性。同日 OSChina 报道苹果 macOS Tahoe 26.5 一次性修了 70+ 漏洞，多个由 Claude 上报，集中在内核、WebKit 和系统服务，部分能拿 root、突破沙箱。组合在一起的信号有两层：一是「LLM 找漏洞」从 demo 进入工业管线，wolfSSL 那种亿级设备库的伪造证书漏洞已经被验证可被自动构造 PoC；二是 Anthropic 自己也承认现在的瓶颈不在挖，而在补——开源 maintainer 处理不过来，所以他们顺势接 OpenSSF Alpha-Omega、把 Claude Security 推到 Beta。如果你做企业 agent，本周值得关心一件事：你 dependency tree 里的开源库是不是 Glasswing 已扫范围，是的话当前披露窗口（90 天）里别瞎升级。

→ [Anthropic 官方更新](https://www.anthropic.com/research/glasswing-initial-update) / [Help Net Security 数据复盘](https://www.helpnetsecurity.com/2026/05/26/anthropic-project-glasswing-update/) / [苹果 macOS 漏洞修复](https://www.oschina.net/news/446228)

### NSA 给 MCP 立规矩，arXiv 同档期连发三篇 MCP 安全论文

NSA 旗下 AI Security Center 在 5 月 20 日发布 CSI《Model Context Protocol: Security Design Considerations for AI-Driven Automation》，明确把 MCP 列为高敏环境必须谨慎部署的协议——传统 authn/authz 不够用，动态工具调用、隐式信任和上下文共享是新风险面。官方建议把 agentic 环境当作「连续体」对待，不能在端点级修补。把这件事放到本周 arXiv 看更有意思：5/26 同一天上架了 ToolRegistry（统一 RPC 抽象，跨 MCP/OpenAPI/LangChain 单一 stub）、LiveMCP-101（动态 MCP benchmark，给多步任务真实压力测试）、MCPXKIT（专门做 MCP 安全分析、针对 Tool Poisoning Attack 给统一工具链）。从 NSA 的高层指引到工具链层面的具体测评/防御套件，整个 MCP 安全生态在一周内被显著拉升。下一步如果你的 Agent 还在用 raw HTTP 调 MCP server，建议先跑一遍 LiveMCP-101 评估，再用 MCPXKIT 验证 server side 的 schema 和权限边界。

→ [NSA 公告](https://www.nsa.gov/Press-Room/Press-Releases-Statements/Press-Release-View/Article/4496698/nsa-releases-security-design-considerations-for-ai-driven-automation-leveraging/) / [ToolRegistry](https://arxiv.org/abs/2507.10593) / [LiveMCP-101](https://arxiv.org/abs/2508.15760) / [MCPXKIT](https://arxiv.org/abs/2508.12538)

## ⚡ 快讯

- **OpenAI Codex 上线「锁屏运行」**：OpenAI 在 5/21 给桌面端 Codex 加了 Locked Use 功能：通过一个 Apple 授权插件临时解锁 Mac 完成任务，用户在手机上就能下任务，屏幕保持锁定状态执行。一线复盘里 Peter Yang 当晚发推说 Codex 用 browser 自检自己工作的能力很强，但前端/设计任务 Claude 仍占优——锁屏 + 浏览器自检的组合让无人值守 desktop agent 的可行性窗口又往前推了一格。 → [OSChina 报道](https://www.oschina.net/news/446124) / [Peter Yang 推文](https://x.com/petergyang/status/2059099566377693305)
- **LangChain 推 Mission Control 接管自托管 LangSmith**：LangChain 5/26 官博推出 Mission Control，目标是给在 K8s 上自托管 LangSmith 的团队一个统一控制面：集群内配置、preflight 检查、健康视图、版本发布、诊断。逻辑跟整个 agent 工具链「harness 化」的趋势一致——基础设施越来越重，靠 helm chart 凑活的时代过去了。如果你已经在 K8s 上跑 LangSmith，本周可以试着把 Mission Control 装上看 preflight 抓到什么之前埋的雷。 → [LangChain 博客](https://www.langchain.com/blog/mission-control-operating-self-hosted-langsmith-on-kubernetes)
- **Snowflake Cortex Code Agent SDK 拆解**：InfoQ 中文 5/26 发出 Snowflake Cortex Code Agent SDK 的深度技术实践文：在 Snowflake 上构建可编程 AI Agent 的完整链路，给的是真实 SDK 调用细节而不是营销稿。对在数据仓库里直接挂 Agent（in-warehouse compute、避免数据外流）的团队是直接的样本。 → [InfoQ 中文](https://www.infoq.cn/article/yB9yJlJADmFBNurNUEaG)
- **OfficeDex 开源：把 Claude/Codex 思路搬到办公场景**：OSChina 5/26 报道国内团队开源 OfficeDex（VibeOfficing 平台），定位是 office 版 coding agent——绕开「HTML 转 PPT 跑版」「AI 写得出方案做不出能交付的 PPT」这些常见坑，主打从 outline 直出可交付件。GitHub 在 officecli/officedex，是少数把 agent 形态做到办公而不是研发场景的开源样本，对国内做内部办公提效产品的团队可以直接读源码。 → [OSChina 报道](https://www.oschina.net/news/446049) / [GitHub](https://github.com/officecli/officedex)
- **DeepSeek 算法-硬件十万亿叙事被拆解**：OSChina 转的 Bookworm Engineer 长文 5/25 火起来：把 DeepSeek 视为「以算法创新撬动中国 AI 硬件生态」的体系玩家，不只是模型实验室。文中具体拆了 KV cache 压缩比、推理阶段访存瓶颈和它怎么反推国产卡设计。叙事偏宏大但技术细节扎实，值得跟昨天 V4 Pro 永久 75% 折扣 + Reasonix 那条线一起读，对推理成本曲线判断有用。 → [OSChina 长文](https://www.oschina.net/news/445744)
- **Anthropic 落地首尔，任命韩国 Representative Director**：Anthropic 5/26 官宣 KiYoung Choi 为韩国负责人，首尔办公室即将开张。继东京、新加坡之后，Anthropic 在亚洲扩张的节奏明显在加快——和 Microsoft 取消内部 Claude Code 授权的传闻形成反差，企业渠道的真实信号还是「往外推」而不是「往后撤」。 → [Anthropic 公告](https://www.anthropic.com/news/kiyoung-choi-representative-director-anthropic-korea)
- **Stop Comparing LLM Agents Without Disclosing the Harness**：arXiv 5/26 一篇立场论文非常应景：在长程任务上，agent 性能差异更多由 harness（上下文构建、工具交互、编排、校验）决定，而不是被包裹的模型本身。论文提出「Binding Constraint Thesis」，建议任何 agent 比较都必须披露 harness 配置才有意义。延续了上周 Hugging Face 词汇表 + Anthropic harness engineering 的讨论——再不披露 harness 的 leaderboard 应该被默认打折。 → [arXiv](https://arxiv.org/abs/2605.23950)
- **Peter Yang：搭好系统比 ship MVP 更重要**：Peter Yang 5/25 一条推文短小但抓得很准：「以前像是拖延的事——搭系统而不是直接做 MVP——现在反而是 AI Agent 时代 ship 速度的前置条件。」他引用 Ryan Carson 一天 ship 10 个 PR 的核心方法：把文档、cron job、skill 文件全部前置搭好。这跟 Steipete 同期吐槽「skill 描述写成长篇大论会污染每条 context」的「token-efficient skill」论点是同一根线——agent 时代的工程效率正在被 skill/harness 的规范性反噬或加成。 → [Peter Yang 推文](https://x.com/petergyang/status/2059029752858775581) / [Steipete 推文](https://x.com/steipete/status/2058917897590673525)
