## 📌 头条

### DeepSeek Harness 把 Codex 变成子 Agent

DeepSeek 官方的 agent harness 公测满一周就发了 v0.1.0-rc.8，14 项更新里最显眼的是两件事。一是多模态：模型适配器可以开启原生图片请求，`/goal`、`/plan` 这类命令能直接吃图文混合输入，`@` 菜单也开始能引用文件和历史会话。二是子 Agent 体系继续吃进别家 CLI——Claude Code 和 Codex 进一步接入，其中 Codex 新增非交互权限模式（可以跑在无人值守流程里）和多命名实例（同时挂多个不同配置、不同名字的 Codex 子 agent 共存）。Harness 自身的定位是「everything is a plugin」：模型适配器、工具注册表、会话日志、沙箱、调度乃至 agent 主循环都是插件，都能从配置里换掉；这一版 Windows 侧还加了持久 PowerShell 会话，极简模式预设默认开启。对你意味着什么：如果你在拼多 agent 编排，rc.8 是目前少见的「把别家 CLI agent 当子进程挂进来」的现成实现，值得先读它的插件契约再决定自己那套要不要重写。

→ [开源中国](https://www.oschina.net/news/502044/deepseek-harness-0-1-0-rc8) / [更新逐条](https://finance.biggo.com/news/084c5434-4491-4b0d-9d16-756454ea4d0b)

### 撞名 harness 的跑分神话被 Terminal Bench 打回

一个和 DeepSeek 官方 harness 撞名的第三方项目本周刷屏：`pip install deepseek-harness` + `dsh` CLI + MCP server 四种封装，README 号称记录了 16 个协议 quirk、12 个 probe、270+ 次试验，卖点是「DeepSeek V4-Flash 配上这个外挂就能打 GLM-5.3、甚至碾压 Claude Fable 5」。GitHub 用户 GoForceX 拿 Terminal Bench 实测的结论正好相反：性能反而下降，token 开销上升，速度更慢，至今没人复现出原始声明。有意思的不是谁赢，而是那个机制——harness 层的 prompt 与协议补丁极容易在自建评测里放大收益，换到公开 benchmark 上就蒸发。对你意味着什么：下次看到「小模型 + harness 碾压旗舰」的说法，先在自己的任务上跑一遍 Terminal Bench 或 SWE-bench 子集，再决定要不要 pip install。

→ [InfoQ 报道](https://www.infoq.cn/article/MKDQBpGhC5Uu3pB4kMbC) / [争议项目](https://github.com/HenryZ838978/deepseek-harness)

## 📦 项目 & 论文

| 项目 | 描述 | 链接 |
|------|------|------|
| Task-Conditioned Least-Privilege | 给终端和 MCP agent 学「任务条件下的最小权限」，针对的是 agent 行使了用户没授权、任务也不需要的权限这类超额授权错误 | [→](https://arxiv.org/abs/2608.18351) |
| One Gate Is Not Enough | 把 authority / resource / evidence 三类 pre-action 门做成可组合的有状态控制，而不是指望单一 gate 兜住所有情况 | [→](https://arxiv.org/abs/2608.18360) |
| Position: MAS 应优先解决并发控制 | 主张「加 agent 反而更不可靠」的根因是并发控制问题，不是协作范式问题 | [→](https://arxiv.org/abs/2608.18092) |
| SkillGate | 长程 agent 的 in-policy skill 选择训练——公开 skill 库已有上千份，「该读哪一份」本身变成了要学的决策 | [→](https://arxiv.org/abs/2608.18852) |
| ComponentBench | computer-use agent 的组件级失败诊断，补上长程工作流 benchmark 与原子 GUI grounding 之间那层没人测的中间地带 | [→](https://arxiv.org/abs/2608.18307) |
| Adversarial Review | 用结构化分歧而非角色分工做仓库级 agentic code review，起点是「堆 agent 数量在仓库级任务上收益递减」 | [→](https://arxiv.org/abs/2608.18167) |

**Looped Language Models Improve Compositional Tool Calling** — 循环语言模型在推理 benchmark 上早有成绩，但在组合式工具调用上一直没人系统研究，这篇把这块补上了。→ [arXiv](https://arxiv.org/abs/2608.18171)

**What Makes Software Issue Resolution Tasks Difficult for Agents?** — benchmark 分数在快速饱和却越来越难解释，作者做的是控制变量地拆解「到底什么让一个 issue 对 agent 变难」。→ [arXiv](https://arxiv.org/abs/2608.18280)

## 📈 趋势

- 🆕 harness 层成了新的竞争面 — 模型之外，插件契约和「能不能把别家 CLI agent 挂成子进程」开始影响生态归属
- 🔺 执行前门控（pre-action control）— 同一批 arXiv 里至少三篇在做授权 / 资源 / 证据门，tool-call 授权正从写在 prompt 里的约束转向可组合的确定性门
- 🔺 agent 的 CI/CD 基础设施 — LangSmith Preview Builds 把「每个 PR 一个 staging」这套 web 时代的成熟做法搬到了 agent 部署上
- 🔻 未复现的 harness 跑分 — 社区对「小模型 + 外挂碾压旗舰」的耐心明显在耗尽，第三方 Terminal Bench 复测正在变成默认要求
