## 📌 头条

### A2A 转入 AAIF，跟 MCP 同一个屋檐

Google 创建的 Agent2Agent（A2A）协议要换个家：从 Linux Foundation 的大盘子里挪出来，成为 Agentic AI Foundation（AAIF）的托管项目，跟 MCP 并列——一个管 agent 连工具，一个管 agent 连 agent。AAIF 去年 12 月成立时不到 40 家成员，现在超过 250 家，Google、微软、亚马逊、Anthropic、OpenAI、Bloomberg、Shopify、Block 都在名单里；AAIF 执行总监 Mazin Gilbert 的说法值得琢磨——「开放协议和开放标准是两回事，企业要的不是某一个协议，而是整个栈都开放」。但协议标准化不等于协作可靠：同期新公开的一篇论文正好指出 A2A/MCP 规定的是传输与发现，不保证效率、个体理性或防策略操纵，作者把交替出价谈判和 VCG 式拍卖编码成 A2A 消息 schema 后实测（每种条件 N=30），两个模型在拍卖里都做到 100% 高效分配，可真实出价的表现天差地别——一个每次都报出自己的真实估值，另一个只有 3.3% 的 trial 如此；三方公平分配任务只产出 4.2% 可用结果，这个负面结果被原样报了出来。结论很实用：机制层面的激励相容不会自动传递到 LLM agent 的行为上。如果你在做跨厂商 agent 互调，别指望协议层帮你兜住博弈层，验证和修复得自己写进消息校验环节。

→ [Axios 独家](https://www.axios.com/2026/08/17/a2a-agentic-ai-foundation-open-ai-standards) / [arXiv 2608.14613](https://arxiv.org/abs/2608.14613)

### agent 自己付钱，预算由基础设施强制

LangChain 和 AWS 一起放出了 AgentCore Payments 中间件：agent 的工具打到付费 API、拿回 HTTP 402 和 x402 payload 时，中间件自己接住——先用本次 session 的预算校验，超限直接拒绝且根本不签名；在预算内才通过 AgentCore PaymentManager 签名，然后带着付款凭证重试原请求，agent 那一侧看起来就像第一次就返回了 200。关键不在于「能付钱」，而在于这个上限是 AgentCore 在基础设施层强制的、不是 prompt 里的一句话，官方明确说即便 agent 被攻破它也仍然成立。接入成本是一个 config 加一条 middleware——`AgentCorePaymentsConfig(auto_session=True, auto_session_budget="5.00")`——对比之前的三种活法（换个免费源、每个付费服务手写 30 到 50 行 wrapper、或者干脆把 paywall 抛给人类），省下的是重复劳动加上一层能审计的账。底层协议 x402 由 Coinbase 在 2025 年 5 月创建、现在归 Linux Foundation 托管，稳定币微支付按秒结算、单笔成本不到一分钱，这是「按次计费」在 agent 负载上能成立的前提；LangSmith 那侧则把「买了什么」和「为什么挑它」记在一起，方便事后对账和上线前跑 eval。如果你的 LangGraph 图里已经有要花钱的工具，把预算断言从 prompt 挪进 middleware 是这周最值得做的一次重构。

→ [LangChain 博客](https://www.langchain.com/blog/langchain-agentcore-payments) / [AWS 实现示例](https://aws.amazon.com/blogs/machine-learning/build-openclaw-agents-that-transact-with-amazon-bedrock-agentcore-payments/)

## ⚡ 快讯

- **OPPO 唐凯**：在同一场支付宝生态大会上给出了一句挺准的诊断——「模型能力已经超过产业链的组织能力」。他的意思是做一个体验不错的 To C agent 已经不难，难的是形成商业闭环，因为行业里还有大量服务和生态孤岛；从 MCP 的「agent 连工具」到 A2A 的「agent 连 agent」，基础设施都在回答同一个问题 → [雷峰网](https://www.leiphone.com/category/industrynews/Fw53BFd8oELxtNMl.html)
- **GitHub Copilot**：官方博客讲了 canvases 的用法：不再把 chat 当作工作发生的唯一地方，而是给开发者和 agent 一块持久的共享画布，让工作随进展可见、可干预、可审批——本质是承认「过程滚没了」才是 agent 协作最大的成本 → [GitHub Blog](https://github.blog/ai-and-ml/github-copilot/how-canvases-make-agentic-workflows-visible-steerable-and-cost-efficient)
- **豆包**：工作任务模式上新 Windows 虚拟桌面：在电脑端选工作任务模式和本地电脑，技能栏点「操作电脑」并完成授权后，豆包就能在虚拟桌面里看屏幕、移鼠标、点按钮、敲键盘。放进虚拟桌面而不是直接接管真实桌面，是这类 computer-use 功能目前较稳妥的边界 → [36氪](https://www.36kr.com/newsflashes/3944597200862593)
- **阿里云**：8 月 18 日启用韩国第三座数据中心，同步上线 Agentic AI 相关服务；本轮扩建后全球覆盖 30 个地域、104 个可用区，还计划拓到巴西等地——agent 服务开始跟着区域基础设施一起铺，延迟和数据驻留是绕不开的现实约束 → [36氪](https://www.36kr.com/newsflashes/3944499339230593)
- **Geoffrey Litt（Notion）**：七月在 AI Engineer 大会上的演讲被重新翻出来讨论，标题很直白：理解才是新的瓶颈。agent 写代码的速度已远超人类吸收代码的速度，但他的结论不是「那就别看了」，而是得换个方式看——这是认知问题不是技术问题 → [开源中国编译](https://www.oschina.net/news/501959/understanding-is-the-new-bottleneck)
- **Pi（Earendil）**：官方博客拆了自家编码助手的 compaction 机制：聊到三十轮上下文炸窗口是所有 LLM 编程助手的共同问题，两种处理路线都不完美，文章讲清了它怎么权衡——想自己给 agent 做上下文压缩的可以直接抄思路 → [开源中国编译](https://www.oschina.net/news/501967/compaction-in-pi)

**Beyond Pass@k: Measuring Reliability and Security of Agentic Code Generation** — 指出当前 AI coding agent benchmark 普遍误用 pass@k：把 n 设成单次提交里的单元测试数量，而不是独立 rollout 次数，于是把测试集规模和尝试独立性混为一谈；作者给出反例证明并提出 reliability@k，即把同一个估计量按 n = 独立尝试次数正确使用。→ [arXiv 2608.14711](https://arxiv.org/abs/2608.14711)

**When Agentic Executions Fail: Detecting and Localizing Runtime Faults from Telemetry** — 可靠性是整条执行链（工具调用、模型调用、guardrail、agent 间消息）的属性，只看最终答案对错说明不了「怎么失败的、为什么失败」。配套的 AGENTCHAOSBENCH 从执行 telemetry 里检测并定位运行时故障。→ [arXiv 2608.14680](https://arxiv.org/abs/2608.14680)

**Anatomy of a Quantized Agent: VRAM Stability and Forecasting** — 少见的严格限定作用域的实测：一个 LangGraph 写的 CUDA kernel 合成 agent（AgentK）、Q4_K_M 量化族、单张 H100、四个模型 backbone、1920 条轨迹，验证峰值 VRAM 能否按权重 / KV cache / 激活三项分解来预测。本地跑 agent 前想算清显存的值得细读。→ [arXiv 2608.15117](https://arxiv.org/abs/2608.15117)

**Workspace Topology as an Attack Vector in Agentic Coding Assistants** — 把目录深度、代码库规模这些「工作区拓扑」维度定义成一个新攻击面：coding agent 在开发者工作区里有宽泛的文件系统权限，而它又在大量吞第三方代码。→ [arXiv 2608.14876](https://arxiv.org/abs/2608.14876)

**MELD: A Protocol for Merging Knowledge Across Distributed Agentic Memories** — agent 之间已经能共享传输、互调工具，但没有协议让两边的记忆对齐「同一个事实的两种说法」、连接被分开存放的相关事实，或在矛盾时不悄悄丢掉一方。MELD 让联邦式 agent 记忆以知识图谱本身为运行时模型做自我协调。→ [arXiv 2608.16357](https://arxiv.org/abs/2608.16357)
