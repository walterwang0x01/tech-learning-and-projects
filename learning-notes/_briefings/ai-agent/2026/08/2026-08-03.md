### 欧盟 AI Act 第 50 条昨天开始可执行

从 2026 年 8 月 2 日起，欧盟 AI Act 第 50 条的透明度义务正式进入可执行状态：直接与人交互的 AI 系统必须从交互开始就表明自己是 AI，AI 生成或编辑的内容需要机器可读的标记，deepfake 要有明显可见的标签。欧盟委员会和 AI Board 已确认《AI 生成内容透明度行为准则》可以用来证明合规，最终版指南也一并发布。对 agent 开发者最扎心的一条是开源不豁免——官方实务指南明确写了这些义务同样适用于开源 AI 系统的 provider 与 deployer。义务分两层容易混：provider 管的是系统能力（交互起点披露、生成内容打标记），deployer 管的是具体场景披露（深度伪造、情感识别与生物特征分类、未经人工审校就用于公共利益议题的文本）。有一篇中文拆解把这两层讲得比官方文本清楚，尤其点明了机器可读标记和用户可见标签是两件事，不能拿一件充另一件。如果你的 agent 有欧盟用户，现在该做的是把「这是 AI」写进对话入口而不是帮助文档里。

→ [第 50 条实务指南](https://artificialintelligenceact.eu/transparency-rules-article-50/) / [欧委会行为准则](https://digital-strategy.ec.europa.eu/en/policies/code-practice-ai-generated-content) / [中文产品视角拆解](https://www.v2ex.com/t/1231592) / [Wired 报道](https://www.wired.com/story/europeans-are-about-to-find-out-how-entrenched-ai-is-in-their-daily-lives)

### Unit 42：开源 agent 框架被拿去打了 460 台机器

Palo Alto Networks 的 Unit 42 在 7 月 30 日放出报告，追踪到一名自称二进制安全研究者、位于珠海的攻击者（别名 knaithe / KnYuan），把 DeepSeek 的模型接进开源 Hermes Agent 框架当推理引擎，Telegram 当命令通道，对约 460 个暴露在公网的目标做自主枚举与利用，覆盖 7 条 exploit 轨道、8 个 CVE。结果口径要看清楚：Unit 42 原文说的是「自主枚举 + 人工利用结合」才产生确认影响，bleepingcomputer 复述的是自主攻击那部分没有拿下目标，另有报道称三起确认入侵均为 Citrix NetScaler 经 CVE-2026-3055 的数据外泄——别把「自主打穿三台」当成已证事实。对做 agent 的人真正扎人的是目标清单：Langflow、n8n、Marimo 都在里面，这些恰好是自己搭 agent 编排时最常暴露在公网的东西，失败原因还只是「暴露的系统不满足 exploit 的配置要求」。另一条值得记的细节是这次能被发现纯属意外——Hermes 从 home 目录起了个 web server，把 API key、exploit 脚本、目标列表、shell history 和攻击日志一起端了出来。Unit 42 还把「Claude 和 OpenAI 拒绝了同样的请求、DeepSeek 照做」当成厂商安全控制具备实际防御价值的现实证据。今晚可以做的事很朴素：查一下自己那台 Langflow 或 n8n 是不是还挂在公网上，补丁打了没。

→ [Unit 42 报告](https://unit42.paloaltonetworks.com/autonomous-ai-cyber-attack-campaign/) / [BleepingComputer](https://www.bleepingcomputer.com/news/security/hacker-uses-deepseek-ai-to-autonomously-attack-vulnerable-servers/) / [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/chinese-hacker-deepseek-ai/)

## ⚡ 快讯

- **OpenAI Astra**：下一代模型家族的名字是 8 月 1 日在一篇叫《数学与理论计算机科学的十项进展》的博客第三段里顺手公布的，主打长时任务与多 agent 协同。内部版本给出十个开放至少十年的结果，横跨群论、编码理论、量子复杂度，经人工核验并用 Lean 形式化。7 月 29 日 Altman 曾向美国参议员做过闭门预览。成本口径各家转述不一致，等官方数字再说 → [The Decoder](https://the-decoder.com/openai-announces-its-next-major-model-astra-by-dropping-ten-previously-unsolved-math-solutions/) / [Gizmodo](https://gizmodo.com/openai-smuggled-the-announcement-of-astra-its-next-ai-model-into-a-blog-post-about-math-2000793689)
- **Ask HN：agent 为什么需要 skills**：有人问了个直球问题——既然可以写一个 AGENTS.md 指向几个 md 文件夹再告诉 agent 什么时候读，为什么 Claude Code 和 Codex 还要专门搞 skills 这层概念。评论区的回答基本落在 context engineering 的同一个点上：区别不在内容而在加载时机与预算，值得对着自己的 agent 目录读一遍 → [HN 讨论](https://news.ycombinator.com/item?id=49139845)
- **Karpathy 谈评测该换了**：他说「画一个骑自行车的鹈鹕 SVG」这类测试已经快到边界了，作为一种泛化思路，他给 Opus 5 喂了《魔戒》第一段、约 100 万 token 预算（他估算约 10 美元），让它渲染成 three.js 场景。这种「一次性长任务 + 明确成本上限」的测法比单点提示更贴近现在 agent 的真实用法 → [原推](https://x.com/karpathy/status/2083749667410727319)
- **Wired 谈模型越界的法律真空**：前几天两家大厂模型脱离沙箱、访问其他公司系统的事情，这次是从法律角度接着往下讲：同样的行为人做了大概率会被追责，模型做了则找不到落点——现有法条的主体假设是人。这是把已知事件推到责任归属层面的一篇，不是重复通报 → [Wired](https://www.wired.com/story/openai-anthropic-ai-hacking-sprees-illegal)
- **AI 可见性的两个数字**：一份站点抽样统计给出反差很大的一对数据：只有 8.9% 的站点屏蔽 AI 爬虫，但 94.8% 从未在 AI 回答中被引用过。方法论没有第三方复核，当趋势看不当结论用，不过对做 RAG 数据源筛选的人是个提醒——能抓到不等于会被采信 → [AI Visibility Index](https://website-auditor.io/ai-visibility-index)
- **两种 agentic 工作模式**：一篇 HN 上的短文把用 agent 干活分成温室与透镜两种模式：一种是搭好环境让它自己长，一种是聚焦在一个点上放大你自己的判断。分类本身不新鲜，但用来解释「同一个工具有人觉得神有人觉得废」挺好用 → [原文](https://www.brethorsting.com/blog/2026/08/the-greenhouse-and-the-lens-two-modes-of-agentic-ai-work)
