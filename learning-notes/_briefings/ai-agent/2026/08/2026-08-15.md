### Cloudflare 让 MCP 流量在网络层变成可识别、可阻断的对象

Cloudflare One 上线了一组 MCP 治理能力：Gateway 现在能在协议层判断「这是不是 MCP 请求」，所有 Zero Trust 客户从今天起在 HTTP 日志里能看到 MCP 标记，并用新选择器 `experimental.is_mcp == true` 直接写 Allow / Block 策略，不用再自己维护一份「看起来像 MCP」的域名清单。检测靠的是 `MCP-Protocol-Version` 头——2025-11-25 spec 要求初始化后每个 HTTP 请求都带它，2026-07-28 spec 更进一步要求每个 POST 都带，并把 `Mcp-Method` 和 `Mcp-Name` 也提到 header 上，普通 HTTP 基建不解包就能看出这次调用是 tools/list 还是 tools/call。官方自己把边界说得很清楚：这个信号只对经过 TLS 解密的流量有效，本地 stdio server、Do Not Inspect 和不过 Gateway 的连接一律看不到，头在则强证据、头不在不能证伪。配套的还有一块 MCP 流量看板（按 server / 用户 / on-ramp 拆分，能直接钻到日志）和 Traffic Source 选择器，写成 `experimental.is_mcp == true and not traffic.onramp in ("mcp_portal")` 就是一条「绕过 Portal 的 MCP 连接全部拦掉」的基线规则。文章还把 shadow MCP（连了没批准的 server）和 Portal bypass（批准的 server 但直连上游、跳过 Access 策略与工具审计）明确拆成两个问题——后者光靠网络层管不住，得让上游 origin 自己拒绝直连。对自己在管一堆 MCP server 的人，最实际的一步是先只开可见性、别急着上 Block 策略，用日志比对一遍「员工实际在连什么」和「你以为批准了什么」。

→ [Cloudflare Blog](https://blog.cloudflare.com/mcp-security-updates) / [MCP 流量检测教程](https://developers.cloudflare.com/cloudflare-one/tutorials/detect-mcp-traffic-gateway-logs/) / [Agents SDK MCP 文档](https://developers.cloudflare.com/agents/model-context-protocol/)

### Hugging Face 用数据说明：agent 已经成了平台第一大用户

Hugging Face 发布《State of Open Models: Summer 2026》，最值得看的是第 6 节——他们 7 月开放的 agent-usage 数据集记录了 coding agent 通过 huggingface_hub / hf CLI 调 Hub 时带的 `agent/<name>` 标识，于是第一次能看清 harness 的市场份额。数字很不稳定：Claude Code 7 月占 44.4%，4 月是 67.8%，5 月只有 6.4%；Codex 则从 10.4% 稳步爬到 20.8%。官方的解读是这个市场没有既有霸主，一次发布或一个默认值改动就能在一个月内挪走一半流量。另一条更值得警惕：7 月接近四分之一的 agent 流量来自数据集尚未登记的 harness，5 月这个比例是 59.8%，4 到 7 月新出现了十几个客户端标识——新入场者比任何注册表命名的速度都快。HF 自己的应对是把平台改造成给机器读的：3 月起论文提供 machine-readable Markdown，4 月把 agent trace 做成一等公民的数据集类型、每个 Gradio Space 带 agents.md 端点，7 月上线 hf_fs MCP 工具，用一个约一千 token 的接口把仓库、存储、文档、论文全暴露出来，外加可挂载的沙箱。同一时期 MCP 本身也进了 Linux Foundation 的 Agentic AI Foundation。报告里还有一条冷峻的记录：7 月 HF 遭遇了疑似首例自主 agent 主动发起并持续的入侵，分析被捕获的攻击代码时前沿闭源模型的安全护栏直接拒绝干活，最后是把量化后的 GLM-5.2 部署在自家基础设施上重建了攻击时间线。如果你在做 agent 可观测性，agent-usage 这个数据集值得直接拉下来对照自己的 harness 分布。

→ [HF Blog](https://huggingface.co/blog/state-of-open-models-summer-2026) / [agent-usage 数据集](https://huggingface.co/datasets/huggingface/agent-usage) / [入侵事件技术时间线](https://huggingface.co/blog/agent-intrusion-technical-timeline)

## ⚡ 快讯

- **GLM-5.3**：智谱昨天发布 GLM-5.3，官方口径是基座模型没换（与 GLM-5.2 同一底座），提升全部来自后训练 Scaling——更多可执行环境、更多样的长程任务、更长的训练时间。两个主打标签是 Coding 和安全：CyberGym 白盒代码审查从 5.2 的 77.2% 提到 84.5%，官方称是最强开源安全模型；发布前两周联合清华、南开等做的红队测试累计发现 2404 个去重后漏洞，其中 1088 个中高危，覆盖系统内核、浏览器引擎、开源基础组件等 220 个项目，最早的 bug 可以追溯到 40 年前。量子位的实测里，它在一个预埋 12 类漏洞的 Node.js 项目上 7 分钟出了 348 行审计报告、12 类一个没漏，修复环节改 22 个文件加 1463 行并自建回归测试跑通 54/54；在没有 NVIDIA GPU 的 Mac 上被要求写 CUDA 时，它把能在 CPU 验证的部分跑了、借 Docker 里的 nvcc 编了一遍，其余全部标 UNVERIFIED。注意第三方复盘提到发布当天权重还没放出（说法是两周内），所以「开源最强」这个说法目前先按官方定位理解，别当成已经能下载的事实。 → [量子位实测](https://www.qbitai.com/2026/08/473038.html) / [官方技术报告](https://z.ai/blog/glm-5.3) / [第三方复盘（权重与定价）](https://www.digitalapplied.com/blog/glm-5-3-launch-post-training-scaling-coding-agents)
- **Claude 文本水印**：Anthropic 解释了为什么以后 Claude 的输出都会带水印：EU AI Act 的透明度行为准则要求（8 月 2 日起生效，约 190 家签署方），实现用的是 Google DeepMind 的 SynthID-Text——不加隐藏字符、不多花 token、不影响价格和速度，只是把「选下一个词时的随机数来源」换成密钥加前文。对写代码的 agent 有一条具体影响：需要精确输出的地方（代码、事实、数学）水印基本不生效，只有注释这种任意选词的地方能挂上，所以代码产物几乎测不出来；同理，让 Claude 只改语法的润色场景也测不出。水印检测 API 还在做，文件类产物走的是 C2PA 元数据而不是水印。全球统一开启，暂时没法按地区收窄。 → [Anthropic News](https://www.anthropic.com/news/claude-text-watermark) / [SynthID-Text 论文](https://www.nature.com/articles/s41586-024-08025-4)
- **Zed Delta**：Zed 发布 Delta，一个面向 AI Agent 编程的多人协作环境，官方把它定位成从「最好的代码编写工具」进入「最好的代码讨论工具」的第二阶段。核心差别是评论不绑 commit：可以在工作树的任意一行加评论，评论随代码演变保持关联。对「人和多个 agent 同时改一棵树」的场景，这比 PR 粒度的 review 更贴近实际工作流。 → [开源中国](https://www.oschina.net/news/501922)
- **VS Code 1.133**：这版更新有三条跟 agent 直接相关：可以在回合之间切换 Claude 会话的模型供应商，不用重新配置 agent host；GitHub 登录不可用时 Agent 窗口仍能用；本地 HTML 预览在编辑时实时刷新。前两条都是在削弱 agent 会话对单一供应商和单一登录态的耦合，跑多模型对照的人会省事。 → [开源中国](https://www.oschina.net/news/501932/vs-code-1-133-released)
- **Qwen3.8-27B**：阿里千问在 8 月 14 日晚开源 Qwen3.8 系列，其中 Qwen3.8-27B 是原生多模态稠密模型，270 亿参数、Apache 2.0，官方说整体水平超过 Qwen3.7-Plus，量化后可在消费级显卡上跑。这跟前天那个 2.4T-A95B 是两回事——后者是 Max 级稀疏 MoE，显存门槛在 TB 级。HF 的年中报告正好给了这个策略一个佐证：Qwen 全尺寸覆盖的路线拿到 20.45 亿次下载，是 Moonshot 前沿-only 路线（3700 万）的约 55 倍，Hub 上 Qwen 衍生模型达 151,448 个。 → [雷峰网](https://www.leiphone.com/category/industrynews/GJAhmR3wyL91CzjO.html) / [HF 年中报告](https://huggingface.co/blog/state-of-open-models-summer-2026)
- **得物复合检索 Agent**：得物技术团队写了他们知识问答系统里「复合检索 Agent」的系统设计实践。这类国内一线电商的 RAG 工程复盘比框架宣传文有用：能看到真实语料下的检索编排取舍，而不是 demo 级的 single-hop retrieve。做企业内知识库的可以对照自己的召回层设计读。 → [开源中国博客](https://my.oschina.net/u/5783135/blog/19738367)
- **推理成本与价格战**：两条从不同角度指向同一件事的报道：Ars Technica 说 OpenAI 和 Anthropic 在中国开源模型逼近的压力下打起了价格战；TechCrunch 报道法国初创 Kog 的观点是「GPU 不适合 agentic 工作负载」属于误解，他们在往更底层榨推理性能。对跑批量 agent 任务的人，这两条合起来的含义是单位 token 成本还有下行空间，长期合约先别锁太死。 → [Ars Technica](https://arstechnica.com/ai/2026/08/openai-and-anthropic-in-price-war-as-chinese-ai-rivals-gain-ground) / [TechCrunch](https://techcrunch.com/2026/08/14/kog-is-going-deeper-to-squeeze-more-inference-out-of-gpus)

**SteerBench-Work: A Benchmark for Agent Steering at Action Boundaries** — 把「agent 下一步就要发邮件 / 合 PR / 打款」这个 pre-commit 时刻单独拿出来做 benchmark：该放行还是该转人工。做 human-in-the-loop 中断点设计的直接相关。→ [arXiv](https://arxiv.org/abs/2608.12654)

**Correct Is Not Governed: Provenance Integrity in Agentic Workflows** — 论点是「结果对」不等于「过程可治理」：一个正确动作可能依赖错误的授权来源或无依据的补全。给 agentic workflow 定义了 provenance 完整性维度。→ [arXiv](https://arxiv.org/abs/2608.12761)

**Labels Are Not Endpoints: Treatment Leakage and Construct Validity in MCP Agent Security Evaluation** — 复审一次已归档的 MCP agent 安全评测活动，把 10,200 条执行记录追溯到 180 个 model-bound 请求和 45 个语义请求，质疑「存下来的标签等于行为事实」这个前提。看 MCP 安全 benchmark 数字前值得先读。→ [arXiv](https://arxiv.org/abs/2608.12880)

**Practice Makes Unsafe: Skill Misevolution in Self-Improving LLM Agents** — 研究自我改进 agent 在积累 skill 的过程中出现的能力退化与安全漂移。跟「让 agent 自己写自己的 skill」这类实践正面相关。→ [arXiv](https://arxiv.org/abs/2608.12851)

**Governed Persistent Memory: Source-Bound State Semantics and Fail-Closed Release for Long-Horizon Agents** — 指出 agent 记忆通常被当成 select–store–retrieve，但检索本身不判断一条被推翻、被撤回、已过期的记录能不能支撑对外结论，于是提出 source-bound 状态语义加 fail-closed 释放。→ [arXiv](https://arxiv.org/abs/2608.12476)

## 📈 趋势

- 🆕 MCP 治理的控制点从客户端配置挪到网络层 — Cloudflare 用协议头把 shadow MCP 和 Portal bypass 变成可查询、可写策略的对象，而这两者被明确区分为不同问题
- 🔺 agent 成为平台的一等用户 — HF 的 agent-usage 数据显示 harness 市场没有既有霸主，且 7 月近四分之一流量来自尚未登记的客户端
- 🔺 Coding 能力和安全能力开始被合并考核 — GLM-5.3 把 CyberGym 白盒审查当主指标，理由是模型一旦真写工程代码，安全就是工程能力的一部分
- 🔺 「可治理」成为 agent 论文的主流切口 — 同一天出现 provenance 完整性、action boundary steering、记忆 fail-closed 释放多篇，共同前提是「结果正确」不足以作为验收标准
- 🔻 MCP Dynamic Client Registration 退场 — 2026-07-28 spec 弃用 DCR，回到管理员预注册 OAuth client，Cloudflare MCP Portal 已支持手工填 client 凭据
