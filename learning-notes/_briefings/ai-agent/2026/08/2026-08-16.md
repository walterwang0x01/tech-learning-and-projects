### MCP 取消会话之后，社区在追问它还剩什么

昨天这里写的是 Cloudflare 怎么在网络层利用新协议头做 MCP 治理，今天补的是协议侧本身的取舍和迁移路径。2026-07-28 规范把 initialize/initialized 握手、Mcp-Session-Id 和协议会话整个从核心请求路径移除，每个请求自带协议版本、客户端身份和能力，于是任何请求都能落到任意实例，自动扩缩不用再保留会话、部署不用再排空迁移。代价换来的收益不只是可扩展性：Streamable HTTP 请求现在必须带 Mcp-Method 和 Mcp-Name（一次工具调用长成 `Mcp-Method: tools/call` + `Mcp-Name: search`），网关、限流器和 WAF 不解包正文就能按方法或按工具动作，评论者 evalstate 指出规范甚至允许把工具参数复制进标头做自定义路由。对做 human-in-the-loop 的人，影响最直接的是 Elicitation 被拆开了：服务器发起的请求不再需要保持一个开放流，改成返回 `input_required`、客户端收答案后重试，一次审批从「一条保持连接」变成两个请求——部署简单了，但等待人工响应的过程不再位于单次调用内部，你的中断点设计要跟着改。授权同时收紧：动态客户端注册已弃用并计划 2027 年夏季之后移除，改用 RFC 9207 颁发者标识，客户端把规范服务器 URI 作为 RFC 8707 resource 发送以绑定令牌受众。Hacker News 上的分歧不在于无状态是不是进步，而在于它揭示了什么：一派认为这证明协议本就不该有状态，评论者 luciana1u 的说法是「发明一个有状态协议，发现状态难扩展，剥掉状态，最后得到的结果是发个 POST 就行」；辩护方不否认相似性，vidarh 的概括是 MCP 真正的优势在于它是一项获得 AI 提供商认可、因而有人真去实现的标准。采用侧的数字来自 Anthropic：MCP SDK 月下载量已超 4 亿次，今年增长三倍。但单个 server 未必吃到这波——一篇咨询公司在 r/AI_Agents 的帖子称审计客户 server 时发现三个月只有 61 次工具调用、其中 58 次来自客户自己的工程师，作者自披露 MCP 业务占其咨询收入很大比例，这是单一来源的轶事而非普遍结论，但它给出的判断值得记下：钱在流向网关、注册中心和认证层，而不是服务器本身。规范与 TypeScript / Python / Go / C# SDK 都已更新，依赖会话、服务器到客户端请求或独立流的 server 可以在现有有状态路由旁并起一条无状态路由，迁完排空活动会话再删旧路径。今天最小的一步：给自己的 MCP server 加上读 Mcp-Method / Mcp-Name 的兼容分支，别等 2027 年 DCR 移除窗口逼上来。

### SpaceX 以 600 亿美元完成收购 Cursor

Cursor 官方博客宣布交易正式完成，Anysphere 以全股票 600 亿美元并入 SpaceX，多家财经媒体依据 SEC 8-K 把它称为史上最大的创业公司收购。时间线是四月双方先结成技术联盟并给 SpaceX 一个「600 亿收购或 10 亿技术合作」的期权，六月 SpaceX 上市后行权，本周正式交割；SpaceX 今年早前已经收购了 xAI，Cursor 这次被并入 SpaceXAI。Cursor 的公告反复强调的不是估值而是算力，原话是将获得「世界上最大的 GPU 集群」，而 SpaceX 的算力此前正在对外出租，客户包括 Anthropic 和 Google——注意这也意味着 Cursor 从今天起和自己模型供应商的东家共用一个基础设施提供方。对写代码的人，真正的变化是格局：三个主流编码 harness 现在分别归属 Anthropic（Claude Code）、OpenAI（Codex）和 SpaceXAI（Cursor），全部由模型方自有，harness 与模型的绑定只会更紧。官方目前没有说要收窄第三方模型接入，所以别急着迁走，但如果你的 CI 或团队工作流里躺着 Cursor，接下来值得盯两件事：可选模型列表是否变化，以及定价与配额是否跟着 SpaceXAI 的算力策略走。把关键流程对 harness 的耦合点先列出来，比事后临时换工具从容。

## ⚡ 快讯

- **Claude Code 的插件设计与上下文工程**：InfoQ 整理了 Anthropic 的 Daisy Hollman（Claude Code 插件与 agent 团队设计负责人）在 NDC Copenhagen 的演讲，一万一千字里有几条可以直接拿来改自己配置的判断。第一，上下文窗口是硬约束且一年没长：2024 年底出现第一批百万 token 窗口，今天最前沿依然是百万级，而模型能力在这一年里暴涨，于是「往窗口里放什么」变成全职工程。第二，MCP 在 monorepo 规模上不扩展——20 个 server × 15 个工具，名称加描述加 schema 就吃掉大半系统 prompt，Anthropic 的缓解手段是工具搜索（先只给名称，再给一个搜工具的工具）。第三，hook 是唯一真正可扩展的插件抽象，因为不匹配就不注入、只在触发时才往上下文里放东西；post tool use hook 相当于给 agent 补上「红色波浪线」，把类型检查和 lint 的输出在犯错那一刻塞回工具结果块里，而这些脚本你本来就有。第四条是个反面教材：Cursor 早期的 Cursor Rules 按任务把规则换进换出，本质是 LRU 缓存，结果被 KV 缓存的硬约束打爆——前缀一改，整段 token 重算，成本高得离谱。她给 2026 年的总结是重心从「把信息喂进模型」转向「把信息从模型交回给人」，因为人的注意力才是系统里最小的那个盒子 → [InfoQ 中文](https://www.infoq.cn/article/aVJlp0XApUkyu6CNLOkL)
- **AstraZeneca Research Assistant**：阿斯利康公开了内部 LLM 系统 Research Assistant 的工程描述：一个 chat 界面，把科学文献、知识图谱、化学数据、临床试验、安全资源、表达数据和内部实验系统的证据汇到一起，同时提供直接问答的 fast 模式和更深的研究模式。这类大药企内部 agent 的一手工程记录比框架宣传文有用——能看到多数据源证据编排在真实合规约束下长什么样 → [arXiv](https://arxiv.org/abs/2608.12395)
- **skill 生态的注意力上限**：一篇题为《@skills: Attention is all you have》的论文给出了一个刺眼的数字：目前有 56,804 个公开 agent skill，团队私有的更多，而主流交付方式是「安装」——装完描述就常驻 system prompt，去争不到 100 个可靠触发位。作者的切入点是安装其实把内容、持久化和触发三件事捆在了一起，本可以拆开。如果你像我一样 ~/.kiro/skills 下已经堆了几十个 skill，这篇给的是一个具体的诊断口径：先数一数有多少 skill 从没被触发过 → [arXiv](https://arxiv.org/abs/2608.12610)
- **多 agent 可靠性不能相乘**：多 agent 系统的组合可靠性推导习惯把各组件可靠率相乘，前提是条件独立——这个假设常被声明、极少被检验。Agent Behavioral Contracts II 检验了它：同一模型的两个实例做两段式 handoff，在 18,000 次预登记任务、纯确定性代码评分（不用 LLM 裁判）的设置下，任一失败时两者共同失败的比例是 90.0%（log OR 6.66，95% CI [6.38, 7.00]，phi 0.916）。做 orchestrator-worker 架构可靠性估算的，这条直接推翻你的乘法模型 → [arXiv](https://arxiv.org/abs/2608.12895)
- **openclaw 自举**：Peter Steinberger 说团队已经改用 openclaw 来开发 openclaw，他点出的关键能力是「agent 会话可以作为 URL 分享」。同一天他还发了一条更容易照抄的实践：在团队共享的 AGENTS.md 里加一条指令，凡是改动 UI 状态的 PR 都要附上录屏视频。后者今天就能加进自己的 AGENTS.md → [@steipete](https://x.com/steipete/status/2088473882357530979) / [AGENTS.md 那条](https://x.com/steipete/status/2088486859244741020)
- **ChatGPT 餐厅预订**：OpenAI 的 Thibault Sottiaux 说 ChatGPT 里找餐厅并订位现在很顺，是本周一批发布中的一项。这是 agentic commerce 从演示走进默认入口的又一格——真实世界副作用类操作的授权边界怎么处理，官方推文没有展开 → [@thsottiaux](https://x.com/thsottiaux/status/2088493756391768252)
- **Gemini 3.7 Flash**：Google 的 Josh Woodward 宣布 3.7 Flash 已经进入 Gemini App。Flash 档是跑批量 agent 任务时最常被拿来压成本的一档，值得在自己的评测集上重跑一遍延迟与工具调用成功率再决定要不要换默认模型 → [@joshwoodward](https://x.com/joshwoodward/status/2088344782821326980)

**Dead text or binding clause? Measuring and restoring constraint influence in black-box LLM dialogues** — 多轮对话里用户撤销约束和施加约束一样容易，但撤销经常不生效：模型继续执行已被撤回的要求，有时还在声称「已移除」的注释下面照做，作者管这叫 behavioral relapse / revocation inertia，并给出逐条度量、事前预测和等预算修复。跑长会话 agent 的人建议直接对着自己的 system prompt 试一遍。→ [arXiv](https://arxiv.org/abs/2608.12599)

**Large Language Models Can Follow Instructions, But Not Many at Once** — 单条约束模型处理得都不错，但推理结构、安全边界、输出 schema 同时要求成立时会出现相变式崩塌。这篇刻画的正是「把所有规则塞进一个 prompt」这种做法的失效曲线。→ [arXiv](https://arxiv.org/abs/2608.12426)

**Beyond Retrieval: Query-Conditioned Reuse of Long-Horizon Agent Trajectories** — 检索能找出一条可能相关的历史轨迹，但没规定用户、实体、约束或环境状态都变了之后该怎么用它；作者把这个「检索之后」的复用步骤单独拎成瓶颈，固定候选检索、目标状态、模型、解码和工具预算来评估。→ [arXiv](https://arxiv.org/abs/2608.12847)

**Teach the Magnitude, Not the Direction（CrEST）** — 多轮工具使用 agent 的 RLVR 把每一轮的异质结果压成一个轨迹级奖励，credit assignment 全糊在一起；这篇提出分层 credit assignment，介于 on-policy 蒸馏的稠密监督和 teacher-bounded 之间。→ [arXiv](https://arxiv.org/abs/2608.13179)

**Privacy-Preserving RAG by Concealing Sensitive Information from External LLMs** — RAG 的隐私研究多在防未授权用户访问，这篇盯的是另一面：外部 generator 本身能看到 query 和检索出来的文档。凡是把内部知识库接到第三方模型 API 上的，这就是你合规评审里最难绕的一条。→ [arXiv](https://arxiv.org/abs/2608.12675)

## 📈 趋势

- 🆕 MCP 的价值主张退回到「约定 + 生态默认」 — 无状态化之后连支持者都承认剩下的是 REST 加一份模型受过训练的约定，而钱在流向网关、注册中心和认证层
- 🔺 编码 harness 与模型厂商完成并表 — Claude Code / Codex / Cursor 现在分属 Anthropic / OpenAI / SpaceXAI，harness 与模型的绑定只会更紧
- 🔺 skill 生态撞上注意力上限 — 5.6 万个公开 skill 去争不到 100 个可靠触发位，「安装式交付」本身成了瓶颈，同期还有 skill 自演化的论文在补另一半
- 🔻 「多 agent 可靠性可以相乘」这个假设 — 预登记实验里同模型两实例 handoff 的共同失败率 90%，条件独立在最简单的两段式 handoff 上就不成立
- 🔺 human-in-the-loop 的中断点被协议层重新定义 — MCP elicitation 从一条保持连接改成 input_required 加重试，等人的过程不再在单次调用内部
