## 📌 头条

### Agent 记忆不是开关，是按模型配的剂量

IBM Research 在 Hugging Face 放出跨 8 个模型的 agentic memory 评测：把 agent 自己蒸馏出来的 guideline 回灌进上下文，收益强烈依赖模型档位。gpt-oss-120b（117B MoE）用「高置信核心 + 按任务检索几条」的方式，AppWorld test_normal 任务完成率（TGC）从 39.9% 涨到 56.0%（+16.1pp），token 只多 5%；同一模型全量灌 guideline 反而涨得更少、成本还高约 50%。DeepSeek-V3.2（671B MoE）正相反，只有全量 guideline 才吃得下，TGC +9.5pp、严格口径 SGC +16.1pp，代价是每任务 148K → 263K token（+78%），且 ReAct 步数几乎没变（≈18–19 步），多出来的全是输入 token 膨胀。GLM-5（745B MoE）在他们的跑法下没有可测收益，作者把这叫「饱和」，并明确说这是观察到的现象、不是已证明的原因。对你意味着：如果你在 LangGraph 里塞过 lessons / guideline 表，先按模型分档做 A/B——弱模型走检索、强模型走全量并靠 prompt caching 压成本（静态 guideline 前缀必须保持稳定才命中缓存），别默认「记忆越多越好」。

→ [原文](https://huggingface.co/blog/ibm-research/altk-evolve-hmm) / [ALTK-Evolve 库](https://github.com/AgentToolkit/altk-evolve) / [技术报告](https://arxiv.org/abs/2603.10600)

### Claude 自主跑完蛋白设计，湿实验回验 14/15

Anthropic 公布了一次几乎无人干预的长时程 agent 运行：在 Claude Science 里给 Opus 4.8 和 Mythos Preview 一段约 3 万 token 的 prompt、联网权限、GPU 以及 Google Drive / Slack / BioRxiv 连接器，然后放手——多目标模式 48 小时 wall time、每个 session 最多 12,500 H100 卡时，token 和 sub-agent 预算不设上限。模型自己选靶点、串联多个公开的结构设计 / 序列设计 / co-folding 模型、跑多轮 in silico 优化并筛掉表达不出来或不溶的候选；Adaptyv Bio 和 Twist Bioscience 独立做湿实验验证，15 个靶点里 14 个拿到 binder，整体命中率 22.6%（Opus 4.8 多目标）到 35.1%（Mythos Preview 单目标），而行业常规是 10–15%。同一篇里 Opus 5 只拿到实验室的原始 NMR / LC-MS 文件和两句话 prompt，23 和 19 分钟出结果，纯度 96.4% vs 实验室 96.33%，中途还自己发现第一轮读数说多了并纠正回来。两个必须一起读的限定：蛋白设计能力在 Fable 5 上是被封的、只走可信访问计划，官方明确写了 dual-use 风险；人类介入虽少但不为零（批准网络访问、下单送检）。对你意味着：这是目前公开材料里最硬的「长时程 agent 编排一堆专用模型」证据，那份 3 万 token 的 prompt 和全部数据都公开了，值得照着看一眼这种量级的 agent 上下文是怎么组织的。

→ [原文](https://www.anthropic.com/research/Claude-accelerates-protein-design) / [prompt 与数据](https://huggingface.co/datasets/Anthropic/claude-protein-binder-design/tree/main)

**Learning Agent Execution for KV-Cache Management in Agentic Serving** — 多 agent 流水线里每个 agent 反复执行同一套 system prompt + 工具定义 + few-shot，现有 serving 系统只靠被动 prefix caching 捡漏；这篇主张预测执行路径来主动管理 KV-cache。→ [arXiv](https://arxiv.org/abs/2608.14624)

**The Hallucination Snowball** — 顺序多 agent 流水线在交接处不做校验，第一阶段注入的幻觉不是被动留存而是逐级变形：原始数字 → 派生计算 → 叙述文字 → 被认可的结论，每变一次可检测性就近乎不可逆地下降。作者把它形式化成状态转移模型。→ [arXiv](https://arxiv.org/abs/2608.14588)

**A Policy Algebra for Trust-Preserving Agentic AI Execution** — 现有 agent 框架优化的是「能不能做到」，但企业要的更强：结果对了也不算可靠，如果它是靠越权取数、被放大的委派权限、未批准的副作用或不可回收的预算烧出来的。论文给出一套策略代数来定义这种可靠性。→ [arXiv](https://arxiv.org/abs/2608.16402)

**Palmyra x6 Technical Report** — MoE 基座上做 Anchored SFT 的企业级 tool-use 模型，配方刻意保守：626 条经校验的合成工具调用轨迹、单 epoch、低学习率、对基座加 KL 锚。适合当「小数据也能调出可用 tool-use」的对照样本。→ [arXiv](https://arxiv.org/abs/2608.16620)

## 📈 趋势

- 🆕 agentic memory 的问法从「要不要上」变成「给多少」——按模型档位配剂量，弱模型走检索、强模型走全量、饱和模型不给
- 🆕 长时程自主 session 开始拿到外部实验级验证：48 小时 wall time、上万 H100 卡时、预算不设限，结果由第三方湿实验回验而不是自评分
- 🔺 agent 自助基础设施在变厚：按分钟计费、靠 CLI + MCP 自己开机的常驻 VM，以及直接复用本机登录态的浏览器 MCP server
- 🔺 「语法合法 ≠ 允许执行」成为共识，运行时准入层（策略代数、数字孪生校验、MCP 凭据治理）明显变密
