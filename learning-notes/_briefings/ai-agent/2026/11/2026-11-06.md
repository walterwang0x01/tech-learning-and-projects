### 英伟达：HBM 只多 3%，每美元 Agent 吞吐最高涨 30 倍

英伟达 11 月 5 日发了篇技术解读，核心观点是 Agent 时代的瓶颈不是堆显存，而是整栈协同。官方给的数字很具体：从 Blackwell Ultra 到 Vera Rubin 平台，每卡 HBM 容量只涨了约 3%，但在 SemiAnalysis AgentX 这个基准上，每美元（和每兆瓦）的 agentic 吞吐最高提升到 30 倍。要注意口径：AgentX 是回放真实 coding-agent 会话、带工具调用间隙和不断增长的上下文，30x 是 Vera Rubin NVL72 对比 GB300 NVL72 的相对值，不是绝对算力翻 30 倍。对做长上下文 agent 的人，信号是 KV cache 和权重在 HBM 里抢带宽这件事，未来靠软硬协同（含 HBF 冷热分层）解，而不是等更大显存。

→ [英伟达博客](https://blogs.nvidia.com/blog/memory-full-stack-codesign/) / [开发者版技术解读](https://developer.nvidia.com/blog/five-ways-nvidia-co-design-maximizes-the-value-of-every-byte-in-the-ai-factory/) / [IT之家中文报道](https://www.ithome.com/1/023/025.htm)

### Anthropic 报告：科研人员到底怎么用 Claude

Anthropic 发布了一份隐私保护口径下的使用研究，统计科研人员如何使用 Claude、Claude Code 和 Claude Science，并拆解不同学科、不同研究任务上的使用差异。报告本身是观察性的——讲的是真实使用分布，而不是 benchmark 跑分。对想把 agent 塞进科研工作流的人，值得看它归纳出的高频任务类型，判断哪些环节现在已经被 LLM 吃掉、哪些还得人来。具体学科分布和结论以原文为准。

→ [Anthropic Research](https://www.anthropic.com/research/how-researchers-use-claude)

## ⚡ 快讯

- **MCP C# SDK 2.0**：InfoQ 报道新版默认启用 HTTP 无状态模式，并新增多轮请求能力——对用 .NET 栈搭 MCP 服务端的人是直接相关的能力更新，具体 API 变更细节要看原文 → [InfoQ](https://www.infoq.cn/article/80iUxvCNB59aOgyXB7LN)
- **SonnetDB 5.0**：开源数据库发布主版本，重点增强 SQL 与关系事务，并开放「九模型 MCP 工具」读写——把数据库直接暴露成 MCP 工具这条路线又多了一个实现，适合给 agent 做结构化数据后端 → [开源中国](https://www.oschina.net/news/503431)
- **arXiv：Agents, Think Only When it Helps**：一篇讲 agent 蒸馏的新论文，质疑把老师完整轨迹（思考+动作交错）全盘灌给学生是否必要，提出按需思考的训练思路——对压缩 agent 推理开销有参考价值 → [arXiv 2611.05709](https://arxiv.org/abs/2611.05709)
- **arXiv：MCP 工具链信任**：《Signed, Sealed, Leaked》指出光有发布者签名和运行时策略还不够，MCP 第三方工具仍有信任缺口——做 agent 安全的可以关注它给出的威胁模型 → [arXiv 2611.06585](https://arxiv.org/abs/2611.06585)
- **英伟达 HBF 冷热分层**：一篇相关 arXiv 工作把 HBM 和高带宽闪存（HBF）做冷热分层服务 agentic LLM，宣称每 8 卡节点省约 7.6kW 读功耗，定位 HBF 为冷层补充而非替代——和英伟达今天的整栈思路呼应 → [arXiv 2609.25782](https://arxiv.org/html/2609.25782)
