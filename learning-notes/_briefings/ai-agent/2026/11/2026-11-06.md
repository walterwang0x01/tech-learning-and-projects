## 📌 头条

### Cloudflare 给 Agent 发「委托书」：服务端终于看得见是谁在替你操作

Cloudflare 发文 《Agents aren't humans (but they kinda are)》，把个人 AI Agent 的流量问题摆上台面：Agent 代表用户去访问网站，但服务端只看到一个「中间人」，既不知道背后是哪个用户、也不知道是哪家 Operator 托管的。它提出一套三方模型——User（下指令的人）、Agent（执行的自动化）、Operator（托管方），底层沿用此前已落地的 Web Bot Auth（用加密签名证明「我是谁」），再叠一层「用户把权限委托给这个 Agent」的凭证，让网站可以按身份放行或限流，而不是把所有自动流量一刀切当爬虫拦掉。对你意味着什么：如果你在做会主动访问外部站点的 Agent，未来「能不能过 Cloudflare 这类网关」会和功能一样重要——值得现在就去读一遍 Web Bot Auth 的签名机制，提前想好你的 Agent 怎么表明身份。

→ [原文](https://blog.cloudflare.com/trusted-agent-delegation)

### LangChain：Agent 正在「异步化」，长任务不再卡住对话

LangChain 发文 《Agents Are Going Async》，讲的是 Deep Agents 里的异步子 Agent 设计：主 Agent 把耗时的活儿（跑测试、查大量资料、长时间等待）甩给后台 worker，自己保持对用户的即时响应，后台做完再通过通知回来，涉及敏感操作时还能停下来等人工审批。这正好踩中 Walter 常用的 LangGraph / 编排栈——过去「一个 Agent 一条线干到底」会被最慢的那步拖住整个会话，异步子 Agent 把「编排层保持响应」和「后台干重活」拆开。对你意味着什么：如果你手里的 Agent 流程里有明显的长任务（CI、批量抓取），可以照这个模式把它改成后台任务 + 通知回收，先拿一条最耗时的链路试试响应速度的差别。

→ [原文](https://www.langchain.com/blog/agents-are-going-async)
