### 预训练投毒 0.1%，Agent 后门洗不掉

开源中国转述了一篇论文《Agentic Backdoors via Pretraining Poisoning》，作者来自伯克利、UIUC 和 Anthropic，署名里有 Nicholas Carlini 和 Javier Rando。据该报道，结论是只污染 0.1% 的预训练数据就能给 Agent 埋后门，而且后续用完全干净的数据做微调和强化学习也清除不掉。这里的信息来自中文媒体的摘要（候选里只有开头部分），触发方式、攻击成功率等细节需要读原论文确认。对做 Agent 的人，含义是：后训练阶段的安全对齐不能当成兜底，用第三方基座模型时，模型来源和数据透明度本身就是风险面。选基座时可以先把「预训练数据来源是否可追溯」列进评估清单。

→ [开源中国报道](https://www.oschina.net/news/503823)

### MCP 服务器不一定站在你这边

今天 HN 上有两条指向同一个问题。一条是 techstackups 的文章，标题称 Google 会让 AI Agent 使用它自己的 MCP 服务器，而其中 Gmail 那个发不了邮件，HN 上有 260 分、220 条评论；Peter Steinberger 在 X 上的吐槽则称 Google 一边推出 MCP，一边限制 gog 之类的 CLI 除非付费，这是他个人的解读，未经 Google 证实。另一条是 Reddit 帖子，标题称 Notion 官方 MCP 往 Agent 上下文里注入隐藏的升级推销指令，目前只有这一个来源，未见 Notion 回应。这两条我只读到标题和少量元数据，没有核对正文，具体能力限制和注入内容要看原文。但方向值得留意：MCP 服务器返回的内容会直接进入模型上下文，等于一个未审计的 prompt 来源。自己接 LangGraph 或 MCP 客户端时，可以把工具返回内容记日志并抽查，必要时加一层过滤。

→ [techstackups 文章](https://techstackups.com/articles/google-workspace-ai-agents-mcp) / [Notion MCP 帖子](https://www.reddit.com/r/ClaudeCode/comments/1y4qm5o/heads_up_if_you_wire_notions_official_mcp_into) / [Steinberger 推文](https://x.com/steipete/status/2125654555262431248)

**Letting Models Manage Their Own Context: Where We Stand** — 比较 harness 触发上下文压缩与模型通过 context API 自己决定何时压缩，在 NVIDIA 开源 harness 上做了对比，摘要被截断，结论需读原文。→ [arXiv](https://arxiv.org/abs/2611.34147)

**Partial Routing** — 让前沿模型把合适的子任务委派给便宜的 worker 模型，而不是整个任务只选一个模型，基于两个模型的历史运行轨迹识别重复子任务。→ [arXiv](https://arxiv.org/abs/2611.33402)

**How Much Effort Does an AI Code Reviewer Need?** — 用 Claude Opus 5.5、Sonnet 5.5、Haiku 5.5 审查 90 个来自 SWE-bench 的 Django Agent 补丁（通过原测试但过不了更强测试），研究 effort 设置与抓错能力的关系。→ [arXiv](https://arxiv.org/abs/2611.33639)

**MINE** — 面向 RAG 间接提示注入的免训练防御，思路是最大化相关性而不是检测攻击。→ [arXiv](https://arxiv.org/abs/2611.34188)

## 📈 趋势

- 🔺 MCP 信任边界 — 服务器返回内容进入上下文，被厂商商业意图或攻击利用的讨论在升温
- 🔺 上下文自管理 — 从 harness 压缩转向模型自己决定保留什么，论文与实践开始对比
- 🆕 分级委派 — 前沿模型带便宜 worker 做子任务，用成本换效率
- 🔻 「后训练能洗掉一切」的假设 — 预训练投毒研究对此提出质疑
