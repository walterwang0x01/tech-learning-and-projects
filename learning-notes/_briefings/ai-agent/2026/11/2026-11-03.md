## 📌 头条

### AWS 把 GPT-6.1 Terra 上 Bedrock，Step Functions 变成 agent 工具

AWS 本周 roundup 的重点不是模型多强，而是触达范围。GPT-6.1 Terra 已在 Bedrock 上线（模型卡强调视觉推理、computer use 与更低价格，10/26 公告称比 5.6 Terra 在 Agents' Last Exam 上高 15 个百分点、token 价至少降一半）。更值得留意的是 Step Functions 现在能直接作为 agent 的工具——它本就编排着 220+ 个 AWS 服务，等于把现成的工作流编排暴露给 agent 调用。对用 Bedrock 搭 agent 的人，这意味着不用自己写一层编排胶水，直接让 agent 触发状态机。

→ [AWS Weekly Roundup](https://aws.amazon.com/blogs/aws/aws-weekly-roundup-gpt-6-1-terra-on-bedrock-step-functions-as-agent-tools-and-more-november-2-2026) / [GPT-6.1 Terra 模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-openai-gpt-6-1-terra.html)

### LangChain 推 Managed Deep Agents，自己不用造 runtime

LangChain 把 deep agent 的运行时托管起来了（私有 beta）：持久化执行、沙箱、工具访问、LangSmith 可观测性一整套打包，省掉自建 runtime 的活。同期 CEO Harrison Chase 发文谈 2026 年底 context engineering 的新难题，核心是 proactive agent（主动发起、不等指令的 agent）带来的 harness 工程挑战。对自建 LangGraph 栈的人，可以对照看看托管版省掉了哪些坑再决定要不要迁。

→ [Managed Deep Agents](https://www.langchain.com/blog/introducing-managed-deep-agents) / [Context engineering 挑战](https://www.langchain.com/blog/context-engineering-challenges-late-2026)

## 📈 趋势

- 🔺 大厂把现成基础设施（Step Functions、托管 runtime）包装成 agent 可直接调用的工具，自建编排层的必要性在下降
- 🆕 agentic retrieval 开始卷性价比——同等效果、价格打到零头，retrieval 成本成为新竞争点
- 🔺 proactive agent（主动发起而非等指令）成为 context engineering 的新难题焦点
