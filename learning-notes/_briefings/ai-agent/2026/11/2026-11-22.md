## 📌 头条

### OpenRouter 清退 3 家推理供应商，125 个端点被移出零留存名单

OpenRouter 官方公告称，安全研究员本周报告部分推理供应商的数据被泄露，或其数据政策没有被执行。OpenRouter 据此清退了 3 家供应商，并把 125 个端点移出 Zero Data Retention（ZDR）资格，同时通知了所有可能受影响的客户。公告称没有发现 OpenRouter 自身被入侵。公告列出了 Novita、Phala、Together 的事件说明，其中 Together 的说明提到 2026 年 6、7 月的请求存在 prompt 泄露；公告还说并非所有受影响的供应商都公开发声。如果你的 Agent 通过聚合网关调用模型，并依赖 ZDR 满足合规，建议现在核对所用端点是否在被移除之列，不要默认「标了 ZDR 就安全」。

→ [OpenRouter 公告](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/) / [HN 用户反馈（MiniMax 请求可能被读取）](https://news.ycombinator.com/item?id=50585962)

### LangChain：Agent 缺的不是上下文，是持续维护的「知识」

LangChain 发文提出「knowledge factory」：区分 context（任务时手边有的信息）和 knowledge（可复用、需要维护的理解，比如指标含义、该信哪个数据源）。他们把需要维护的知识分成三类：怎么做事（Skills）、业务如何运转（领域知识）、去哪取最新数据（数据访问指引）。LangChain 自己的 GTM 和内容 Agent，以及 LangSmith Engine 都按这个思路为每个 Agent 维护知识库；摘要里写到由 Agent 标记缺失、后台 curator Agent 补齐。如果你在用 LangGraph 做企业 Agent，可以把 Skills 文档和「数据在哪」的说明单独成库维护，而不是塞进 system prompt。

→ [原文](https://www.langchain.com/blog/knowledge-factory)
