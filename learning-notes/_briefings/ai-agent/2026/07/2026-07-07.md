## 📌 头条

### AWS 为 AI Agent 推出专用 WorkSpaces

AWS 在 7 月 6 日的周报中正式推介 Amazon WorkSpaces for AI agents——面向需要安全隔离运行环境的 agent 部署场景，配合 Claude Sonnet 5 登陆 AWS 的消息，云厂商正在把「给 agent 一台专用机器」变成标准化产品能力。这意味着你不用自己搭 Docker + VPC 隔离方案，可以直接在托管桌面环境里跑 coding agent 或 browser agent，网络策略和审计日志由平台兜底。如果你在用 Claude Code 或自建 LangGraph agent 处理企业数据，值得关注这套 WorkSpaces 的权限模型和是否支持 MCP server 挂载。

→ [AWS 官方](https://aws.amazon.com/blogs/aws/aws-weekly-roundup-claude-sonnet-5-on-aws-amazon-workspaces-for-ai-agents-aws-service-availability-updates-and-more-july-6-2026)

### 首例 AI Agent 勒索攻击细节披露

TechCrunch 跟进披露了上周喧嚣的「首个 AI 自主勒索攻击」——技术执行确实由 AI agent 完成，但受害者选择、基础设施搭建和凭证盗取仍由人类操控，并非完全自主的黑客系统。这个区分很重要：它说明当前 agent 已经有能力串联「侦察→加密→勒索」的技术链路，但编排层仍需人类介入。对做 agent 安全的团队来说，这是比 benchmark 分数更实在的信号——需要在 tool permission 和 human-in-the-loop 上设硬边界，而不是寄希望于模型「自觉」。

→ [TechCrunch](https://techcrunch.com/2026/07/06/the-first-ai-run-ransomware-attack-still-needed-a-human)
