## 📌 头条

### 小红书开源 Search Agent「Iris」，35B 摸到万亿参数模型的搜索能力

Search Agent 是最难训练也最难评测的一类 agent：要在真实网络里边搜边读边推理，还得自己判断证据够不够、能不能停下来作答。小红书 AllSpark 团队刚开源的 Iris 把这件事往前推了一步——35B 的体量在 BrowseComp 上拿到 82.2 分，官方称已逼近 Kimi-K2.6 这类万亿参数模型的搜索表现。对做 RAG / 深度检索 agent 的人来说，值得关注的不只是分数，而是一个中等体量、可自部署的开源检索 agent 能不能替掉一部分靠超大模型堆出来的检索链路。BrowseComp 82.2 这个数字目前只有官方一处来源，配方与评测口径要等仓库和技术报告细读再下结论。

→ [报道](https://www.oschina.net/news/502468)

### LangChain 公布内部 GTM Agent：Deep Agents + 人在环 + 全程可审计

LangChain 把自家销售用的 GTM agent 拆开讲了一遍，对 LangGraph 栈的人是难得的一手工程案例。它建在 Deep Agents 上，因为这是一个长跑、多步、要可靠编排多个工具和大量数据的流程：Salesforce 来新线索就自动接管，先找「不该发」的理由（有人刚提工单、同事本周已联系过就停手），再拉 Salesforce/Gong/LinkedIn 做调研，最后把带推理和来源的草稿丢进 Slack 等销售批准。三条硬约束值得抄作业——人在环（不经批准绝不发出）、联系历史感知、每一次 send/edit/cancel 都打进 LangSmith trace 用来评估质量和抓回归。官方给的效果是线索到商机转化率涨 250%、每位销售每月省下 40 小时，这些是 LangChain 自报数据，看趋势不看绝对值。

→ [原文](https://www.langchain.com/blog/how-we-built-langchains-gtm-agent) / [Paid Media Agent](https://www.langchain.com/blog/paid-media-agent)

**Harness or Model? Isolating the Harness Effect in Agentic Coding** — 在私有、防污染的题库上用「同模型配不同 harness」的成对对比，量化厂商自家 harness（工具+提示+控制流）到底贡献了多少，而不是全归功于模型本身。做 coding agent 选型时值得一读。→ [arXiv](https://arxiv.org/abs/2609.11987)

**SoK: Rethinking Jailbreaking in the Era of Agentic AI** — 系统梳理 agentic AI（会推理、规划、调工具、持久记忆、跨 agent 通信）时代的越狱攻击与防御：现代模型原生对齐更强，但 agent 的工具/记忆/多步执行开出了新的攻击面。→ [arXiv](https://arxiv.org/abs/2609.12413)

**Skill Issue: Lessons from Optimizing Repository SKILLs for Coding Agents** — coding agent 越来越依赖仓库里随代码一起版本化的 SKILL.md 知识文件，这篇讲怎么优化这些文件（尤其是没有现成 benchmark 的裸仓库场景）。→ [arXiv](https://arxiv.org/abs/2609.12742)

**AIM: A Privacy-Aware Interoperable Memory Framework for Multi-Agent Multi-User** — 面向多 agent、多用户系统的隐私感知、可互操作记忆框架，解决现有 agent 记忆多停留在单用户级、难以安全共享公共知识的问题。→ [arXiv](https://arxiv.org/abs/2609.12320)

## 📈 趋势

- 🔺 「人在环 + 全程 trace 可审计」正在从安全口号变成 agent 工程的标配设计（LangChain GTM agent 是典型）

- 🆕 MCP 成为 agent 接入外部系统的通用接口层：从身份鉴权（Casdoor）到项目排期（ProGantt）都在以 MCP 暴露能力
