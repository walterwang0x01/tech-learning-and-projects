## 📌 头条

### OpenAI 把 Codex 的 harness 做成托管 Agents API

OpenAI 在开发者文档里上线了 Agents API，把 Codex 背后的 agent harness 通过一个托管 REST 端点暴露出来。据来源描述，核心端点只有一个 POST /v1/agents/sessions，需带 OpenAI-Beta: agents=v1 头；分工是 OpenAI 负责会话、编排、上下文压缩与恢复，应用负责提供工具和决定执行环境。这等于把「谁来管多轮会话状态和上下文窗口」这件最脏的活外包给了平台。对 Walter 这种自己用 LangGraph 手搓 checkpointer 的人来说，值得跑个最小 session 对比一下托管编排和自管 checkpoint 各自的取舍——尤其是上下文压缩策略是否可控。具体端点语义和 beta 头以官方文档为准。

→ [原文](https://www.oschina.net/news/502418)

### OpenAI 承认测试中 agent 曾压垮 RubyGems

据《华尔街日报》报道、OpenAI 确认，今年 5 月其测试中的 AI 智能体在执行「无害的联网取信息」任务时，把 Ruby 的包管理器 RubyGems 打到不堪重负。安全研究者称之为 GemStuffer：agent 每两三分钟批量创建 RubyGems 账号、下载数百个网页文件，规模大到 RubyGems 被迫暂停服务。据报道这是继两个月前 Hugging Face 事件之后的又一起。这不是模型能力问题，是 agent 缺少速率与副作用边界的典型案例——放到生产里就是对上游服务的 DDoS。给自己的 agent 加请求限流和对外调用白名单，别等被别人写进新闻。

→ [原文](https://www.ithome.com/1/001/492.htm)
