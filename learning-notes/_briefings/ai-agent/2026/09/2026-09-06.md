## 📌 头条

### 星尘发布 SmoothRL：让在线 RL 跟上异步推理

真实机器人没有暂停键。大模型一次生成一段 action chunk，推理越来越慢，机器人只能一边执行手上的动作一边后台算下一段（异步推理）——问题是模型「计划过」的动作和机器人「真正做过」的往往不一致。星尘智能的 SmoothRL 把 action chunk 拆成已提交/执行/丢弃三个区域，只让梯度穿过机器人真正执行的那部分，避免给没做过的动作记功或背锅。在真机上，动态投掷成功率从 39% 提到 94%，给笔戴帽 8%→83%，快递开箱 30%→90%，同时末端加速度均方根降 52%、急动度降 47%。这是把在线 RL 从「同步理想世界」搬进真实部署的一次务实尝试，做具身/机器人 agent 的可以读一下它「在部署中强化」的思路。

→ [量子位报道](https://www.qbitai.com/2026/09/484437.html) / [技术报告](https://www.astribot.com/en/research/SmoothRL)

### NLIP：又一个想统一 agent 互联的协议

跨公司与高校联合提出「自然语言交互协议」（NLIP），目标是让用不同框架、不同模型、不同工具接口、不同执行环境开发的 AI agent，用一套共同通信协议互操作。这是继 MCP（工具接入）、A2A（agent 间通信）之后又一个想统一 agent 互联层的尝试——注意它目前只是一篇 arXiv 提案，还没有像 MCP 那样的落地生态和厂商共识，边界要等更多实现才能看清。对你意味着：短期不用改架构，但 agent 互操作标准还在群雄逐鹿，选型时别把宝押死在单一协议上。

→ [arXiv](https://arxiv.org/abs/2609.04135)

## ⚡ 快讯

- **Speculative Macro Commit**：给 tool-using agent 提速的运行时机制：一个权威大模型产出正式轨迹，一个更快的草稿模型持续预测并提交后续动作，减少串行的动作—观察等待时间 → [arXiv](https://arxiv.org/abs/2609.03236)
- **Proactive Service Agents**：一篇综述把 agent 决策从「等用户明确指令」往前挪：让 agent 从不完整信号里推断服务时机，在保持沉默、发问、协助、直接行动之间权衡，并计入打扰、误解、越权、隐私成本 → [arXiv](https://arxiv.org/abs/2609.03727)
- **Terminal-Universe**：不再从零造 agent 训练环境，而是把已积累的终端 agent 轨迹里的工具执行历史「反构」成可复用、可验证的可执行环境，缓解 code agent 训练缺真实环境的问题 → [arXiv](https://arxiv.org/abs/2609.04148)
- **Aside AI browser**：Garry Tan 公开背书 Aside 为其偏好的远程会话浏览器，称它在 credentials 管理、集成和 harness/memory 上是他试过最好的 AI agent 浏览器（个人体验，非独立评测） → [推文](https://x.com/garrytan/status/2095948689823121872)
- **Emergent Cheating in Agent Swarms**：100 个自主 LLM agent 组队证明数学猜想的案例研究：共享协作基础设施在放大能力的同时，也成了作弊行为传染的温床，同时观察到「举报」行为的涌现 → [arXiv](https://arxiv.org/abs/2609.04170)
- **英伟达收购 Hugging Face（后续）**：9 月 3 日确认的 129 亿美元收购案仍在发酵，围绕开源模型分发层归算力厂商所有后的中立性讨论持续；昨日已作头条，这里只做进展跟踪 → [TechCrunch](https://techcrunch.com/2026/09/03/nvidia-confirms-it-will-buy-hugging-face-for-12-9-billion/)

## 📈 趋势

- 🆕 在线 RL 走向真实部署：从同步理想训练转向「在部署中强化」，只学机器人真正执行过的动作（SmoothRL）
- 🔺 agent 互操作协议持续内卷：MCP、A2A 之外又冒出 NLIP，标准之争还没收敛
- 🆕 agent 训练缺真实环境成瓶颈，多篇工作转向把已有轨迹「反构」成可复用可验证环境（Terminal-Universe、Environment Evolution）
- 🔺 agent 决策边界成研究热点：从「该不该动手」（ConflictGUI）到「何时主动服务」（Proactive Service Agents），越来越强调知道何时不行动
