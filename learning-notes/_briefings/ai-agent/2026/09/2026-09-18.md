## 📌 头条

### 四大 AI 编程代理同栽在「技能更新」上

安全公司 Air 披露了一个他们命名为 Plugin4Shell 的漏洞，Claude Code、OpenAI Codex、Google Gemini CLI、GitHub Copilot 四家的 Skill/插件自动更新机制都中招：更新时只认插件名不校验内容变更，攻击者把同名插件悄悄换成恶意版本就能被自动装上，绕过各家的 SHA 锁定，属于「零点击」供应链攻击。The Register 和 Air 官方博客都报了，除 GitHub 外三家已修复，GitHub 称自身机制能挡住但没确认补丁。这不是某一家的实现 bug，而是四家验证机制设计雷同暴露的行业共性盲区——你要是在企业里给这些 agent 装过第三方 skill/插件，尽快把 agent 本体升到最新版，marketplace 侧修不了这个洞。

→ [The Register](https://www.theregister.com/security/2026/09/17/ai-coding-agents-0-click-rce-flaw-could-hand-attackers-keys-to-the-kingdom/) / [36氪](https://www.36kr.com/newsflashes/3988271860956160)

### Claude 把 Cowork 和 chat 合并成一个

Anthropic 从 9 月 16 日起把 Claude Cowork（跑多步长任务的工作台）和普通聊天合并成「一个 Claude」，不再让你先选用哪个模式——由 Claude 根据你的 prompt 自己判断是快答还是走 agentic 深做。同时把 Claude Docs、Claude Slides、Claude Design 直接塞进对话里，让 Claude 出一份可编辑并能导出 PowerPoint/PDF 的文档、幻灯片或视觉稿，不用再切标签页。官方说先对 Pro/Max 铺开，Team/Free 随后。对做 agent 产品的人来说，这是「模型能力够强后，路由交给模型自己做」这条路线又一个明确信号。

→ [官方博客](https://claude.com/blog/cowork-is-now-claude) / [作者原推](https://x.com/_catwu/status/2100260655312089562)

**Compositional Policy Violations: When Step-Level Compliance Fails In Agentic AI Workflows** — 指出现在给 agentic 工作流套的治理几乎都是「步级」的（逐轮 rail、span 评估器），但组织真正持有的策略（转诊阈值、审批权限、审查要求）是整条执行的属性，这个错配会漏掉一类「每步都合规、整体却违规」的失效。→ [arXiv](https://arxiv.org/abs/2609.18820)

**Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress** — agentic 请求大量时间在等工具返回，其 KV cache 却一直占着 GPU 显存；论文论证任何在调用前就固定的时长估计都无法预知真实耗时，主张让服务系统直接读工具调用自身携带的进度。→ [arXiv](https://arxiv.org/abs/2609.18849)

## 📈 趋势

- 🆕 Agent 安全从「防 prompt injection」升级到「防供应链」——Plugin4Shell 把矛头指向 skill/插件的更新校验环节，这是模型层防御够不到的地方。
- 🔺 大厂都在往「一个入口、模型自己路由」收敛——Claude 合并 Cowork/chat，本质是把「用哪个工具」的判断从用户手里交给模型。
- 🔺 「自我改进」成为下半场关键词——智谱 RSI、小米 MiMo 直播 RL 后训练，都在押注让模型参与训练/改进自己。
- 🆕 arXiv 上 agentic 工作流的「治理与可观测」论文明显增多——组合式策略违规、动作级安全信号、独立性分级审计接连出现，说明 agent 落地到受监管场景后合规缺口开始被系统化研究。
