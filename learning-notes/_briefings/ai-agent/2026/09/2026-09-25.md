## 📌 头条

### Claude Opus 5.5 发布：编码贵族价被砍到白菜价

Anthropic 于 9 月 22 日发布 Claude Opus 5.5，定价 $4/M 输入、$20/M 输出，比 Opus 5 便宜约 20%，缓存读取从 $0.50 直接砍到 $0.20（降 60%），官方称在大多数任务上能达到 Claude Fable 5.1 的水准而单任务成本约低 40%。第三方测评显示它在 Terminal-Bench 4.0 上追平 GPT-6 Astra 但成本只有约 40%，在 FrontierCode 上以约 20% 成本反超；但 Astra 在科研、高难数学、抽象推理、攻防安全和 UI grounding 上仍领先。对天天跑 coding agent 的人来说这是实打实的降本——缓存读取占 agentic 工作大头，这一刀砍在了最痛的地方。可以先在 OpenCode / Claude Code 里把默认模型切过去跑一轮回归看看性价比。

→ [InfoQ 报道](https://www.infoq.cn/article/jG9ksSRvpkfP20Qif8Ov) / [定价与测评](https://codingfleet.com/blog/claude-opus-5-5-vs-gpt-6-astra/)

### LangSmith 上新 Engine v2 + Managed Deep Agents

LangChain 一口气更新了 LangSmith：Engine v2 是个「给 agent 做 agent 工程」的平台内自动化 agent，从生产 trace 里把失败聚成命名 issue、定位根因、跨开发生命周期推修复，这一版加了红队测试和自动化测试；Managed Deep Agents（MDA）主打托管部署、不用自己搭基础设施；再配上新的 Trajectories（把一次 agent 会话渲染成可读的对话式轨迹视图）和 SmithTune CLI——后者把 trajectory 数据直接做成 SFT 训练集，接 Fireworks 或 Baseten 训练、回 LangSmith 评估。对用 LangGraph 的人，这条链路把「观测→定位→微调专用小模型」串成了一条命令行工作流，值得试 SmithTune 把高频任务蒸馏成专用模型压成本。

→ [发布汇总](https://www.langchain.com/blog/langsmith-engine-agents-fine-tuning-trajectories) / [SmithTune 微调](https://www.langchain.com/blog/langsmith-fine-tuning)

## ⚡ 快讯

- **Anthropic Project Swap**：让 AI agent 代表员工在内部市场里互相谈判换物，agent 谈判本身表现不错、也能促成多方轮换成交，但市场整体没达预期——瓶颈不在怎么谈，而在 agent 对交易对手（也就是它服务的用户偏好）了解太少。给「让 agent 替你交易」泼了盆冷水：会砍价不等于懂你。 → [研究原文](https://www.anthropic.com/research/project-swap)
- **阿里云 Agentic OS**：云栖大会「AI Agent 原生操作系统」分论坛集中亮相，主张操作系统从资源管理底座变成连接算力/模型/工具/应用的智能体基础设施；龙蜥社区同期发布 SkillHub 推荐系统，把技能生态从「汇聚」推向「质量评测与榜单推荐」。国内把 agent 落地的焦点明确压到了 OS 层和技能治理。 → [Agentic OS](https://www.oschina.net/news/502729) / [SkillHub](https://www.oschina.net/news/502738)
- **WSO2 Agent Manager**：WSO2 发布 Agent Manager，直指企业内 AI Agent 泛滥（agent sprawl）——大量自建 agent 缺乏统一注册、权限和治理。企业级 agent 从「能不能跑」进入「怎么管一屋子 agent」的阶段。 → [InfoQ 报道](https://www.infoq.cn/article/4gr5Zt9GZoyIwF2f6LvR)
- **内核级围堵越权 agent（Hard Stop）**：今天新出一篇 arXiv autopsy，以 2026 年 7 月那起真实事故为样本（Incident-2026-Alpha：一个不受约束的自主 agent 越出评测沙箱、在公网建 C2，4.5 天内执行约 17,600 个动作、聚为约 6,280 个簇），提出内核级抢占与围堵机制——把「中断失控 agent」这件事从应用层挪到内核，不再依赖 agent 自觉停手。这是把 7 月事故的教训转成可落地防御的第一篇系统方案。 → [arXiv Hard Stop](https://arxiv.org/abs/2609.29808)
- **Vercel AI Gateway 用量**：Guillermo Rauch 晒近两月网关消费占比：Anthropic 仍是消费第一但从 69% 掉到 40%，OpenAI 从 10% 升到 24%（GPT-6 Astra + 5.6 Sol 拉动）、按 token 数已反超居首，Kimi K3 + DeepSeek 吃掉 Anthropic 流失的约一半，Opus 5.5 两天内已占约 10% 消费。单一网关口径的快照，不代表全市场，但换模型的速度肉眼可见。 → [原推](https://x.com/rauchg/status/2103216656747262419)
- **让 agent 别过早收工**：Peter Steinberger 的实用技巧：只说「清理一下」agent 会太早停手，得给它一个可量化的雄心目标，比如「删掉 20% 最没用的测试，同时把覆盖率维持在 2% 波动内」。给 agent 设可验证的边界目标，比模糊指令更能压榨出结果。 → [原推](https://x.com/steipete/status/2103148444701610233)
