## 📌 头条

### Google Home 开放 MCP，任意 Agent 都能管你的智能家居

Google 于 9 月 16 日开放了 Google Home MCP 服务器的早期访问，让任何支持 Model Context Protocol 的 Agent——包括 Claude、ChatGPT、Hermes、OpenClaw 以及 Google 自家的 Antigravity——用自然语言发现设备、读取状态与摄像头事件历史、执行受控操作，甚至把 Google Home 音箱当成 Agent 的「嗓子」。这是 MCP 从开发者协议走进消费级硬件入口的一个标志性动作：智能家居不再只认 Gemini，用户可以自己换 Agent。目前仅面向美国、英语、Google Home Premium Advanced 用户灰度。如果你在做 MCP 集成，值得去申请早期访问、看看它把「设备控制」这类高风险动作的授权与安全边界怎么划的。

→ [The Verge](https://www.theverge.com/tech/996310/google-home-mcp-integration-agentic-ai-smart-home-price-release-date) / [TechCrunch](https://techcrunch.com/2026/09/16/your-ai-agents-can-now-control-your-google-home-devices)

### MCP 正在取代 CLI，成为 Agent 集成的默认方式

Anthropic 的 Thariq(@trq212)抛出一个观察：MCP 现在比 CLI 更适合大多数集成场景。理由有二——模型的工具调用能力已经明显变强,而 MCP 现在是无状态的,只要给工具加上 query 之类的参数就能组合、过滤数据。这条个人判断呼应了当天 Google Home 用 MCP 而非 CLI 开放家居控制的选择。对做 Agent 平台的人是个方向信号:如果你还在给每个集成手写 CLI 封装,可能该重新评估把能力包成 MCP tool 的投入产出了。注意这是一条工程师的一手观点,不是官方结论。

→ [原推](https://x.com/trq212/status/2099958388230873165)
