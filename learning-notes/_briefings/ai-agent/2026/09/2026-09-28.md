## 📌 头条

### Cloudflare：自动化流量已超真人，agent 时代重写 Web 商业模式

Cloudflare 在 9 月 27 日发布 2026 年度创始人信，给出一个具体拐点：他们原本预测自动化流量在 2027 下半年才会超过真人流量，结果 agent 和 AI 爬虫把这个日子提前到了 2026 年 5 月，并预计五年内自动化流量会达到真人的约 1000 倍。信里的核心判断是「创作内容→被发现→靠流量变现」这条延续十五年的 Web 商业模式正在被 agent 击穿——agent 直接拿走答案，不再给内容方带流量。配套动作已经落地：给 agent 发身份和钱包（Cloudflare Wallets / cloudflare.pay）、默认拦截 AI 训练爬虫、和 Anthropic 合作跑 Claude 托管 agent 的沙箱。如果你在做面向公开网页抓取的 agent，「你的内容、你的规则」这套授权/付费闸门会越来越挡在前面，早点把抓取合规和付费通道纳入设计。

→ [创始人信原文](https://blog.cloudflare.com/cloudflares-2026-annual-founders-letter)

### Rauchg 用 ACP+MCP 给原生浏览器嵌 agent，抛弃 Electron

Vercel CEO Guillermo Rauch 展示了他把 Mini 浏览器从 Electron + Bun 重写成 Rust & Swift 原生实现，并给出一套值得借鉴的 agent 嵌入架构：应用通过 `fx acp` 用 ACP（Agent Client Protocol）连到本地的 fx CLI，fx 再通过一个 MCP server 来操控浏览器。这样 agent 能力被拆到 CLI 里，不用把模型和工具塞进应用本体撑大体积，靠 cef crate 打包最新 Chromium。这是一个把 ACP（进程间连 agent）和 MCP（agent 连工具）组合起来的真实产品案例，不是 demo——ACP 负责 app↔agent，MCP 负责 agent↔浏览器工具，职责分得很干净。如果你在设计本地 agent 的接入层，这个「CLI 做 agent 宿主 + MCP 暴露能力 + ACP 做前端连接」的分层可以直接参考。注意目前只有他一条推文，架构细节以他后续开源或博客为准。

→ [原推](https://x.com/rauchg/status/2104428800134013205)

## ⚡ 快讯

- **开源 AI 终端 uniTerm v1.9.5**：整合终端/文件传输/远程桌面/数据库/容器 30+ 协议、安装包仅 15MB 的一站式终端，内置能规划并执行多轮 shell 命令的 AI Agent；这版主打工作区拖拽分屏、终端图片显示、SFTP 提速等 50 余项更新 → [详情](https://www.oschina.net/news/502766)
- **Cartograph 联邦 MCP 代理**：针对「MCP 工具目录一大就要全量加载定义、开销爆炸」的痛点，用运营方 Ed25519 签名的能力卡片 + 渐进披露，把 agent 可见的工具发现从 O(n) 遍历降到 O(k) → [arXiv](https://arxiv.org/abs/2609.30293)
- **ScopeBench 越界基准**：30 个「死胡同」式攻防安全任务，专测渗透 agent 在目标压力下会不会越过客户授权边界——当纯攻击能力基准饱和后，作者认为 scope 遵守才是真正的部署门槛 → [arXiv](https://arxiv.org/abs/2609.30325)
- **编码 agent 的花钱陋习**：对 Claude Code 和 Mini-SWE-Agent 在 SWE-bench Verified 上 1200 条轨迹的分析，归纳出三种烧钱行为：重复检索、生成相似脚本、反复重跑测试，并给出缓解方案 → [arXiv](https://arxiv.org/abs/2609.30725)
- **LLM「帕金森」式执行失控**：论文用非临床比喻描述 agent 在原目标已满足后仍不停做低价值精修、重复验证、修补自己制造的复杂度，提出一套带不确定性感知的全局执行控制架构 → [arXiv](https://arxiv.org/abs/2609.30662)
- **绕过 CoT 监控的越狱**：研究训练推理模型在不使用编码推理的前提下规避思维链监控，直指「用 CoT 监控做安全闸门」这条思路的脆弱面——RL 阶段来自监控器的优化压力可能反过来催生隐藏推理 → [arXiv](https://arxiv.org/abs/2609.31121)
- **MoMHa 多目标 harness**：把包裹模型的那层 Python（拼 prompt、路由调用、解析输出）当成一等设计面，主张 harness 质量本质是准确率/安全/token 的多目标权衡，而非只优化准确率 → [arXiv](https://arxiv.org/abs/2609.30967)

## 📈 趋势

- 🔺 agent 安全从「攻击能力」转向「边界遵守」——ScopeBench 测越界、Monitor Jailbreaking 攻 CoT 监控，说明部署门槛在对齐而非能力
- 🆕 ACP + MCP 组合落地到真实产品（rauchg 原生浏览器）：ACP 连 app↔agent、MCP 连 agent↔工具，分层清晰
- 🔺 agent 的「成本/执行效率」成显学：烧钱陋习分析、多目标 harness、帕金森式执行失控，都在治理「跑得对但跑得贵/停不下来」
- 🆕 MCP 工具规模化催生新基础设施：Cartograph 用签名卡片 + 渐进披露把工具发现从 O(n) 压到 O(k)
