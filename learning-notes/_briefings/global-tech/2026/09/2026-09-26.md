### 微软重塑 Copilot：聊天、编程、常驻智能体合一

微软 9 月 25 日发布重构后的 Copilot，把对话（Chat/Cowork）、编程（Code）和常驻智能体（Autopilot，即 Build 上发布的 Scout 改名）塞进同一个 App，还内置了 Word/Excel/PowerPoint 的 Office 能力。官方类比这是「AI 时代的 Office」，意图很明确：抢企业市场、正面对上 Anthropic 和 OpenAI。对开发者的实际信号是——Code 面板基于 GitHub Copilot 同一套技术，让非技术用户也能起简单编程项目，Autopilot 则能在 Teams/Outlook 里跑长任务。是否真如宣传那样「重新定义工作方式」还得看实际落地，但这是微软把散落的 AI 产品线收拢成单一入口的一步。

→ [微软官方博客](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/) / [The Verge](https://www.theverge.com/news/1000532/microsoft-copilot-super-app-chat-coding-autopilot)

### GitHub 弃用 CSS-in-JS，靠「多发 CSS」提性能

GitHub 工程团队发文，讲了 github.com 如何彻底迁移出 CSS-in-JS。核心思路反直觉：与其在运行时用 JS 生成样式，不如直接多发静态 CSS，把样式计算从浏览器主线程和 JS 包里挪出去，换来更快的首屏和更小的 JS 体积。对 Walter 的 TS/React 栈是个直接相关的案例——CSS-in-JS 的运行时成本一直是社区争论点，一手大厂的迁移经验比泛泛的对比文章更有参考价值。如果你的项目也在用 styled-components/emotion 这类方案，值得读一读他们踩过的坑和度量口径。

→ [GitHub 工程博客](https://github.blog/engineering/architecture-optimization/improving-site-performance-by-shipping-more-css)
