### Mojo 1.0 发布：三年之后给出稳定性承诺

Modular 在 8 月 11 日随 Modular 26.5 发布了 Mojo 1.0，这是这门语言 2023 年首次亮相以来第一次给出正式的兼容性承诺。官方的说法很务实：稳定策略先覆盖一小批被标记为 stable 的标准库 API，之后逐版本扩大，语言层面的变更以「只增不改」为原则。新版本还带来了 Python 风格的 lambda 内联闭包语法、改进过的 LSP 服务端（对接 VS Code 一类编辑器）以及 Mojo AI skills。值得一起看的背景是所有权变了——Qualcomm 已于 7 月 29 日完成对 Modular 的收购（约 39.2 亿美元全股票交易），Chris Lattner 带着 Mojo 和 MAX 一起进了 Qualcomm 的 AI 软件体系。如果你此前因为「语言还在天天变」而观望，1.0 是重新评估的合理时点，但先确认你要用的 API 是否真的在 stable 名单里。

### Tailscale 揪出潜伏 16 年的 SQLite WAL-Reset bug

Tailscale 去年底开始 uptime 不稳，半年里出现 19 次独立的数据库损坏事件，最终定位到 SQLite 里一个存在了 16 年的 WAL-Reset 数据竞争。他们的控制平面按 SQLite 官方推荐的单写入者架构用了三年多，本该是最保守的用法——这也是这篇复盘最扎心的地方：问题不在你的架构，在你脚下这层库。SQLite 官方的措辞也说明了难度：这是一个时序条件极窄的数据竞争，维护者自己从未有机组复现过，只能往 SQLite 里加专门的测试逻辑来人为触发，才能验证修复有效。定位过程用到了 Antithesis 的确定性模拟测试，他们同步发了自己那侧的技术复盘；SQLite 侧的修复已随 3.52 版本发布。用 SQLite 做生产状态存储的先查一下版本。

→ [Tailscale 复盘](https://tailscale.com/blog/sqlite-wal-reset-bug) / [Antithesis: Breaking the WAL](https://antithesis.com/blog/2026/wal-reset-bug) / [The Register](https://www.theregister.com/databases/2026/08/12/deeply-buried-16-year-old-sqlite-bug-caused-last-years-tailscale-outages/5287004) / [SQLite 3.52 修复](https://linuxiac.com/sqlite-3-52-released-with-wal-corruption-fix-and-cli-improvements/)
