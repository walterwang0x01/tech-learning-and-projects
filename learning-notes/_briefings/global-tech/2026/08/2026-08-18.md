### GitHub 宕机七个半小时，HN 冒出「换掉 GitHub」

8 月 17 日 13:40 UTC，GitHub 状态页开了一起大面积故障，范围一路铺到 web、API、Actions、Issues、Pull Requests、Webhooks 和仓库归档下载。itnews 按状态页口径记的数字是：web 与 API 错误率约 20%，归档下载和 raw 仓库内容失败率约 50%；GeekWire 称故障从开始到宣布解决约七个半小时（美东 14:15），期间八项受影响服务中有七项在 16:59 UTC 被标记缓解，Copilot 的零散登录失败又拖了更久。根因至今没公开，GitHub 说会出详细的 root cause analysis。真正的信号不在这一次故障本身，而在 HN 同时挂着的两条帖：「Ask HN: Alternatives to GitHub」545 分，开帖第一句是发帖人自己的判断——「过去几个月 GitHub 一直在挂」；另一条「Ask HN: GitHub employees what's going on?」102 分。多数团队的 CI、依赖拉取、容器构建都把 github.com 当成隐式可用的基础设施，今天值得花十分钟翻一遍 CI 配置：有没有对 raw.githubusercontent.com 和 codeload 归档下载的硬依赖，能不能换成本地缓存或镜像。

### DuckDB v2.0 预览：从进程内库长成一台服务器

官方 8 月 17 日放出 v2.0 预览（代号 Cyanoptera，秋季发布），自 3 月 v1.5 以来累积一万多次提交，HN 586 分 106 评。方向上最大的变化是 client/server：quack 扩展在 v2.0 转正，任何 DuckDB 进程都能把自己的库通过网络服务出去，另一端用新的 `CONNECT` 语句接过去；`CONNECT` 也能直连 PostgreSQL / MySQL，配合新的远端下推优化器把 SQL 推到对面执行，而不是把整张表拉回本地。日常能立刻用上的有三样：触发器补齐（BEFORE / AFTER、行级与语句级、`REFERENCING OLD/NEW TABLE` 过渡表）、VARIANT 打通了从存储到执行的 shredded 全链路（官方说后续打算反过来用 VARIANT 实现常规 JSON 类型，但明确写了「别拿这个当承诺」）、以及全引擎异步 I/O，Parquet 先落地、CSV 和自有格式跟上，收益主要在对象存储而不是本地盘。硬指标官方也给了：100 万条边的单源可达性递归 CTE 微基准，从 v1.5.4 的 4.90 秒降到 v2.0 预览的 0.12 秒，约 40 倍——底下是重写过的递归 CTE 引擎。另外沿用多年的 PostgreSQL 派生解析器被自研 PEG 解析器替掉（扩展从此能挂进语法本身），默认存储格式升到 2.0.0，ICU 依赖被整个移掉、时区数据自建压到约 45 kB。破坏性变更包括新默认存储格式和 lambda 语法过渡收尾，preview build 现在就能装，值得先拿非生产库试 `CONNECT` 和触发器。

→ [DuckDB 官方博客](https://duckdb.org/2026/08/17/duckdb-20-highlights) / [HN 讨论](https://news.ycombinator.com/item?id=49330781) / [开源中国](https://www.oschina.net/news/501974/duckdb-2-0-highlights-preview)
