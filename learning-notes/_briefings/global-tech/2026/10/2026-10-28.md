### CPython 实验性 JIT 要被移除了

2024 年随 Python 3.13 进入 CPython 的实验性 JIT 编译器走到了尽头。指导委员会今年 6 月暂停了主分支上的 JIT 工作，要求维护者提交一份正式的标准跟踪 PEP（限期六个月）来讲清它的维护承诺、兼容性和成功指标，否则就从主分支删掉代码。维护者为此起草了 PEP 836，经过数月讨论后主动撤回，JIT 开发目前基本停摆。对写 Python 的人来说短期没影响——这个 JIT 一直是默认关闭的实验特性、加速有限，真正值得注意的是 CPython 提速的重心短期内还是会压在解释器本体和外部方案（PyTorch compile、Numba、CinderX）上。

→ [LWN](https://lwn.net/SubscriberLink/1102102/0c00e4d550f25f8c/) / [HN 讨论](https://news.ycombinator.com/item?id=50257419)

### PHP 两个严重漏洞被在野利用，CISA 下三天整改令

美国网络安全机构 CISA 确认，一对 PHP 严重漏洞（被称为 PHP2Shell）已在实际攻击中被利用，并要求联邦民用机构三天内修复。漏洞允许攻击者无需密码远程入侵，而 PHP 据称支撑着约 70% 的面向 Web 的服务器，一些政府和大公司为修复甚至临时下线了站点。更值得警惕的是这条新闻背后的趋势：这两个漏洞两年前就被发现、当时被判为无法实际利用而搁置，今年安全公司 Calif 借助 AI 模型找到了利用链才变成真实威胁。老旧且长期缺乏资金的 Web 基础组件，正因为 AI 挖洞能力的进步被重新翻出来。自查手头 PHP 服务是否已升到上周发布的补丁版本。

→ [TechCrunch](https://techcrunch.com/2026/10/27/us-government-says-hackers-are-now-exploiting-critical-php-web-bugs/)
