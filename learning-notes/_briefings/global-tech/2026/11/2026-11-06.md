## 📌 头条

### 「sshole」：超长密码就能绕过 Alpine 的 SSH 认证

OpenSSH 11 月 5 日发了 10.6p2 紧急修复一个关键漏洞（CVE-2026-123158，外号 sshole）。触发条件很窄但后果很重：只在用 musl libc 且关掉 PAM 的系统上（Alpine 是典型，OpenWrt 也受影响），sshd 自己校验密码时出问题——对一个本不该接受密码的账户（比如只配了密钥的账户，密码字段是 `*`），攻击者发一个 257 到 1024 字节的超长密码就能登进去，包括 root。glibc 系统、开了 `UsePAM yes` 的、Dropbear 和 OpenBSD 都不受影响。Alpine 已经把修复 backport 到各维护分支甚至几个 EOL 分支。跑 Alpine 容器或 musl 系统的，今天就该把 openssh 升到带修复的版本。

→ [Alpine 安全公告](https://alpinelinux.org/posts/2026-11-05-openssh-password-authentication-bypass/) / [Ars Technica](https://arstechnica.com/security/2026/11/vulnerability-allows-attackers-to-log-into-some-linux-devices-sans-password/)

### GitHub 重构 Git 存储：为「上千 agent 同推一个仓库」而建

GitHub 工程博客拆解了新的 Git 存储架构，开篇直接点题：这套设计的目标是让上千个 agent 能同时往同一个仓库 push。这反映出一个很现实的工程假设——未来代码写入方不只是人，而是大量并发的自动化 agent，底层存储得按这个量级重新设计并发与一致性。对关注 Git 内核、大规模协作和 AI 编码落地的人，值得看它怎么处理这种写入竞争。具体架构细节以原文为准。

→ [GitHub Blog](https://github.blog/engineering/architecture-optimization/inside-githubs-new-git-storage-architecture)
