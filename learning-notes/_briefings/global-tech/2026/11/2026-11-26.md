### Anthropic 把 Messages API 从 Python 迁到 Rust

Anthropic 发文讲了 Messages API 从 Python 迁到 Rust 的过程。2024 年初到 2026 年秋，API 流量涨了约 1800 倍，每个请求都要经过校验、转成 prompt、分词和安全分类器，Python 在每一步都带来额外开销。文中说 Claude 大约一周写出了请求核心路径的第一版，真正难的是证明 Rust 版和线上行为一致：Python 版迁移期间还在改，Claude 对同一请求的回复本来就不确定，团队也不能读客户请求。他们的做法是让线上的 Messages API 本身当验证器，用真实流量测试 Rust 版、找出差异，再自动派 Agent 去修。按文章的说法，上线后每个请求的 CPU 用量降了约 70%，首 token 中位延迟降了约 20%，全程没有停服，也没有冻结功能开发。这些数字是 Anthropic 自述，没有第三方复测。要迁移线上系统的团队可以参考“用线上流量对比新旧实现”这个思路。

→ [Anthropic](https://www.anthropic.com/research/migrating-api-to-rust)

### NFS2ROOT：Linux NFS 服务端 12 年的未认证远程 root 漏洞

OpenSec 披露 CVE-2026-99362，CVSS 9.8：Linux 内核 nfsd 在处理 NFSv4.1/4.2 的 SEQUENCE 请求时，客户端可以把会话槽的回复缓存设为 0 字节，服务端仍会把完整回复拷进去，造成内核堆溢出（越界写 61 字节）。攻击只需连到 tcp/2049，不用登录。该提交 2014 年进入 Linux 3.16，此后的内核都带着它。修复版本是 6.12.117、6.18.61、7.3.2 和 7.4-rc1，漏洞 11 月 20 日公开。OpenSec 称他们用自家的 Antara 工具发现并自动构造出 root shell，ANSSI 的 Jérémy Jean 独立发现并提交了上游补丁；利用代码未公开。这是 OpenSec 的一手披露。暂时不能升级的，限制 2049 端口只对存储网络开放，或在 /etc/nfs.conf 的 [nfsd] 段关闭 NFSv4.1 和 4.2（会失去 pNFS 和部分 4.2 特性）。发行版内核要看更新说明里是否列出该 CVE。

→ [OpenSec](https://opensec.in/blog/nfs2root-cve-2026-99362)
