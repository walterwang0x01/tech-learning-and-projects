# Go 类型系统与泛型

> Author: Walter Wang

<!-- version-check: Go 1.26, Generics 1.18+, Type Aliases 1.24+, checked 2026-05-28 -->

## 1. Go 类型系统的原则

```
Go 的设计哲学：
├─ 类型简单而严格（不像 TypeScript 那么复杂）
├─ 显式优于隐式（不自动类型转换）
├─ 组合优于继承（struct + interface）
└─ 结构化类型（duck typing）
```

## 2. 类型定义 vs 类型别名

```go
// 类型定义：新类型，不兼容原类型
type UserID int64

var id UserID = 123
// var x int64 = id    // ❌ 不能直接赋值
var x int64 = int64(id) // ✅ 显式转换

// 类型别名：同一个类型的别名，完全兼容
type MyInt = int64

var a MyInt = 1
var b int64 = a  // ✅ 直接赋值
```

**实战**：给 ID 类型做 `type XxxID int64` 比裸 `int64` 更安全（编译器防止混用用户 ID 和订单 ID）。

## 3. 结构化接口（Duck Typing）

Go 的接口**不需要显式实现**：

```go
type Stringer interface {
    String() string
}

// Dog 自动实现 Stringer（因为有 String() 方法）
type Dog struct { Name string }
func (d Dog) String() string { return "Dog: " + d.Name }

func greet(s Stringer) { fmt.Println(s.String()) }

greet(Dog{Name: "Rex"})  // ✅
```

### 经典三大接口

```go
// io.Reader - 读
type Reader interface {
    Read(p []byte) (n int, err error)
}

// io.Writer - 写
type Writer interface {
    Write(p []byte) (n int, err error)
}

// error - 错误
type error interface {
    Error() string
}
```

标准库几乎所有 I/O 都基于这三个接口组合，所以你写的自定义类型能无缝接入生态。

## 4. 组合优于继承

Go 没有类和继承，只有 struct 嵌入：

```go
type Animal struct {
    Name string
    Age  int
}

func (a Animal) Describe() string {
    return fmt.Sprintf("%s, %d years old", a.Name, a.Age)
}

type Dog struct {
    Animal       // 嵌入，不是继承
    Breed string
}

func main() {
    d := Dog{Animal: Animal{Name: "Rex", Age: 3}, Breed: "Husky"}
    fmt.Println(d.Describe())  // ✅ 可以直接调用 Animal 的方法
    fmt.Println(d.Name)         // ✅ 字段提升
}
```

## 5. 泛型（Go 1.18+）

```go
// 基本泛型函数
func Max[T cmp.Ordered](a, b T) T {
    if a > b { return a }
    return b
}

Max(1, 2)         // int
Max("a", "b")     // string
Max(1.5, 2.5)     // float64

// 类型约束
type Number interface {
    ~int | ~int64 | ~float64  // ~ 表示"底层类型为"
}

func Sum[T Number](nums []T) T {
    var total T
    for _, n := range nums {
        total += n
    }
    return total
}

// 泛型类型
type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }
func (s *Stack[T]) Pop() (T, bool) {
    var zero T
    if len(s.items) == 0 { return zero, false }
    n := len(s.items) - 1
    v := s.items[n]
    s.items = s.items[:n]
    return v, true
}

s := &Stack[int]{}
s.Push(1)
s.Push(2)
v, _ := s.Pop()  // v = 2
```

## 6. 标准库的泛型工具（Go 1.21+）

```go
import (
    "slices"
    "maps"
    "cmp"
)

// slices
nums := []int{3, 1, 4, 1, 5}
slices.Sort(nums)                    // [1, 1, 3, 4, 5]
slices.Contains(nums, 3)             // true
slices.Index(nums, 4)                // 3
slices.Max(nums)                     // 5
slices.Reverse(nums)

// maps
m := map[string]int{"a": 1, "b": 2}
keys := slices.Collect(maps.Keys(m))    // 1.23+
values := slices.Collect(maps.Values(m))
maps.Clone(m)

// cmp
slices.SortFunc(users, func(a, b User) int {
    return cmp.Compare(a.Age, b.Age)
})
```

## 7. 泛型类型别名（Go 1.24+）

```go
// 以前：只能是具体类型的别名
type StringList = []string

// 1.24+：可以泛型
type List[T any] = []T
type Set[T comparable] = map[T]struct{}

var nums List[int] = []int{1, 2, 3}
var set Set[string] = map[string]struct{}{"a": {}}
```

## 8. 空接口与 any

```go
// Go 1.18+ 推荐用 any 替代 interface{}
var x any = 42
var s any = "hello"

// 类型断言
if n, ok := x.(int); ok {
    fmt.Println(n + 1)
}

// 类型 switch
switch v := x.(type) {
case int:
    fmt.Println("int:", v)
case string:
    fmt.Println("string:", v)
case []int:
    fmt.Println("slice:", v)
default:
    fmt.Println("unknown type")
}
```

**原则**：能用具体类型就不用 any。滥用 any 是 Go 代码坏味道。

## 9. 泛型使用建议

```
✅ 适合泛型：
├─ 容器类（Stack、Queue、Set）
├─ 算法函数（Map、Filter、Reduce）
├─ 辅助函数（Ptr[T]、Default[T]）
└─ 类型安全的缓存

❌ 不适合泛型：
├─ 业务逻辑（直接写具体类型更清晰）
├─ 单一用途函数
└─ 泛型 + 反射（几乎总是错的）
```

## 10. 反模式

```
❌ 用类型断言替代多态
func handle(x any) {
    switch v := x.(type) { ... }   // 应该用 interface
}

❌ 泛型嵌套过深
func Foo[T Bar[Baz[Qux]]]() { ... }   // 可读性爆炸

❌ 用 interface{} / any 作为参数类型图方便
func Process(data any) error   // 失去了类型安全

❌ 空 interface 当"基类"
type Animal interface{}        // 没有方法的 interface 等于 any
```
