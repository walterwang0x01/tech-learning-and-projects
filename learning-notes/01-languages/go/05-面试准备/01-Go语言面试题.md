## 1. 基础语法

### Q：Go 的零值（zero value）是什么？

```
int / float   → 0
bool          → false
string        → ""
pointer/slice/map/channel/interface/func → nil
struct        → 字段都是零值
```

零值是 Go 和很多语言不同的设计：**永远不会有未初始化的"未知"状态**。

### Q：make 和 new 的区别

```go
// new(T)：分配零值的 T 指针
p := new(int)   // p 是 *int，指向 0

// make(T, ...)：只能用于 slice / map / channel，返回已初始化的值
s := make([]int, 10, 100)
m := make(map[string]int)
c := make(chan int, 10)
```

**记忆**：`new` 返回指针，`make` 返回引用类型本身且已可用。

### Q：切片的底层结构

```go
type slice struct {
    array unsafe.Pointer  // 指向底层数组
    len   int             // 长度
    cap   int             // 容量
}
```

追问：为什么 `append` 可能改变 slice 的底层数组？

```go
s1 := []int{1, 2, 3}
s2 := append(s1, 4)       // s2 可能共享 s1 的数组，也可能是新数组
                           // 取决于 cap 是否够
s2[0] = 99                 // s1[0] 是否被改？不一定！
```

### Q：map 并发安全吗？

**不是**。`sync.Map` 或加锁。

```go
// 不加锁
m := make(map[string]int)
go func() { m["a"] = 1 }()
go func() { m["a"] = 2 }()
// → fatal error: concurrent map writes
```

## 2. 并发

### Q：Goroutine 为什么轻量

```
OS 线程：初始栈 1-8 MB
Goroutine：初始栈 2 KB，按需增长

一个进程可以轻松跑 100 万 Goroutine，OS 线程顶多几千
```

### Q：Channel 的底层实现

```go
type hchan struct {
    qcount    uint           // 当前元素数
    dataqsiz  uint           // 容量
    buf       unsafe.Pointer // 循环队列
    sendx, recvx uint        // 发送/接收下标
    recvq, sendq waitq       // 阻塞的 goroutine 队列
    lock      mutex
}
```

无缓冲 channel 的 send/recv 是同步的；有缓冲的异步（缓冲满时阻塞）。

### Q：select 机制

```go
select {
case v := <-ch1:        // ch1 准备好
case ch2 <- val:        // ch2 可写
case <-time.After(1s):  // 超时
default:                // 非阻塞
}
```

- 所有 case 随机选择（非顺序）
- 所有 case 都不就绪时：有 default 走 default，否则阻塞

### Q：goroutine 泄漏怎么排查

```
常见原因：
├─ Channel 没 close + reader 阻塞
├─ select 没写 ctx.Done()
├─ 死锁
└─ HTTP Handler 里起的 goroutine 没 timeout

排查工具：
├─ runtime.NumGoroutine()
├─ pprof goroutine profile
├─ go.uber.org/goleak（测试中检测）
```

### Q：sync.WaitGroup 的坑

```go
// ❌ Add 在 goroutine 里
go func() {
    wg.Add(1)  // race condition
    ...
}()

// ✅ Add 在 goroutine 外
wg.Add(1)
go func() {
    defer wg.Done()
    ...
}()

// ❌ 复制 WaitGroup
w := wg   // 新 WaitGroup，和原来的不通
```

### Q：Mutex 的 Lock/Unlock 成对吗？一定要 defer 吗？

成对必须，但不一定用 defer：

```go
// 短临界区，可以手动 Unlock
mu.Lock()
x++
mu.Unlock()

// 长临界区或可能 panic 的，用 defer
mu.Lock()
defer mu.Unlock()
if err := foo(); err != nil {  // 即使 foo 内部 panic，锁也能释放
    return err
}
bar()
```

## 3. 接口

### Q：interface 的底层结构

Go 的 interface 有两种：

```go
// 不含方法的 interface（iface）：类型信息 + 数据指针
type eface struct {
    _type *_type
    data  unsafe.Pointer
}

// 含方法的 interface：itab（方法表）+ 数据指针
type iface struct {
    tab  *itab
    data unsafe.Pointer
}
```

### Q：nil interface 陷阱

```go
type MyError struct{ msg string }
func (e *MyError) Error() string { return e.msg }

func foo() error {
    var e *MyError = nil
    return e          // 返回 nil？不是！
}

if err := foo(); err != nil {
    fmt.Println("err is not nil")  // 会进这里！
}
```

原因：`err` 是 interface，type = *MyError, data = nil。**interface 的 nil 判断要求 type 和 data 都是 nil**。

### Q：接口的"隐式实现"有什么好处

```
好处：
├─ 解耦：定义接口的人不需要修改实现者代码
├─ 灵活：标准库的 io.Reader 可以被任何 struct 实现
└─ 测试：容易 mock

代价：
└─ 编译器错误消息有时不直观（"does not implement X"）
```

## 4. 内存与 GC

### Q：Go 的 GC 是什么算法

```
三色标记 + 并发标记清除
├─ 低延迟（暂停通常 < 1ms）
├─ 和 mutator 并发
└─ 每轮 GC 三阶段：Mark Setup、Mark、Mark Termination
```

### Q：逃逸分析

```go
// 栈上分配（不逃逸）
func foo() {
    x := 42  // 栈上
    _ = x
}

// 堆上分配（逃逸）
func bar() *int {
    x := 42
    return &x   // 指针被返回，x 逃逸到堆
}
```

查看逃逸分析：`go build -gcflags="-m"`。

### Q：内存泄漏的常见场景

```
1. Goroutine 泄漏（见上面）
2. Slice 切片保留大数组
   big := make([]int, 1_000_000)
   small := big[:10]   // small 仍然持有 big 的引用

3. time.Ticker / time.NewTimer 没 Stop
4. http.Client 共享但没复用 Transport
5. 强引用 Map 没清理（用 TTL 或 LRU）
```

## 5. 实战题

### Q：实现一个并发安全的计数器

```go
type Counter struct {
    mu sync.Mutex
    n  int64
}

func (c *Counter) Inc() {
    c.mu.Lock()
    c.n++
    c.mu.Unlock()
}

func (c *Counter) Get() int64 {
    c.mu.Lock()
    defer c.mu.Unlock()
    return c.n
}

// 或用 atomic（更快）
type AtomicCounter struct {
    n atomic.Int64
}

func (c *AtomicCounter) Inc() { c.n.Add(1) }
func (c *AtomicCounter) Get() int64 { return c.n.Load() }
```

### Q：实现一个并发限制

```go
// 用 channel 做信号量
func process(items []Item, concurrency int) {
    sem := make(chan struct{}, concurrency)
    var wg sync.WaitGroup

    for _, item := range items {
        sem <- struct{}{}
        wg.Add(1)
        go func(i Item) {
            defer wg.Done()
            defer func() { <-sem }()
            doWork(i)
        }(item)
    }
    wg.Wait()
}

// 或 errgroup（更好）
import "golang.org/x/sync/errgroup"

func processWithErr(items []Item) error {
    g, _ := errgroup.WithContext(ctx)
    g.SetLimit(10)
    for _, item := range items {
        item := item
        g.Go(func() error { return doWork(item) })
    }
    return g.Wait()
}
```

### Q：写一个生产者-消费者

```go
func producerConsumer() {
    jobs := make(chan int, 10)
    results := make(chan int, 10)

    // 消费者
    var wg sync.WaitGroup
    for w := 0; w < 3; w++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for j := range jobs {
                results <- j * 2
            }
        }()
    }

    // 生产者
    go func() {
        for i := 1; i <= 10; i++ {
            jobs <- i
        }
        close(jobs)
    }()

    // 等所有消费者完成后关闭 results
    go func() {
        wg.Wait()
        close(results)
    }()

    for r := range results {
        fmt.Println(r)
    }
}
```

## 6. 2026 年新热点

### Q：Go 1.22 的 for-loop 变量语义变化

```go
// Go 1.21 及以前：变量在循环外共享
for _, v := range items {
    go func() {
        fmt.Println(v)   // bug：可能都打印最后一个
    }()
}

// Go 1.22+：每次迭代新变量
for _, v := range items {
    go func() {
        fmt.Println(v)   // 正确：每次是独立 v
    }()
}
```

### Q：Go 1.25 容器感知 GOMAXPROCS

```
以前：GOMAXPROCS = 宿主机核数（K8s 里是节点 32 核）
1.25+：自动读 cgroup 的 CPU limit（容器 2 核 → GOMAXPROCS=2）

影响：
├─ 不用在 K8s 中手动设 GOMAXPROCS 环境变量
├─ 过度调度问题自动解决
```

### Q：泛型带来了什么？不适合什么？

```
适合：
├─ 容器：Stack[T]、Set[T]
├─ 算法：Map、Filter、Reduce
└─ 工具函数：Ptr[T]、Default[T]

不适合：
├─ 业务逻辑（具体类型更清晰）
├─ 与反射结合
└─ 深度泛型嵌套
```

## 7. 常见陷阱题

```
1. range 循环里修改 slice：
   for i, v := range s {
       s = append(s, v*2)  // 循环次数已固定，不会无限循环
   }

2. map 的遍历顺序随机
   Go 故意不保证顺序，防止你依赖

3. defer 的执行顺序是 LIFO
   defer fmt.Println(1)
   defer fmt.Println(2)
   defer fmt.Println(3)
   // 输出：3 2 1

4. 字符串是不可变的
   s := "hello"
   s[0] = 'H'   // ❌ 编译错

5. select 空 case 永久阻塞
   select {}    // 主 goroutine 常用来"挂起"
```
