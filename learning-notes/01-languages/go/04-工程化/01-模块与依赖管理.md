> Author: Walter Wang

## 1. Go Modules 基础

```bash
# 初始化
go mod init example.com/myapp

# 添加依赖
go get github.com/gin-gonic/gin@v1.11.0
go get github.com/gin-gonic/gin@latest
go get github.com/gin-gonic/gin@v1.11   # 任何 1.11.x

# 升级
go get -u ./...                 # 升级所有
go get -u github.com/xxx        # 升级单个

# 整理
go mod tidy                     # 清理未用的依赖，补齐缺失的
go mod verify                   # 校验
go mod why github.com/foo       # 为什么依赖这个
go mod graph                    # 依赖图
go mod vendor                   # 下载到 vendor/
```

## 2. go.mod 语义

```go
// go.mod
module example.com/myapp

go 1.24                          // 最低 Go 版本
toolchain go1.26.0               // 推荐工具链版本（1.21+）

require (
    github.com/gin-gonic/gin v1.11.0
    github.com/redis/go-redis/v9 v9.6.1
)

require (
    // 间接依赖
    github.com/bytedance/sonic v1.12.0 // indirect
)

// 替换（调试、私有库用）
replace github.com/foo/bar => ../local/fork

// 排除特定版本
exclude github.com/buggy/lib v1.2.3
```

## 3. 版本选择规则

Go Modules 使用 **Minimum Version Selection (MVS)**：

```
规则：
├─ 每个依赖要求最低版本
├─ Go 选择"满足所有要求的最低版本"
└─ 不像 npm 那样自动升到最新

例子：
  A 要求 foo >= 1.2
  B 要求 foo >= 1.5
  → 选 foo 1.5（最低满足）
```

**优势**：可重现构建，不会因为 CI 跑的时间不同而装到不同版本。

## 4. 语义化版本 + 主版本号

```
v1.2.3 → v1.2.4   向后兼容，自动升级
v1.x.x → v2.x.x   破坏性变更，必须改 import path

v2+ 的特殊规则：
  import "example.com/foo/v2"   ← 路径必须带 /v2
  go.mod 的 module 也要改：module example.com/foo/v2

  Reason: 同一个程序可以同时依赖 v1 和 v2
```

## 5. Workspace 模式（多模块协同开发）

```bash
# 新建工作区
mkdir mywork && cd mywork

# 假设我们同时开发两个模块
go work init ./shared ./app

# 生成 go.work
cat go.work
# go 1.24
# use (
#     ./shared
#     ./app
# )
```

优点：`app` 里 `import "example.com/shared"` 会自动用本地的 `./shared`，不用 `replace`。

## 6. 私有模块

### 6.1 配置 GOPRIVATE

```bash
# 告诉 Go 这些模块不走公共 proxy 和 sumdb
export GOPRIVATE=github.com/myorg/*,gitlab.internal.com/*

# 或在 ~/.bashrc / CI 环境变量
go env -w GOPRIVATE=github.com/myorg/*
```

### 6.2 认证（Git 模块）

```bash
# SSH
git config --global url."git@github.com:".insteadOf "https://github.com/"

# 或 netrc
cat ~/.netrc
# machine github.com login USERNAME password TOKEN
```

## 7. Go Proxy（公共代理）

```bash
# 默认（Google 官方代理）
go env GOPROXY
# https://proxy.golang.org,direct

# 国内常用
go env -w GOPROXY=https://goproxy.cn,direct

# 多代理 fallback
go env -w GOPROXY=https://proxy.golang.org,https://goproxy.cn,direct
```

**代理的价值**：
- 国内访问 GitHub 慢时能快速下载
- 即使原仓库删除，代理上的历史版本还在
- 组织级镜像

## 8. go.sum 和 checksum

```go
// go.sum：所有依赖的 hash
github.com/gin-gonic/gin v1.11.0 h1:XXXXX...
github.com/gin-gonic/gin v1.11.0/go.mod h1:YYYYY...
```

**必须提交 go.sum 到 Git**，CI 会用 `-mod=readonly` 验证 hash 没变，防止供应链攻击。

```bash
# 严格模式
go build -mod=readonly     # 不允许自动修改 go.sum
go build -mod=vendor       # 只用 vendor/ 里的代码
```

## 9. 安全扫描

```bash
# 内置（Go 1.18+）：查已知漏洞
go install golang.org/x/vuln/cmd/govulncheck@latest
govulncheck ./...

# 输出类似：
# Vulnerability #1: GO-2023-XXXX
#   Affected: github.com/foo@v1.2.3
#   Fix:      github.com/foo@v1.2.4
```

CI 里跑一遍，有高危漏洞就中断构建。

## 10. 版本发布

```bash
# 给你的模块打 tag
git tag v1.0.0
git push origin v1.0.0

# 用户就能 go get example.com/your-module@v1.0.0
```

**v2+ 发布流程**：
1. 修改 `go.mod` 的 `module` 为 `example.com/foo/v2`
2. 所有内部 import 改成 `example.com/foo/v2/xxx`
3. 打 `v2.0.0` tag

推荐工具：`goreleaser`（自动化 release）：

```yaml
# .goreleaser.yaml
project_name: myapp
builds:
  - env: [CGO_ENABLED=0]
    goos: [linux, darwin, windows]
    goarch: [amd64, arm64]
archives:
  - format: tar.gz
release:
  github:
    owner: myorg
    name: myapp
```

## 11. 反模式

```
❌ 不提交 go.sum
   → 供应链风险

❌ 使用 replace 到本地路径并提交
   → 别人拉代码无法构建

❌ 一直 go get -u ./...
   → 随意升级可能引入 breaking

❌ v2 不改 import path
   → 用户同时依赖 v1 v2 时冲突

❌ 不运行 go mod tidy
   → go.mod 和代码不一致

❌ CI 不用 -mod=readonly
   → 可能构建时间不一致
```
