## 1. 单元测试基础

Go 的测试内置在 `testing` 包，不需要第三方框架：

```go
// math_test.go （文件名以 _test.go 结尾）
package math

import "testing"

func TestAdd(t *testing.T) {
    got := Add(2, 3)
    want := 5
    if got != want {
        t.Errorf("Add(2, 3) = %d; want %d", got, want)
    }
}
```

```bash
# 运行
go test ./...

# 带覆盖率
go test -cover ./...

# 详细输出
go test -v ./...

# 生成覆盖率报告
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out

# 跑特定测试
go test -run TestAdd
```

## 2. Table-Driven 测试（Go 惯例）

```go
func TestAdd(t *testing.T) {
    tests := []struct {
        name    string
        a, b    int
        want    int
    }{
        {"positive", 2, 3, 5},
        {"negative", -1, -2, -3},
        {"zero", 0, 0, 0},
        {"overflow", math.MaxInt, 1, math.MinInt},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := Add(tt.a, tt.b)
            if got != tt.want {
                t.Errorf("Add(%d, %d) = %d; want %d", tt.a, tt.b, got, tt.want)
            }
        })
    }
}
```

## 3. testify 增强断言

标准 `testing` 的断言比较啰嗦，生产项目常用 `testify`：

```bash
go get github.com/stretchr/testify
```

```go
import (
    "testing"
    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/require"
)

func TestUser(t *testing.T) {
    user, err := NewUser("Alice", "a@example.com")

    require.NoError(t, err)  // 出错就 Fail 且停止（后面代码不执行）
    assert.NotNil(t, user)
    assert.Equal(t, "Alice", user.Name)
    assert.Contains(t, user.Email, "@")
    assert.True(t, user.IsActive())
}
```

**require vs assert**：
- `require`：失败立即停止（常用于前置条件）
- `assert`：失败继续执行（能报多个错）

## 5. Mock 和 Stub

### 5.1 接口注入 + 手写 Mock

Go 惯例是**通过接口注入依赖**，测试时替换成 Mock：

```go
// 定义接口
type UserRepo interface {
    FindByID(ctx context.Context, id int64) (*User, error)
}

// 生产实现
type pgUserRepo struct{ db *pgx.Pool }

// 服务依赖接口
type UserService struct {
    repo UserRepo
}

// 测试：手写 Mock
type mockUserRepo struct {
    users map[int64]*User
}

func (m *mockUserRepo) FindByID(ctx context.Context, id int64) (*User, error) {
    u, ok := m.users[id]
    if !ok {
        return nil, ErrNotFound
    }
    return u, nil
}

func TestUserService_GetUser(t *testing.T) {
    repo := &mockUserRepo{
        users: map[int64]*User{1: {ID: 1, Name: "Alice"}},
    }
    svc := NewUserService(repo)

    u, err := svc.GetUser(context.Background(), 1)
    require.NoError(t, err)
    assert.Equal(t, "Alice", u.Name)
}
```

### 5.2 mockery / gomock 自动生成

接口多的项目用工具生成 Mock：

```bash
# mockery（推荐）
go install github.com/vektra/mockery/v3@latest
mockery  # 读 .mockery.yaml 批量生成

# gomock
go install go.uber.org/mock/mockgen@latest
mockgen -source=user.go -destination=mocks/user_mock.go
```

mockery 生成的 Mock：

```go
repo := mocks.NewUserRepo(t)
repo.EXPECT().FindByID(mock.Anything, int64(1)).Return(&User{Name: "Alice"}, nil)

svc := NewUserService(repo)
u, err := svc.GetUser(context.Background(), 1)
```

## 6. 集成测试：testcontainers-go

```bash
go get github.com/testcontainers/testcontainers-go
```

```go
func TestUserRepo_Integration(t *testing.T) {
    ctx := context.Background()

    // 启动 PostgreSQL 容器
    pgContainer, err := postgres.Run(ctx, "postgres:18-alpine",
        postgres.WithDatabase("test"),
        postgres.WithUsername("test"),
        postgres.WithPassword("test"),
        testcontainers.WithWaitStrategy(
            wait.ForLog("database system is ready to accept connections").
                WithOccurrence(2).WithStartupTimeout(30*time.Second)),
    )
    require.NoError(t, err)
    defer pgContainer.Terminate(ctx)

    dsn, _ := pgContainer.ConnectionString(ctx)
    pool, err := pgxpool.New(ctx, dsn)
    require.NoError(t, err)
    defer pool.Close()

    // 运行迁移
    runMigrations(t, pool)

    // 真实的 Repo 测试
    repo := NewUserRepo(pool)
    u := &User{Name: "Alice", Email: "a@example.com"}
    require.NoError(t, repo.Create(ctx, u))
    require.NotZero(t, u.ID)

    got, err := repo.FindByID(ctx, u.ID)
    require.NoError(t, err)
    assert.Equal(t, "Alice", got.Name)
}
```

**testcontainers 的价值**：集成测试用真实的数据库、Redis、Kafka，不用 SQLite 这种"替身"。

## 7. Golden Files

对比结构化输出（JSON、YAML、HTML）：

```go
func TestRender(t *testing.T) {
    got := Render(testData)

    goldenPath := "testdata/render.golden"
    if *updateGolden {  // go test -update
        os.WriteFile(goldenPath, []byte(got), 0644)
        return
    }

    want, _ := os.ReadFile(goldenPath)
    if got != string(want) {
        t.Errorf("mismatch\nGot:\n%s\nWant:\n%s", got, want)
    }
}

var updateGolden = flag.Bool("update", false, "update golden files")
```

func BenchmarkStringBuilder(b *testing.B) {
    b.Run("concat", func(b *testing.B) {
        for i := 0; i < b.N; i++ {
            s := ""
            for j := 0; j < 100; j++ {
                s += "a"
            }
        }
    })

        for i := 0; i < b.N; i++ {

            }
            _ = sb.String()
        }
    })

## 9. Fuzz 测试（Go 1.18+）

```go
func FuzzReverse(f *testing.F) {
    // Seed
    f.Add("hello")
    f.Add("你好")

    f.Fuzz(func(t *testing.T, orig string) {
        rev := Reverse(orig)
        revRev := Reverse(rev)
        if orig != revRev {
            t.Errorf("Reverse(Reverse(%q)) = %q", orig, revRev)
        }
        if utf8.ValidString(orig) && !utf8.ValidString(rev) {
            t.Errorf("Reverse produced invalid UTF-8")
        }
    })
}
```

```bash
go test -fuzz=FuzzReverse -fuzztime=30s
```

Fuzzer 会自动生成边界输入，找出你没想到的 bug。

## 12. 2026 年特性：testing/synctest

Go 1.25 stable。模拟时间流逝，测试定时器逻辑：

```go
import "testing/synctest"

func TestRetry(t *testing.T) {
    synctest.Test(t, func(t *testing.T) {
        start := time.Now()

        RetryWithBackoff(func() error {
            return errors.New("fail")
        }, 3, 1*time.Second)

        elapsed := time.Since(start)
        // synctest 中 elapsed 是模拟的，不是真的 7 秒
        assert.Equal(t, 7*time.Second, elapsed)
    })
}
```

这比以前 `time.Now = func() ...` 注入时间干净得多。

> 更新于 2026-07-10
>
> **`sync.WaitGroup` 与 bubble 关联的坑**：`WaitGroup` 在第一次调用 `Add`/`Go` 时才会与当前 bubble 绑定；一旦绑定，从 bubble **外部**调用 `Add`/`Go` 会触发 fatal error。有个容易踩的限制——**包级别的 `var wg sync.WaitGroup` 变量不能正确关联 bubble**（其上的操作可能不是"durably blocking"），必须用指针形式：
>
> ```go
> // ❌ 包级变量，synctest 无法正确追踪其 durably-blocking 状态
> var wg sync.WaitGroup
>
> // ✅ 改为指针，可以被 bubble 正确关联
> var wg = new(sync.WaitGroup)
> ```
>
> 该限制目前没有文档之外的“干净”解决方案，写新测试代码时直接遵循这个约定即可。来源：[testing/synctest 官方文档](https://pkg.go.dev/testing/synctest)
