## 0. 这篇的定位

前面 10 篇给的是**已经沉淀下来的知识**。这篇给的是**获取新知识的能力**——这决定你在笔记不再更新之后还能不能继续前进。

一个现实前提：**你不需要读很多论文。** 工程岗位的绝大多数工作不需要读论文，靠文档和源码就够。这篇的目标不是让你变成研究者，而是让你在真正需要时（比如要复现某个方法、要判断某个技术方案是否可行）能读得动、判断得准。

## 1. 三层阅读法：15 分钟决定值不值得细读

读论文最大的浪费是**从第一页读到最后一页**。正确做法是分层推进，每层结束都做一次「继续/放弃」的决策。

```
第一层  5 分钟   标题 → 摘要 → 图表 → 结论
                  ↓
            这篇解决什么问题？跟我有关吗？
                  ↓
           无关 → 放弃（这是最常见的正确结果）
                  ↓
第二层  15 分钟  引言 → 方法概述 → 实验设置 → 主要结果
                  ↓
            它的核心思路是什么？实验可信吗？
                  ↓
           不可信或不适用 → 放弃
                  ↓
第三层  1~3 小时 逐节精读 → 推导公式 → 看代码
                  ↓
            我能复现它吗？边界条件是什么？
```

**关键心态：放弃是正常且高频的结果。** 读了 5 分钟决定不读了，这不是浪费，这是筛选成功。

### 第一层该看什么（按顺序）

| 顺序 | 看什么 | 判断 |
| --- | --- | --- |
| 1 | 标题 | 关键词是否在你关心的范围内 |
| 2 | 摘要最后两句 | 通常是「我们做了什么 + 效果如何」 |
| 3 | **图表**（尤其架构图和主结果表） | 论文的核心信息密度最高的地方 |
| 4 | 结论第一段 | 作者自己认为的贡献 |

**为什么先看图表**：一篇好论文的架构图能在 30 秒内告诉你它的思路。如果图看不懂、或者根本没有说明性的图，往往说明这篇写作质量不高，读起来会很费劲。

### 第二层的关键：看实验设置，不只看结果

新手容易只看「效果提升了多少」，而真正决定可信度的是**实验怎么做的**：

| 检查项 | 红旗信号 |
| --- | --- |
| 对比的基线是什么 | 只跟很弱的基线比，或基线没调参 |
| 数据集是什么 | 只在一个数据集上验证；或数据集与测试集可能重叠 |
| 跑了几次 | 只报单次结果，没有均值±标准差 |
| 消融实验有没有 | 没有消融，说不清是哪个改动起了作用 |
| 超参怎么选的 | 新方法精调、基线用默认值（不公平对比） |

第三条尤其值得警惕，理由见 [实验设计与可复现性](../machine-learning/01-机器学习基础/03-实验设计与可复现性.md)：单次实验的随机波动常常大于论文声称的提升幅度。

## 2. 一个具体的阅读检查清单

读任何方法类论文时，用这七个问题自问。**能回答全部七个，说明你真读懂了**：

```
1. 它解决什么问题？        用一句话，不用术语
2. 之前的方法为什么不够？   问题的具体形态是什么
3. 它的核心改动是什么？     通常只有一两处，其余是工程细节
4. 为什么这个改动有效？     作者给的解释是机制解释还是「实验表明」
5. 代价是什么？            没有免费的午餐，一定有代价（算力/数据/复杂度）
6. 什么情况下会失效？       论文的 limitation 部分，或者没写但你能想到的
7. 我能用它做什么？         对你的实际工作有什么可迁移的
```

**第 5 和第 6 个问题最容易被跳过，但最有价值。** 论文倾向于突出优点、淡化代价。你能自己识别代价和失效边界，才算真的掌握了这个方法。

举例（拿本库已有的内容对照）：

| 方法 | 核心改动 | 代价 | 何时失效 |
| --- | --- | --- | --- |
| LoRA | 只训低秩增量矩阵 | 表达能力受 rank 限制 | 需要大幅改变模型行为时 |
| KV Cache | 缓存历史 K/V | 显存随序列长度线性增长 | 长上下文 + 大 batch 时显存爆 |
| DPO | 用闭式解替代 RL | 对分布外数据敏感 | 偏好数据与模型分布差距大时 |

这三个例子的完整讨论分别见 [PEFT 参数高效微调](../llm/04-微调与对齐/02-PEFT参数高效微调.md)、[KV Cache 与显存分析](../llm/05-推理优化/01-KV-Cache与显存分析.md)、[DPO 与免 RL 对齐](../llm/04-微调与对齐/04-DPO与免RL对齐.md)。

## 3. 怎么筛选：从「主动搜索」到「被动接收」

AI 领域每天新增论文数以百计，**主动搜索是不可持续的策略**。

### 三层信息漏斗

```
第一层  被动接收（每天 5 分钟）
  订阅少数高质量信息源，只扫标题
        ↓ 命中你关心的关键词
第二层  快速判断（每周 30 分钟）
  对命中的做第一层阅读（5 分钟法）
        ↓ 值得深入的（每周通常 0~2 篇）
第三层  深度阅读（按需）
  第二、三层阅读法
```

**关键设计：默认不读。** 只有被明确信号命中才升级到下一层。这跟「怕错过所以什么都看」是相反的策略，但后者的实际结果是什么都没真正读。

### 本库已有的机制

你的仓库里已经有一套简报系统，可以直接用作第一层：

```
learning-notes/_briefings/
├── ai-agent/       每日 AI Agent 动态
├── china-tech/     国内科技动态
└── global-tech/    国际科技动态
```

由 `.kiro/hooks/` 下的简报 hook 自动采集。**用法建议：只扫标题，不点开细读**——第一层的唯一目的是「有没有命中我关心的关键词」。

### 设定你的关键词清单

被动接收要有效，前提是你知道自己关心什么。建议写下来（放在进度文件里）：

```
我关心的（会点开看）：
  - Agent 架构、工具调用、上下文管理
  - 推理优化、量化、成本
  - 微调方法、对齐

我不关心的（直接跳过）：
  - 新模型榜单排名
  - 融资、人事变动
  - 纯理论、无代码
```

**这个清单会随你的阶段变化**，每季度回看一次。

## 4. 怎么判断真突破还是营销

看到「新模型刷新 SOTA」「性能提升 300%」这类消息，用下面几个问题过一遍。

### 红旗清单

| 红旗 | 为什么可疑 |
| --- | --- |
| 只在自建 benchmark 上领先 | 换个基准可能就不行了 |
| 对比的是旧版本或未调参的基线 | 不公平对比 |
| 提升幅度巨大但没有机制解释 | 「实验表明」而非「因为 X 所以 Y」 |
| 没有开源、没有可复现细节 | 无法验证 |
| 只报最好结果，不报方差 | 可能是挑出来的一次运行 |
| 强调参数量/数据量而非方法 | 更大更多不是方法创新 |

### 三个实用判断

**判断一：它属于哪一层？**

用 [AI 技术全景与概念辨析](../00-入门准备/01-AI技术全景与概念辨析.md) 的分层框架：

```
底层创新（架构、训练范式）  → 值得深入理解原理
中层改进（优化方法、技巧）  → 了解思路，知道何时可用
上层封装（框架、工具、产品）→ 知道存在，用到时看文档
```

绝大多数「突破」实际在上层。

**判断二：解决了新问题，还是换了个包装？**

```
Transformer 出现时：解决「RNN 无法并行」这个真问题  → 真突破
第 N 个 Agent 框架：都是「LLM + 工具调用循环」的封装 → 换包装
```

**判断三：等三个月还有人提吗？**

这是最省力的过滤器。真正重要的工作三个月后会被反复引用、被工程化；营销性质的三个月后无人再提。

**除非你的工作需要抢时间窗口，否则「晚三个月了解」的成本远低于「读了一堆最后发现没用」的成本。**

## 5. 一个反直觉建议：读源码常比读论文有用

对工程岗位来说，很多时候：

| | 论文 | 源码 |
| --- | --- | --- |
| 告诉你 | 为什么这样设计、效果多好 | 实际怎么实现、有哪些细节 |
| 隐藏了 | 工程细节、失败尝试、trick | 设计动机 |
| 可验证性 | 需要复现才能验证 | 直接跑、直接改 |

**很多论文里一句「我们使用了标准的训练设置」，背后是源码里几十行的细节**——学习率 warmup 步数、梯度裁剪阈值、初始化方式，这些常常才是能否复现的关键。

实用组合：**先用第一层阅读法看论文建立框架，再读源码补细节。**

## 6. 一个可运行的小工具：论文阅读记录

读完不记录，两周后就只剩「我好像读过这个」。下面这个脚本生成结构化的阅读笔记模板，并能统计你的阅读情况。

"""论文阅读记录小工具

生成结构化模板（对应第 2 节的七个问题），并统计阅读情况。
只依赖标准库。
"""

import json
import os
import tempfile
from datetime import date


TEMPLATE = """# {title}

> 阅读日期: {read_date}
> 来源: {source}
> 阅读层级: {level}

## 七问

1. **解决什么问题**（一句话，不用术语）:
   {q1}

2. **之前方法为什么不够**:
   {q2}

3. **核心改动是什么**（通常只有一两处）:
   {q3}

4. **为什么有效**（机制解释 or 仅「实验表明」）:
   {q4}

5. **代价是什么**（算力/数据/复杂度，一定有）:
   {q5}

6. **什么情况会失效**:
   {q6}

7. **我能用它做什么**:
   {q7}

## 可信度检查

| 检查项 | 结果 |
| --- | --- |
| 基线是否公平 | {c1} |
| 数据集数量 | {c2} |
| 是否报方差 | {c3} |
| 有无消融实验 | {c4} |
| 是否开源 | {c5} |

## 结论

{verdict}
"""


def make_note(title, source, level, answers, checks, verdict):
    return TEMPLATE.format(
        title=title, source=source, level=level,
        read_date=date.today().isoformat(),
        **{f"q{i}": answers.get(f"q{i}", "（待填）") for i in range(1, 8)},
        **{f"c{i}": checks.get(f"c{i}", "未检查") for i in range(1, 6)},
        verdict=verdict,
    )

        "q5": "表达能力受 rank 限制；需要选 rank/alpha/目标模块，多了一组超参",
        "q6": "需要大幅改变模型行为时（如换语言、换领域）低秩假设可能不成立",
        "q7": "在单卡上微调中等规模模型；可训练多个 LoRA 按需切换",
    },
    checks={
        "c1": "✅ 与全参微调、Adapter、Prefix Tuning 对比",
        "c2": "多个（本库未逐一记录具体数量）",
        "c3": "⚠️ 待确认（原论文的方差报告情况未核实）",
        "c4": "✅ 有 rank 与目标模块的消融",
        "c5": "✅ 已有多个开源实现",
    },
    verdict="值得掌握。它是目前个人和中小团队微调大模型的默认选择，"

tmp = tempfile.mkdtemp()
path = os.path.join(tmp, "reading-note-demo.md")
with open(path, "w", encoding="utf-8") as f:
    f.write(demo)

print("=" * 58)
print("生成的阅读笔记模板（前 30 行）")
print("=" * 58)

## 7. 长期策略：把 80% 时间投在不过期的东西上

这一节和 [学习路线与常见误区](../00-入门准备/03-学习路线与常见误区.md) 的第 6 节呼应，但角度不同：那里讲「怎么学」，这里讲「怎么持续」。

```
                        过期速度      投入建议
┌──────────────────────────────────────────────┐
│ 数学、反向传播、优化理论   几乎不过期   ★★★★★  │
│ Transformer 架构、注意力   多年仍主流   ★★★★   │
│ 训练/推理的工程原理        变化缓慢     ★★★★   │
│ 主流方法选型（用哪个归一化）半年~一年   ★★     │
│ 框架 API                   数周~数月    ★      │  ← 用到再查
│ 模型榜单排名               数周         －     │  ← 基本不用管
└──────────────────────────────────────────────┘
```

**一个具体的判断标准**：如果一个知识点你三年后还会用到，值得系统学；如果三个月后就换了，用到时查文档。

### 建立你自己的「更新触发器」

不要定期主动检查所有东西，而是设置触发条件：

| 触发条件 | 该做什么 |
| --- | --- |
| 简报里同一个概念一周内出现 3 次以上 | 值得花 15 分钟了解一下 |
| 你要做的任务现有方法明显不够 | 这时才去搜新方法 |
| 某个你笔记里的「现状描述」被现实打脸 | 更新那一篇（本库有 8 篇标了 version-check） |
| 换工作/换方向 | 重新校准关键词清单 |

本库的 `.kiro/hooks/41-tool-doc-update-check` 已经实现了自动化的增量更新，且**刻意设置了「原理层默认跳过」**——因为给不过期的内容加更新标记只会制造噪音。

## 8. 小结

| 要点 | 内容 |
| --- | --- |
| **三层阅读法** | 5 分钟 → 15 分钟 → 精读，每层都可以放弃 |
| **放弃是正常结果** | 读 5 分钟决定不读，是筛选成功不是浪费 |
| 先看图表 | 架构图和主结果表信息密度最高 |
| **看实验设置，不只看结果** | 基线是否公平、有没有报方差、有没有消融 |
| 七问检查 | 第 5（代价）和第 6（何时失效）最有价值 |
| 信息漏斗 | 被动接收 → 快速判断 → 深度阅读，**默认不读** |
| 判断真突破 | 属于哪一层？新问题还是新包装？三个月后还有人提吗？ |
| **读源码常比读论文有用** | 论文讲动机，源码给细节 |
| 长期策略 | 80% 时间投不过期的原理层 |
