# AI 技术全景与概念辨析

> Author: Walter Wang

> **读完你能回答的 3 个问题**
>
> 1. AI、机器学习、深度学习、大模型、Agent 这五个词是什么关系？谁包含谁？
> 2. 「训练」和「推理」有什么区别？为什么它们的成本结构完全不同？
> 3. 别人说「我们用 AI 做了个东西」，你怎么判断他实际在说哪一层？

## 0. 这篇解决什么问题

从 0 开始学 AI 最先撞上的不是技术难度，是**概念混乱**：

```
朋友说「我在搞大模型」        → 他是在训模型？还是在调 API？
新闻说「AI 突破」            → 是新算法？新模型？还是新应用？
招聘写「熟悉机器学习」        → 要会推公式？还是会调库？
博主说「Agent 是未来」        → Agent 和 ChatGPT 什么关系？
```

这些词在日常对话里被混着用，但它们**处在完全不同的层级**。这篇的目标：给你一张地图，让你听到任何 AI 词汇都知道它在哪一层。

## 1. 五层包含关系

先看最重要的一张图。这五个概念是**层层包含**的，不是并列的：

```
┌─────────────────────────────────────────────────────┐
│  人工智能 AI                                         │
│  「让机器做需要智能的事」这个目标                       │
│                                                     │
│  ┌───────────────────────────────────────────────┐  │
│  │  机器学习 ML                                   │  │
│  │  实现 AI 的一种方法：从数据里学规律              │  │
│  │                                               │  │
│  │  ┌─────────────────────────────────────────┐  │  │
│  │  │  深度学习 DL                             │  │  │
│  │  │  用多层神经网络做机器学习                  │  │  │
│  │  │                                         │  │  │
│  │  │  ┌───────────────────────────────────┐  │  │  │
│  │  │  │  大语言模型 LLM                    │  │  │  │
│  │  │  │  基于 Transformer 的超大规模模型     │  │  │  │
│  │  │  │                                   │  │  │  │
│  │  │  │  ┌─────────────────────────────┐  │  │  │  │
│  │  │  │  │  Agent 智能体                │  │  │  │  │
│  │  │  │  │  让 LLM 能调工具、多步决策     │  │  │  │  │
│  │  │  │  └─────────────────────────────┘  │  │  │  │
│  │  │  └───────────────────────────────────┘  │  │  │
│  │  └─────────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**注意两件事**：

1. **越往内越具体，但不代表越先进**。外层的东西不会因为内层出现就过时——比如决策树（属于 ML 但不属于 DL）在表格数据上至今常常打败神经网络
2. **有些 AI 不是机器学习**。比如早期的专家系统（人工写规则）、A* 搜索算法，它们属于 AI 但不属于 ML

| --- | --- | --- | --- |

## 2. 三种学习范式（横向切分）

上面是纵向的包含关系，这里是横向的分类方式。**机器学习按「学习信号从哪来」分三大类**：

```
监督学习              无监督学习            强化学习
                                        
数据 + 标准答案        只有数据无答案         环境 + 奖励信号
  ↓                    ↓                    ↓
学「输入→输出」映射     学数据内在结构        学「什么行为得分高」
                                        
例：图片→是猫是狗       例：把用户分成几群      例：下棋、机器人控制
    邮件→是否垃圾           降维可视化             RLHF 对齐大模型
```

| 范式 | 学习信号 | 典型任务 | 本库对应 |
| --- | --- | --- | --- |
| 监督学习 | 人工标注的答案 | 分类、回归 | [经典算法](../01-machine-learning/02-经典算法/01-线性回归与逻辑回归推导.md) |
| 无监督学习 | 无（自己找结构） | 聚类、降维 | [聚类](../01-machine-learning/02-经典算法/06-聚类.md)、[降维](../01-machine-learning/02-经典算法/07-降维.md) |
| 强化学习 | 环境给的奖励 | 序列决策 | [强化学习基础](../01-machine-learning/08-强化学习基础/01-MDP与价值函数.md) |

### 自监督学习：大模型的关键

还有一个必须单独说的第四类，**它是大模型能成立的根本原因**：

> **自监督学习：用数据自己造标签，不需要人工标注。**

```
一句话:  "今天天气真不错"

造训练样本（把后面的词遮住，让模型猜）:
  输入: "今天"                 → 答案: "天气"
  输入: "今天天气"              → 答案: "真"
  输入: "今天天气真"            → 答案: "不错"
                                    ↑
                        标签是数据自带的，不用人标！
```

**这就是 GPT 系列的预训练方式**。为什么它这么重要：人工标注贵且慢，全世界的标注数据加起来也不够训一个大模型；但互联网上的原始文本几乎无限。自监督把「无限的无标注数据」变成了「无限的训练信号」。

详见 [GPT 与自回归路线](../02-llm/03-预训练范式/02-GPT与自回归路线.md)。

## 3. 训练 vs 推理：两种完全不同的成本结构

这是新手最容易混淆、但对理解成本最关键的一组概念。

```
        训练 Training                    推理 Inference
        （造模型）                        （用模型）
                                       
   数据 ──► 模型反复调整参数            输入 ──► 模型算一次 ──► 输出
              ↓                                    
        跑几天到几个月                        毫秒到几秒
        需要几千张 GPU                       一张 GPU 甚至 CPU
        一次性投入                           每次调用都花钱
```

| | 训练 | 推理 |
| --- | --- | --- |
| 做什么 | 用数据调整模型参数 | 用固定参数处理新输入 |
| 参数是否变 | **变**（这就是学习） | **不变** |
| 耗时 | 小时到月 | 毫秒到秒 |
| 成本模式 | 一次性大额投入 | 按调用量持续付费 |
| 需要什么 | 大量数据 + 大量算力 | 一个训好的模型 |
| 优化目标 | 让损失下降 | 让延迟低、吞吐高、成本低 |

**为什么这个区分对你重要**：

- 你说「我要学 AI」，绝大多数情况下你实际要做的是**推理侧**的工作（调 API、做应用、微调），而不是从零训练
- 从零训练一个大模型需要的资源是普通人拿不到的；但**微调**（在已有模型上小改）和**推理优化**是可以做的
- 面试问「你了解 AI 成本吗」，本质是问你懂不懂这两种成本模式的差异

推理侧的成本优化是一个专门领域，详见 [KV Cache 与显存分析](../02-llm/05-推理优化/01-KV-Cache与显存分析.md)、[量化](../02-llm/05-推理优化/02-量化.md)。

### 中间态：微调

```
预训练（造通用模型）  →  微调（调成专用）  →  推理（使用）
    极贵，大厂做          可负担，你能做       按量付费
```

微调是「拿别人训好的模型，用你的数据小改一下」。成本比预训练低几个数量级，是个人和中小团队最主要的模型定制手段。详见 [PEFT 参数高效微调](../02-llm/04-微调与对齐/02-PEFT参数高效微调.md)。

## 4. 高频词速查表

学习过程中会不断撞上这些词，这里给出「一句话定位」，方便你随时判断它在说哪一层。

### 模型相关

| 词 | 是什么 | 在哪一层 |
| --- | --- | --- |
| 神经网络 | 一堆矩阵乘法 + 非线性函数堆起来的结构 | DL |
| Transformer | 一种神经网络架构，靠注意力机制工作 | DL |
| 参数 / 权重 | 模型里可以被训练调整的数字 | DL |
| 7B / 70B | 参数个数（B = billion 十亿） | LLM |
| 预训练模型 | 已经在大量数据上训好、可直接用或微调的模型 | LLM |
| 基座模型 / base model | 只做过预训练、没做过指令微调的模型 | LLM |
| Instruct / Chat 模型 | 在基座上做过指令微调，能听懂人话的版本 | LLM |

### 输入输出相关

| 词 | 是什么 | 常见误解 |
| --- | --- | --- |
| Token | 模型处理的最小单位，不等于「字」或「词」 | 中文 1 字常≈1~2 token，英文 1 词≈1~1.5 token |
| 上下文窗口 | 模型一次能看多少 token | 窗口大 ≠ 全部内容都被有效利用 |
| Embedding | 把文本/图片变成一串数字（向量） | 它是**表示**，不是模型本身 |
| Prompt | 你给模型的输入 | — |
| 温度 temperature | 控制输出随机性的参数 | 高 = 更随机，不是「更聪明」 |

Token 与上下文窗口的详细讨论见 [大语言模型基础](../04-ai-agent/00-基础概念/02-大语言模型基础.md)，分词原理见 [分词算法](../02-llm/02-分词与表示/01-分词算法.md)。

### 训练方法相关

| 词 | 全称 | 干什么 |
| --- | --- | --- |
| 预训练 | Pre-training | 在海量无标注数据上自监督学习 |
| SFT | Supervised Fine-Tuning | 用「指令-回答」对微调，让模型会听指令 |
| RLHF | RL from Human Feedback | 用人类偏好训练，让输出更符合期望 |
| DPO | Direct Preference Optimization | RLHF 的简化替代，不需要单独训奖励模型 |
| LoRA | Low-Rank Adaptation | 只训一小部分新增参数，省显存的微调方法 |
| 量化 | Quantization | 用更少的位数存权重，省显存换一点精度 |
| 蒸馏 | Distillation | 让小模型学大模型的输出 |

这一整套详见 [微调与对齐](../02-llm/04-微调与对齐/01-三阶段范式与数据构造.md)。

### 应用层相关

| 词 | 是什么 | 关键点 |
| --- | --- | --- |
| RAG | 检索增强生成 | 先查资料再回答，解决「模型不知道你的私有数据」 |
| Function Calling | 工具调用 | 让模型能返回结构化的「我要调这个函数」 |
| MCP | Model Context Protocol | 一种让模型接外部工具的协议标准 |
| Agent | 智能体 | LLM + 工具 + 多步决策循环 |
| 多 Agent | 多智能体 | 多个 Agent 分工协作 |
| 幻觉 hallucination | 模型编造事实 | 不是 bug，是概率生成的固有特性 |

## 5. 一个判断练习

回到开头的问题：别人说「我们用 AI 做了个东西」，怎么判断他在哪一层？

问三个问题就能定位：

```
问题 1：你们训模型吗？
  ├─ 从零训练 ────────────► 极少数大厂，需要数千 GPU
  ├─ 微调别人的模型 ──────► 中小团队常见，需要几张 GPU
  └─ 不训，只调 API ──────► 绝大多数应用，需要 API Key

问题 2：模型的知识从哪来？
  ├─ 模型自带 ───────────► 纯 Prompt 工程
  ├─ 现场查资料 ─────────► RAG
  └─ 训进参数里 ─────────► 微调

问题 3：模型能不能自己做多步操作？
  ├─ 一问一答 ───────────► 就是个聊天/生成应用
  └─ 能调工具、多步决策 ──► Agent
```

**为什么这个判断有用**：AI 领域大量的表述含混不清，同一句「我们用了大模型」可能意味着从零训练（技术含量极高），也可能意味着接了个 API（一天就能做）。学会这个判断，能帮你在阅读技术方案、评估招聘要求、判断新闻真伪时保持清醒。

## 6. 常见误解澄清

| 误解 | 实际情况 |
| --- | --- |
| 「深度学习淘汰了传统机器学习」 | 表格数据上，梯度提升树（XGBoost/LightGBM）常常比神经网络更好，且训练快得多 |
| 「模型越大越好」 | 大模型贵且慢。很多任务小模型 + 好数据 + 微调完全够用 |
| 「AI 会自己学习进化」 | 部署后的模型参数是**冻结**的，不会自己变聪明。要变必须重新训练 |
| 「参数量决定能力」 | 数据质量、训练方法、对齐质量同样关键。同规模模型能力差异巨大 |
| 「上下文窗口越大越好用」 | 窗口大 ≠ 有效利用。长上下文里中间部分常被「忽略」 |
| 「Agent 就是 ChatGPT」 | ChatGPT 是产品；Agent 是「LLM + 工具 + 决策循环」的架构模式 |
| 「学 AI 必须先学完数学」 | 需要「看懂公式」的程度，不需要「会做题」的程度。边学边补更现实 |
| 「幻觉是可以彻底消除的 bug」 | 幻觉源于「按概率生成下一个词」这个机制本身，只能缓解不能根除 |

最后两条特别值得强调。第七条对你尤其相关——数学的正确学法见 [微积分够用篇](../01-machine-learning/00-数学基础/01-微积分够用篇.md) 的开头说明。

## 8. 小结

| 要点 | 内容 |
| --- | --- |
| 五层包含关系 | AI ⊃ ML ⊃ DL ⊃ LLM ⊃ Agent |
| 外层不会过时 | 决策树在表格数据上至今常胜过神经网络 |
| 三种学习范式 | 监督（有答案）、无监督（无答案）、强化（有奖励） |
| **自监督** | **用数据自造标签，大模型能成立的根本原因** |
| **训练 vs 推理** | **参数变 vs 不变；一次性投入 vs 持续付费** |
| 三种定制层次 | 预训练（大厂）→ 微调（你能做）→ Prompt/RAG（最轻） |
| 判断三问 | 训不训模型？知识从哪来？能不能多步操作？ |

**如果只记一件事**：听到任何 AI 词汇，先问它在哪一层。层级搞清楚了，后面所有讨论都会变清晰。
