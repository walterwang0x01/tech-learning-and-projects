# 实验设计与可复现性

> Author: Walter Wang

> **读完你能回答的 3 个问题**
>
> 1. 固定随机种子之后，为什么换一台机器或换一个 batch size 重跑，结果还是可能不一样？
> 2. 为什么"跑一次实验，效果比 baseline 好"这个结论不可信，应该怎么报告结果才算靠谱？
> 3. 消融实验最常见的错误做法是什么，正确的做法应该怎么设计？

## 1. 训练结果跑不出来是常态，不是意外

深度学习和很多机器学习算法的训练过程本身包含随机性——初始化、数据顺序、正则化手段里都嵌着随机数生成器。这意味着**同一套代码、同一份数据、同一套超参数，跑两次也可能得到不完全一样的结果**。这不是代码 bug，而是训练过程的固有特性。把"这次效果差"简单归因于代码问题，或把"这次效果好"当作确定性进步，都是对随机性认识不足导致的误判。第 6 节会用具体数值展示波动有多大。

## 2. 随机源清单：种子固定不等于结果完全一致

一次训练里常见的随机源：

- **参数初始化**：权重的随机初始化值直接影响优化轨迹落在哪个局部最优附近。
- **数据顺序（shuffle）**：mini-batch 样本分组不同，每步梯度估计方向都不同，小 batch size 下影响更明显。
- **Dropout**：每次前向传播随机丢弃的神经元不同，等价于每步都在训练一个略有差异的子网络。
- **数据增强**：随机裁剪、翻转、颜色扰动，每个 epoch 看到的实际输入不完全一样。
- **GPU 计算的非确定性**：某些并行浮点运算（如某些卷积实现、原子加法的浮点累加顺序）在 GPU 上执行顺序不完全确定，带来的微小误差会被非线性层逐层放大。

## 3. 种子固定能做到什么，做不到什么

固定随机种子（`np.random.seed`、`torch.manual_seed` 等）能保证：**同一份代码、同一个环境（相同硬件、相同库版本），重复运行结果完全一致**——这对调试和消融实验（排除随机性干扰，只看某改动的真实效果）很重要。

做不到的：**跨硬件、跨库版本、跨并行策略的一致性**。换 GPU 型号、换 CUDA/cuDNN 版本、改 batch size 或数据并行切分方式，即使种子相同，底层浮点运算顺序和精度也会变化，结果依然漂移——这正是第 2 节"GPU 非确定性"的体现，不受 Python 层种子控制。因此**种子固定是"同环境可复现"的必要条件，不是"任意环境结果一致"的充分条件**，团队协作时环境信息（依赖版本、硬件）也要记录清楚。

## 4. 单次实验结果不可信：应报多种子均值 ± 标准差

只跑一次实验就下结论（"改了超参数，效果从 A 提升到 B"），无法排除这个提升是不是这次随机种子的运气。正确做法是**固定其他所有条件，只改变随机种子，重复跑多次，报告均值和标准差**（或标准误差）。如果两个配置均值差距在标准差量级以内，就不能断言谁更好。第 6 节会具体展示这种波动范围，以及种子数量增加后均值估计如何更稳定。

## 5. 消融实验：一次只变一个因素

消融实验（ablation study）回答"某个具体设计选择对最终效果的贡献有多大"：

**正确做法**：固定基线配置，**每次只改变一个因素**（如只改学习率，数据切分、epoch 数、batch size、模型结构全部不变），跑多个种子取均值±标准差，和基线对比。任何差异都能唯一归因到这一个因素。

**常见错误**：一次同时改多个因素（换了数据增强策略、调大模型、换学习率调度），结果变好了却分不清是哪个改动起作用，甚至某改动在拖后腿、另一个收益更大只是被平均抵消——这种"打包对比"没有因果解释力。另一常见错误是**不跑多种子**，只跑一次就断言"去掉某模块效果下降 X%"，如果 X 在随机波动量级以内，这个结论就是噪声而非真实效应。

## 6. 最小可运行实现：多种子重复实验揭示单次结果的方差

```python
"""
多随机种子重复实验，展示：
  1. 单次实验结果的方差有多大，为何只跑一次不可信
  2. 种子数量增加后，均值估计的标准误差如何收缩
  3. 消融实验正确做法：一次只变一个因素，同样报多种子均值±标准差
"""
import numpy as np


def make_dataset(rng, n=200, n_features=10, noise=1.0):
    """生成带噪声的线性回归数据集"""
    X = rng.normal(size=(n, n_features))
    true_w = rng.normal(size=n_features)
    y = X @ true_w + rng.normal(scale=noise, size=n)
    return X, y, true_w


def sgd_train(X, y, rng, lr=0.01, epochs=30, batch_size=16):
    """简化版 mini-batch SGD 线性回归：随机初始化 + 每轮打乱顺序，均为随机源"""
    n, d = X.shape
    w = rng.normal(scale=0.1, size=d)  # 随机初始化——随机源 1
    for _ in range(epochs):
        order = rng.permutation(n)  # 每轮打乱数据顺序——随机源 2
        for start in range(0, n, batch_size):
            idx = order[start:start + batch_size]
            xb, yb = X[idx], y[idx]
            pred = xb @ w
            grad = xb.T @ (pred - yb) / len(idx)
            w -= lr * grad
    return w


def mse(y_true, y_pred):
    return np.mean((y_true - y_pred) ** 2)


# 固定数据集，只让训练过程的随机种子变化
data_rng = np.random.default_rng(0)
X, y, true_w = make_dataset(data_rng)
X_train, y_train = X[:150], y[:150]
X_val, y_val = X[150:], y[150:]

print("=== 实验 1：同一份数据/超参数，只换训练随机种子 ===")
val_losses = []
for seed in range(20):
    train_rng = np.random.default_rng(seed)
    w = sgd_train(X_train, y_train, train_rng)
    val_losses.append(mse(y_val, X_val @ w))
val_losses = np.array(val_losses)
print(f"20 个种子的验证 MSE: 均值={val_losses.mean():.4f}, 标准差={val_losses.std():.4f}")
print(f"最小值={val_losses.min():.4f}, 最大值={val_losses.max():.4f}")

print("\n=== 实验 2：种子数量增加，均值估计的标准误差如何变化 ===")
for n_seeds in [3, 5, 10, 20]:
    subset = val_losses[:n_seeds]
    sem = subset.std(ddof=1) / np.sqrt(n_seeds) if n_seeds > 1 else float("nan")
    print(f"  用前 {n_seeds:>2} 个种子: 均值={subset.mean():.4f}, 标准误差(SEM)={sem:.4f}")

print("\n=== 实验 3：消融实验——只改学习率（其余不变），每个配置跑 8 个种子 ===")
for lr in [0.001, 0.01, 0.05]:
    losses = []
    for seed in range(8):
        train_rng = np.random.default_rng(seed)
        w = sgd_train(X_train, y_train, train_rng, lr=lr)
        losses.append(mse(y_val, X_val @ w))
    losses = np.array(losses)
    print(f"  lr={lr:<6}: 验证 MSE 均值={losses.mean():.4f} ± {losses.std():.4f}（8 种子）")
```

实测输出（numpy 2.4.4）：

```
=== 实验 1：同一份数据/超参数，只换训练随机种子 ===
20 个种子的验证 MSE: 均值=1.3847, 标准差=0.0205
最小值=1.3416, 最大值=1.4161

=== 实验 2：种子数量增加，均值估计的标准误差如何变化 ===
  用前  3 个种子: 均值=1.3923, 标准误差(SEM)=0.0102
  用前  5 个种子: 均值=1.3798, 标准误差(SEM)=0.0103
  用前 10 个种子: 均值=1.3815, 标准误差(SEM)=0.0075
  用前 20 个种子: 均值=1.3847, 标准误差(SEM)=0.0047

=== 实验 3：消融实验——只改学习率（其余不变），每个配置跑 8 个种子 ===
  lr=0.001 : 验证 MSE 均值=7.5807 ± 0.4112（8 种子）
  lr=0.01  : 验证 MSE 均值=1.3822 ± 0.0167（8 种子）
  lr=0.05  : 验证 MSE 均值=1.2906 ± 0.0197（8 种子）
```

实验 1 印证第 4 节的核心观点：同一份数据、同一套超参数，仅改变随机种子，验证 MSE 就在 1.3416 到 1.4161 之间波动，标准差 0.0205——只跑一次刚好碰到 1.3416 附近，会误以为找到了特别好的配置，实际只是运气。实验 2 说明为什么要跑多个种子：标准误差随种子数从 3 增加到 20，从 0.0102 收缩到 0.0047，种子越多对真实均值的估计越可信，这也是"至少跑 3-5 个种子"经验法则的数值依据。实验 3 是干净的消融实验——三个配置只有学习率不同：`lr=0.001` 明显欠优化（均值 7.58，标准差 0.41 也更大，说明小学习率下不同初始化收敛程度差异更大）；`lr=0.01` 和 `lr=0.05` 的差距（1.38 vs 1.29）已超过两者标准差之和，可初步认为 `lr=0.05` 在此设置下确实更优，而非噪声。

## 7. 超参搜索的预算分配

超参搜索本质是在"探索更多配置"和"每个配置跑得更充分（多种子/多 epoch）"之间分配有限的计算预算，两个极端都不理想：

- **配置多但每个种子数不足**：容易被噪声误导，选出的"最优配置"可能只是那次随机种子恰好运气好，换个种子就打回原形。
- **配置少但每个跑得很充分**：可能根本没搜到更优的超参数区域，陷入局部最优的假象。

实用的分配策略是分阶段：**第一阶段用较少种子（1-2 个）、较小的搜索空间粗筛掉明显差的配置；第二阶段只对少数候选（如前 3-5 名）用完整种子数复测确认**，避免把预算浪费在明显不可行的区域上。搜索方法上，随机搜索（random search）在高维超参数空间中通常比网格搜索（grid search）更高效——网格搜索的每一维都均匀切分，当只有少数维度真正重要时会在不重要的维度上浪费大量组合。

## 8. 验证集过拟合：反复调参的隐性代价

验证集本意是"训练过程看不到"的数据，用来估计模型的真实泛化能力。但如果**反复根据验证集分数调整超参数、模型结构、甚至特征工程**，验证集分数会逐渐变成一个新的"训练目标"——每次调整都是在验证集上做了一次隐式的梯度下降，多轮迭代后，模型（或整套 pipeline）事实上已经过拟合到验证集本身，验证集分数不再能代表真实泛化能力。这个现象在大规模超参搜索、长期迭代的项目里尤其明显。缓解办法：保留一个**只在项目最终阶段用一次**的测试集（不参与任何中间决策），或者用嵌套交叉验证（外层估计泛化性能，内层做超参选择），把"调参"和"评估泛化能力"这两件事在数据上物理隔离。

## 9. 实验记录应包含哪些字段

没有系统记录的实验，几周后自己都无法复现当时的结论。一条完整的实验记录至少应包含：

- **代码版本**：commit hash 或版本标签，确保能找到对应的确切代码。
- **数据版本**：数据集的版本号/快照时间，避免"数据后来改过但没人知道"。
- **超参数全集**：不只是这次改的那个参数，而是能完整复现训练的所有超参数（学习率、batch size、epoch 数、正则化系数、模型结构参数等）。
- **随机种子**：本次运行用的种子，或者种子列表（多种子实验）。
- **环境信息**：框架版本、硬件型号（CPU/GPU 型号），用于排查"同种子结果不同"的问题。
- **评估结果**：不只是最终分数，还有多种子的均值和标准差、训练曲线（如果适用）。
- **实验目的与结论**：这次实验想验证什么假设，结果支持还是拒绝了这个假设——没有目的的实验记录几个月后无法回溯"当时为什么跑这个"。

## 10. 基线的重要性：简单基线常被低估

任何新方法的价值，只能通过和一个合理的基线（baseline）对比才能确认。常见误区是**跳过简单基线，直接和另一个复杂方法比**，或者**基线实现得很粗糙（没有调参、没有用合理的默认设置）**，导致"新方法更好"的结论其实只是"新方法调得比基线认真"。一个诚实的评估流程应该给基线投入和新方法同等量级的调参精力——简单基线（比如线性模型、"预测训练集均值/多数类"这类零智能基线）往往比预期表现更好，如果新方法的提升幅度落在多种子标准差量级以内，或者连简单基线都打不过，说明复杂方法的额外成本可能并不值得。

## 11. 小结

| 主题 | 关键结论 |
| --- | --- |
| 随机源 | 初始化、数据顺序、dropout、数据增强、GPU 非确定性 |
| 种子固定 | 保证同环境可复现，不保证跨硬件/跨版本一致 |
| 单次实验 | 不可信，应报多种子均值±标准差 |
| 消融实验 | 一次只变一个因素，每个配置都要多种子 |
| 超参搜索 | 分阶段分配预算，先粗筛再精调 |
| 验证集过拟合 | 反复调参会让验证集分数失真，需要隔离最终测试集 |
| 实验记录 | 代码/数据版本、超参、种子、环境、结果、目的缺一不可 |
| 基线 | 要认真调参，简单基线常比预期更强 |
