## 2. Ollama 本地部署

```bash
# 安装 Ollama
curl -fsSL https://ollama.com/install.sh | sh

# 下载并运行模型
ollama pull llama3.1:8b
ollama pull qwen2.5:14b
ollama run llama3.1:8b "什么是 AI Agent？"

# 查看已下载模型
ollama list
```

```python
# Python 调用 Ollama（兼容 OpenAI API）
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

response = client.chat.completions.create(
    model="qwen2.5:14b",
    messages=[
        {"role": "system", "content": "你是一个有帮助的助手"},
        {"role": "user", "content": "解释 RAG 的核心流程"},
    ],
    temperature=0.7,
)
print(response.choices[0].message.content)
```

## 4. llama.cpp（GGUF 量化推理）

```bash
# 安装 llama-cpp-python
pip install llama-cpp-python

# 下载 GGUF 量化模型
# huggingface-cli download TheBloke/Llama-3.1-8B-Instruct-GGUF \
#   llama-3.1-8b-instruct.Q4_K_M.gguf
```

```python
from llama_cpp import Llama

llm = Llama(
    model_path="./models/llama-3.1-8b-instruct.Q4_K_M.gguf",
    n_ctx=8192,       # 上下文长度
    n_gpu_layers=35,  # GPU 加速层数（-1 = 全部）
    n_threads=8,      # CPU 线程数
)

output = llm.create_chat_completion(
    messages=[{"role": "user", "content": "什么是 MCP 协议？"}],
    temperature=0.7,
    max_tokens=500,
)
print(output["choices"][0]["message"]["content"])
```

## 5. 量化方案对比

## 7. GPU 资源规划

```python
def estimate_gpu_memory(param_billions: float, precision: str = "fp16") -> float:
    """估算模型显存需求（GB）"""
    bytes_per_param = {"fp32": 4, "fp16": 2, "int8": 1, "int4": 0.5}
    model_size = param_billions * bytes_per_param[precision]
    # 推理额外开销约 20%
    return model_size * 1.2

# 示例
print(f"Qwen2.5-14B FP16: {estimate_gpu_memory(14, 'fp16'):.0f} GB")   # ~34 GB
print(f"Qwen2.5-14B INT4: {estimate_gpu_memory(14, 'int4'):.0f} GB")   # ~8 GB
print(f"Llama-70B INT4:   {estimate_gpu_memory(70, 'int4'):.0f} GB")   # ~42 GB

# GPU 选型参考
# RTX 4090 (24GB): 14B FP16 / 70B INT4（勉强）
# A100 (80GB):     70B FP16 / 405B INT4
# H100 (80GB):     70B FP16（更快）
```

### vLLM 0.20.x（2026-04）

vLLM 从 0.16 跃升至 0.20，经历了多个重大版本：

| 版本 | 关键变化 |
|------|---------|
| 0.19.0 | 448 commits / 197 贡献者；ROCm 7.2.1 支持 |
| 0.20.0 | 752 commits / 320 贡献者；DeepSeek V4 初始支持；CUDA 13.0 默认；PyTorch 2.11；Python 3.14 支持；Transformers v5 兼容；FlashAttention 4 默认 MLA prefill；TurboQuant 2-bit KV cache |
| 0.20.1 | DeepSeek V4 稳定化和性能优化；多流 pre-attention GEMM |

**核心新特性**：
- **DeepSeek V4 支持**：V4-Pro 和 V4-Flash 均可通过 vLLM 部署，支持 1M 上下文高效推理
- **TurboQuant 2-bit KV cache**：4x KV cache 容量，显著降低长上下文显存需求
- **在线量化前端**：端到端在线量化，支持 FP8 和 MXFP8
- **vLLM IR**：初始 IR 骨架，为未来内核优化奠定基础

```bash
# 2026 年推荐安装方式（使用 uv）
uv pip install vllm --torch-backend auto

# 部署 DeepSeek V4-Flash（需要多 GPU）
python -m vllm.entrypoints.openai.api_server \
    --model deepseek-ai/DeepSeek-V4-Flash \
    --tensor-parallel-size 4 \
    --max-model-len 131072 \
    --gpu-memory-utilization 0.9 \
    --port 8000
```

### vLLM 0.24.0（2026-06-29，7 月生产推荐版本）

> 🔄 更新于 2026-07-08

0.20 → 0.24 跨越四个 minor 版本，571 commits / 256 贡献者。截至 7 月初仍为最新稳定版（无 0.25 发布）。

| 领域 | 关键变化 |
|------|---------|
| 新模型 | **MiniMax-M3**（MXFP4 / FP8 / ROCm 调优）、**DiffusionGemma**（含 CPU 路径）、Hierarchical Reasoning Model、OpenMOSS |
| DeepSeek V4 | FlashInfer 稀疏索引缓存（TTFT -2~4%）、prefill chunk-planning（E2E +4%）、SM120 / XPU / ROCm 注意力路径 |
| Model Runner V2 | 默认支持量化模型、GraniteMoE 默认启用、Qwen + DeepSeek-V2 MoE 迁移、DFlash 投机解码 |
| Streaming Parser Engine | 统一 tool call / reasoning / 结构化输出解析（Qwen3、MiniMax-M2、GLM、Nemotron） |
| 破坏性变更 | 移除 Transformers v4 支持；不再内部设置 `CUDA_VISIBLE_DEVICES`，改用 `device_ids` 参数 |
