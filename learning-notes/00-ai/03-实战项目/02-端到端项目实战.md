## 0. 这篇的定位

前面的笔记都是**单点知识**：反向传播怎么算、正则化怎么用、PyTorch 怎么写训练循环。

但真实项目不是把这些拼起来那么简单——**顺序错了、少了某个环节，前面所有努力都会打折**。这篇把散点串成一条线。

本篇用一个完整可运行的例子走完全流程，代码只依赖 numpy（不需要 GPU、不需要下载数据）。

## 1. 项目全流程地图

```
① 定义问题与成功标准     ← 最容易被跳过，但决定一切
       ↓
② 划分数据集             ← 必须在任何数据分析之前做
       ↓
③ 探索数据（只看训练集）
       ↓
④ 做一个笨基线           ← 不做基线，你不知道模型好不好
       ↓
⑤ 特征工程 / 预处理
       ↓
⑥ 训练模型（迭代）
       ↓
⑦ 评估与错误分析         ← 看错在哪，比看对了多少更有用
       ↓
⑧ 决定是否上线           ← 不只看指标
```

**两个顺序陷阱**，是新手最常犯的：

| 陷阱 | 为什么错 |
| --- | --- |
| 先分析全部数据，再划分数据集 | 你已经用测试集的信息指导了决策，测试集失去意义 |
| 直接上复杂模型，跳过基线 | 拿到 92% 准确率，不知道笨方法能做到 90% 还是 60% |

## 2. 阶段①：定义问题与成功标准

**这是最容易被跳过、代价最大的一步。**

三个必须回答的问题：

| 问题 | 反例（模糊） | 正例（可验证） |
| --- | --- | --- |
| 要预测什么？ | 「预测用户行为」 | 「预测用户下单后 7 天内是否退货」 |
| 用什么指标？ | 「准确率高一点」 | 「召回率 ≥ 0.8 前提下最大化精确率」 |
| 多好算成功？ | 「效果好就行」 | 「比当前人工规则的误报率降低 30%」 |

**指标选择比模型选择更重要**。举个具体的坑：

```
任务：识别欺诈交易（欺诈占 0.5%）
                    
模型 A: 全部预测「不是欺诈」  → 准确率 99.5%  但一个欺诈都没抓到
模型 B: 抓到 80% 欺诈，误报一些 → 准确率 97%   实际有用
                                        ↑
                        按准确率排，废物模型 A 赢了
```

不平衡数据下必须看精确率/召回率/PR 曲线，不能看准确率——这块的完整讨论见 [模型评估与度量选择](../01-machine-learning/01-机器学习基础/02-模型评估与度量选择.md)。

## 3. 阶段②：划分数据集（必须最先做）

```
全部数据
   │
   ├── 训练集 (60~80%)   用来学参数
   ├── 验证集 (10~20%)   用来调超参、选模型、早停
   └── 测试集 (10~20%)   ★ 只在最后用一次，用来报告最终性能
```

### 为什么必须最先划分

> **一旦你看过测试集的数据分布，你就已经用它的信息影响了决策。**

```
❌ 错误顺序
   看全部数据 → 发现某特征有用 → 据此设计模型 → 在测试集上评估
                                                    ↑
                              测试集的信息已经通过你的大脑泄漏进模型了
                              报告的性能会偏高

✅ 正确顺序
   先划分 → 只看训练集做一切决策 → 最后用测试集报告一次
```

### 三条铁律

| 铁律 | 原因 |
| --- | --- |
| **测试集只用一次** | 反复在测试集上调整 = 把它变成第二个验证集 |
| 时序数据按时间切分 | 用未来预测过去是穿越，见 [时序与窗口特征](../01-machine-learning/03-特征工程/03-时序与窗口特征.md) |
| 分层抽样保持类别比例 | 否则验证集可能一个正样本都没有 |

## 4. 阶段④：先做一个笨基线

**这一步被跳过的频率极高，但它是判断模型好坏的唯一参照。**

```
没有基线：
  「我的深度模型准确率 92%」  →  好还是坏？不知道

有基线：
  多数类基线 (全猜最多的类)     : 85%
  逻辑回归                     : 89%
  你的深度模型                 : 92%
                              ↑
              现在你知道：深度模型比逻辑回归只多 3 个点，
              而复杂度和维护成本高一个数量级 —— 值得吗？
```

### 基线阶梯

按复杂度从低到高，至少做前两个：

| 基线 | 做法 | 意义 |
| --- | --- | --- |
| **多数类 / 均值** | 全部预测最常见的类（或均值） | 绝对下限，低于它说明模型学反了 |
| **简单线性模型** | 逻辑回归 / 线性回归 | 真正的参照线 |
| 树模型 | 决策树 / 梯度提升 | 表格数据上常常就是最优解 |
| 深度模型 | 神经网络 | 只在前面明显不够时才上 |

**一个反复被验证的事实**：表格数据上，梯度提升树（XGBoost/LightGBM）常常打败神经网络，而且训练快几个数量级。见 [集成学习](../01-machine-learning/02-经典算法/03-集成学习.md)。

## 5. 阶段⑦：错误分析比指标更有用

拿到 92% 准确率之后，**不要立刻去调参**。先看那 8% 错在哪。

```
错误分析的三个问题：
                    
1. 错误集中在哪一类？        → 可能是类别不平衡或标签噪声
2. 错误样本有共同特征吗？    → 可能缺了关键特征
3. 人类看这些样本会错吗？    → 如果人也会错，说明接近上限了
```

**为什么这比调参有用**：调参通常只能榨出 1~2 个点，而找到一类系统性错误（比如某个特征在特定条件下缺失）常常能带来 5~10 个点。

混淆矩阵是错误分析的主要工具，详见 [模型评估与度量选择](../01-machine-learning/01-机器学习基础/02-模型评估与度量选择.md)。

## 6. 阶段⑧：验证集 95% 能上线吗

不能，至少还要看四件事：

| 检查项 | 为什么 |
| --- | --- |
| **测试集性能** | 验证集被反复用过，已经被「过拟合」了 |
| **多种子稳定性** | 单次结果是随机变量的一次采样，见 [实验设计与可复现性](../01-machine-learning/01-机器学习基础/03-实验设计与可复现性.md) |
| **分组表现** | 整体 95%，但某个重要用户群只有 60%？ |
| **推理成本与延迟** | 准确率高 2% 但延迟高 10 倍，业务可能不接受 |

第二条最容易忽略。如果同一配置跑 5 次是 93.1 / 95.2 / 94.0 / 92.8 / 94.7（波动 ±1.2%），那「95%」这个数字本身就有很大不确定性。

目的：演示完整流程与每个阶段的关键动作

只依赖 numpy。所有模型手写，便于看清每一步。

print("  目标  : 召回率 ≥ 0.70 前提下，精确率尽可能高")

def make_dataset(n=3000, seed=0):
    """构造一个带真实项目特征的数据集：
    - 不平衡（正样本约 15%）
    - 有 2 个无用特征（噪声）
    - 有缺失值（用 nan 表示）
    """
    g = np.random.default_rng(seed)
    # 有用特征
    tenure = g.exponential(20, n)                    # 使用时长
    complaints = g.poisson(0.5, n)                   # 投诉次数
    monthly = g.normal(60, 20, n)                    # 月消费
    # 无用特征（纯噪声，用来检验特征选择能否识别）
    noise1 = g.normal(0, 1, n)
    noise2 = g.uniform(0, 100, n)

    # 真实规则：时长短 + 投诉多 + 消费低 → 容易流失
    logit = 0.4 - 0.08 * tenure + 1.3 * complaints - 0.015 * monthly
    p = 1 / (1 + np.exp(-logit))
    y = (g.random(n) < p).astype(int)

    X = np.column_stack([tenure, complaints, monthly, noise1, noise2])

    # 人为制造缺失（monthly 列 8% 缺失，真实数据常见）
    miss_idx = g.choice(n, size=int(0.08 * n), replace=False)
    X[miss_idx, 2] = np.nan

    return X, y


feature_names = ["tenure", "complaints", "monthly", "noise1", "noise2"]
X_all, y_all = make_dataset(3000, seed=0)

print(f"  数据规模: {X_all.shape[0]} 条 × {X_all.shape[1]} 个特征")
print(f"  正样本率: {y_all.mean():.2%}  ← 不平衡，准确率会有欺骗性")

def stratified_split(X, y, ratios=(0.6, 0.2, 0.2), seed=0):
    """分层划分：保证每份里正负样本比例一致"""
    g = np.random.default_rng(seed)
    idx_tr, idx_va, idx_te = [], [], []
    for cls in np.unique(y):
        idx = np.where(y == cls)[0]
        g.shuffle(idx)
        n1 = int(len(idx) * ratios[0])
        n2 = int(len(idx) * (ratios[0] + ratios[1]))
        idx_tr += list(idx[:n1])
        idx_va += list(idx[n1:n2])
        idx_te += list(idx[n2:])
    for lst in (idx_tr, idx_va, idx_te):
        g.shuffle(lst)
    return np.array(idx_tr), np.array(idx_va), np.array(idx_te)


i_tr, i_va, i_te = stratified_split(X_all, y_all, seed=1)
X_tr, y_tr = X_all[i_tr], y_all[i_tr]
X_va, y_va = X_all[i_va], y_all[i_va]

class Preprocessor:
    """预处理器：fit 只用训练集，transform 用同一套参数处理所有集合

    这是防数据泄漏的关键——如果用全量数据算均值，测试集信息就泄漏了
    """

    def fit(self, X):
        self.median_ = np.nanmedian(X, axis=0)      # 用中位数填缺失，比均值抗离群
        Xf = self._fill(X)
        self.mean_ = Xf.mean(axis=0)
        self.std_ = Xf.std(axis=0) + 1e-8
        return self

    def _fill(self, X):
        Xf = X.copy()
        for j in range(X.shape[1]):
            Xf[np.isnan(Xf[:, j]), j] = self.median_[j]
        return Xf

    def transform(self, X):
        return (self._fill(X) - self.mean_) / self.std_


prep = Preprocessor().fit(X_tr)          # ★ 只 fit 训练集
Xtr, Xva, Xte = prep.transform(X_tr), prep.transform(X_va), prep.transform(X_te)

print(f"  填缺失用的中位数（从训练集算）: monthly = {prep.median_[2]:.3f}")
print(f"  标准化后训练集均值 ≈ {Xtr.mean():.2e}，标准差 ≈ {Xtr.std():.4f}")
print("  ★ 验证集/测试集用的是训练集的统计量，避免数据泄漏")


# ══════════════════════════════════════════════════════
# 评估函数（不平衡数据，看精确率/召回率）
# ══════════════════════════════════════════════════════
def metrics(y_true, y_prob, threshold=0.5):
    y_pred = (y_prob >= threshold).astype(int)
    tp = int(((y_pred == 1) & (y_true == 1)).sum())
    fp = int(((y_pred == 1) & (y_true == 0)).sum())
    fn = int(((y_pred == 0) & (y_true == 1)).sum())
    tn = int(((y_pred == 0) & (y_true == 0)).sum())
    acc = (tp + tn) / len(y_true)
    prec = tp / (tp + fp) if tp + fp else 0.0
    rec = tp / (tp + fn) if tp + fn else 0.0
    f1 = 2 * prec * rec / (prec + rec) if prec + rec else 0.0
    return dict(acc=acc, precision=prec, recall=rec, f1=f1,
                tp=tp, fp=fp, fn=fn, tn=tn)


def show(name, m):
    print(f"  {name:22s} 准确率={m['acc']:.4f}  精确率={m['precision']:.4f}  "
          f"召回率={m['recall']:.4f}  F1={m['f1']:.4f}")

# 基线 2：逻辑回归（手写）
def train_logreg(X, y, lr=0.1, epochs=600, l2=1e-3):
    w = np.zeros(X.shape[1])
    b = 0.0
    n = len(y)
    for _ in range(epochs):
        z = X @ w + b
        p = 1 / (1 + np.exp(-z))
        gw = X.T @ (p - y) / n + l2 * w
        gb = (p - y).mean()
        w -= lr * gw
        b -= lr * gb
    return w, b


w_lr, b_lr = train_logreg(Xtr, y_tr)
p_va_lr = 1 / (1 + np.exp(-(Xva @ w_lr + b_lr)))
m_lr = metrics(y_va, p_va_lr)
show("基线2 逻辑回归", m_lr)

def train_mlp(Xtr, ytr, Xva, yva, hidden=16, lr=0.05, epochs=400,
              patience=40, seed=0):
    g = np.random.default_rng(seed)
    d = Xtr.shape[1]
    # He 初始化（配 ReLU）
    W1 = g.normal(0, np.sqrt(2.0 / d), (d, hidden))
    b1 = np.zeros(hidden)
    W2 = g.normal(0, np.sqrt(2.0 / hidden), hidden)
    b2 = 0.0

    best = dict(loss=np.inf, params=None, epoch=0)
    bad = 0
    n = len(ytr)

    for ep in range(1, epochs + 1):
        # 前向
        h = np.maximum(0, Xtr @ W1 + b1)
        z = h @ W2 + b2
        p = 1 / (1 + np.exp(-z))
        # 反向（交叉熵 + sigmoid 的联合梯度就是 p - y，见损失函数篇）
        dz = (p - ytr) / n
        gW2 = h.T @ dz
        gb2 = dz.sum()
        dh = np.outer(dz, W2) * (h > 0)
        gW1 = Xtr.T @ dh
        gb1 = dh.sum(axis=0)
        # 更新
        W1 -= lr * gW1; b1 -= lr * gb1; W2 -= lr * gW2; b2 -= lr * gb2

        # 验证集损失，用于早停
        hv = np.maximum(0, Xva @ W1 + b1)
        pv = 1 / (1 + np.exp(-(hv @ W2 + b2)))
        eps = 1e-12
        vloss = -np.mean(yva * np.log(pv + eps) + (1 - yva) * np.log(1 - pv + eps))

        if vloss < best["loss"] - 1e-5:
            best = dict(loss=vloss,
                        params=(W1.copy(), b1.copy(), W2.copy(), b2),
                        epoch=ep)
            bad = 0
        else:
            bad += 1
            if bad >= patience:
                break

    return best


best = train_mlp(Xtr, y_tr, Xva, y_va)
W1, b1, W2, b2 = best["params"]
print(f"  早停于 epoch {best['epoch']}，最佳验证损失 {best['loss']:.4f}")


def mlp_prob(X):
    h = np.maximum(0, X @ W1 + b1)
    return 1 / (1 + np.exp(-(h @ W2 + b2)))


m_mlp = metrics(y_va, mlp_prob(Xva))
show("MLP (阈值0.5)", m_mlp)

thresholds = [0.5, 0.4, 0.35, 0.3, 0.25, 0.2, 0.15, 0.1, 0.05]
for th in thresholds:

    if ok and chosen is None:
        chosen = th
    print(f"  {th:6.2f} {m['precision']:10.4f} {m['recall']:10.4f} "
          f"{m['f1']:10.4f}  {'✅' if ok else '❌'}")

if chosen is None:                      # 兜底：没有阈值达标时取召回率最高的
    chosen = min(thresholds)
    print()
    print(f"  ⚠️ 无阈值满足召回率≥0.70，退而取最低阈值 {chosen}")
print()
print(f"  → 选定阈值 {chosen}")
print("  → 默认阈值 0.5 是任意的，业务目标应该决定阈值")


# ══════════════════════════════════════════════════════
# 阶段⑦ 错误分析
# ══════════════════════════════════════════════════════
print()
print("=" * 60)
print("阶段⑦ 错误分析（看错在哪，比看对多少有用）")
print("=" * 60)

m_final = metrics(y_va, p_va_mlp, chosen)
print(f"  混淆矩阵（阈值 {chosen}）")
print(f"                预测:不流失   预测:流失")
print(f"    真实:不流失  {m_final['tn']:10d}  {m_final['fp']:10d}")
print(f"    真实:流失    {m_final['fn']:10d}  {m_final['tp']:10d}")
print()

pred_va = (p_va_mlp >= chosen).astype(int)
fn_mask = (pred_va == 0) & (y_va == 1)
tp_mask = (pred_va == 1) & (y_va == 1)
print("  漏报样本 vs 正确捕获样本的原始特征均值对比:")

for j, nm in enumerate(feature_names[:3]):

print("  → 这类信息比单看指标更能指导下一步（比如补充行为特征）")

print("=" * 60)

print("=" * 60)

print("  A. 测试集最终评估（★ 全程只用这一次）")
m_te_lr = metrics(y_te, 1 / (1 + np.exp(-(Xte @ w_lr + b_lr))), chosen)
m_te_mlp = metrics(y_te, mlp_prob(Xte), chosen)
show("逻辑回归 @测试集", m_te_lr)
show("MLP     @测试集", m_te_mlp)

print()
print("  B. 多种子稳定性（单次结果不可信）")
f1s = []
for sd in range(5):
    bt = train_mlp(Xtr, y_tr, Xva, y_va, seed=sd)
    Wa, ba, Wb, bb = bt["params"]
    hh = np.maximum(0, Xte @ Wa + ba)
    pp = 1 / (1 + np.exp(-(hh @ Wb + bb)))
    f1s.append(metrics(y_te, pp, chosen)["f1"])
f1s = np.array(f1s)
print(f"    5 个种子的测试集 F1: {np.round(f1s, 4)}")
print(f"    均值 ± 标准差: {f1s.mean():.4f} ± {f1s.std(ddof=1):.4f}")
print(f"    → 报告结论时必须带上这个波动范围")

print()
print("  C. 与基线对比，判断是否值得上线")
gain = m_te_mlp["f1"] - m_te_lr["f1"]
print(f"    MLP 相对逻辑回归的 F1 提升: {gain:+.4f}")
print(f"    单种子波动（标准差）      : {f1s.std(ddof=1):.4f}")
sd = f1s.std(ddof=1)
if gain < -sd:                          # 明显更差
    print("    → MLP 显著劣于基线，不应上线")
    print("    → 结论：上逻辑回归（更简单、可解释、推理快，且效果更好）")
elif gain < sd:                         # 差异在噪声范围内
    print("    → 提升幅度小于随机波动，不能声称 MLP 更好")
    print("    → 结论：优先上更简单的逻辑回归")
else:                                   # 明显更好
    print("    → 提升幅度超过随机波动，MLP 的优势可能是真实的")
    print("    → 但仍需权衡：复杂度、推理成本、可解释性")

print()
print("  D. 上线前还需检查（本示例未覆盖，真实项目必做）")
for item in ["分组表现（各用户群是否都达标）",
             "推理延迟与成本",
             "特征在线可得性（训练用的特征线上能拿到吗）",
             "监控方案（数据漂移、指标下滑告警）"]:
    print(f"    - {item}")

## 8. 这次实测结果本身就是一课

注意上面的实测输出里，**MLP 输给了逻辑回归**（测试集 F1：0.5673 vs 0.6026）。

这不是我把例子设计坏了，而是真实项目里非常常见的结果，值得单独说：

| 观察 | 含义 |
| --- | --- |
| MLP F1 比逻辑回归低 0.0353 | 神经网络在这个任务上并没有优势 |
| 多种子波动只有 0.0079 | 这个差距是**稳定存在**的，不是运气 |
| 数据只有 5 个特征、1800 条训练样本 | 数据量和特征维度都不足以让神经网络发挥 |

**正确的结论是「上逻辑回归」**——它效果更好，还更简单、更可解释、推理更快。

如果我当初跳过基线直接上 MLP，看到「测试集 F1 = 0.57」可能会觉得还不错，然后花时间调参，完全不知道一个二十行的逻辑回归就能做得更好。**这就是基线的价值。**

顺带说明一个我在写这段代码时踩的坑：最初的判断逻辑写成 `if abs(gain) < std`，用了绝对值——结果 MLP 明明更差（gain 为负），程序却输出「MLP 的优势可能是真实的」。这类符号错误在实际项目里会直接导致上线错误的模型，已修正为三分支判断。

## 9. 这个例子演示的关键点

回看代码里标了 ★ 的地方，都是真实项目里容易出错的位置：

| 位置 | 要点 |
| --- | --- |
| 阶段② | 分层划分，**先划分再分析** |
| 阶段⑤ | 预处理统计量**只从训练集算**（防泄漏） |
| 阶段④ | 基线阶梯，多数类基线暴露了「准确率骗人」 |
| 阈值调优 | **0.5 是任意的**，业务目标该决定阈值 |
| 阶段⑦ | 错误分析看漏报样本的特征分布 |
| 阶段⑧ | 测试集只用一次 + 多种子 + 与基线比 |

最后那条 **C** 的判断逻辑值得单独强调：**如果模型提升小于随机波动，正确结论是选更简单的模型**，而不是选指标高的那个。简单模型在维护成本、可解释性、推理速度上都有优势。

## 10. 小结

| 阶段 | 关键动作 | 最容易犯的错 |
| --- | --- | --- |
| ① 定义问题 | 定可验证的成功标准 | 指标选错（不平衡数据用准确率） |
| ② 划分数据 | **最先做**，分层/按时间 | 先分析全量数据 |
| ③ 探索数据 | 只看训练集 | 看了测试集 |
| ④ 做基线 | 多数类 + 线性模型 | **跳过基线** |
| ⑤ 预处理 | 统计量只从训练集算 | 用全量数据算均值（泄漏） |
| ⑥ 训练 | 用验证集早停 | 用测试集早停 |
| ⑦ 错误分析 | 看错在哪、有无共性 | 只看总指标就去调参 |
| ⑧ 上线决策 | 测试集一次 + 多种子 + 比基线 | 只看单次验证集指标 |

**如果只记三件事**：先划分数据集；一定做基线；提升小于波动就选简单模型。
