## 1. 自回归解码的带宽瓶颈本质

回顾 [01-KV-Cache与显存分析.md](01-KV-Cache与显存分析.md) 的结论：Decode 阶段每步只处理 1 个新 token，矩阵乘法退化成向量乘矩阵，计算量很小，但要把模型全部权重（数十亿参数）和 KV Cache 从显存搬到计算单元参与运算。

**这就是带宽瓶颈的本质**：GPU 算力（FLOPs/s）远超它把数据从显存搬到计算单元的速度（显存带宽，Bytes/s）。Decode 阶段每步计算量太小，根本喂不满算力，大部分时间花在"等数据从显存搬过来"，而非"真正在计算"。这称为**显存带宽受限（memory-bandwidth-bound）**，与之相对的是**计算受限（compute-bound）**（如 Prefill 阶段）。

```
Decode 每步的时间开销 ≈ max(计算时间, 数据搬运时间) ≈ 数据搬运时间（计算量太小，搬运时间占主导）
数据搬运时间 ≈ 模型参数量 × 字节数 / 显存带宽
```

若一步只能生成 1 个 token，生成 N 个就要重复 N 次"搬运数据 → 算一点点 → 再搬运"的过程。**投机解码的核心思路：能否一次搬运权重，验证多个候选 token，把搬运成本分摊到更多产出上？**

## 2. 投机解码：验证机制与接受/拒绝采样

投机解码（Speculative Decoding）用一个**更小更快的草稿模型（draft model）**先快速生成若干候选 token，再用**目标模型（target model）**一次性并行验证这些候选，接受符合目标模型分布的部分，拒绝不符合的部分。

```
1. 草稿模型自回归生成 k 个候选 token: x1, x2, ..., xk（这一步快，模型小）
2. 目标模型对 [已有上文, x1, ..., xk] 做一次前向，并行算出每个位置的真实分布
3. 从左到右逐个验证 x_i 是否被接受，一旦某个被拒绝，后面候选全部丢弃
4. 用目标模型分布修正/采样出下一个 token，作为这一轮的最终产出
```

**核心问题**：草稿模型分布 `q(x)` 和目标模型分布 `p(x)` 不一样，若直接采用草稿生成的 token，输出分布会被污染。投机解码要解决的是：**如何设计接受/拒绝机制，使最终采样的 token 分布严格等于目标模型独立采样的分布 `p(x)`**，不多不少。

### 接受/拒绝采样的推导

对草稿模型生成的候选 `x`，接受概率定义为：

```
accept_prob(x) = min(1, p(x) / q(x))
```

若被接受，直接采用 `x` 作为输出；若被拒绝，则从修正分布中重新采样：

```
p_residual(x) = normalize( max(0, p(x) - q(x)) )
```

**为什么这样设计能保证输出分布严格等于 `p(x)`**：随机变量 `x` 先从 `q` 中采样，再按 `accept_prob(x)` 决定是否接受。最终输出为 `x` 的概率，由"从 q 采样到 x 且被接受"与"被拒绝后从残差分布重新采样到 x"两部分组成：

```
P(最终输出 = x)
  = q(x) · min(1, p(x)/q(x))                      ← 直接接受这条路径
  + P(拒绝) · p_residual(x)                        ← 拒绝后重新采样这条路径
```

对第一项，`q(x)·min(1, p(x)/q(x)) = min(q(x), p(x))`。对总拒绝概率 `P(拒绝) = Σ_x max(0, q(x)-p(x)) = 1 - Σ_x min(q(x),p(x))`。而 `p_residual(x) = max(0, p(x)-q(x)) / P(拒绝)`，所以第二项 `P(拒绝)·p_residual(x) = max(0, p(x)-q(x))`。

两项相加：`P(最终输出=x) = min(q(x),p(x)) + max(0, p(x)-q(x))`。若 `p(x)≥q(x)`，等于 `q(x)+(p(x)-q(x))=p(x)`；若 `p(x)<q(x)`，等于 `p(x)+0=p(x)`。**两种情况都等于 `p(x)`**，证明输出分布严格等于目标模型分布，与草稿模型 `q` 的具体选择无关。

这就是投机解码"免费加速"的数学基础：只要验证机制设计正确，用什么草稿模型都不会改变最终输出分布，纯粹是在做"生成候选、批量验证"的效率优化，不牺牲精度。

## 3. 草稿模型选择与接受率权衡
草稿模型选择直接决定加速效果，核心是**接受率（acceptance rate）**：草稿模型生成的候选被目标模型接受的比例。

```
接受率高 → q 与 p 接近 → 每轮验证能"批量确认"更多 token → 加速明显
接受率低 → 候选大多被拒绝 → 大部分候选是无效计算，加速有限甚至负收益
```

**权衡关系**：草稿模型越小越快，生成开销越低，但通常与目标模型分布差异越大，接受率越低；草稿模型越接近目标模型（如量化版本、蒸馏小模型），接受率越高，但生成开销也上升。理想草稿模型是"足够快、又足够像目标模型"的平衡点。

常见草稿模型来源：目标模型的量化版、蒸馏出的小模型、同系列参数量更小的模型。

## 4. Medusa/多 token 预测头的思路

投机解码依赖独立草稿模型，需要额外部署维护。另一类思路是**不引入独立草稿模型，在目标模型自身上增加多个"预测头"**，让模型一次前向就能对多个未来位置给出候选预测。

```
标准解码：  [模型主干] → 预测头 → 下一个 token（只预测 1 步）
多头预测：  [模型主干] → 预测头0 → 第 1 步 token
                      → 预测头1 → 第 2 步候选
                      → 预测头2 → 第 3 步候选
```

每个预测头基于主干共享隐藏状态，预测"未来第几步"的候选（头 `i` 学习预测第 `i+1` 个位置）。这些候选同样需要经过验证机制（或树状验证结构）确认能否被接受。

**相比独立草稿模型的差异**：不需单独训练部署完整小模型，只需加轻量预测头，部署更简单；但预测头基于同一主干隐藏状态，能提供的"独立视角"不如完全独立训练的草稿模型，多步之外的预测准确度通常下降更快。

## 5. Flash Attention：IO 感知的分块与重计算

标准 attention 中，计算 `softmax(QKᵀ/√d)·V` 需先算出完整的 `QKᵀ` 打分矩阵（大小 `seq_len × seq_len`），中间矩阵需写入显存、再读出做 softmax 和后续乘法。序列越长，中间矩阵越大，读写开销越大——**这不是算力瓶颈，而是显存 IO 瓶颈**。

**Flash Attention 的核心思路：IO 感知（IO-aware）**——不是减少计算量，而是重排计算顺序，让中间结果尽量留在更快的片上缓存（GPU SRAM）里，避免频繁写回再读取较慢的显存（HBM）。

### 分块（tiling）

把 `Q`、`K`、`V` 切成小块，每次只处理一小块，在片上缓存内完成这一块的 `QKᵀ`、softmax、`·V` 全部计算，不需把完整打分矩阵写入显存：

```
标准做法：完整计算 QK^T（写显存）→ 读出做 softmax（写回）→ 读出做 ·V（写显存）
Flash Attention：
  for 每个 Q 块:
      for 每个 K,V 块:
          在片上缓存计算这一小块的部分 QK^T、softmax 统计量、加权和
          在线更新累积到最终结果（不存储完整中间打分矩阵）
  只在最外层写一次最终结果到显存
```

### 重计算（recomputation）换显存

标准实现反向传播需用到前向的 `QKᵀ` 打分矩阵，正向时会保存下来。Flash Attention **不保存这个大矩阵，反向时用已保存的少量统计量（每块的 softmax 归一化因子等）重新算一遍所需部分**：

```
标准做法：前向保存完整打分矩阵（显存占用大）→ 反向直接读取
Flash Attention：前向只保存少量统计量 → 反向按需重新计算
```

**这就是"用重计算换显存带宽"**：多花一点计算量，省掉大量显存读写。Decode/Prefill 场景显存带宽通常比算力更紧张，这个权衡整体划算。

## 6. 连续批处理与调度

连续批处理的基本思想已在 [01-KV-Cache与显存分析.md](01-KV-Cache与显存分析.md) 介绍：动态换入换出请求，避免槙位空闲。结合投机解码后，调度层还需额外处理：

- **每轮验证长度不固定**：投机解码每轮实际接受的候选数量因请求而异，调度器需要处理"同一 batch 内不同请求这一轮产出的 token 数不同"，不能假设每轮每个请求固定产出 1 个 token。
- **草稿模型的资源分配**：若用独立草稿模型，需额外调度其计算资源，通常与目标模型共享 GPU 分时复用，或用更小的独立资源。
- **动态调整批大小**：验证阶段计算量随批内请求数和草稿长度变化，调度器需平衡"更大批次提升吞吐"和"更长草稿序列增加验证计算量"的资源分配。

## 7. 推理引擎关键能力对比维度

选择或评估 LLM 推理引擎时，可从以下维度考察能力覆盖情况（不涉及具体产品名称、版本号或吞吐量数字）：

| 维度 | 关注点 |
| --- | --- |
| KV Cache 管理 | 是否支持分页管理（PagedAttention 类思路）、前缀缓存共享 |
| 批处理策略 | 是否支持连续批处理，调度是否考虑请求优先级、SLA 差异 |
| 量化支持 | 支持哪些量化格式（INT8/INT4/FP8 等），是否支持 KV Cache 量化 |
| 并行策略 | 是否支持张量并行、流水线并行等多卡/多机部署，如何权衡延迟和吞吐 |
| 投机解码支持 | 是否支持独立草稿模型或多头预测机制，验证逻辑是否正确（分布不变） |
| Attention 实现 | 是否使用 IO 感知的高效实现，是否支持 MQA/GQA 等压缩变体 |
| 可观测性 | 是否提供请求级延迟分解（排队/prefill/decode 各阶段耗时）、显存监控 |
| 多模型/多 LoRA 支持 | 是否支持同时服务多个模型或多个 LoRA 适配器，资源如何隔离复用 |

**核心结论**：这些维度相互影响（更激进的批处理策略可能与投机解码调度冲突，量化格式选择会影响能否叠加其他优化），实际选型需结合具体延迟/吞吐/成本目标综合权衡，而非单一维度"越先进越好"。

## 8. 代码：numpy 模拟投机解码的接受/拒绝采样

用 numpy 构造简化词表分布场景，模拟草稿分布 `q` 与目标分布 `p`，实现接受/拒绝采样，统计接受率，验证最终采样分布是否收敛到目标分布 `p`。

```python
import numpy as np

rng = np.random.default_rng(0)
vocab_size = 6  # 简化的小词表，方便观察分布

# 构造目标分布 p 和草稿分布 q（故意让两者有差异）
p_logits = rng.normal(0, 1.5, vocab_size)
q_logits = p_logits + rng.normal(0, 1.0, vocab_size)  # q 在 p 基础上加噪，模拟不完全一致的草稿模型


def softmax(logits):
    e = np.exp(logits - np.max(logits))
    return e / np.sum(e)


p = softmax(p_logits)
q = softmax(q_logits)


def speculative_sample_once(p, q, rng):
    """单次投机采样：按 q 采样候选 x，以 min(1, p(x)/q(x)) 概率接受；
    拒绝则从残差分布 normalize(max(0, p-q)) 重新采样。返回 (token, 是否接受)"""
    x = rng.choice(len(q), p=q)
    accept_prob = min(1.0, p[x] / q[x])
    if rng.random() < accept_prob:
        return x, True
    residual = np.maximum(0.0, p - q)
    residual_sum = residual.sum()
    if residual_sum <= 1e-12:
        return rng.choice(len(p), p=p), False
    residual = residual / residual_sum
    return rng.choice(len(residual), p=residual), False


n_trials = 200000
final_samples = np.zeros(n_trials, dtype=int)
accepted_count = 0

for i in range(n_trials):
    token, accepted = speculative_sample_once(p, q, rng)
    final_samples[i] = token
    if accepted:
        accepted_count += 1

acceptance_rate = accepted_count / n_trials
empirical_dist = np.bincount(final_samples, minlength=vocab_size) / n_trials

print(f"目标分布 p:      {np.round(p, 4)}")
print(f"草稿分布 q:      {np.round(q, 4)}")
print(f"接受率:          {acceptance_rate:.4f}")
print(f"实验得到的最终分布: {np.round(empirical_dist, 4)}")

max_diff_from_p = np.max(np.abs(empirical_dist - p))
max_diff_from_q = np.max(np.abs(empirical_dist - q))
print(f"\n最终分布与 p 的最大差异: {max_diff_from_p:.4f}  (应该很小)")
print(f"最终分布与 q 的最大差异: {max_diff_from_q:.4f}  (通常明显更大)")
print(f"结论：最终分布更接近目标模型 p: {max_diff_from_p < max_diff_from_q}")
```

实测输出（numpy 2.4.4）：

```
目标分布 p:      [0.1513 0.1028 0.3275 0.1467 0.0561 0.2156]
草稿分布 q:      [0.4353 0.2069 0.1265 0.0323 0.0235 0.1754]
接受率:          0.6108
实验得到的最终分布: [0.1503 0.1036 0.3291 0.147  0.0561 0.2139]

最终分布与 p 的最大差异: 0.0017  (应该很小)
最终分布与 q 的最大差异: 0.2850  (通常明显更大)
结论：最终分布更接近目标模型 p: True
```

结果验证了第 2 节的数学推导：即使草稿分布 `q` 与目标分布 `p` 差异明显（最大差异约 0.285），经过接受/拒绝采样处理后，20 万次采样得到的实验分布与真实目标分布 `p` 的最大差异仅 0.0017（采样误差范围内），远小于与 `q` 的差异——证明投机解码的验证机制确实严格保持输出分布等于目标模型分布，草稿模型的选择不会"污染"结果，只影响接受率（这里约 61%）从而影响加速效果。

## 9. 小结

| 主题 | 核心结论 |
| --- | --- |
| 带宽瓶颈本质 | Decode 阶段计算量小但要搬运全部权重和 KV Cache，瓶颈是显存带宽而非算力 |
| 投机解码思路 | 草稿模型快速生成候选，目标模型一次前向并行验证，把搬运成本分摊到多个产出 |
| 接受/拒绝采样 | `accept_prob = min(1, p/q)`，拒绝后从残差分布重采样，数学上严格保证输出分布等于 `p` |
| 接受率权衡 | 草稿模型越接近目标模型接受率越高，但生成候选的开销也越高 |
| Medusa/多头预测 | 不用独立草稿模型，在主干上加轻量预测头，部署更简单但多步预测准确度下降更快 |
| Flash Attention | IO 感知的分块计算 + 反向重计算，用多算一次换掉大量显存读写 |
| 连续批处理调度 | 投机解码下每轮产出 token 数不固定，调度器需适配这种不确定性 |
| 推理引擎评估 | 从 KV Cache 管理、批处理、量化、并行策略、投机解码、attention 实现等维度综合考察 |
