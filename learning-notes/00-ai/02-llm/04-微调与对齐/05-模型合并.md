# 模型合并

> Author: Walter Wang

> **读完你能回答的 3 个问题**
>
> 1. 为什么两个独立微调的模型可以直接在参数空间做加减，这个操作的前提假设是什么？
> 2. TIES 和 DARE 各自解决了朴素权重平均的什么问题，处理手段有何不同？
> 3. 什么情况下模型合并会失败，如何在合并前判断可行性？

## 1. 问题：多个能力如何叠加到一个模型上

假设你在同一个基座模型上分别微调出了三个专用模型：一个擅长代码、一个擅长中文写作、一个擅长数学。现在想要一个同时具备这三种能力的模型。

传统做法有两条：

**做法一：混合数据重新微调。** 把三份数据混在一起再训一遍。问题是要重新付一次训练成本，而且三份数据的配比需要反复调（配比问题参见 [三阶段范式与数据构造](01-三阶段范式与数据构造.md) 第 2 节），调错了会互相干扰。

**做法二：部署三个模型 + 路由。** 推理时按任务类型分发。问题是显存占用三倍，且路由本身会出错。

**模型合并（Model Merging）是第三条路**：直接在参数空间把三个模型的权重融合成一个，不需要任何训练，不需要原始数据，几分钟就能完成。

这听起来不合理——神经网络的参数不是可以随便加减的数值，为什么能这么干？

## 2. 前提：线性模式连通性

模型合并能工作，依赖一个经验发现：**从同一个预训练检查点出发、用不同数据微调得到的模型，在参数空间中往往位于同一个"损失盆地"（loss basin）内**。

这个现象叫**线性模式连通性（Linear Mode Connectivity, LMC）**：如果两个模型 $\theta_A$ 和 $\theta_B$ 满足 LMC，那么它们之间的线性插值路径上的所有点

$$\theta(\alpha) = (1-\alpha)\theta_A + \alpha\theta_B, \quad \alpha \in [0, 1]$$

损失都不会显著升高。换句话说，从 A 走到 B 的直线路径上没有"损失屏障"。

```
损失景观示意（一维简化）

损失
 │      ╱▔▔╲              ╱▔▔╲
 │     ╱     ╲            ╱     ╲
 │    ╱  屏障  ╲          ╱       ╲
 │───╱──────────╲────────╱─────────╲───
 │  A            B      A'    B'
 │  └─不同盆地─┘        └─同一盆地─┘
 │   插值会崩            插值安全
 └────────────────────────────────► 参数空间

从随机初始化独立训练的两个模型 → 不同盆地，插值失败
从同一预训练权重微调的两个模型   → 同一盆地，插值可行
```

**这是模型合并最关键的前提条件**：所有待合并的模型必须来自同一个预训练基座。两个从头训练的模型、或者基座不同（比如一个从 Llama、一个从 Qwen）的模型，参数空间没有对应关系，合并只会得到噪声。

## 3. 方法一：朴素权重平均

最简单的合并方式是直接对参数取平均：

$$\theta_{\text{merged}} = \frac{1}{N}\sum_{i=1}^{N}\theta_i$$

这个方法在 Model Soup 系列工作里被验证有效——对同一任务的多个不同超参微调结果做平均，往往比其中任何单个模型都好，效果类似集成学习但不增加推理成本（集成学习原理参见 [集成学习](../../01-machine-learning/02-经典算法/03-集成学习.md)）。

**但用于合并不同任务的模型时，朴素平均有明显问题**：每个模型的关键参数会被其他模型的参数"稀释"。如果模型 A 在某个参数上学到了 +0.5 的重要调整，而模型 B、C 在这个参数上没有变化（值为 0），平均后变成 +0.17，能力被削弱到三分之一。

## 4. 方法二：Task Arithmetic（任务向量算术）

核心思路是把"微调学到的东西"从"基座本身"里分离出来。定义**任务向量（task vector）**：

$$\tau_i = \theta_i - \theta_{\text{base}}$$

$\tau_i$ 代表"为了掌握任务 i，参数需要往哪个方向移动多少"。有了任务向量，可以做加减法：

```
能力叠加：  θ_new = θ_base + λ(τ_code + τ_math + τ_chinese)
能力移除：  θ_new = θ_base - λ·τ_toxic        （遗忘不良行为）
能力迁移：  θ_new = θ_base + λ(τ_A - τ_B + τ_C)  （类比推理）
```

$\lambda$ 是缩放系数，通常取 0.3~1.0。$\lambda$ 太大会让模型偏离基座太远导致语言能力退化，太小则合并效果不明显。

**"能力移除"这个用法特别实用**：如果有一个在有害数据上微调过的模型，用它的任务向量做减法可以降低基座模型的有害输出倾向，而不需要重新做对齐训练（对齐方法参见 [RLHF全链路](03-RLHF全链路.md)）。

## 5. 方法三：TIES-Merging（解决符号冲突）

Task Arithmetic 的问题在于**参数干扰**，具体分两类：

**冗余干扰**：任务向量里大部分参数的变化量都很小（接近 0），这些微小变化累加起来会引入噪声，但对能力没贡献。

**符号冲突**：同一个参数位置上，模型 A 想要 +0.5，模型 B 想要 -0.4。直接相加得到 +0.1，两个模型的意图都没实现。

TIES（**T**rim, **E**lect sign, **M**erge）分三步处理：

```
Step 1 — Trim（修剪）
  每个任务向量只保留幅值最大的 top-k%（通常 k=20），其余置零
  作用：去掉冗余干扰

Step 2 — Elect Sign（选举符号）
  对每个参数位置，统计所有任务向量在该位置的正负幅值总和
  哪一方总幅值大，就采纳该方向的符号
  作用：解决符号冲突

Step 3 — Disjoint Merge（不相交合并）
  只对符号与选举结果一致的值取平均（符号相反的直接丢弃）
  作用：避免反向值拉低幅度
```

举例说明第 2、3 步：某参数位置上三个任务向量的值是 `[+0.5, -0.4, +0.3]`。

- 正方向总幅值 = 0.5 + 0.3 = 0.8，负方向 = 0.4 → 选举结果为正
- 只平均正值：(0.5 + 0.3) / 2 = 0.4
- 对比 Task Arithmetic 的结果：(0.5 - 0.4 + 0.3) / 3 = 0.13

TIES 保留了 0.4 的有效幅度，而朴素相加只剩 0.13。

## 6. 方法四：DARE（随机丢弃 + 重缩放）

DARE（**D**rop **A**nd **RE**scale）基于一个反直觉的观察：**微调产生的参数变化极度冗余，随机丢掉 90% 甚至 99% 都不影响能力**。

做法两步：

$$\tilde{\tau} = \frac{\text{Bernoulli}(1-p) \odot \tau}{1-p}$$

1. **Drop**：以概率 $p$ 随机把任务向量的元素置零
2. **Rescale**：剩下的元素除以 $(1-p)$，保持期望值不变

重缩放这一步是关键——不做的话任务向量整体幅值会缩小到 $(1-p)$ 倍，能力明显下降。

DARE 通常作为**预处理步骤**和其他方法组合使用，比如 `DARE + TIES`：先用 DARE 稀疏化每个任务向量，再用 TIES 做符号选举合并。这个组合是目前实践中效果最稳的方案之一。

**注意 DARE 的适用边界**：它假设任务向量足够稀疏和冗余，这在 SFT 后的模型上成立（微调只改动了一小部分参数），但如果模型经过了大量继续预训练（参数变化幅度大且密集），DARE 的高丢弃率会损失真实信息。

## 7. 方法五：SLERP（球面线性插值）

前面几种方法都是在做线性插值。SLERP 的观察是：**高维空间中的权重向量，其"方向"比"数值"更重要**，线性插值会改变向量的范数。

SLERP 沿着两个向量所在的球面弧线插值：

$$\theta(t) = \frac{\sin((1-t)\Omega)}{\sin\Omega}\theta_A + \frac{\sin(t\Omega)}{\sin\Omega}\theta_B$$

其中 $\Omega = \arccos\left(\frac{\theta_A \cdot \theta_B}{\|\theta_A\|\|\theta_B\|}\right)$ 是两向量夹角。

SLERP 的限制是**只能合并两个模型**（球面弧线由两点确定）。合并多个模型时需要两两递归合并，顺序会影响结果。

## 8. 最小可运行实现：四种方法对比

用 NumPy 模拟两个任务向量的合并，观察各方法在符号冲突场景下的行为差异：

```python
import numpy as np

np.random.seed(42)

D = 10  # 参数维度（简化演示）
base = np.zeros(D)

# 构造两个任务向量：前 3 维符号冲突，中间 3 维一致，后 4 维冗余（接近 0）
tau_a = np.array([ 0.8,  0.6,  0.5,  0.4,  0.3,  0.5, 0.01, -0.02, 0.01, 0.00])
tau_b = np.array([-0.7, -0.5,  0.4,  0.5,  0.4,  0.3, -0.01, 0.02, 0.00, 0.01])


def task_arithmetic(taus, lam=1.0):
    """任务向量直接相加"""
    return lam * np.sum(taus, axis=0)


def ties_merge(taus, k=0.5):
    """TIES: Trim -> Elect Sign -> Disjoint Merge"""
    taus = np.array(taus)

    # Step 1: Trim — 每个任务向量保留幅值 top-k
    trimmed = np.zeros_like(taus)
    n_keep = max(1, int(taus.shape[1] * k))
    for i, t in enumerate(taus):
        idx = np.argsort(np.abs(t))[-n_keep:]   # 幅值最大的 n_keep 个
        trimmed[i, idx] = t[idx]

    # Step 2: Elect Sign — 按正负总幅值投票决定每个位置的符号
    pos_mass = np.sum(np.where(trimmed > 0, trimmed, 0), axis=0)
    neg_mass = np.sum(np.where(trimmed < 0, -trimmed, 0), axis=0)
    elected_sign = np.where(pos_mass >= neg_mass, 1.0, -1.0)

    # Step 3: Disjoint Merge — 只平均符号与选举结果一致的值
    merged = np.zeros(taus.shape[1])
    for j in range(taus.shape[1]):
        col = trimmed[:, j]
        agree = col[np.sign(col) == elected_sign[j]]
        agree = agree[agree != 0]
        merged[j] = agree.mean() if len(agree) > 0 else 0.0
    return merged


def dare(tau, p=0.7, rng=None):
    """DARE: 随机丢弃 p 比例后重缩放，保持期望不变"""
    rng = rng or np.random.default_rng(0)
    mask = rng.random(tau.shape) > p          # 保留概率 (1-p)
    return (tau * mask) / (1 - p)


def slerp(a, b, t=0.5, eps=1e-8):
    """球面线性插值（仅支持两个向量）"""
    na, nb = np.linalg.norm(a), np.linalg.norm(b)
    if na < eps or nb < eps:
        return (1 - t) * a + t * b
    cos_omega = np.clip(np.dot(a, b) / (na * nb), -1.0, 1.0)
    omega = np.arccos(cos_omega)
    if abs(np.sin(omega)) < eps:             # 接近共线时退化为线性插值
        return (1 - t) * a + t * b
    return (np.sin((1 - t) * omega) / np.sin(omega)) * a + \
           (np.sin(t * omega) / np.sin(omega)) * b


taus = [tau_a, tau_b]
rng = np.random.default_rng(7)

results = {
    "朴素平均":        np.mean(taus, axis=0),
    "TaskArithmetic": task_arithmetic(taus, lam=0.5),
    "TIES":           ties_merge(taus, k=0.6),
    "DARE+TIES":      ties_merge([dare(t, p=0.5, rng=rng) for t in taus], k=0.6),
    "SLERP":          slerp(tau_a, tau_b, t=0.5),
}

np.set_printoptions(precision=3, suppress=True)
print("原始任务向量")
print(f"  tau_a = {tau_a}")
print(f"  tau_b = {tau_b}")
print("\n前 3 维为符号冲突区，第 4~6 维为方向一致区，后 4 维为冗余区\n")

for name, merged in results.items():
    conflict_mag = np.abs(merged[:3]).mean()      # 冲突区保留的幅度
    agree_mag = np.abs(merged[3:6]).mean()        # 一致区保留的幅度
    noise_mag = np.abs(merged[6:]).mean()         # 冗余区残留的噪声
    print(f"{name:16s} 冲突区均幅={conflict_mag:.3f}  "
          f"一致区均幅={agree_mag:.3f}  冗余噪声={noise_mag:.4f}")
    print(f"{'':16s} {merged}")
```

运行结果：

```
朴素平均          冲突区=0.183  一致区=0.400  噪声=0.0025
                 [0.05  0.05  0.45  0.45  0.35  0.4   0.    0.    0.005 0.005]
TaskArithmetic   冲突区=0.183  一致区=0.400  噪声=0.0025
                 [0.05  0.05  0.45  0.45  0.35  0.4   0.    0.    0.005 0.005]
TIES             冲突区=0.617  一致区=0.400  噪声=0.0000
                 [0.8   0.6   0.45  0.45  0.35  0.4   0.    0.    0.    0.   ]
DARE+TIES        冲突区=1.267  一致区=0.533  噪声=0.0250
                 [ 1.6   1.2   1.    0.    0.8   0.8  -0.02  0.04  0.02  0.02]
SLERP            冲突区=0.277  一致区=0.604  噪声=0.0038
                 [0.075 0.075 0.679 0.679 0.528 0.604 0.    0.    0.008 0.008]
```

四个可以直接读出的结论：

1. **符号冲突区是核心差异点**：朴素平均把 `+0.8` 和 `-0.7` 抵消成 `0.05`，两个模型的意图互相摧毁；TIES 通过符号选举保留了 `0.8` 和 `0.6` 的完整幅度（因为该位置只有 A 的符号被选中，B 的负值被丢弃）

2. **冗余区**：TIES 的 Trim 步骤把接近 0 的噪声完全清零（噪声=0.0000），朴素方法残留 `0.0025`

3. **方向一致区所有方法表现接近**：0.40~0.60 之间。这说明**合并方法的价值只在冲突场景体现**，如果你的多个模型任务正交、参数改动不重叠，朴素平均就够了

4. **DARE 的幅值会放大，这不等于效果更好**：DARE+TIES 的冲突区达到 `1.267`，是因为 rescale 步骤把保留下来的值除以了 $(1-p)=0.5$，幅值翻倍。在这个 10 维玩具例子里，随机丢弃 50% 后剩下的样本太少，重缩放放大了个别值也放大了噪声（噪声从 0 涨到 0.025），还把第 4 维完全丢成了 0。**DARE 依赖高维度下的大数定律**——真实模型有上亿参数时，随机丢弃的统计性质才成立。小维度上用 DARE 会得到高方差的结果，这正是它不适合小模型或稀疏任务向量的原因。

> 注：本例中「朴素平均」和「TaskArithmetic(λ=0.5)」结果完全相同，是因为只有 2 个模型时 $\frac{1}{2}\sum\tau_i$ 恰好等于 $0.5\sum\tau_i$。3 个以上模型时两者会分开。

## 9. 什么情况下合并会失败

模型合并不是万能的，以下情况需要警惕：

| 失败场景 | 原因 | 判断方法 |
| --- | --- | --- |
| **基座不同** | 参数空间无对应关系 | 检查 config 的 `_name_or_path` 是否同源 |
| **词表不一致** | Embedding 层维度不匹配 | 对比 `vocab_size` 和 tokenizer 哈希 |
| **架构改动** | 层数/隐藏维度/注意力头数不同 | 对比 config 的架构字段 |
| **微调幅度过大** | 已跑出原始损失盆地，LMC 不成立 | 计算 $\|\theta_i - \theta_{\text{base}}\|/\|\theta_{\text{base}}\|$，超过 0.1 需谨慎 |
| **任务严重对立** | 一个模型学"要拒答"、另一个学"要回答" | 只能靠评测发现，无法事前判断 |
| **RLHF 后模型** | 对齐训练改动密集，DARE 高丢弃率会损失信息 | 降低 drop rate 或改用 TIES |

**必须做的验证**：合并后一定要跑评测集，不能假设"合并了就有能力"。实践中常见的失败模式是合并后每个单项能力都下降 10~20%，得到一个"什么都会一点但都不精"的模型——这时候不如部署多个模型加路由（路由方案参见 [模型路由与网关](../../04-ai-agent/12-模型服务/03-模型路由与网关.md)）。评测集构建方法参见 [Agent评估与基准](../../04-ai-agent/14-可观测与评估/03-Agent评估与基准.md)。

## 10. 工程实践建议

**工具选择**：生产环境用 [mergekit](https://github.com/arcee-ai/mergekit)，它实现了上述全部方法且支持不加载全部权重到显存的分片合并。一个典型配置：

```yaml
merge_method: dare_ties
base_model: Qwen/Qwen2.5-7B
models:
  - model: ./qwen-code-sft
    parameters: { weight: 0.5, density: 0.5 }
  - model: ./qwen-math-sft
    parameters: { weight: 0.3, density: 0.5 }
  - model: ./qwen-chinese-sft
    parameters: { weight: 0.4, density: 0.5 }
parameters:
  int8_mask: true
dtype: bfloat16
```

`density` 对应 DARE 的保留比例，`weight` 对应任务向量的缩放系数。

**调参顺序**：先固定 `density=0.5` 调 `weight`（这个影响最大），再微调 `density`。合并只需几分钟，可以网格搜索。

**LoRA 场景更简单**：如果三个能力都是 LoRA 适配器，直接合并 LoRA 权重比合并全量模型更稳（LoRA 的低秩结构天然稀疏，参数干扰小）。具体做法参见 [PEFT参数高效微调](02-PEFT参数高效微调.md) 第 7 节的多 LoRA 结合。

## 11. 小结

| 方法 | 核心思路 | 适用场景 | 主要限制 |
| --- | --- | --- | --- |
| 朴素平均 | 参数直接取平均 | 同任务多超参结果（Model Soup） | 不同任务会互相稀释 |
| Task Arithmetic | 任务向量加减 | 能力叠加、能力移除 | 符号冲突无法处理 |
| TIES | 修剪 + 符号选举 + 不相交平均 | 多任务合并的默认选择 | 需调 top-k 比例 |
| DARE | 随机丢弃 + 重缩放 | 作为预处理与 TIES 组合 | 密集变化的模型不适用 |
| SLERP | 球面插值保持范数 | 精细合并两个模型 | 只支持两个模型 |

一句话决策：**同任务多结果用朴素平均，多任务合并用 DARE+TIES，只有两个模型且追求质量用 SLERP。所有情况下合并前先确认基座同源，合并后必须跑评测。**
