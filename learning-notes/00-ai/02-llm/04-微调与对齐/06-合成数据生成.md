# 合成数据生成

> Author: Walter Wang

> **读完你能回答的 3 个问题**
>
> 1. 用模型生成的数据训练模型，为什么不是纯粹的"左脚踩右脚"，什么条件下它真的有效？
> 2. Self-Instruct 和 Evol-Instruct 的核心差别在哪，各自适合什么场景？
> 3. 模型崩溃（model collapse）是怎么发生的，工程上如何避免？

## 1. 问题：人工标注数据的成本墙

微调需要高质量指令数据。人工写一条高质量的指令-回答对，成本大致是：

```
简单问答         5~15 元/条
带推理过程       30~80 元/条
专业领域（医法金） 100~500 元/条
多轮复杂对话     50~200 元/条
```

一个像样的 SFT 数据集需要 5 万~50 万条。按最便宜的算，5 万条 × 10 元 = 50 万元，且需要几个月和一支标注团队。这个成本对多数团队是不可承受的。

**合成数据的思路**：用强模型生成训练数据，去训练目标模型。这在 2023 年之后成为事实上的主流做法——Alpaca、WizardLM、Orca、Phi 系列全部依赖合成数据。

但这里有个显而易见的质疑：**模型生成的数据能包含模型自己不知道的信息吗？如果不能，用它训练不就是在原地打转？**

## 2. 为什么合成数据能工作

合成数据有效不是因为凭空创造了知识，而是三个机制在起作用：

**机制一：能力蒸馏（跨模型）**

用 GPT-5 / Claude 生成数据训练 7B 小模型，本质是知识蒸馏——把大模型的能力压缩到小模型里。这里信息是从高到低流动的，不存在自我循环问题。这是最常见也最有效的用法（蒸馏原理参见 [蒸馏与剪枝](../05-推理优化/03-蒸馏与剪枝.md)）。

**机制二：格式转换（同模型也有效）**

模型"知道"某个知识（预训练时见过）但"不会按指令格式输出"。合成数据把预训练里的隐式知识转换成显式的指令-回答格式，这是格式对齐而非知识注入。所以即使用同一个模型生成数据训练自己，在指令遵循能力上也能提升。

**机制三：可验证信号放大（最可靠）**

对于有客观验证手段的任务，可以生成大量候选、只保留验证通过的：

```
数学题   → 生成 100 条解法 → 用答案对比筛选 → 保留正确的 20 条
代码题   → 生成 100 个实现 → 跑单元测试 → 保留通过的 15 个
SQL      → 生成 100 条查询 → 在数据库执行对比结果 → 保留正确的
```

这里的关键是**验证器比生成器更可靠**。模型可能不会一次写对，但它有一定概率写对，而验证器能 100% 识别哪次对了。反复采样 + 筛选，等价于把模型的"偶尔能对"变成"稳定的正确样本"。这是 STaR / RFT（Rejection Sampling Fine-tuning）系列方法的原理，也是目前最不容易出问题的合成路径。

**三者的可靠性排序**：可验证信号放大 > 跨模型蒸馏 > 同模型格式转换。

## 3. 方法一：Self-Instruct（从种子扩散）

Self-Instruct 是最早的系统化方案，Alpaca 用它从 175 条人工种子扩展出 52K 数据。

流程四步：

```
Step 1 — 种子池初始化
  人工写 175 条高质量指令（覆盖不同任务类型）

Step 2 — 指令生成
  从种子池随机抽 6 条人工指令 + 2 条已生成指令作为 few-shot 示例
  让模型续写第 9 条新指令

Step 3 — 过滤
  ├─ ROUGE-L 相似度 > 0.7 的与已有指令重复 → 丢弃
  ├─ 含图片/音频等模型无法处理的内容 → 丢弃
  └─ 指令过长过短、含特定关键词 → 丢弃

Step 4 — 生成回答
  对通过过滤的指令，让模型生成回答
  分类任务用「先输出类别再补输入」的反向生成，避免类别不平衡

  → 通过的指令加回种子池，回到 Step 2 循环
```

**混合 few-shot 示例是关键设计**：只用人工种子会导致多样性不足（生成的都像那 175 条），只用生成结果会导致质量漂移（逐轮退化）。6:2 的配比是在多样性和质量之间取平衡。

**Self-Instruct 的局限**：生成的指令普遍偏简单。因为 few-shot 示例的难度就是天花板，模型倾向生成和示例难度相近的内容，不会主动"加难度"。

## 4. 方法二：Evol-Instruct（定向进化）

WizardLM 提出的方案，直接针对 Self-Instruct 的"难度不足"问题：**不生成新指令，而是把已有指令改写得更难**。

两类进化算子：

**深度进化（In-depth Evolving）** — 让同一个问题变难：

| 算子 | 做法 | 示例 |
| --- | --- | --- |
| 增加约束 | 添加限制条件 | "写个排序函数" → "写个排序函数，要求原地排序且不用额外空间" |
| 深化 | 要求更具体 | "解释 HTTP" → "解释 HTTP/2 的多路复用如何解决队头阻塞" |
| 具体化 | 泛化概念替换为具体实例 | "处理异常" → "处理 PostgreSQL 连接池耗尽的异常" |
| 增加推理步骤 | 要求多步推导 | "算面积" → "先求出交点坐标，再算围成的面积" |
| 复杂化输入 | 输入数据变复杂 | 简单列表 → 嵌套结构含缺失值 |

**广度进化（In-breadth Evolving）** — 让话题变宽：基于现有指令生成同领域但不同角度的全新指令，用于覆盖长尾场景。

**淘汰机制（Elimination Evolving）**：进化后的指令需要检查四类失败，失败则回退：

```
1. 进化后信息量没增加（模型只是换了说法）
2. 进化后模型自己都答不了（超出能力边界，会产生错误标签）
3. 回答只有标点或极短（进化失败的信号）
4. 回答明显是在复制指令里的词句
```

**实际用法**：Self-Instruct 和 Evol-Instruct 通常组合使用——先用 Self-Instruct 铺量和覆盖面，再用 Evol-Instruct 把其中一部分升维成难题。难度分布应该是金字塔形，不能全是难题（全难题会导致模型在简单问题上过度思考）。

## 5. 方法三：拒绝采样（可验证任务的首选）

对有客观验证器的任务，这是最可靠的方法：

```
对每个问题 q：
  1. 用较高 temperature 采样 k 个回答（k 通常 4~64）
  2. 用验证器判断每个回答的正确性
  3. 从正确的回答里选 1~n 条加入训练集
     ├─ 选最短的（简洁性偏好）
     ├─ 选 log-prob 最高的（模型最"自信"的）
     └─ 或全部保留（数据增强）
  4. 如果 k 个全错 → 这道题超出当前能力，丢弃或降难度
```

**为什么这个方法可靠**：训练数据的正确性由验证器保证，不依赖生成模型的可靠性。模型只需要有非零的正确率，采样次数就能把正确样本挖出来。

**迭代式拒绝采样（STaR 思路）**：用第 1 轮筛出的数据微调，得到能力更强的模型；用新模型对之前"k 个全错"的难题重新采样，此时部分难题能做对了；把新增的正确样本加入数据集，再训一轮。这个循环能逐步攻克越来越难的题目。

**关键约束**：必须有可靠验证器。数学题需要标准答案，代码需要测试用例，SQL 需要可执行数据库。没有验证器的开放式任务（如写作、闲聊）用不了这个方法。

## 6. 方法四：LLM-as-Judge 筛选

对没有客观验证器的任务，退而用另一个模型当裁判打分筛选。

```
生成阶段：模型 A 生成 n 条候选回答
评分阶段：模型 B（裁判）按 rubric 给每条打分
筛选阶段：保留 top-k 或分数 > 阈值的
```

**必须注意的偏差**：

| 偏差类型 | 表现 | 缓解 |
| --- | --- | --- |
| 位置偏差 | 偏向排在前面的选项 | 交换顺序各评一次取平均 |
| 长度偏差 | 偏向更长的回答 | rubric 里显式说明简洁性也是加分项 |
| 自我偏好 | 裁判偏向自己生成的风格 | 裁判用与生成模型不同的模型 |
| 谄媚 | 对自信的错误答案给高分 | rubric 要求先验证事实再打分 |

**rubric 设计要点**：不要只给"1-10 分请打分"这种模糊指令，要拆成维度 + 权重 + 每档的具体描述。这套方法论和评测集构建是一回事，详见 [Agent评估与基准](../../04-ai-agent/14-可观测与评估/03-Agent评估与基准.md)。

## 7. 模型崩溃：合成数据最大的风险

**模型崩溃（Model Collapse）** 指反复用合成数据训练导致分布逐代退化。机制分两层：

**早期崩溃**：分布的尾部先消失。低频事件（罕见词、少见句式、边缘案例）在采样中出现概率低，第一代合成数据里就缺失了，训出的模型更不会生成它们，第二代进一步缺失。

**晚期崩溃**：分布收窄到均值附近，多样性大幅下降，模型开始输出高度模板化的内容。

```
分布演化示意

原始人类数据    ▁▂▄▆█▆▄▂▁    （有厚尾）
第 1 代合成      ▁▃▆█▆▃▁      （尾部变薄）
第 2 代合成       ▄█▄         （尾部消失）
第 3 代合成        █          （collapse，方差趋于 0）
```

**工程上的四条防线**：

1. **保底真实数据比例**：训练集中真实数据不低于 20~30%。研究表明只要保留一定比例的真实数据，崩溃可以被显著延缓而非只是减速
2. **不做多代自循环**：合成数据只从更强的模型来，不要"用自己生成的数据训自己再生成再训"迭代多轮（拒绝采样例外，因为有验证器把关）
3. **监控多样性指标**：跟踪生成数据的 distinct-n、self-BLEU、embedding 空间的平均距离，发现收窄立即停
4. **保持种子多样性**：种子池要覆盖足够多的任务类型和难度，种子的多样性决定了合成数据的多样性上限

## 8. 最小可运行实现：模拟崩溃与真实数据保底的效果

用高斯分布模拟"迭代式合成训练"。关键设计是**用最大似然估计（MLE）拟合分布参数**——这对应真实训练的行为，而 MLE 对方差是有偏的（系统性低估），这正是崩溃的数学根源：

```python
import numpy as np

TRUE_MU, TRUE_SIGMA = 0.0, 1.0
N_SAMPLES = 25      # 每代采样数：越小，崩溃越快（有限采样是根源）
N_GENERATIONS = 30


def run_loop(real_ratio, seed):
    """real_ratio: 每代混入真实数据的比例"""
    rng = np.random.default_rng(seed)
    data = rng.normal(TRUE_MU, TRUE_SIGMA, N_SAMPLES)
    sigmas = [data.std(ddof=0)]

    for _ in range(N_GENERATIONS):
        # 训练：用 MLE（ddof=0）估计参数
        # 这一步是关键 —— MLE 对方差是有偏估计，期望值为 (n-1)/n · σ²，系统性偏小
        mu, sigma = data.mean(), data.std(ddof=0)

        n_real = int(round(N_SAMPLES * real_ratio))
        n_syn = N_SAMPLES - n_real

        synth = rng.normal(mu, sigma, n_syn)              # 上一代模型生成
        if n_real > 0:
            real = rng.normal(TRUE_MU, TRUE_SIGMA, n_real)  # 补充真实数据
            data = np.concatenate([synth, real])
        else:
            data = synth
        sigmas.append(data.std(ddof=0))

    return sigmas


RATIOS = [0.0, 0.1, 0.3]
N_TRIALS = 200   # 多次实验取平均，消除单次随机性

avg = {}
for r in RATIOS:
    runs = np.array([run_loop(r, s) for s in range(N_TRIALS)])
    avg[r] = runs.mean(axis=0)

print(f"真实 sigma={TRUE_SIGMA}，每代采样 {N_SAMPLES} 条，{N_TRIALS} 次实验取平均\n")
print(f"{'代数':<6}" + "".join(f"{'真实'+str(int(r*100))+'%':>12}" for r in RATIOS))
for gen in [0, 5, 10, 15, 20, 25, 30]:
    print(f"{gen:<6}" + "".join(f"{avg[r][gen]:>12.4f}" for r in RATIOS))

print("\n第 30 代 sigma 保留率：")
for r in RATIOS:
    ratio = avg[r][-1] / TRUE_SIGMA
    print(f"  真实数据 {int(r*100):>2}%  →  {ratio:6.1%}  {'█' * int(ratio * 40)}")
```

运行结果：

```
真实 sigma=1.0，每代采样 25 条，200 次实验取平均

代数            真实0%       真实10%       真实30%
0           0.9538      0.9538      0.9538
5           0.7983      0.8545      0.9289
10          0.7015      0.8569      0.9458
15          0.5901      0.8339      0.9411
20          0.4928      0.8150      0.9341
25          0.4173      0.8261      0.9432
30          0.3540      0.8326      0.9508

第 30 代 sigma 保留率：
  真实数据  0%  →   35.4%  ██████████████
  真实数据 10%  →   83.3%  █████████████████████████████████
  真实数据 30%  →   95.1%  ██████████████████████████████████████
```

三个可以直接读出的结论：

1. **纯合成循环单调衰减**：sigma 从 0.95 一路降到 0.35，30 代后分布方差只剩三分之一。这不是随机波动——200 次实验取平均后趋势依然单调，说明是系统性偏差在累积

2. **只需 10% 真实数据就能大幅缓解**：从 35.4% 提升到 83.3%，且曲线在第 10 代后趋于平稳而非继续下滑。少量真实数据起到了"锚定"作用

3. **30% 真实数据基本止住崩溃**：稳定在 95% 左右，与真实分布几乎无差异

**衰减速率可以算出来**：MLE 方差估计的期望是 $\frac{n-1}{n}\sigma^2$，所以每代 sigma 大约乘以 $\sqrt{\frac{n-1}{n}}$。$n=25$ 时 30 代后约为 $\left(\frac{24}{25}\right)^{15} \approx 0.54$ 的量级——采样量 $n$ 越大衰减越慢，这也解释了为什么大规模数据集的崩溃不那么明显，但方向不会改变。

这个玩具模型只展示了方差收窄一个维度，真实的模型崩溃还包括语义多样性丧失、罕见知识遗忘等更复杂的现象，但机制是同源的：**有限采样必然丢失尾部，丢失会逐代累积**。

## 9. 数据质量把关流程

生成出来的数据不能直接用，标准流程：

```
生成
  ↓
① 格式校验         JSON 可解析 / 字段完整 / 长度合理
  ↓
② 精确去重         MinHash / SimHash 去掉近似重复
  ↓
③ 语义去重         Embedding 聚类，同簇只保留代表样本
  ↓
④ 质量过滤         LLM-as-Judge 打分 或 规则过滤（拒答/复述指令/明显错误）
  ↓
⑤ 污染检查         与评测集比对，去掉泄露样本
  ↓
⑥ 难度/类型配比     按目标分布重采样，避免某类占比过高
  ↓
⑦ 人工抽检         随机抽 1~3% 人工核验，估计整体错误率
  ↓
入库
```

**第 5 步污染检查绝对不能省**。合成数据的种子如果来自公开数据集，很可能与 MMLU / GSM8K 等评测集重叠，导致评测分数虚高。去污染方法参见 [三阶段范式与数据构造](01-三阶段范式与数据构造.md) 第 3 节。

**第 7 步人工抽检是唯一能发现系统性错误的环节**。曾经出现过的真实案例：合成的代码数据里 30% 用了某个已废弃的 API，因为生成模型的知识截止日期早于 API 变更——这类错误自动化流程完全发现不了。

## 10. 成本与收益的实际估算

以生成 5 万条 SFT 数据为例（用 DeepSeek 或通义这类国产模型做生成器，价格按 2026 年水平估）：

| 环节 | 用量估算 | 成本量级 |
| --- | --- | --- |
| 指令生成 | 5 万次调用 × 约 500 token | 几十元 |
| 回答生成 | 5 万次 × 约 1500 token | 一两百元 |
| 拒绝采样（k=8） | 上一项 × 8 | 一两千元 |
| LLM-as-Judge 筛选 | 5 万次 × 约 800 token | 一两百元 |
| 人工抽检 1% | 500 条 × 人工成本 | 几千元 |

即使算上拒绝采样和人工抽检，总成本在**几千元量级**，相比人工标注的 50 万元是两个数量级的差距。这是合成数据成为主流的根本原因。

**但要清楚它买不到什么**：合成数据买不到生成模型不具备的知识。垂直领域（内部业务规则、专有工艺、企业私有流程）的数据，通用模型生成的内容大概率是编的。这些领域仍然需要真实数据或领域专家参与，合成只能用来做格式包装和数量扩充。

## 11. 小结

| 方法 | 是否需要验证器 | 主要作用 | 可靠性 |
| --- | --- | --- | --- |
| 跨模型蒸馏 | 否 | 把强模型能力压到小模型 | 高（信息从高到低） |
| Self-Instruct | 否 | 铺量、扩覆盖面 | 中（难度受限于种子） |
| Evol-Instruct | 否 | 提升难度和复杂度 | 中（需淘汰机制把关） |
| 拒绝采样 | **是** | 生成可验证任务的正确样本 | **最高** |
| LLM-as-Judge 筛选 | 否 | 开放任务的质量把关 | 中（有多种偏差） |

一句话决策：**有验证器就用拒绝采样，没有就用更强的模型做蒸馏；Self-Instruct 铺量、Evol-Instruct 加难度；任何情况下保留 20~30% 真实数据，不做多代自循环。**
