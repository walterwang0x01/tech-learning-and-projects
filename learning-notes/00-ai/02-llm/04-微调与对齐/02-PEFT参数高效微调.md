# PEFT参数高效微调

> Author: Walter Wang

> **读完你能回答的 3 个问题**
>
> 1. 全参微调为什么显存开销远大于模型参数量本身，多花的显存去哪了？
> 2. LoRA 的低秩假设具体假设了什么，rank 增大会带来什么影响？
> 3. QLoRA 里的量化和 LoRA 是怎么配合工作的，谁负责省显存、谁负责保留可训练性？

## 1. 为什么全参微调显存开销这么大

微调一个大模型时，显存占用远不止"存一份模型参数"这么简单。用主流的 Adam 系优化器做全参微调，每个可训练参数在训练过程中实际对应四份存储：

```
参数本身                        1x
梯度 (gradient)                  1x
优化器一阶矩 (momentum)           1x
优化器二阶矩 (variance)           1x
                              ────
                               约 4x 参数量的显存（不含激活值）
```

Adam 优化器需要为每个参数维护一阶矩和二阶矩估计（分别近似梯度的均值和方差）用于自适应调整学习率，这两份状态和梯度、参数本身一样大。混合精度训练还需额外保留一份全精度（fp32）参数副本用于数值稳定的更新，进一步增加显存。再加上训练时需要缓存前向传播的中间激活值（用于反向传播，参见 [反向传播推导](../../01-machine-learning/04-神经网络原理/02-反向传播推导.md) 第 2 节），总显存开销会远超"参数量本身"这一个数字。

**参数高效微调（PEFT, Parameter-Efficient Fine-Tuning）**的核心思路是：冻住绝大部分原始参数（不产生梯度、不需要优化器状态），只让一小部分新增或选中的参数参与训练。可训练参数少了几个数量级，梯度、一阶矩、二阶矩都跟着大幅减少，显存压力从"和全模型参数量成正比"变成"和一小部分可训练参数量成正比"。

## 2. LoRA 的低秩假设与数学形式

LoRA（Low-Rank Adaptation）的核心假设是：**模型在微调过程中，权重需要发生的变化量本身是低秩的**。即便原始权重矩阵 `W` 是满秩的大矩阵，微调所需叠加的增量 `ΔW` 并不需要那么高的自由度——用远低秩的矩阵就能近似表达微调所需要学到的变化方向。

数学形式：把要学习的权重增量 `ΔW`（形状 `d × k`）用两个小矩阵的乘积近似：

```
W' = W + ΔW = W + B·A

其中：
  W  是原始权重矩阵，形状 (d, k)，训练时冻结不更新
  A  形状 (r, k)，随机初始化
  B  形状 (d, r)，初始化为全零
  r  是秩（rank），r << min(d, k)
```

前向传播时，输出变成 `h = Wx + BAx`，原始路径和新增的低秩路径**并行叠加**。训练时只更新 `A` 和 `B`，`W` 全程冻结。`B` 初始化为零保证训练刚开始时 `ΔW = 0`，模型行为和原始模型完全一致，训练从一个"无害"的起点开始。

**参数量对比**：全量微调这一层需要更新 `d × k` 个参数；LoRA 只需要更新 `r × k + d × r = r × (d + k)` 个参数。当 `r` 远小于 `d` 和 `k` 时，参数量的减少是数量级的。

## 3. rank、alpha、目标模块选择的影响

**rank (r)**：决定低秩近似的表达能力上限。`r` 越大，`ΔW` 能表达的变化空间越大，理论上更接近全参微调效果，但可训练参数和显存也线性增加。`r` 太小可能学不到任务所需的全部调整方向（欠拟合）；`r` 太大则失去 PEFT 省参数的意义，也可能过拟合小数据集。实践中往往需要针对具体任务尝试几个不同的 `r` 做对比。

**alpha (lora_alpha)**：LoRA 输出实际会乘以一个缩放系数 `alpha / r`：

```
h = Wx + (alpha / r) · BAx
```

`alpha` 控制新增低秩路径相对原始路径的影响强度，独立于 `r` 的选择。如果只调 `r` 不重新调 `alpha`，改变 `r` 会同时改变"表达能力"和"每次更新的影响幅度"两件事；引入 `alpha / r` 缩放后可以把两个维度分开调整。

**目标模块选择（target_modules）**：LoRA 不要求给每一层都加低秩适配器，可以只对某些模块（比如注意力里的 query/value 投影矩阵）加。选择更多模块能提升表达能力和效果上限，但增加可训练参数量；只选关键模块（很多实践发现注意力投影矩阵通常是效果收益最高的位置）可以用更少参数拿到大部分收益。具体该加哪些模块通常需结合任务类型和实验结果决定，没有对所有任务通用的固定答案。

## 4. QLoRA：NF4 量化与双量化

QLoRA 解决的是另一维度的问题：即便用 LoRA 大幅减少了可训练参数，**冻结的基座模型本身依然要以某种精度加载进显存**，参数量很大的基座模型即便冻结不训练，光是加载它就可能超出显存容量。

QLoRA 把冻结的基座模型量化到 4-bit 精度存储，同时保持 LoRA 新增的适配器矩阵仍以更高精度（通常 16-bit）训练。两者分工明确：

```
基座模型 W（冻结，不参与训练）→ 量化为 4-bit 存储，大幅降低显存占用
LoRA 适配器 A, B（可训练）      → 保持较高精度（如 bf16），正常参与梯度更新和优化器状态维护

前向传播时：
  基座权重先从 4-bit 反量化回计算精度 → 与输入做矩阵乘 → 与 LoRA 路径的输出相加
```

"省显存"交给量化（作用在不参与训练、只需读取的基座权重上），"保留可训练性和精度"交给 LoRA 路径（作用在数量很小、需要精细梯度更新的新增参数上）——两者各管一段，不冲突。

**NF4（4-bit NormalFloat）**：普通均匀量化把数值范围等距划分成若干区间，但神经网络权重的实际分布通常更接近正态分布（中间密集、两端稀疏）。NF4 是专门针对正态分布设计的 4-bit 数据类型，量化区间的划分让"分布密集的区域"获得更精细的分辨率，在同样 4-bit 的比特预算下比均匀量化更好地保留权重的原始信息、减少量化误差。

**双量化（double quantization）**：量化过程需要为每个量化的小块存储一个缩放系数（scale），这些系数本身也占用一部分存储。双量化就是对这些缩放系数**再做一次量化**，进一步压缩存储开销。这是"精度换空间"进一步细化的技巧，收益相对量化本身较小，但在极端显存受限场景下仍有意义。

## 5. Adapter / Prefix Tuning / P-Tuning v2 / IA3 对比

| 方法 | 核心思路 | 特点 |
| --- | --- | --- |
| Adapter | 在层间插入小型瓶颈结构（降维再升维的小FFN），只训练插入模块 | 结构简单，但插入位置在前向路径上会增加推理时的层数和延迟 |
| Prefix Tuning | 每层注意力key/value前拼接一段可训练"虚拟token"（连续向量） | 不改原有计算路径结构，但需为每层单独学前缀向量，占用部分上下文长度 |
| P-Tuning v2 | 每层都插入可训练连续提示向量，并做训练稳定性改进 | 相比早期只在输入层加提示向量的方法，多层插入让小模型效果更可靠 |
| IA3 | 学习一组缩放向量，对激活值做逐元素重新缩放，不新增矩阵加法 | 可训练参数比LoRA更少，推理额外计算更轻，表达能力上限更低 |

这些方法的共同点是都只训练一小部分新增或选中的参数；差异在于"新增自由度加在哪里、用什么形式加"——插入新层（Adapter）、在输入前缀拼接虚拟token（Prefix/P-Tuning），还是给现有激活值做低秩加法（LoRA）或缩放（IA3）。选择哪种通常要在表达能力、推理延迟、可训练参数量之间权衡。

## 6. LoRA 变体：DoRA 与 rsLoRA

**DoRA（Weight-Decomposed Low-Rank Adaptation）**：把权重矩阵分解为"大小（magnitude）"和"方向（direction）"两部分分别处理——用一个标量向量学习每个权重的幅度变化，用类似 LoRA 的低秩结构学习方向变化。动机是全参微调时权重的大小和方向会独立调整，标准 LoRA 只能用一个低秩加法项同时影响两者，解耦后能更贴近全参微调的更新模式。

**rsLoRA（Rank-Stabilized LoRA）**：把标准的缩放系数 `alpha / r` 改为 `alpha / sqrt(r)`。动机是：`r` 增大时 `alpha / r` 会随之迅速缩小，导致大 `r` 下梯度信号过弱、训练不稳定；改成除以 `sqrt(r)` 能让不同 `r` 取值下的有效学习信号更稳定，使增大 `r` 真正换来表达能力提升而不被缩放系数抵消。

> ⚠️ 待确认：LoRA 变体这个方向仍在持续演进，此处只列出机制明确、有公开资料支撑的两种，其余变体暂不展开。

## 7. 合并推理与多 LoRA 结合

**合并推理（merge）**：训练完成后，如果只需要用这一个适配器，可以把 `B·A` 直接加回原始权重 `W`，得到新的单一权重矩阵 `W' = W + BA`。合并后推理时不再需要额外计算 LoRA 路径，路径和一个原生稠密模型完全一样，没有任何额外计算或显存开销——这是 LoRA 相比 Adapter 类方法在推理效率上的优势，Adapter 插入的额外层无法这样合并消除。

**多 LoRA 结合**：因为 LoRA 适配器本身很小，同一个基座模型可以同时加载多个针对不同任务/风格训练的 LoRA 适配器，根据请求动态选择或组合使用，而不需要为每个任务单独存一份完整模型权重。这在需要同时服务多个细分场景时能显著节省存储和显存。需要注意的是，多个 LoRA 叠加使用时不同适配器学到的低秩方向之间可能存在干扰，效果不一定是简单叠加，实践中通常需要验证具体组合的效果。

## 8. 用 NumPy 演示低秩分解与参数量对比

用 NumPy 模拟 LoRA 核心机制：构造权重矩阵，用低秩矩阵 `B·A` 近似目标增量，对比不同 rank 下的参数量和近似误差。

```python
import numpy as np


def count_params_full(d, k):
    """全量微调这一层权重的参数量"""
    return d * k


def count_params_lora(d, k, r):
    """LoRA 需训练参数量：A(r,k) + B(d,r)"""
    return r * k + d * r


def lora_forward(x, W, B, A, alpha, r):
    """LoRA 前向：h = Wx + (alpha/r) * B*A*x，W 冻结，B/A 可训练"""
    base = W @ x
    delta = (alpha / r) * (B @ (A @ x))
    return base + delta


def fit_low_rank_update(delta_w_target, r, n_steps=500, lr=0.05, seed=0):
    """
    用简单梯度下降拟合一个低秩分解 B*A，使其逼近给定的目标增量矩阵 delta_w_target。
    这模拟的是"微调真正想要学到的增量"，LoRA 假设它可以被低秩近似。
    """
    rng = np.random.default_rng(seed)
    d, k = delta_w_target.shape
    B = rng.normal(0, 0.01, size=(d, r))
    A = rng.normal(0, 0.01, size=(r, k))

    for _ in range(n_steps):
        pred = B @ A
        diff = pred - delta_w_target
        grad_B = diff @ A.T
        grad_A = B.T @ diff
        B -= lr * grad_B
        A -= lr * grad_A

    approx = B @ A
    rel_error = np.linalg.norm(approx - delta_w_target) / np.linalg.norm(delta_w_target)
    return B, A, rel_error


if __name__ == "__main__":
    d, k = 256, 256  # 模拟一个权重矩阵，真实模型里维度通常更大

    print(f"权重矩阵形状: ({d}, {k})")
    print(f"全参微调需训练参数量: {count_params_full(d, k):,}\n")

    print("不同 rank 下 LoRA 参数量与压缩比：")
    for r in [1, 4, 8, 16, 64]:
        n_lora = count_params_lora(d, k, r)
        ratio = n_lora / count_params_full(d, k)
        print(f"  r={r:>3d}: LoRA参数量={n_lora:>7,}  压缩比={ratio:.4f}  ({ratio*100:.2f}%)")

    # 构造一个"真实"的低秩增量目标（秩为 8），验证不同 r 下的拟合误差
    print("\n用低秩梯度下降拟合一个真实秩为 8 的目标增量矩阵：")
    rng = np.random.default_rng(42)
    true_rank = 8
    # 乘以 0.1 控制数值尺度，避免梯度下降在大数值矩阵上发散
    B_true = rng.normal(0, 1, size=(d, true_rank)) * 0.1
    A_true = rng.normal(0, 1, size=(true_rank, k)) * 0.1
    delta_w_target = B_true @ A_true  # 目标增量矩阵，真实秩就是 8

    for r in [2, 8, 16]:
        _, _, rel_error = fit_low_rank_update(delta_w_target, r)
        print(f"  用 rank={r:>2d} 拟合秩为{true_rank}的目标: 相对误差={rel_error:.4f}")
```

实测输出（numpy 2.4.4）：

```
权重矩阵形状: (256, 256)
全参微调需训练参数量: 65,536

不同 rank 下 LoRA 参数量与压缩比：
  r=  1: LoRA参数量=    512  压缩比=0.0078  (0.78%)
  r=  4: LoRA参数量=  2,048  压缩比=0.0312  (3.12%)
  r=  8: LoRA参数量=  4,096  压缩比=0.0625  (6.25%)
  r= 16: LoRA参数量=  8,192  压缩比=0.1250  (12.50%)
  r= 64: LoRA参数量= 32,768  压缩比=0.5000  (50.00%)

用低秩梯度下降拟合一个真实秩为 8 的目标增量矩阵：
  用 rank= 2 拟合秩为8的目标: 相对误差=0.8185
  用 rank= 8 拟合秩为8的目标: 相对误差=0.0000
  用 rank=16 拟合秩为8的目标: 相对误差=0.0042
```

结果验证了 LoRA 的核心假设：真实增量秩为 8 时，用 `r=2`（小于真实秩）误差很大（0.82），表达能力不足；用 `r=8`（恰好等于真实秩）误差几乎降到 0；`r=16` 误差略有上升（0.0042），是多余自由度在有限步数梯度下降中带来的轻微过参数化噪声，但量级极小，不影响"匹配真实秩即可精确拟合"这个结论。这正是"选择合适 rank"的实践依据——`r` 需不小于任务真正需要的有效秩，选得刚好或略大都能拟合好，继续增大收益迅速递减。

## 9. 小结

| 概念 | 一句话总结 |
| --- | --- |
| 全参微调显存 | 参数+梯度+两份优化器状态，约参数量4倍，还不含激活值 |
| LoRA | 假设微调增量低秩，用 B·A 两个小矩阵近似，只训练这两个小矩阵 |
| rank / alpha | rank 决定表达能力上限，alpha/r 缩放控制新增路径的影响强度 |
| QLoRA | 基座量化到 4-bit 省显存，LoRA 路径保持高精度保留可训练性 |
| NF4 / 双量化 | 针对正态分布优化的量化区间划分；对量化缩放系数再量化进一步省空间 |
| Adapter/Prefix/IA3 | 新增自由度加的位置不同：插入层、拼接虚拟token、缩放激活值 |
| DoRA / rsLoRA | 分别解耦大小方向、修正缩放公式，缓解标准 LoRA 局限 |
| 合并推理 | B·A 可直接加回原权重，推理时零额外开销，Adapter 类方法做不到 |
