## 1. 语音输入的特征提取：波形到梅尔频谱

原始语音是一维波形（waveform），采样率通常上万 Hz，直接把每个采样点当作模型输入维度太高、冗余太多（相邻采样点高度相关，且波形本身对人耳感知的频率信息不是线性可读的）。传统语音模型的标准做法是先转换成梅尔频谱（mel spectrogram）：

```
波形 (1D, 采样点序列)
  │ 分帧：每 25ms 取一帧，帧间重叠(如每 10ms 滑动一次)
  ▼
短时傅里叶变换 STFT：每帧做频域分解，得到该帧的频谱（幅度谱）
  │
  ▼
梅尔滤波器组：把线性频率轴映射到梅尔刻度（mel scale）
  │  梅尔刻度模拟人耳对频率的非线性感知——人耳对低频差异更敏感，
  │  对高频差异不敏感，梅尔刻度压缩高频区间、保留低频区间的分辨率
  ▼
梅尔频谱 (2D: 时间帧数 x 梅尔滤波器数)，通常再取对数得到 log-mel spectrogram
```

结果是一张二维"图"：横轴是时间帧，纵轴是频率（压缩到几十到上百个梅尔频带），数值是能量。这个表示既压缩了原始波形的冗余信息，又贴近人耳感知规律，是几乎所有语音模型（ASR、TTS 声学模型）的标准输入/中间表示。

## 2. CTC 损失：解决对齐问题的核心思路

语音识别的根本困难在于**长度不对齐**：一段 3 秒的音频可能对应几百个梅尔频谱帧，但转录文本只有十几个字符——模型不知道"第 37 帧到第 52 帧"对应哪个字，训练数据通常也只标注了"这段音频对应这句话"，没有逐帧标注。

CTC（Connectionist Temporal Classification）的解法是：**让模型对每一帧独立预测一个字符（或特殊的 blank 符号），再用一套确定性规则把预测序列"折叠"成目标文本，训练时枚举所有能折叠成目标文本的路径，把它们的概率加起来作为目标**。

```
折叠规则：
  1. 连续重复的同一符号视为一次输出（aab -> ab）
  2. blank 符号被丢弃，且用来分隔本应连续但需要区分的重复字符

例：目标文本 "ab"，某条候选路径 [a, a, blank, b, b] 折叠后仍是 "ab"
    另一条路径 [blank, a, blank, b, blank] 折叠后也是 "ab"
    两条路径都算作"预测正确"，训练时把所有这类路径的概率求和
```

直接枚举所有路径计算量是指数级的，实际用**前向算法（forward algorithm）**做动态规划：定义在"标签序列插入 blank 后的扩展序列"上逐帧递推的状态转移，把指数复杂度降到多项式，这正是本文代码要实现和验证的部分。

CTC 的关键假设是**条件独立**：每一帧的输出预测只依赖当前帧特征，不显式建模字符间的语言依赖（这一点后来被证明是精度短板，衍生出 RNN-T 等改进方案，在 CTC 基础上引入自回归的语言状态）。

## 3. Whisper：encoder-decoder 结构与弱监督训练

Whisper 代表了另一条路线——不用 CTC，而是用标准的 **encoder-decoder Transformer** 结构做语音识别：

```
音频 → log-mel spectrogram → [Transformer Encoder] → 音频特征
                                                          │
文本 (自回归生成) ← [Transformer Decoder] ← cross-attention ┘
```

Encoder 把音频编码成一组特征向量，Decoder 以自回归方式逐 token 生成文本，通过 cross-attention 读取 encoder 的音频特征——这个结构和文本翻译模型（参考 [../../machine-learning/07-RNN与序列/02-seq2seq与注意力起源.md](../../01-machine-learning/07-RNN与序列/02-seq2seq与注意力起源.md)）几乎一致，只是把源语言文本换成了音频特征。因为是自回归生成而非逐帧独立分类，Decoder 天然能建模输出文本内部的语言依赖，不受 CTC 条件独立假设的限制。

**弱监督（weak supervision）训练**指训练数据的获取方式：不依赖专业标注团队逐句精确转写音频，而是直接使用互联网上大规模存在的"音频配文本"数据（如带字幕的视频），规模远大于传统语音数据集，但转写质量参差不齐。Whisper 证明了**用规模换质量**在语音识别上是可行的路线——数据量大到一定程度，模型能自行学会忽略噪声标注，泛化能力反而优于在小规模精标数据上训练的模型。这和 GPT 类模型用海量互联网文本做自监督预训练（参考 [../03-预训练范式/02-GPT与自回归路线.md](../03-预训练范式/02-GPT与自回归路线.md)）在方法论上是同一脉络：不追求标注精确，追求规模。

## 4. 流式识别的难点

上述 Whisper 结构是**离线（offline）识别**：必须等到完整音频输入完毕，才能跑一次完整的 encoder-decoder 推理。但语音助手、实时字幕等场景需要**流式（streaming）识别**——音频边说边转写，不能等说完整句话才出结果。

流式带来的结构性困难：

```
1. Encoder 的双向依赖问题
   标准 Transformer encoder 每个位置的表示依赖整个序列（包括未来帧），
   流式场景下"未来帧"还没说出来，无法计算完整的双向注意力

2. Decoder 何时该输出的问题
   自回归 decoder 需要知道"当前已有的音频信息是否足够生成下一个词"，
   过早输出容易出错（后面的音频可能澄清或改变前面的语义），
   过晚输出增加延迟，这是准确率和延迟的直接权衡

3. 计算复用问题
   随着音频流逐渐变长，如果每来一小段新音频就重新跑一次完整
   encoder，计算量随时间线性累积，需要专门设计增量式计算
   （只对新增部分做计算，复用之前的计算结果，类似 KV Cache 的思路，
   参考 ../05-推理优化/01-KV-Cache与显存分析.md）
```

流式模型通常采用限制注意力窗口（只看有限长度的未来帧，牺牲精度换可行性）或专门的流式架构（分块处理、CTC 结合流式解码），本质都是在"等信息完整再判断"和"尽快给出结果"之间做工程折衷。

## 5. TTS 两条路线：声学模型+声码器 vs 端到端

文本转语音（TTS, Text-to-Speech）的经典流程分两阶段：

```
路线A：声学模型 + 声码器（两阶段）
文本 → [声学模型] → 梅尔频谱（或其他中间声学特征） → [声码器 Vocoder] → 波形

路线B：端到端（直接建模波形或波形的离散表示）
文本 → [端到端模型] → 波形（或波形对应的离散 token 序列）
```

**两阶段路线**的声学模型负责"应该听起来是什么样"（音高、时长、频谱包络等），声码器负责把频谱特征还原成真实可听的波形。拆成两阶段的好处是每个模块职责单一、可独立优化替换；代价是误差可能在两阶段之间累积——声学模型输出的频谱不够精确，声码器也无法凭空补回信息。

**端到端路线**试图用一个模型直接完成文本到波形的映射，避免中间表示的信息损失和误差累积，但训练难度更高：波形采样率很高，直接建模的序列长度远超文本或频谱表示，对模型容量和训练数据要求更高。

## 6. 神经声码器与离散音频 token

声码器（vocoder）负责"频谱 → 波形"这一步的还原，经历了从传统信号处理算法到神经网络的演进：

```
传统声码器（如 Griffin-Lim）：
  纯信号处理算法，从幅度谱迭代估计相位信息重建波形，无需训练，
  但重建质量有限，容易出现机械感、金属声

神经声码器（如基于 GAN / 扩散的声码器）：
  用神经网络学习"频谱 → 波形"的映射，训练数据是大量真实
  <频谱,波形> 对，重建质量远超传统方法，波形更自然
```

近年语音/音乐生成模型进一步引入**离散音频 token**：用专门训练的编解码器（audio codec，如基于 VQ-VAE 思路的模型）把连续波形编码成一串离散整数 token（类似文本 token id），生成模型只需在这串离散 token 序列上做自回归预测——**把语音生成问题转化成序列生成问题，可直接套用 LLM 的自回归建模框架**。生成完 token 序列后，再用编解码器的解码器部分还原成波形。

这个思路能流行的核心原因是**统一了多模态生成的建模范式**：无论文本、音频、视频，只要能把连续信号量化成离散 token，都能复用同一套自回归 Transformer 基础设施，不需要为每个模态单独设计生成架构。

## 7. 视频生成：时空建模与一致性难点

视频比图像多了一个维度——时间。视频生成模型的核心困难是**既要生成每一帧在空间上合理，又要保证帧与帧之间在时间上连贯（同一物体不能突然变形、背景不能突然跳变、运动轨迹要符合物理直觉）**。

```
图像生成：只需建模空间维度（H x W x C）
视频生成：需要同时建模空间维度 + 时间维度（T x H x W x C）
          时间维度上前后帧强相关，但又不是简单复制——需要连贯的运动
```

常见思路是把扩散模型（参考 [./02-扩散模型原理.md](./02-扩散模型原理.md)）从图像扩展到视频：在时间维度上也加入注意力机制（时空注意力，spatial-temporal attention），让模型在生成/去噪某一帧时，能同时参考同一视频里其他帧的信息，而不是把每帧当作独立图像逐帧生成。

**一致性难点**主要体现在：长时依赖（视频越长需保持一致的时间跨度越大，模型有效关注窗口有限，容易出现远距离帧不一致）；物理合理性（训练数据里的运动模式是唯一先验来源，没有显式物理引擎，遇到罕见运动方式容易生成不符合直觉的结果）；计算成本（时空联合建模计算量远超单帧图像生成，训练和推理成本大幅上升）。

> ⚠️ 待确认：当前主流视频生成模型在时空注意力的具体实现方式（全时空联合注意力 vs 分解式的空间/时间注意力交替）上路线不完全统一，这里不展开评判具体一致性保持机制细节。

## 8. 代码：CTC 前向算法验证

用 numpy 实现 CTC 前向算法（forward algorithm），在一个极小规模的例子上和暴力枚举所有路径的结果对比，验证前向算法确实计算的是"所有能折叠成目标标签序列的路径"概率之和。

```python
import numpy as np

rng = np.random.default_rng(0)


def insert_blanks(labels, blank=0):
    """CTC 扩展标签序列：在每个字符前后插入 blank，形成 l' = [b, l1, b, l2, b, ..., ln, b]
    长度从 n 变为 2n+1，是前向算法在扩展路径图上递推的基础"""
    ext = [blank]
    for lb in labels:
        ext.append(lb)
        ext.append(blank)
    return ext


def ctc_forward_log_prob(log_probs, labels, blank=0):
    """CTC 前向算法（forward algorithm），在 log 空间里计算所有能对齐到 labels 的
    路径概率之和，即 P(labels | 输入)。log_probs: shape (T, num_classes)，每行已是
    该时间步各类别的 log 概率。

    核心思想：CTC 允许同一个标签重复多帧（表示发音拉长）、允许插入 blank（表示
    静音或过渡帧），把"输入帧数 T"和"标签长度 n"的对齐问题转化成一个动态规划——
    在扩展序列 l' 上定义 alpha[t][s] = 到时间步 t 为止，走到扩展序列第 s 个位置的
    所有路径概率之和，递推时只允许停留、前进一步、或跳过一个 blank 前进两步。
    """
    ext_labels = insert_blanks(labels, blank)
    S = len(ext_labels)  # 扩展序列长度 = 2n+1
    T = log_probs.shape[0]

    NEG_INF = -1e9

    def log_sum_exp(a, b):
        """log 空间里的加法：log(exp(a)+exp(b))，数值稳定写法"""
        if a <= NEG_INF:
            return b
        if b <= NEG_INF:
            return a
        m = max(a, b)
        return m + np.log(np.exp(a - m) + np.exp(b - m))

    alpha = np.full((T, S), NEG_INF)

    # 初始化 t=0：只能停在扩展序列的第0位(blank)或第1位(第一个真实标签)
    alpha[0, 0] = log_probs[0, ext_labels[0]]
    if S > 1:
        alpha[0, 1] = log_probs[0, ext_labels[1]]

    for t in range(1, T):
        for s in range(S):
            # 情况A：停留在 s，或从 s-1 前进一步（两者都总是允许）
            val = alpha[t - 1, s]
            if s - 1 >= 0:
                val = log_sum_exp(val, alpha[t - 1, s - 1])
            # 情况B：从 s-2 跳过一个 blank 前进两步——仅当 s 不是 blank，
            # 且 s 与 s-2 处标签不同（相同标签必须经过中间 blank，不能跳）
            if s - 2 >= 0 and ext_labels[s] != blank and ext_labels[s] != ext_labels[s - 2]:
                val = log_sum_exp(val, alpha[t - 1, s - 2])
            alpha[t, s] = val + log_probs[t, ext_labels[s]]

    # 终止：最后一帧必须停在扩展序列最后一位(blank)或倒数第二位(最后一个真实标签)
    total = alpha[T - 1, S - 1]
    if S > 1:
        total = log_sum_exp(total, alpha[T - 1, S - 2])
    return total


def brute_force_ctc_log_prob(log_probs, labels, blank=0):
    """暴力法验证：枚举所有长度为 T 的路径，映射规则是"去连续重复+去blank"，
    只对能映射回 labels 的路径求和。T 很小时才能穷举，用于验证前向算法正确性。"""
    T, C = log_probs.shape

    def collapse(path):
        out = []
        prev = None
        for p in path:
            if p != blank and p != prev:
                out.append(p)
            prev = p
        return out

    total_prob = 0.0
    # 递归枚举所有 C^T 条路径（C, T 都很小时可行）
    def rec(t, path):
        nonlocal total_prob
        if t == T:
            if collapse(path) == list(labels):
                prob = 1.0
                for i, p in enumerate(path):
                    prob *= np.exp(log_probs[i, p])
                total_prob += prob
            return
        for c in range(C):
            rec(t + 1, path + [c])

    rec(0, [])
    return np.log(total_prob) if total_prob > 0 else -np.inf


# --- 构造一个小规模例子：3个类别(0=blank,1=a,2=b)，T=4帧，标签序列是 [1,2]("ab") ---
np.random.seed(0)
T, C = 4, 3
logits = rng.normal(0, 1, (T, C))
log_probs = logits - np.log(np.sum(np.exp(logits), axis=1, keepdims=True))  # log_softmax

labels = [1, 2]  # 代表 "a","b"

fwd_logp = ctc_forward_log_prob(log_probs, labels, blank=0)
brute_logp = brute_force_ctc_log_prob(log_probs, labels, blank=0)

print("实验1：CTC 前向算法 vs 暴力枚举，验证 P(labels|输入) 计算是否一致")
print(f"  前向算法  log P(ab|X) = {fwd_logp:.6f}   P = {np.exp(fwd_logp):.6f}")
print(f"  暴力枚举  log P(ab|X) = {brute_logp:.6f}   P = {np.exp(brute_logp):.6f}")
print(f"  差值 = {abs(fwd_logp - brute_logp):.2e}（应接近0，验证前向算法正确）")

# --- 实验2：更长序列下前向算法仍可行，暴力法组合数爆炸不再对比，只展示扩展序列结构 ---
labels2 = [1, 2, 1]  # "aba"
ext2 = insert_blanks(labels2, blank=0)
print("\n实验2：标签序列扩展结构展示（CTC 前向算法在此扩展序列上做动态规划）")
print(f"  原始标签序列: {labels2} (1=a, 2=b)")
print(f"  插入blank后 : {ext2} (0=blank)  长度从 {len(labels2)} 变为 {len(ext2)}")

T2 = 6
logits2 = rng.normal(0, 1, (T2, C))
log_probs2 = logits2 - np.log(np.sum(np.exp(logits2), axis=1, keepdims=True))
fwd_logp2 = ctc_forward_log_prob(log_probs2, labels2, blank=0)
print(f"  T={T2} 帧输入下 log P(aba|X) = {fwd_logp2:.6f}   P = {np.exp(fwd_logp2):.6f}")
```

实测输出（numpy 2.4.4）：

```
实验1：CTC 前向算法 vs 暴力枚举，验证 P(labels|输入) 计算是否一致
  前向算法  log P(ab|X) = -2.126793   P = 0.119219
  暴力枚举  log P(ab|X) = -2.126793   P = 0.119219
  差值 = 0.00e+00（应接近0，验证前向算法正确）

实验2：标签序列扩展结构展示（CTC 前向算法在此扩展序列上做动态规划）
  原始标签序列: [1, 2, 1] (1=a, 2=b)
  插入blank后 : [0, 1, 0, 2, 0, 1, 0] (0=blank)  长度从 3 变为 7
  T=6 帧输入下 log P(aba|X) = -2.372002   P = 0.093294
```

实验1的前向算法和暴力枚举给出完全一致的结果（差值 0.00e+00），验证了前向算法的动态规划递推确实等价于枚举所有可折叠路径求和，只是把指数复杂度降到了多项式复杂度。实验2展示了标签序列插入 blank 后的扩展结构——"aba"这样中间字符重复的序列，扩展后长度从 3 变为 7，重复字符 a 之间必须经过 blank（对应第2节提到的"相同标签不能跳过中间 blank"的规则），这正是 CTC 区分"两个连续的 a"和"拉长发音的一个 a"的关键设计。

## 9. 小结

| 主题 | 核心结论 |
| --- | --- |
| 梅尔频谱 | 波形经 STFT+梅尔滤波压缩到时间x频率二维表示，贴近人耳感知规律 |
| CTC | 用 blank+折叠规则处理长度不对齐，前向算法把枚举路径降到动态规划 |
| Whisper | encoder-decoder 自回归结构，弱监督规模换质量，思路与 GPT 预训练一脉相承 |
| 流式识别 | 双向依赖、输出时机、增量计算三重难点，本质是精度与延迟的权衡 |
| TTS 两路线 | 两阶段（声学模型+声码器）职责清晰但误差累积，端到端避免累积但训练更难 |
| 神经声码器 | 从信号处理算法到神经网络，离散音频 token 让语音生成复用 LLM 自回归框架 |
| 视频生成 | 在扩散模型基础上加时空注意力，长时一致性和计算成本是核心难点 |
