## 1. 为什么需要注意力机制：RNN 的顺序依赖瓶颈

在 Transformer 之前，处理序列数据的主流架构是 RNN（及其变体 LSTM、GRU）。RNN 按时间步逐个处理序列：`h_1 = f(x_1, h_0)`，……，`h_t = f(x_t, h_{t-1})`，计算 `h_t` 必须依赖 `h_{t-1}` 已经算出来。

这里藏着两个根本性问题。**问题一：无法并行化训练**——序列长度为 `T`，就要串行算 `T` 步，GPU 最擅长的大规模并行计算能力完全用不上，这在训练数据以十亿、万亿 token 计的规模下是致命的效率瓶颈。**问题二：长距离依赖难以捕捉**——序列开头的信息要经过层层传递才能影响到很远的位置，每一步传递都有信息损失（与反向传播中的梯度消失是同一类问题，只是这里讨论前向信息流的衰减）。序列越长，开头信息传到末尾时衰减越严重。

Transformer 的解法是**彻底抛弃顺序依赖，用自注意力机制让序列中任意两个位置直接建立联系**——任何两个位置之间只隔着"一次注意力计算"，无论它们相距多远。这既解决了并行化问题（所有位置的注意力可以同时计算），也解决了长距离依赖问题（任意两点的距离在计算图上变成了常数级）。

## 2. 缩放点积注意力：逐步推导

### 2.1 三个角色向量与注意力分数

给每个 token 准备三个角色向量（都是原始 embedding 经过不同的线性变换得到）：`Q`（Query，我在找什么）、`K`（Key，我有什么）、`V`（Value，我的内容是什么）。为什么要三个不同的向量而不是用同一个向量三用？因为"查询"、"被查询"和"实际聚合的信息"在语义角色上是不同的任务，让模型分别学三组独立的线性变换（`W_Q`, `W_K`, `W_V`），表达能力显著强于共享一份表示。

对序列中每一个位置的 Query 向量 `q_i`，和每一个位置的 Key 向量 `k_j` 做点积，得到"位置 i 对位置 j 的原始注意力分数" `score_{ij} = q_i · k_j`。向量化写成矩阵形式：`Scores = Q · Kᵀ`（`Q, K` 形状都是 `[序列长度, d_k]`，`Scores` 形状是 `[序列长度, 序列长度]`）。

### 2.2 为什么要除以 sqrt(d_k)：方差分析

这是缩放点积注意力（scaled dot-product attention）名字里"scaled"的来源，也是最容易被忽略但很重要的一个细节。

**问题的起点**：假设 `q` 和 `k` 的每个分量都是独立同分布的随机变量，均值为 0，方差为 1（常见的初始化假设）。两个 `d_k` 维向量的点积 `q · k = Σ_{i=1}^{d_k} q_i · k_i` 是 `d_k` 个独立随机变量乘积的和。由 `Var[q_i·k_i] = E[q_i²]·E[k_i²] - 0 = 1` 及方差可加性：

```
Var[q · k] = Σ_{i=1}^{d_k} Var[q_i · k_i] = d_k × 1 = d_k
```

**结论：点积的方差随向量维度 `d_k` 线性增长**。`d_k` 通常是 64 或更大，未经缩放的点积数值范围会随维度增大而急剧扩大。

**这会带来什么后果**：注意力分数要经过 softmax 转换成概率分布，而 softmax 对输入的数值范围非常敏感——当输入的数值范围很大时，softmax 的输出会高度集中在最大值对应的位置，几乎变成 one-hot，梯度在这种"饱和"区域趋近于 0（softmax 的导数在极端输入下几乎为 0），反向传播时这一层几乎学不到东西，这是梯度消失的另一种表现形式。

**缩放的解法**：把点积除以 `sqrt(d_k)`，正好抵消掉方差随维度线性增长的效应：

```
Var[q·k / sqrt(d_k)] = Var[q·k] / d_k = d_k / d_k = 1
```

除以 `sqrt(d_k)` 之后，缩放后的分数方差恢复到 1（与维度无关的常数），softmax 的输入数值范围回到一个稳定、适中的区间。**为什么是 `sqrt(d_k)` 而不是 `d_k`**：要抵消的是方差（二阶量）。若除以 `d_k`，由 `Var[cX]=c²·Var[X]`，方差会变成 `d_k/d_k²=1/d_k`，反而在维度大时把分数压得过小。正确做法是除以 `sqrt(d_k)`：`Var[q·k/sqrt(d_k)] = d_k/(sqrt(d_k))² = 1`，恰好抵消。

完整的缩放点积注意力公式：

```
Attention(Q, K, V) = softmax( Q·Kᵀ / sqrt(d_k) ) · V
```

`softmax` 把每一行的分数转成一个概率分布（每行元素非负、和为1），再用这个概率分布对 `V` 做加权求和——这就是"注意力权重"的直接含义：**每个位置以多大的权重去聚合其他位置的信息**。

## 3. 多头注意力：为什么有效，参数量怎么算

### 3.1 拆分子空间，独立计算，再拼接

单头注意力用一组 `(W_Q, W_K, W_V)` 只能学出一种关注模式，但语言中的依存关系是多样的（同一个词可能需要同时关注语法主语、语义指代对象、临近修饰词等）。多头注意力（multi-head attention）的做法：把 `d_model` 维向量空间拆分成 `h` 个独立的子空间（每个子空间维度 `d_k = d_model/h`），在每个子空间里独立做一次缩放点积注意力，最后拼接：

```
对每个头 i = 1...h，独立计算：
  Q_i = X · W_Q_i,   K_i = X · W_K_i,   V_i = X · W_V_i     （W_Q_i 等形状 [d_model, d_k]）
  head_i = Attention(Q_i, K_i, V_i)                          （形状 [序列长度, d_k]）

拼接所有头: Concat(head_1, ..., head_h)                      （形状 [序列长度, d_model]）
输出投影: MultiHead(X) = Concat(head_1, ..., head_h) · W_O    （W_O 形状 [d_model, d_model]）
```

每个头有独立的 `(W_Q_i, W_K_i, W_V_i)`，训练中不同头会自发学出关注不同类型关系的模式——这不是设计者手工指定的，而是梯度下降在优化整体损失时自动分化出来的（若不同头都学出一样的模式，对降低损失没有额外贡献，梯度会推动它们分化以获得更多互补信息）。这类似卷积网络里多个卷积核各自学习不同特征模式。

### 3.2 参数量计算

设 `d_model` 是模型的隐藏维度，`h` 是头数，则每个头的维度 `d_k = d_model / h`。

```
单头的参数：W_Q_i, W_K_i, W_V_i 各是 [d_model, d_k]，参数量各为 d_model × d_k
  单头三个矩阵总参数量 = 3 × d_model × d_k = 3 × d_model × (d_model/h)

h 个头的总参数量 = h × 3 × d_model × (d_model/h) = 3 × d_model²    ← h 被约掉了

再加上输出投影 W_O，形状 [d_model, d_model]，参数量 = d_model²

多头注意力总参数量 = 3 × d_model² + d_model² = 4 × d_model²
```

**关键观察：多头注意力的总参数量只与 `d_model` 有关，与头数 `h` 无关**（`h` 在计算里被约掉了）。这意味着"分成更多头"不会增加参数量——它只是把同样大小的参数矩阵拆成多个更小的子空间并行计算，是一种表达能力的重新组织，不是参数量的增加。这也是为什么增加头数几乎不增加计算/存储成本，却能提升模型捕捉多种依赖关系的能力。

## 4. 复杂度与显存瓶颈：O(n²)

回顾 `Scores = Q · Kᵀ`，`Q` 和 `K` 形状都是 `[n, d_k]`（`n` 是序列长度），这个矩阵乘法的计算量约为 `O(n²×d_k)`——序列长度翻倍，计算量变成 4 倍。这是自注意力相对 RNN（`O(n)`）的直接代价——用并行化换取了更差的复杂度增长曲线。

除了计算量，`Scores` 矩阵本身（形状 `[n,n]`）需要被存储下来才能做 softmax 和加权求和，显存占用同样是 `O(n²)`（与 batch size、头数还要再相乘）。序列长度足够长时，注意力矩阵本身的显存占用可能超过模型参数占用的显存。这个瓶颈正是 Flash Attention、稀疏注意力、线性注意力等"长上下文"技术方向要解决的核心问题（具体优化技术属于另一话题，这里只指出问题根源）。

## 5. 最小可运行实现：numpy 实现单头与多头注意力前向

```python
"""
用 numpy 实现缩放点积注意力的前向计算：
  1. 单头注意力，验证 softmax 和缩放的数值效果
  2. 多头注意力，验证参数量与头数无关的性质
仅依赖 numpy，注释用中文。
"""
import numpy as np


def softmax(x, axis=-1):
    """数值稳定的 softmax：先减去每行最大值再算 exp，避免溢出"""
    x_shifted = x - np.max(x, axis=axis, keepdims=True)
    exp_x = np.exp(x_shifted)
    return exp_x / np.sum(exp_x, axis=axis, keepdims=True)


def scaled_dot_product_attention(Q, K, V, mask=None):
    """
    缩放点积注意力: Attention(Q,K,V) = softmax(Q·K^T / sqrt(d_k)) · V
    Q, K, V 形状: [序列长度, d_k]（这里演示不带 batch 维度的单样本版本）
    """
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)   # 缩放点积，核心：除以 sqrt(d_k)
    if mask is not None:
        scores = np.where(mask, -1e9, scores)
    weights = softmax(scores, axis=-1)   # 每一行是一个概率分布
    output = weights @ V
    return output, weights


def multi_head_attention(X, num_heads, d_model, seed=0):
    """
    多头注意力前向计算：
    X: 输入序列，形状 [序列长度, d_model]
    拆分成 num_heads 个头，每个头维度 d_k = d_model / num_heads，独立算注意力后拼接
    """
    assert d_model % num_heads == 0, "d_model 必须能被 num_heads 整除"
    d_k = d_model // num_heads
    rng = np.random.default_rng(seed)

    heads_output = []
    all_weights = []
    for h in range(num_heads):
        W_Q = rng.normal(0, 0.1, (d_model, d_k))
        W_K = rng.normal(0, 0.1, (d_model, d_k))
        W_V = rng.normal(0, 0.1, (d_model, d_k))

        Q, K, V = X @ W_Q, X @ W_K, X @ W_V
        head_out, weights = scaled_dot_product_attention(Q, K, V)
        heads_output.append(head_out)
        all_weights.append(weights)

    # 拼接所有头的输出，形状从 [seq_len, d_k]*num_heads 变成 [seq_len, d_model]
    concat_output = np.concatenate(heads_output, axis=-1)

    # 输出投影 W_O，形状 [d_model, d_model]
    W_O = rng.normal(0, 0.1, (d_model, d_model))
    output = concat_output @ W_O
    return output, all_weights


def count_multi_head_params(d_model, num_heads):
    """验证多头注意力总参数量只与 d_model 相关，与头数无关"""
    d_k = d_model // num_heads
    per_head = 3 * d_model * d_k             # 每个头: W_Q, W_K, W_V 各 d_model x d_k
    total_heads = num_heads * per_head
    w_o = d_model * d_model                  # 输出投影 W_O
    return total_heads + w_o


if __name__ == "__main__":
    rng = np.random.default_rng(42)
    seq_len, d_model, num_heads = 5, 8, 2

    X = rng.normal(0, 1, (seq_len, d_model))

    print("=== 单头缩放点积注意力（不带缩放 vs 带缩放，对比 softmax 分布） ===")
    d_k = d_model
    Q = X @ rng.normal(0, 1, (d_model, d_k))
    K = X @ rng.normal(0, 1, (d_model, d_k))
    V = X @ rng.normal(0, 1, (d_model, d_k))

    raw_scores = Q @ K.T                      # 不缩放
    scaled_scores = Q @ K.T / np.sqrt(d_k)     # 缩放

    print("不缩放分数的标准差:", np.std(raw_scores).round(3))
    print("缩放后分数的标准差:", np.std(scaled_scores).round(3))
    print("不缩放 softmax 第一行（更容易接近 one-hot）:",
          softmax(raw_scores, axis=-1)[0].round(3))
    print("缩放后 softmax 第一行（更平滑）:      ",
          softmax(scaled_scores, axis=-1)[0].round(3))

    print("\n=== 多头注意力前向 ===")
    output, weights = multi_head_attention(X, num_heads=num_heads, d_model=d_model)
    print("输入形状:", X.shape)
    print("多头注意力输出形状:", output.shape)
    print("头数:", num_heads, " 每个头的注意力权重矩阵形状:", weights[0].shape)

    print("\n=== 参数量验证：与头数无关 ===")
    for h in [1, 2, 4, 8]:
        if d_model % h == 0:
            params = count_multi_head_params(d_model, h)
            print(f"  头数={h}: 总参数量={params}")
```

实测输出（numpy 2.4.4）：

```
=== 单头缩放点积注意力（不带缩放 vs 带缩放，对比 softmax 分布） ===
不缩放分数的标准差: 6.872
缩放后分数的标准差: 2.43
不缩放 softmax 第一行（更容易接近 one-hot）: [0.002 0.672 0.    0.    0.326]
缩放后 softmax 第一行（更平滑）:       [0.066 0.517 0.015 0.002 0.4  ]

=== 多头注意力前向 ===
输入形状: (5, 8)
多头注意力输出形状: (5, 8)
头数: 2  每个头的注意力权重矩阵形状: (5, 5)

=== 参数量验证：与头数无关 ===
  头数=1: 总参数量=256
  头数=2: 总参数量=256
  头数=4: 总参数量=256
  头数=8: 总参数量=256
```

结果验证了两个核心结论：

1. **缩放效果**：不缩放时分数标准差 6.872，softmax 后已出现权重高度集中（`[0.002, 0.672, 0, 0, 0.326]`）；缩放后标准差降到 2.43，softmax 更平滑（`[0.066, 0.517, 0.015, 0.002, 0.4]`）。这里 `d_k=8` 不算高，真实模型 `d_k` 通常 64 以上，未缩放时权重集中效应会更极端。
2. **参数量与头数无关**：头数从 1 变到 8，总参数量始终是 256（`d_model=8` 时，`4×64=256`），与第 3 节推导一致。

## 6. 小结

| 组件 | 核心作用 | 关键设计要点 |
| --- | --- | --- |
| 缩放点积注意力 | 让任意两位置直接建立联系，替代 RNN 的顺序传递 | 除以 `sqrt(d_k)` 抵消点积方差随维度线性增长，避免 softmax 梯度饱和 |
| 多头注意力 | 让模型同时学习多种不同类型的依赖关系 | 参数量只与 `d_model` 相关（`4×d_model²`），与头数无关 |
| 复杂度瓶颈 | 长序列场景下的计算与显存代价 | `Q·Kᵀ` 及其存储都是 `O(n²)`，是长上下文技术要解决的核心问题 |
