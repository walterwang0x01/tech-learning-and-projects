## 📌 头条

### Gemma 4 用多 token 预测 drafter 把推理速度直接拉起来

Google 今天放出 Gemma 4 的推理加速博客（HN 454 分 / 200 评论），把多 token 预测（MTP）drafter 正式推到开源主线——推测式解码不再是研究话题，而是写进了 Gemma 的官方工具链。实测场景下，长输出任务的端到端延迟可以压下来一大截，尤其是那些此前被 Agent 循环里的"多轮小调用"拖慢的管线。对自建推理栈或者跑 Gemma/Llama 家族的团队来说，这是本周最值得拿来复用的工程实践——不需要换模型，换一个 draft 路径就能拿到显著加速。想做 Agent 成本优化的朋友，先把你推理侧的 p95 测一遍，再看 MTP 能救多少。

→ [Google 官方博客](https://blog.google/innovation-and-ai/technology/developers-tools/multi-token-prediction-gemma-4/) / [HN 讨论](https://news.ycombinator.com/item?id=48024540)

### Computer Use 比结构化 API 贵 45 倍，Reflex 给出第一份定量对账

Reflex 团队发了篇 HN 321 分的硬核对比：同一任务用 Anthropic Computer Use / 浏览器 Agent 走视觉路径，比用结构化 API 贵 45 倍，延迟也同一个量级地糟。作者追出来的根因是每一屏截图 + HTML 注释都在吃 token，外加反复重试。结论很直白——如果目标系统有 API，永远别用 Computer Use；只有在真找不到 API 的"最后一公里"才调它。这跟昨天 Anthropic "Decoupling brain from hands" 和前几天的 Cloudflare Code Mode MCP 是同一个潮流：Agent 的经济学从"怎么让它能做"走到了"怎么让它算得过账"。

→ [Reflex 原文](https://reflex.dev/blog/computer-use-is-45x-more-expensive-than-structured-apis/) / [HN 讨论](https://news.ycombinator.com/item?id=48024859)
