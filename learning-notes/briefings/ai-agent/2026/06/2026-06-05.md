## 📌 头条

### OpenAI 发布 Dreaming V3：ChatGPT 记忆系统彻底重构

OpenAI 正式上线 Dreaming V3 记忆系统——ChatGPT 不再依赖用户主动说「记住这个」，而是在后台自动从对话历史中合成结构化记忆档案，按工作、兴趣、旅行偏好等维度分类存储。计算开销降低 80%，解决了旧系统「记忆过时」和「遗忘」两大痛点。目前 Plus/Pro 用户可用，Free 用户即将跟进。对你意味着什么：如果你在做 agent 的 memory 模块，Dreaming V3 的「后台异步合成 + 分类归档」模式值得参考——这比 RAG 式逐条存储在连续对话场景更高效。

→ [OpenAI 官方博客](https://openai.com/index/chatgpt-memory-dreaming)

### LangGraph 容错三件套：生产 Agent 不再裸奔

LangChain 发布 LangGraph 容错机制详解：RetryPolicy（指数退避自动重试）、TimeoutPolicy（wall-clock + idle 两种超时策略）、error_handler（重试耗尽后的清理逻辑）。三者可组合，配合 SAGA 模式处理多步 workflow 中的副作用回滚。这解决了生产 agent 最常见的问题——原型阶段不会遇到的网络抖动、工具超时、级联失败。对你意味着什么：如果你用 LangGraph 跑生产 agent，现在可以在 workflow 定义里直接声明 retry/timeout/cleanup，不用自己套 try-catch。

→ [LangChain Blog](https://www.langchain.com/blog/fault-tolerance-in-langgraph)

## 📈 趋势

- 🆕 Agent Memory 正在从「被动存储」转向「主动合成」——OpenAI Dreaming V3 和多篇 arXiv 论文都在解决同一个问题：agent 如何在超长时序中维护准确、不过时的记忆
- 🔺 MCP 安全债务加速暴露——tool poisoning、description-code 不一致、跨会话 prompt injection 三重威胁并发，生产部署 MCP 的团队需要立即审计 tool 描述的真实性
- 🔺 容错与可观测性成为 agent 框架竞争焦点——LangGraph 的 RetryPolicy/TimeoutPolicy、Anthropic 的沙箱隔离，都说明生产化阶段的核心问题不是「能不能跑」而是「坏了怎么办」
