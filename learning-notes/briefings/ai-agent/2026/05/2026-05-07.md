### Code with Claude 大会：Managed Agents 新增 dreaming + multi-agent 编排，Claude Code 算力翻倍

Anthropic 在 5/6 的 Code with Claude 大会上一口气端出多个东西：Managed Agents 获得 **dreaming**（离线回看历史 session、提取模式、curate 长期记忆）、**outcomes**（评测结果闭环）、**multiagent orchestration**（原生子 Agent 编排）和 **webhooks**。配套发了 [Claude Code routines](https://claude.com/blog/introducing-routines-in-claude-code)——把一次性 prompt 打包成可被 cron、API 或 GitHub webhook 触发的云端自动化。同一天宣布和 SpaceX 在孟菲斯的 **Colossus 1** 签下 300MW / 22 万张 NVIDIA GPU 的独占合约，顺势把 Claude Code 的五小时速率限制直接翻倍，Opus API 也显著放宽。这一整套组合拳把前几天的方法论（"脑手分离" Managed Agents、Harness Profile）具象化成了今天就能用的能力：dreaming 让 Agent 真有了"今晚想想昨天的事"的能力，multi-agent orchestration 让你不用自己缝 supervisor 就能跑协作流水线。如果你在 Claude Code 上做事，今天先去把 routines 试一下——把重复的 code review / 依赖升级 / backlog 分拣搬进 routine，再观察一周能省多少手工操作。

### OpenAI 把 MRC 网络协议交给 OCP：GPU 间的"RDMA 多路径"正式成为行业标准

OpenAI 联合 AMD、Broadcom、Intel、Microsoft、NVIDIA 把 **Multipath Reliable Connection (MRC)** 开源到 Open Compute Project。这是一个 RDMA 传输协议，让单条连接同时跑在数百条网络路径上，遇到链路故障能在微秒级检测并切换。背景是大模型训练的 GPU 互联越做越大，传统 RoCEv2 的单路径容易被尾延迟和单点故障拖慢。NVIDIA 同步把 MRC 塞进了 Spectrum-X Ethernet fabric。这事对应用层开发者短期没直接影响，但关乎未来一年 inference 集群的弹性和成本：多路径传输把"网络瘫痪 → 训练任务中断"的成本显著压下，对 Anthropic/OpenAI 这类超大规模 RL/推理负载是基础设施拐点。如果你的 Agent 架构跑在自建集群或 colo 上，值得关注 MRC 在 OCP 里的演进，明年的 IB/NIC 选型会绕不开它。

→ [OpenAI 公告](https://openai.com/index/mrc-supercomputer-networking) / [AMD 技术解析](https://www.amd.com/en/blogs/2026/next-gen-networking-transport-for-large-scale-ai-training.html) / [Microsoft 工程博客](https://techcommunity.microsoft.com/t5/azure-high-performance-computing/building-resilient-networks-for-ai-supercomputers/ba-p/4516919)
