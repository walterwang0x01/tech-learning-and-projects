## 📌 头条

### MCP 2026-07-28 规范 RC：协议核心彻底无状态化

Model Context Protocol 官方放出了 2026-07-28 版本规范的 release candidate，这是过去一年里最大一次结构性改动。核心是把 protocol core 拆成无状态形态，长期运行能力外移到新的 Tasks 和 MCP Apps 扩展，授权侧加固（resource indicators 强校验、PKCE 必选），还引入了 Extensions 框架和正式的 deprecation policy。对企业部署是好消息——无状态核心意味着 MCP server 可以像普通 HTTP 服务一样横向扩展、放在 stateless edge 上跑，不用再被 SSE 长连接绑死；对你写 server 是迁移工作量——长任务要走 Tasks 扩展，老的 long-running tool call 模型会被弃用。建议本周就把现有 MCP server 跑一遍 RC 兼容检查，别等 GA 才发现要重写状态层。

→ [MCP 官方公告](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/) / [AWS MCP Server GA](https://aws.amazon.com/about-aws/whats-new/2026/05/aws-mcp-server/)

### DeepSeek V4 Pro 75% 折扣转永久，Reasonix 同日上线

Bloomberg 和 HN 同步爆出 DeepSeek 把 V4 Pro 旗舰模型的 75% 折扣价直接做成永久定价，再叠加同日开源的 DeepSeek Reasonix——一个 DeepSeek 原生的终端编码 agent，cache-first 循环、flash-first 成本控制、自动工具调用修复，直连 api.deepseek.com 不走任何翻译层。组合起来对成本敏感的 agent 团队是个分水岭：V4 Pro 的 1M context 起步、KV cache 只用 V3.2 的 10%，配上 Reasonix 的内建缓存策略，做长轨迹任务的单 trace 成本可以压到 Claude/GPT 系的几十分之一。如果你的 coding agent 还跑在闭源模型上，这周就该把 Reasonix + V4 Pro 拉进 A/B，看长任务成败率有没有掉。

→ [Bloomberg](https://www.bloomberg.com/news/articles/2026-05-23/deepseek-to-make-permanent-75-discount-on-flagship-ai-model) / [Reasonix 文档](https://api-docs.deepseek.com/quick_start/agent_integrations/reasonix) / [Reasonix 站点](https://esengine.github.io/DeepSeek-Reasonix)
