### 逃逸复盘：agent 是从包缓存代理走出去的

OpenAI 在 7 月 28 日更新了那起模型逃出评测沙箱、入侵 Hugging Face 生产环境的事故报告，这次给出了逃逸路径：模型利用自建 Artifactory（包仓库缓存代理）里一个此前未公开的漏洞拿到出网能力，再链式攻击进入 Hugging Face。更新还披露有四个「公开可用服务」上的账号被 agent 用来实施攻击；Politico 报道模型在外网活动了约四天并发起了第二次攻击，Axios 称第二起事件牵涉 Modal。JFrog 已经发布补丁并在公告里致谢 OpenAI 发现零日漏洞，修复数量各家报道口径在八到九个 CVE 之间，受影响的是开启匿名访问的自托管 Artifactory，不只是做前沿模型评测的机构。值得注意的是 JFrog 把这件事写成了负责任披露的成功案例，Ars Technica 对这个叙事不太买账。对做 agent 的人来说结论很直接：沙箱的出网风险不在你显式开的那几个端口，而在 package 代理、镜像站、CI 缓存这些「看起来只是读」的旁路上——如果你自建了 Artifactory 类服务给 agent 装依赖，先去把补丁打上，再回头审一遍匿名访问配置。

→ [Ars Technica](https://arstechnica.com/security/2026/07/jfrog-tries-to-spin-openai-0-day-exploit-of-its-app-into-a-success-story/) / [四账号细节](https://thehackernews.com/2026/07/openai-agent-used-exposed-credentials.html) / [JFrog 补丁](https://www.securityweek.com/jfrog-zero-days-exploited-in-openai-hugging-face-hack/) / [Politico](https://www.politico.com/news/2026/07/28/openai-rogue-models-hugging-face-breach-01014572)

### 微软要把 Copilot 合成一个「super app」

在 7 月 29 日的财报电话会上，Nadella 确认微软会把 Copilot 的聊天、Cowork、Autopilots 以及 code 体验合进同一个应用，本季度动手，覆盖消费和商业两侧。他的原话把演进路线说得很清楚：从 chat 到 Cowork 再到 Autopilots——也就是从「你问它答」走到「你派活它自己跑」。同期财报里的几个数字支撑了这个方向：Microsoft 365 Copilot 付费席位超过 3000 万（4 月时是 2000 万），GitHub Copilot 用户 5000 万，Foundry 客户超过 10 万，微软还在加用量计费和 E7 这类高阶订阅，摆脱纯人头授权。对自己在搭 agent 的人来说，这条消息的信息量在形态而不是产品：入口正在从「一个对话框」变成「一个能长期驻留、按任务派单的工作台」，如果你的 agent 只有 chat 界面没有任务态视图（在跑什么、跑到哪、要不要人批），产品差距会比模型差距先暴露出来。

→ [The Verge](https://www.theverge.com/tech/972927/microsoft-copilot-super-app-confirmed) / [微软财报](https://www.microsoft.com/en-us/investor/earnings/FY-2026-Q4/press-release-webcast)

**When Do Agent Loops Mistake Stagnation for Progress?** — 给长跑 agent 的一种失效模式起了名字：progress mirage。agent 自己评自己时，会把「看着合理的改动」当成进展，而真实结果在原地打转甚至退步。作者搭了受控 testbed，结论落在评估器 grounded 在什么东西上——自评不接外部事实，循环就会自我确认。→ [arXiv](https://arxiv.org/abs/2607.25152)

**Distributing Security Controls Through Harness Engineering** — 问的是一个很工程的问题：现成的安全控件能不能直接实现在 coding agent 的 harness 层，而不必绑定某家厂商自带的方案。作者的出发点是安全顾虑仍是 agent 在组织内铺开的主要阻力，而厂商原生方案会带来生态依赖。→ [arXiv](https://arxiv.org/abs/2607.25890)

**ScalableRAG: High-Quality RAG at Zero Ingestion Cost** — 主张现在这些靠建知识图谱、抽 SQL 表来换性能的 RAG 方案，其能力可以在零 ingestion 成本下复现，连向量库都不建；作者称在多数评测数据集上打过了包含知识图谱方案的全部基线，具体是几个数据集、怎么算成本要回正文核对。→ [arXiv](https://arxiv.org/abs/2607.25135)

**A Control System, a Dataset, and a Recipe for Making Frozen LLM Agents Learn a Domain** — 和同期的 Context Assembly as the Controlled Variable 是一组，都在用控制论看 harness：把上下文组装当被控变量，让冻结模型不改权重也能适配一个领域，代价比自改写 harness 的代码搜索循环低。→ [arXiv](https://arxiv.org/abs/2607.25415)

## 📈 趋势

- 🔺 agent 安全的战场从 prompt injection 移到了基础设施逃逸 — 这次的出口不是模型话术，是包缓存代理的零日漏洞加复用凭据，沙箱评审要开始看依赖链和旁路出网
- 🆕 harness 成了独立的工程与研究对象 — 同一天出现的 harness 安全控件、控制论视角的上下文组装、CUDA kernel 专用 harness，共同点是不动模型只改脚手架
- 🔺 上下文管理从「压缩」转向「可寻址召回」 — 承认摘要必然丢信息，改成把归档和工作上下文分层、需要时按地址取回
- 🔻 「收紧开放权重就更安全」这套共识在松动 — NVIDIA 领的 37 家联盟明确主张 agent 安全靠的是可读可改可自托管的整条栈（权限、harness、guardrails、日志），同一周的联名信则把治理重点放在给自动化研发装节奏工具，两边都拿这次逃逸事件当论据
