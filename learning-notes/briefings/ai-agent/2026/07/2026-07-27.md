## 📌 头条

### Anthropic 砍掉 Claude Code 八成系统提示

Anthropic 7 月 24 日公布了 Claude 5 代模型（Opus 5 / Sonnet 5 / Fable 5）的 context engineering 新规则：他们把 Claude Code 的系统提示删掉了 80% 以上，编码评测没有出现可测量的下降。逻辑很直白，过去为了兜住模型能力写的那一大堆「不要做 X」「记得先读文件」的规训，在新一代模型上从收益变成了噪声，反而挤占了本该留给真实代码的 token 预算。同一波讨论里还有个细节值得留意：有人在 Claude Code 里翻出硬编码指令，明确告诉 Opus 5 不要动 subagent，说明官方自己也在收紧默认编排层级。这件事对你意味着一次实打实的减法作业——把 CLAUDE.md、自建 agent 的 system prompt、还有那些堆了半年的 few-shot 例子拉出来，删掉解释模型已经会的部分，只留项目独有的约定和工具契约，然后跑一遍你自己的 eval 看有没有掉点。

→ [Anthropic 博客](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models) / [subagent 硬编码讨论](https://old.reddit.com/r/ClaudeCode/comments/1v6y5q2/claude_code_has_a_hardcoded_instruction_telling)

### MCP 新规范明天定稿：协议转向无状态

MCP 2026-07-28 规范明天正式转正，这是协议诞生以来最大一次改动：协议核心彻底无状态，去掉 initialize 握手和 session id，版本与能力信息改为每个请求自带；同时引入 Extensions 框架、Tasks、MCP Apps，并重写授权模型，旧版本给 12 个月弃用窗口。无状态化的直接好处是 MCP server 终于能按普通 HTTP 服务那套来做负载均衡、重试、缓存和可观测，不用再为 sticky routing 折腾网关。但安全面是双刃剑，Akamai 的分析指出协议级 session hijacking 这类漏洞被消灭了，代价是鉴权与网络层的责任更多压到实现方自己身上。如果你手里有自建 MCP server，这周值得做的事是：确认 SDK 版本能跟上 2026-07-28，把去掉握手后的 client 兼容路径过一遍，顺手检查授权逻辑有没有依赖已被废弃的 session 语义。

→ [官方 RC 公告](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/) / [安全影响分析](https://www.securityweek.com/new-enterprise-ready-mcp-specification-brings-new-security-challenges/)

## 📈 趋势

- 🔺 context engineering 从「加提示」转向「减提示」，删掉模型已经会的规训成了主流优化手段
- 🆕 MCP 无状态化落地，agent 基建开始按普通 HTTP 服务的运维范式来建
- 🔺 agent 安全的威胁模型从 prompt injection 升级到自主横向渗透，沙箱隔离本身成了被攻破的对象
- 🔺 长程 agent 的成本与状态管理工具化：token profiler、KV cache offload、增量 checkpoint 同期出现
