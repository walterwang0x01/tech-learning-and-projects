## 📌 头条

### Kimi K3 开权重，顺手把 Agent 训练基建也开了

月之暗面 7 月 27 日晚在 Kimi K3 开放日放出模型权重和技术报告：2.8 万亿总参数的 MoE，约 1040 亿激活参数，原生视觉理解，100 万 token 上下文，架构基于自研的 Kimi Delta Attention 与 Attention Residuals。这是业界第一个进入 3T 级别的开放权重模型，距离 7 月 16 日以托管 API 形式首发只隔了 11 天。对做 agent 的人来说，比权重更值得看的是同时开源的三件训练基建：MoonEP、FlashKDA 和 AgentEnv。官方只列了名称未作说明，但如果 AgentEnv 确实是 agent 训练环境，那长程 agent 的 RL 训练链路第一次有了来自前沿实验室的开源参考。要真跑起来门槛不低，官方建议 64 张以上加速器的超节点配置，社区实测加载量级在数百 GB 到 1.4TB 之间，取决于量化方案；另外许可里带按收入分层的商用条款，接到产品里之前先把这段读完。现实一点的动作是先在托管 API 上跑通你的 agent 评测集，再决定值不值得自建推理。

→ [官方博客](https://www.kimi.com/blog/kimi-k3) / [开源中国](https://www.oschina.net/news/481061) / [许可条款分析](https://xenospectrum.com/en/kimi-k3-open-weights-revenue-tiered-license/)

### MCP 无状态规范今天转正，SDK 已就位

MCP 2026-07-28 规范今天正式定稿，协议核心转为无状态：initialize/initialized 握手和协议级 session 全部移除，版本与能力信息改由每个请求自带，同时落地 Extensions 框架、Tasks、MCP Apps 和收紧后的授权模型，旧版本有 12 个月弃用窗口。生态跟进比规范本身更能说明进度：Cloudflare Agents SDK v0.20.0 已经改用新 client，对每个连接先用 server/discover 探测，探测失败才回落旧握手；GitHub MCP Server 在 7 月 23 日就提前支持了新规范；Pydantic 放出 MCP Python SDK v2 beta；Azure Functions 那边则给出了用 Tasks 扩展承载长运行工具调用的范式。落到你自己的 server 上，本周该做的是三件事：升级 SDK 到支持 2026-07-28、把网关上为 session 做的 sticky routing 和 Redis 会话存拆掉、检查授权逻辑有没有偷偷依赖 session 语义。

→ [官方博客](https://blog.modelcontextprotocol.io/posts/) / [Cloudflare Agents SDK](https://developers.cloudflare.com/changelog/post/2026-07-27-agents-sdk-v0.20.0-mcp-sdk-v2/) / [GitHub MCP Server](https://github.blog/changelog/2026-07-23-github-mcp-server-supports-the-next-mcp-specification) / [Pydantic SDK v2](https://pydantic.dev/articles/mcp-python-sdk-v2-beta)

## 📦 项目 & 论文

| 项目 | 描述 | 链接 |
|------|------|------|
| AgentEnv / MoonEP / FlashKDA | Kimi K3 随权重一起开源的三件训练基建，官方仅公布名称；AgentEnv 若为 agent 训练环境，长程 agent 的 RL 链路就有了前沿实验室的参考实现 | [→](https://www.kimi.com/blog/kimi-k3) |
| AgentKVShift | agentic memory 每次检索都要把带摘要和标签的记忆单元全量重编码成 KV，这篇做 KV cache 复用把这块推理开销砍下来 | [→](https://arxiv.org/abs/2607.21604) |
| SwiftMem | 指出现有记忆框架即使底层用了 HNSW，检索仍是 query-agnostic 地扫全量 embedding 空间，改成 query-aware 索引提速 | [→](https://arxiv.org/abs/2601.08160) |
| FlowEvo | agent 执行中摸索出的有用流程通常是一次性的，用完就丢；这套方案让 workflow 和可执行 skill 协同演化，把过程沉淀下来 | [→](https://arxiv.org/abs/2607.21596) |
| Nanbeige4.2-3B | 3B 非嵌入参数的紧凑 agentic 模型，从零预训练 28T token，主打 code-agent / office-agent 和复杂工具调用 | [→](https://arxiv.org/abs/2607.22083) |
| Dynamic Capability Scoping | 企业 agent 通常在配置期就拿到角色可能用到的全部工具凭证，这篇把动态最小权限当成事前预防机制来设计，附合成数据集 | [→](https://arxiv.org/abs/2607.22445) |

**The Regression Tax: Decomposing Why Skills Help and Hurt LLM Agents** — 给 agent 加 procedural skill 通常只看平均成功率提升，这篇跨两个办公自动化 benchmark、三套 model harness 做了近 6000 次运行，把「skill 也会让 agent 变差」这部分成本单独量化出来。→ [arXiv](https://arxiv.org/abs/2607.22520)

**Do Agent Benchmarks Measure Capability? Protocol Validity in the Age of Agentic AI** — agent 评测覆盖仓库编辑、网页调研、终端操作，但分数只在评测协议真的让目标能力成为成功必要条件时才成立；作者指出 agent 常靠翻出公开解法等捷径过关，给出协议有效性的判据。→ [arXiv](https://arxiv.org/abs/2607.22368)
