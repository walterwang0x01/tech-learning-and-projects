## 2. Dockerfile 安全

```dockerfile
# ❌ 反模式
FROM ubuntu:latest             # 太大、有很多未用的东西
WORKDIR /app
COPY . .
RUN apt-get update && apt-get install -y ...   # 层缓存差
RUN pip install -r requirements.txt
USER root                       # 默认 root
CMD ["python", "app.py"]

# ✅ 推荐
# 多阶段 + distroless + 非 root
FROM python:3.14-slim AS builder
WORKDIR /build
COPY requirements.txt .
RUN pip install --user --no-cache-dir -r requirements.txt

FROM gcr.io/distroless/python3-debian12:nonroot
WORKDIR /app
COPY --from=builder /root/.local /home/nonroot/.local
COPY app.py .
USER nonroot:nonroot
ENV PATH=/home/nonroot/.local/bin:$PATH
ENTRYPOINT ["python", "app.py"]
```

**关键点**：
- 基础镜像：`distroless`、`alpine`、`scratch`
- 非 root 用户
- 多阶段丢掉构建工具
- 不要 `ADD URL`（用 COPY + 校验 hash）
- 不装不必要的工具（没有 curl、wget、bash）

## 3. 镜像扫描

```bash
# Trivy（最全）
trivy image python:3.14-slim --severity HIGH,CRITICAL

# Grype
grype python:3.14-slim

# Docker Scout（Docker Desktop 内置）
docker scout cves python:3.14-slim

# 在 CI 中硬门禁
trivy image --severity HIGH,CRITICAL --exit-code 1 myapp:latest
```

## 4. 镜像签名（Sigstore）

```bash
# 用 GitHub OIDC 身份签名（无密钥）
cosign sign --yes ghcr.io/myorg/myapp:v1.0.0

# K8s 中强制验证（Kyverno）
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: verify-images
spec:
  validationFailureAction: Enforce
  rules:
    - name: check-signature
      match:
        any:
          - resources: {kinds: [Pod]}
      verifyImages:
        - imageReferences: ["ghcr.io/myorg/*"]
          attestors:
            - entries:
                - keyless:
                    subject: "https://github.com/myorg/*"
                    issuer: "https://token.actions.githubusercontent.com"
```

详见 [05-供应链安全.md](./05-供应链安全.md)。

## 5. Pod Security Standards（PSA）

K8s 1.25+ 内置的三级标准：

```
Privileged     最宽松（kube-system）
Baseline       默认（阻止最危险的设置）
Restricted     最严格（生产推荐）
```

```yaml
# 给 namespace 打标签强制标准
apiVersion: v1
kind: Namespace
metadata:
  name: production
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/warn: restricted
```

**Restricted 标准要求**：

```yaml
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    fsGroup: 1000
    seccompProfile: {type: RuntimeDefault}
  containers:
    - name: app
      securityContext:
        allowPrivilegeEscalation: false
        privileged: false
        readOnlyRootFilesystem: true
        capabilities:
          drop: [ALL]
      resources:
        requests: {cpu: 100m, memory: 128Mi}
        limits: {cpu: 500m, memory: 512Mi}
```

## 6. RBAC 最小权限

```yaml
# 只读权限
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: production
  name: pod-reader
rules:
  - apiGroups: [""]
    resources: [pods, pods/log]
    verbs: [get, list, watch]

---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: production
subjects:
  - kind: User
    name: alice
    apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**反模式**：
- 给 ServiceAccount 绑定 `cluster-admin`
- 使用 `*` 资源或动词
- 共用一个 SA（每个应用应该有自己的 SA）

## 7. NetworkPolicy（强烈推荐）

默认 K8s 里所有 Pod 可以互相通信。**生产必须启用 NetworkPolicy**：

```yaml
# 默认禁止
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: production
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]

---
# 白名单：只允许 frontend 访问 backend
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-backend
  namespace: production
spec:
  podSelector:
    matchLabels: {app: backend}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector:
            matchLabels: {app: frontend}
      ports:
        - protocol: TCP
          port: 8080
```

Cilium、Calico 提供的 NetworkPolicy 比标准版功能更丰富（DNS 策略、L7）。

## 8. Admission Control：Kyverno 或 OPA Gatekeeper

在资源创建前拦截不合规的：

```yaml
# Kyverno：强制所有 Deployment 有 resources.limits
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-resources
spec:
  validationFailureAction: Enforce
  rules:
    - name: check-resources
      match:
        any:
          - resources: {kinds: [Deployment, StatefulSet]}
      validate:
        message: "CPU and memory limits are required"
        pattern:
          spec:
            template:
              spec:
                containers:
                  - resources:
                      limits:
                        memory: "?*"
                        cpu: "?*"
```

其他常见策略：
- 不允许 latest tag
- 必须有 Owner 标签
- 只能从可信 Registry 拉镜像
- 不允许 privileged 容器
- 必须有 NetworkPolicy

## 9. Secrets 安全

K8s 原生 Secret **不是加密的**，只是 base64 编码。必须：

```
├─ 启用 Encryption at Rest（etcd 加密）
├─ RBAC 严格（只有必要的 SA 能访问）
├─ 用 External Secrets Operator 拉取 Vault / AWS SM
├─ 不要把 Secret 放到 ConfigMap
└─ 不要 Secret 进 Git（即使 Base64 编码）
```

## 10. 运行时安全：Falco

eBPF 监控异常行为：

```yaml
# Helm 安装
helm install falco falcosecurity/falco

# 规则：检测 shell in container
- rule: Shell in container
  desc: A shell was spawned in a container
  condition: >
    spawned_process and container
    and shell_procs and proc.tty != 0
  output: >
    Shell spawned in container (user=%user.name
    container_id=%container.id image=%container.image.repository)
  priority: WARNING
```

类似工具：Sysdig、Aqua Runtime、Tracee。

K8s 的安全基线测试：

```bash
# kube-bench 自动扫描节点
docker run --rm --pid=host -v /etc:/etc:ro -v /var:/var:ro \
    aquasec/kube-bench:latest run --targets=node

# 会输出未达标项

```

AWS/GCP/Azure 托管 K8s 默认已通过大部分 CIS 项。

## 12. 容器逃逸防护

```
威胁：
├─ 攻陷 Pod → 逃到节点 → 控制整个集群
├─ 挂载敏感宿主路径（/、/var/run/docker.sock）
├─ 提权漏洞（Dirty Cow、PwnKit）
└─ Kernel exploit

防护：
├─ 不运行 privileged 容器
├─ 不挂载 docker.sock
├─ drop 所有 capabilities，按需添加
├─ readOnlyRootFilesystem: true
├─ 定期打 OS 补丁
├─ Kata Containers / gVisor（强隔离）
└─ SELinux / AppArmor 启用
```

## 14. Kubernetes 1.36 安全增强（2026-04-22）

> 🔄 更新于 2026-05-14

K8s 1.36 "ハル (Haru)" 是 2026 年首个大版本，包含 70 项改进（18 stable、25 beta、25 alpha），安全相关的重点：

### 14.1 Declarative Validation GA

ValidatingAdmissionPolicy 正式 GA，无需 Webhook 即可用 CEL 表达式验证资源：

```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicy
metadata:
  name: require-labels
spec:
  matchConstraints:
    resourceRules:
      - apiGroups: ["apps"]
        apiVersions: ["v1"]
        operations: ["CREATE", "UPDATE"]
        resources: ["deployments"]
  validations:
    - expression: "has(object.metadata.labels) && 'app.kubernetes.io/name' in object.metadata.labels"
      message: "Deployment must have app.kubernetes.io/name label"
```

**优势**：比 Webhook 延迟低、无外部依赖、CEL 表达式可审计。

### 14.2 Manifest-Based Admission Control

不可删除的 Admission Policy——策略以 manifest 形式嵌入集群配置，即使 cluster-admin 也无法通过 API 删除：

```
适用场景：
├─ 合规要求（SOC 2、PCI DSS）
├─ 防止内部人员绕过安全策略
└─ 多租户集群的强制隔离
```

### 14.3 Fine-Grained Kubelet API Authorization GA

Kubelet API 细粒度授权正式 GA：

```
之前：能访问 kubelet API = 能看所有 Pod 信息
现在：按 Pod/Container 级别控制 kubelet API 访问
```

### 14.4 PSI Metrics GA + Node Conditions

Pressure Stall Information（PSI）指标正式 GA，kubelet 可以基于 PSI 设置 node conditions：

```yaml
# kubelet 配置
pressureStallInformation:
  enabled: true
  nodeConditions:
    - type: MemoryPressure
      threshold: "some avg10 > 50"
```

### 14.5 AI/GPU 工作负载安全

K8s 1.36 新增 Workload-Aware Preemption（alpha），将 AI 训练 PodGroup 作为一个抢占单元处理，避免部分 Pod 被驱逐导致整个训练任务失败。

### 14.6 版本选择建议

| 场景 | 推荐版本 |
| ---- | -------- |
| 新集群 | K8s 1.36（最新安全特性） |
| 生产稳定 | K8s 1.35.x（上一个稳定版） |
| 托管服务 | 跟随云厂商推荐版本 |
