
## 3. A01 Broken Access Control（访问控制失败）

**仍然是第一**。常见问题：

```
├─ IDOR（Insecure Direct Object Reference）：修改 URL 里的 ID 就能看别人数据
├─ 缺少权限检查（直接调 API 绕过前端）
├─ 越权：普通用户能调管理员接口
├─ JWT 未验签就信任
└─ CORS 过于宽松
```

**代码示例（Python）**：

```python
# ❌ 容易 IDOR
@app.get("/api/orders/{order_id}")
def get_order(order_id: int):
    return db.query(Order).filter_by(id=order_id).first()

# ✅ 检查所有者
@app.get("/api/orders/{order_id}")
def get_order(order_id: int, user: User = Depends(get_current_user)):
    order = db.query(Order).filter_by(id=order_id).first()
    if not order or order.user_id != user.id:
        raise HTTPException(404)
    return order

# ✅ 更好：数据库层面加约束（PG RLS）
# ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
# CREATE POLICY user_orders ON orders USING (user_id = current_user_id());
```

## 4. A02 Cryptographic Failures

```
常见问题：
├─ 用 MD5/SHA1 做密码哈希     → 改 bcrypt/argon2
├─ 自己实现加密             → 用标准库
├─ 硬编码密钥              → Secrets 管理器
├─ 静态 IV / Nonce         → 每次随机
├─ ECB 模式加密            → 用 GCM / CTR
├─ 不用 HTTPS              → 全站 HTTPS + HSTS
└─ 弱随机数（time()）       → 用 CSPRNG

推荐算法（2026）：
├─ 密码哈希：Argon2id / bcrypt
├─ 对称加密：AES-256-GCM / ChaCha20-Poly1305
├─ 非对称：Ed25519 / X25519 / RSA-4096
├─ 哈希：SHA-256 / SHA3
└─ 密钥派生：HKDF / Argon2
```

## 5. A03 Software Supply Chain Failures

2024-2026 年最热的攻击面。详见 [05-供应链安全.md](./05-供应链安全.md)。

```
关键实践：
├─ SBOM（CycloneDX / SPDX）
├─ 依赖扫描（Trivy、Snyk、Grype）
├─ 代码签名（Sigstore cosign）
├─ 锁依赖（package-lock.json、go.sum、Cargo.lock）
├─ Pin SHA，不 pin tag（GitHub Actions）
└─ Secrets 不进 Git
```

## 6. A04 Insecure Design

不是实现 bug，是**架构层面的缺陷**：

```
├─ 没有威胁建模
├─ 信任边界不明
├─ 没有速率限制
├─ 过度的数据收集
└─ 无二次验证的敏感操作（转账、删账）

对策：
├─ Threat Modeling（STRIDE）
├─ Secure by Design 培训
└─ Security Review 进入 PR 流程
```

## 7. A05 Security Misconfiguration

```
常见：
├─ 默认密码（admin/admin）
├─ 错误页暴露堆栈
├─ 云存储 Bucket 公开
├─ K8s API 暴露 + 无 RBAC
├─ 调试端点在生产（/debug、/admin）
└─ CORS 设 *

工具：
├─ Trivy Config（IaC 扫描）
├─ Checkov
├─ kube-bench（K8s CIS 基线）
└─ cloudsploit（云资源扫描）
```

## 8. A06 Vulnerable and Outdated Components

基本是 A03 的一部分。关键：

```
├─ 每周扫依赖
├─ 设 SLA（CRITICAL 24h、HIGH 7d）
├─ Dependabot / Renovate 自动 PR
└─ 废弃的包主动替换
```

## 9. A07 Exceptional Condition Handling（新）

**错误处理不当导致的安全问题**：

```
├─ 错误消息泄露堆栈 / 数据库结构
├─ 异常时默认放行（fail-open）
├─ 资源耗尽未处理（内存爆 / 连接池满）
└─ 交易失败未回滚
```

```python
# ❌ 暴露内部
try:
    result = db.query(...)
except Exception as e:
    return {"error": str(e)}  # 可能泄露表名、SQL

# ✅ 通用错误给用户，细节进日志
try:
    result = db.query(...)
except Exception as e:
    logger.exception("db query failed")
    raise HTTPException(500, "internal error")

# ❌ Fail-open（出错默认放行）
try:
    if authorize(user, resource):
        return do_action()
except:
    return do_action()  # 危险

# ✅ Fail-closed
try:
    if not authorize(user, resource):
        raise Forbidden()
except Exception:
    raise Forbidden()     # 出错也拒绝
return do_action()
```

## 10. A08 Identification and Authentication Failures

```
├─ 明文密码、弱密码策略
├─ Session Token 没过期 / 未随机
├─ 登录爆破无限制
├─ MFA 缺失或绕过
└─ Password Reset 流程不安全

2026 推荐：
├─ OAuth 2.1 + PKCE
├─ Passkey / WebAuthn
├─ Rate Limiting + 账号锁定
├─ MFA 默认启用
├─ Session 15 分钟过期 + Refresh Token 轮换
└─ Account Takeover 监测
```

详见 [02-认证与授权体系.md](./02-认证与授权体系.md)。

## 11. A09 Security Logging and Monitoring Failures

```
问题：
├─ 关键操作无日志（删账、权限变更、支付）
├─ 日志没集中（服务挂了日志也没了）
├─ 没告警（入侵了都不知道）
├─ 日志含敏感信息（密码、Token）
└─ 保留期太短（攻击者几个月前就进来了）

实践：
├─ 所有 AAA 事件入日志（认证、授权、审计）
├─ 结构化日志 + 集中（Loki / ELK）
├─ PII 脱敏
├─ 异常告警（多次失败登录、奇怪 IP）
├─ 保留 6-12 个月（合规）
└─ SIEM（Splunk / Wazuh / OpenSearch SIEM）
```

## 12. A10 Unsafe Consumption of APIs（新）

**调用第三方 API 带来的风险**：

```
├─ 盲目信任第三方响应（重定向、恶意数据）
├─ 未限制第三方调用（超时、大小）
├─ 未校验第三方证书
├─ Webhook 未验签（SSRF、伪造）
└─ SDK 过时（用了有漏洞的版本）

对策：
├─ 所有外部调用有超时
├─ 响应大小限制
├─ 证书验证必启
├─ Webhook 必验签
├─ 调用方和被调方签 SLA
└─ 熔断 + 降级
```

```python
# ❌
resp = requests.get(user_provided_url)   # SSRF 风险

# ✅
# 1. 白名单
allowed_hosts = ["api.trusted.com"]
if urlparse(url).netloc not in allowed_hosts:
    raise ValueError("URL not allowed")

# 2. 超时 + 大小
resp = requests.get(url, timeout=5, stream=True)
content = resp.raw.read(10_000_000)  # 最多 10 MB

# 3. 内网 IP 拦截
ip = socket.gethostbyname(hostname)
if ipaddress.ip_address(ip).is_private:
    raise ValueError("private IP not allowed")
```
