## 1. 时序场景为什么更容易穿越

普通监督学习假设样本**独立同分布（i.i.d.）**，随机打乱不会破坏这个假设。时序数据打破了这个前提：样本天然按时间排序，且存在自相关——`t` 时刻的值往往和 `t-1`、`t-2` 高度相关。

这个结构本身不是问题，时序建模正是要利用它。真正的风险在于：**时序特征工程的每一步操作都有机会不小心把 `t` 之后的信息混进 `t` 时刻的特征里**，而这种混入在时序里比在普通表格数据里更隐蔽，原因有三层：

```
1. 窗口边界差一位：写"过去N天"时用[:t+1]还是[:t]，一字之差就是泄露
2. 全局统计量跨越整个时间轴："历史平均评分"不按时间切片就包含未来
3. 随机划分数据集在时序上等价于用未来训练、拿过去验证
```

这三类问题在普通表格数据里几乎不存在（没有"未来"这个概念），但在时序里是默认要主动防范的头号风险。

## 2. 时间对齐的铁律

时序特征工程只有一条铁律，其余规则都是它的展开：**预测 `t` 时刻的目标，只能使用严格早于 `t`（不晚于 `t-1`）的信息**。

```
过去 ────────────────────────┼──────────────────────→ 未来
                              t（预测目标所在时刻）
可用信息区间：[ ... , t-1 ]      禁止使用：[ t, t+1, ... ]
```

任何一个特征，只要计算过程中用到了 `t` 及之后的数据，就违反了这条铁律——不管特征叫"滞后特征""窗口统计"还是"全局画像"，命名不影响铁律适用范围。

## 3. 滞后特征（lag features）

滞后特征直接把历史时刻的值平移到当前时刻作为新特征：`lag_1(t)=x(t-1)`，`lag_7(t)=x(t-7)`，`lag_30(t)=x(t-30)`。

滞后阶数（lag order）的选择依据：

- **业务周期**：日粒度常用 `lag_7`（周周期）、`lag_30`（月周期）；有星期效应的场景 `lag_7` 往往比 `lag_1` 更有信息量。
- **自相关强度**：观察序列自相关系数在不同滞后阶数下的衰减速度——衰减快说明近期滞后更重要，有周期性反弹说明该阶数对应真实周期。
- **代价**：每加一个 `lag_k` 特征，序列至少要有 `k` 个历史点才能算出非缺失值，阶数越高开头可用样本越少，需要权衡信息量和可用样本量。

## 4. 滚动窗口统计：含当前点 vs 不含当前点

滚动窗口统计（rolling window statistics）把过去 `N` 个点的聚合（均值、方差等）作为 `t` 时刻的特征，是时序特征工程里**出错率最高**的一类操作，核心是窗口边界的选择：

```
正确（不含当前点）：rolling_mean(t) = mean( x[t-N], ..., x[t-1] )
                    窗口区间 [t-N, t-1]，t 本身不参与计算

错误（含当前点）：  rolling_mean(t) = mean( x[t-N+1], ..., x[t] )
                    窗口区间 [t-N+1, t]，t 本身参与了计算
```

如果目标就是预测 `t` 时刻的值，"含当前点"版本相当于**把答案的一部分直接算进了特征里**——模型不需要真正学习历史规律，只要多做一次除法就能"预测"出接近真实值的结果，训练/验证分数会好看得虚假，一旦上线（此时 `t` 时刻真实值还不存在）就会崩掉，因为线上拿不到这个特征需要的输入。

许多现成滚动窗口 API 默认窗口右边界含当前行，直接用默认参数不做位移处理，是这个坑最常见的触发方式。

## 5. 扩展窗口与指数加权

**扩展窗口（expanding window）**：左边界固定在序列起点，右边界随 `t` 增长，用**截止到 `t-1` 的全部历史**计算统计量：`expanding_mean(t) = mean( x[0], ..., x[t-1] )`。适合历史累计类特征，缺点是早期样本太少波动大，且对久远和最近行为给了相同权重。

**指数加权（EW）**：用指数衰减权重把"越近权重越高"编码进统计量：

```
EWMA(t) = α · x(t-1) + (1-α) · EWMA(t-1)
α: 衰减系数，越大越依赖最近观测，越小历史记忆越长
```

指数加权只需维护一个累积值，不需存整个窗口，适合流式场景；同样要用 `x(t-1)` 更新而非 `x(t)`，否则依然是含当前点的泄露。

## 6. 周期性特征的三角函数编码

时间的周期性信息（星期几、小时、月份）直接用整数序号表示（周日=0,...,周六=6）会引入虚假断点：周六（6）和周日（0）数值相差 6，但真实周期上相邻。线性模型看到的是断点，丢失了首尾相接的周期结构。

三角函数编码把周期变量映射到单位圆上：

```
sin_feature = sin(2π · t / T)
cos_feature = cos(2π · t / T)
t: 周期内位置（如星期几取0-6），T: 完整周期长度（如7）
```

用一对 `(sin, cos)` 而非单独 `sin`，是因为单独 `sin` 在周期内有两个取值相同的点，组合后单位圆上每个角度对应唯一坐标，且首尾在圆上是真正相邻的两个点。

## 7. 节假日与事件特征

很多"异常"波动不是随机噪声，而是可预测的日历事件驱动，显式编码这些事件能帮模型区分结构性波动和随机噪声：

```
is_holiday, days_to_next_holiday / days_since_last_holiday
is_promotion_day, event_type（类别特征，可结合上一篇的编码方法处理）
```

这类特征构造通常不涉及时间泄露（节假日日历提前已知），但如果特征来自"实际发生的业务结果"（如"当天是否为爆款日"由当天真实销量倒推），就要重新审视是否违反第 2 节铁律——判定标准不是特征名字，而是生成它用到的信息在 `t` 时刻是否已确定可知。

## 8. 时序交叉验证：前向链式验证

普通 K 折随机打乱、轮流留一折验证，前提是样本独立同分布——这在时序上不成立，随机划分会混入比验证集更晚的时间点，验证分数系统性偏乐观。

标准做法是**前向链式验证（forward chaining / walk-forward validation）**：

```
普通K折（不适用）：随机打乱后平均分K份轮流验证  [fold1][fold2][fold3][fold4][fold5]

前向链式验证（适用）：
  第1轮: train=[t0..t10]  validate=[t11..t15]
  第2轮: train=[t0..t15]  validate=[t16..t20]
  第3轮: train=[t0..t20]  validate=[t21..t25]
  训练集持续向后扩展，验证集永远在训练集覆盖范围的"未来"
```

每轮验证集时间都严格晚于训练集，模拟"只能用已发生数据预测未发生数据"。前向链式验证通常还限制训练窗口最大长度（滑动窗口而非一直扩展），评估近期模式变化是否让旧模型过时。

## 9. 训练/推理时特征可用性不一致的坑

即使特征工程没有泄露，还有一类更隐蔽的问题：**训练时能拿到的数据，推理时可能不可用或有延迟**：

```
数据入库延迟：某特征真实值要T+1才能确认，推理那一刻还没产生
统计口径变化：训练数据经后续修正，推理时看到的是原始值
特征链路不同源：训练特征来自离线批处理，推理特征来自实时计算，口径可能有差异
```

排查思路和泄露类似但方向相反——泄露关注训练时是否偷看了不该看的信息，这里关注推理时是否真的能复现训练时的特征计算条件。常见应对：**训练特征生成也走一遍推理时的实时计算路径**，而非维护两套独立实现。

## 10. 代码：滚动窗口统计的泄露量化

用随机游走序列构造滚动均值特征，对比"窗口不含当前点（正确）"和"窗口含当前点（泄露）"两种实现，看它们与预测目标的相关系数、以及最小二乘拟合后 R² 的虚增幅度，并观察窗口大小对泄露程度的影响。

```python
"""滚动窗口统计：对比"正确实现（不含当前点）"与"错误实现（含当前点）"，
量化后者的信息泄露。目标：用滚动均值特征预测 t 时刻真实值本身。"""
import numpy as np

rng = np.random.default_rng(3)
n_steps = 2000
noise = rng.normal(0, 1.0, n_steps)
series = np.cumsum(rng.normal(0, 0.05, n_steps)) + noise  # 趋势+噪声
target = series  # 预测目标：t 时刻真实值本身（用于演示泄露）


def rolling_mean_correct(x, window):
    """正确：t 位置只用 [t-window, t-1] 历史，不含 t 本身"""
    n = len(x)
    out = np.full(n, np.nan)
    cumsum = np.cumsum(x)
    for t in range(window, n):
        s = cumsum[t - 1] - (cumsum[t - window - 1] if t - window - 1 >= 0 else 0.0)
        out[t] = s / window
    return out


def rolling_mean_leaky(x, window):
    """错误：窗口右边界含 t 本身，用 [t-window+1, t] 计算"""
    n = len(x)
    out = np.full(n, np.nan)
    cumsum = np.cumsum(x)
    for t in range(window - 1, n):
        s = cumsum[t] - (cumsum[t - window] if t - window >= 0 else 0.0)
        out[t] = s / window
    return out


def corr(a, b):
    mask = ~(np.isnan(a) | np.isnan(b))
    a, b = a[mask] - a[mask].mean(), b[mask] - b[mask].mean()
    return np.sum(a * b) / (np.sqrt(np.sum(a ** 2)) * np.sqrt(np.sum(b ** 2)))


def fit_and_eval(feat, target):
    """单变量最小二乘 y=a*feat+b，返回拟合系数和训练集 R^2"""
    mask = ~np.isnan(feat)
    x, y = feat[mask], target[mask]
    A = np.vstack([x, np.ones_like(x)]).T
    coef, _, _, _ = np.linalg.lstsq(A, y, rcond=None)
    pred = A @ coef
    r2 = 1 - np.sum((y - pred) ** 2) / np.sum((y - y.mean()) ** 2)
    return coef, r2


window = 10
fc, fl = rolling_mean_correct(series, window), rolling_mean_leaky(series, window)
print(f"窗口大小={window}: 正确实现与target相关系数={corr(fc, target):.4f}, "
      f"泄露实现={corr(fl, target):.4f}")

coef_c, r2_c = fit_and_eval(fc, target)
coef_l, r2_l = fit_and_eval(fl, target)
print(f"最小二乘拟合: 正确实现 系数={coef_c[0]:.4f} R^2={r2_c:.4f}; "
      f"泄露实现 系数={coef_l[0]:.4f} R^2={r2_l:.4f}")

print("换不同窗口观察泄露程度变化:")
for w in [3, 10, 30]:
    fc_w, fl_w = rolling_mean_correct(series, w), rolling_mean_leaky(series, w)
    _, r2_cw = fit_and_eval(fc_w, target)
    _, r2_lw = fit_and_eval(fl_w, target)
    print(f"  window={w:>3}: 正确R^2={r2_cw:.4f}, 泄露R^2={r2_lw:.4f}, 虚增={r2_lw - r2_cw:.4f}")
```

实测输出（numpy 2.4.4）：

```
窗口大小=10: 正确实现与target相关系数=0.5565, 泄露实现=0.6535
最小二乘拟合: 正确实现 系数=0.8418 R^2=0.3097; 泄露实现 系数=0.9900 R^2=0.4270
换不同窗口观察泄露程度变化:
  window=  3: 正确R^2=0.2403, 泄露R^2=0.5814, 虚增=0.3411
  window= 10: 正确R^2=0.3097, 泄露R^2=0.4270, 虚增=0.1173
  window= 30: 正确R^2=0.3279, 泄露R^2=0.3697, 虚增=0.0417
```

结果印证了第 4 节的分析：窗口 10 时，泄露实现相关系数（0.6535）高于正确实现（0.5565）；最小二乘拟合后泄露实现 R² 达 0.4270，比正确实现 0.3097 虚增 0.1173。三个窗口对比复现同一规律：窗口越小当前点权重（`1/window`）越大，虚增越夸张（`window=3` 时 0.3411）；窗口越大单点泄露被稀释，虚增收窄（`window=30` 时 0.0417），但从未降到 0——"含当前点"是无论窗口多大都系统性存在的结构性泄露，唯一修复方式是修正窗口边界，而非换更大窗口。

## 11. 小结

| 主题 | 核心结论 |
| --- | --- |
| 时序更容易泄露的原因 | 窗口边界差一位、全局统计量跨越时间轴、随机划分混入未来 |
| 时间对齐铁律 | 预测 t 时刻只能用严格早于 t 的信息，是所有规则的唯一来源 |
| 滞后特征 | 阶数依据业务周期和自相关衰减选择，阶数越高历史样本损耗越大 |
| 滚动窗口 | 含当前点是最常见泄露源，窗口越小虚增越明显但从不消失 |
| 扩展窗口/指数加权 | 扩展窗口等权重看全部历史，指数加权用衰减权重强调近期 |
| 周期性编码 | sin/cos 对编码保留周期首尾相接性，避免整数序号虚假断点 |
| 时序交叉验证 | 前向链式验证保证验证集时间严格晚于训练集，K 折会系统性乐观 |
| 训练/推理不一致 | 数据延迟、口径修正、链路不同源，无泄露也会导致线上线下不一致 |
