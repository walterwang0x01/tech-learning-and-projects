## 1. 学习率为何是最重要的超参

回顾梯度下降的更新公式：

```
w ← w - η · ∂L/∂w
```

`η`（学习率）直接决定了每一步"信任梯度多少"：

- **太大**：可能在损失曲面上来回震荡，甚至直接发散（loss 变成 `nan`）——这在 [反向传播推导](../04-神经网络原理/02-反向传播推导.md) 的实测里就出现过：训练到 400 步时损失从 0.0039 反弹到 0.079，正是学习率偏大导致在极小值附近震荡
- **太小**：收敛极慢，可能几万步都到不了一个还不错的解，浪费大量计算资源
- **恰好合适**：其他超参（模型结构、batch size、正则化强度）调整带来的收益，往往都不如把学习率调对来得明显

这也是为什么几乎所有训练配置文档里，学习率（及其调度策略）都是最先被列出、被最仔细调整的超参——模型能不能训起来、训得好不好，学习率的影响通常是压倒性的。

## 2. Warmup

### 2.1 为什么需要

Warmup 是指训练最开始的若干步，让学习率从很小的值线性（或其他方式）增长到目标学习率，而不是一开始就用完整的学习率：

```
lr(step) = base_lr * step / warmup_steps     (step < warmup_steps 时)
```

原因来自训练初期的两个不稳定因素：

1. **参数是随机初始化的**，此时模型的损失曲面还没有被任何有效梯度信息塑造过，梯度方向和幅度都可能不可靠。用大学习率在一个"还没搞清楚方向"的点上大步迈进，容易一步迈进一个很差的区域，甚至直接导致数值不稳定
2. **自适应优化器（如 Adam）的二阶矩估计 `v` 在训练初期还没有积累足够的统计量**，早期几步的自适应学习率缩放本身就不准，如果配合较大的 base_lr，容易在最初几步产生异常大的更新

### 2.2 为什么大模型必须 warmup

大模型（尤其是深层 Transformer）对训练初期的不稳定更敏感：

- 模型层数深，梯度需要经过更长的传播路径（即使有残差连接和 Pre-LN 缓解，见 [归一化技术](03-归一化技术.md)），初始阶段任何一层的异常都可能被放大传递
- 大模型通常用较大的 batch size 和相对较大的目标学习率来提升训练效率，这进一步放大了"没有 warmup 直接上大学习率"的风险
- 大规模训练一次失败（loss 发散、需要从 checkpoint 重启）的时间和算力成本很高，warmup 是用极小的额外步数成本换取训练启动阶段的稳定性，性价比极高

**没有 warmup 会发生什么**：训练最初几步用完整学习率直接更新，容易出现 loss 剧烈震荡甚至发散为 `nan`；即使没有直接发散，参数也可能被带偏到一个次优的区域，后续训练难以完全修正过来。

## 3. 学习率调度策略

Warmup 之后，学习率通常还要按某种策略衰减，让训练后期的更新更精细（避免在极小值附近像上面提到的那样震荡）。

### 3.1 Step Decay

每隔固定的步数（或 epoch），把学习率乘上一个衰减因子：

```
lr(step) = base_lr * decay_factor ^ floor(step / decay_every)
```

简单直接，但衰减是突变的（阶梯状），衰减点前后学习率有明显跳变。

### 3.2 Cosine Decay

学习率沿余弦曲线从 `base_lr` 平滑衰减到 `min_lr`：

```
progress = (step - warmup_steps) / (total_steps - warmup_steps)
lr(step) = min_lr + (base_lr - min_lr) * 0.5 * (1 + cos(π * progress))
```

`progress` 从 0 到 1 时，`cos(π·progress)` 从 1 平滑降到 -1，整个学习率曲线是一条没有突变、衰减速率先慢后快再慢的平滑曲线。这是目前最常用的调度之一，因为衰减过程连续、没有 Step Decay 的突变问题。

### 3.3 OneCycle

OneCycle 把一次训练的学习率压缩成"一个周期"：先升到比 warmup 阶段更高的峰值，再降到比初始值更小的最终值：

```
学习率
 │        ╱╲
 │      ╱    ╲___
 │    ╱           ╲___
 │  ╱                  ╲___
 │____________________________ 训练步数
   升(warmup)  降(主体)  微调
```

训练中期用大学习率快速探索、跳过不好的局部区域，后期用很小的学习率精细收敛。相比单纯 warmup+cosine，部分场景下能用更少步数达到接近的效果，但需要仔细选择峰值学习率。

## 4. 梯度裁剪（Gradient Clipping）

梯度裁剪限制梯度的幅度，防止某一步的梯度异常大（比如遇到一个特别陡的损失曲面区域）导致参数被"一步迈太远"，是防止梯度爆炸、训练发散的直接手段。最常用的是**按全局范数裁剪**：

```
total_norm = sqrt(Σ ‖g_i‖²)             对所有参数的梯度求整体范数（不是逐个裁剪）
if total_norm > max_norm:
    g_i ← g_i * (max_norm / total_norm)  按同一比例缩小所有梯度，保持梯度方向不变
```

**保持方向不变**是关键：裁剪只压缩梯度的整体幅度，不改变各参数梯度之间的相对比例，因此不会扭曲梯度指向的更新方向，只是让这一步的步子不要迈得过大。

## 5. 梯度累积（Gradient Accumulation）

梯度累积解决的是**显存不足以放下期望的 batch size** 这个问题，与梯度裁剪要解决的问题完全不同（裁剪是防止梯度过大导致训练不稳定，累积是用时间换显存空间）：

```
清零累积梯度 grad_accum = 0
for i in range(accumulation_steps):
    micro_batch = 从大 batch 中切出的一小份
    loss = forward(micro_batch) / accumulation_steps   ← 除以步数，保证梯度量级等价于大 batch
    loss.backward()             ← 梯度会累加到 grad_accum，不立即更新参数
optimizer.step()                ← 累积够 accumulation_steps 次后才真正更新一次参数
optimizer.zero_grad()
```

效果上等价于用一个大 batch size 训练（多次小 batch 的梯度平均 ≈ 一次大 batch 的梯度），但每一步的显存占用只相当于小 batch——用多跑几步前向反向的时间成本，换取显存占用的降低。

## 6. 混合精度训练

### 6.1 FP16 / BF16 的差异

混合精度训练用低精度（16 位）浮点数做大部分计算（矩阵乘法等），同时在数值敏感的地方（如某些累加、归一化统计量）保留 FP32，以提升计算速度、降低显存占用。两种常见的 16 位格式：

```
FP32:  1 位符号 + 8 位指数 + 23 位尾数    表示范围大，精度高
FP16:  1 位符号 + 5 位指数 + 10 位尾数    表示范围远小于 FP32，尾数精度也更低
BF16:  1 位符号 + 8 位指数 + 7  位尾数    表示范围与 FP32 相同（指数位数一致），但尾数精度更低
```

**关键区别**：BF16 的指数位数和 FP32 一样多，所以**表示范围（能表示的最大/最小量级）与 FP32 相当**，几乎不会有"数值太小变成 0（下溢）"或"数值太大变成 inf（上溢）"的问题，代价是精度（有效数字位数）比 FP16 更低。FP16 的指数位数少，表示范围远小于 FP32，训练中常见的很小的梯度值很容易在 FP16 下直接下溢为 0。

### 6.2 为什么 FP16 需要 loss scaling，BF16 通常不需要

深层网络反向传播时，越靠前的层梯度经过越多次链式法则乘积（回顾 [反向传播推导](../04-神经网络原理/02-反向传播推导.md) 的梯度消失分析），数值量级往往很小，容易落到 FP16 表示范围之外直接变成 0——这会导致对应参数完全不更新，且不会报错，非常隐蔽。

**Loss scaling**：反向传播前把 loss 乘一个较大的 `scale`。因为反向传播是线性的，loss 放大 `scale` 倍，算出的梯度也等比放大 `scale` 倍，把原本会下溢的小梯度"抬"到 FP16 可表示范围内；更新参数前再除以 `scale` 还原：

```
scaled_loss = loss * scale
scaled_loss.backward()          ← 得到的梯度是真实梯度的 scale 倍
grad = grad / scale             ← 还原真实梯度大小，再用于参数更新
```

BF16 的表示范围本身就和 FP32 相当，常见梯度量级几乎不会在 BF16 下下溢，所以通常不需要 loss scaling——这是很多新硬件、新框架转向优先支持 BF16 的动机之一。

> ⚠️ 待确认：不同硬件对 FP16/BF16 的计算吞吐差异、以及具体框架里 loss scaling 是静态还是动态调整，请以对应硬件和框架官方文档为准。

## 7. 梯度检查点（Gradient Checkpointing）

回顾 [反向传播推导](../04-神经网络原理/02-反向传播推导.md) 提到的一点：反向传播需要用到前向时缓存的中间激活值，这是训练比推理更耗显存的主要原因。层数越深，需要缓存的中间激活越多。

梯度检查点用**计算换显存**：前向传播时不保存所有中间激活，只保存少数"检查点"位置的激活；反向传播需要某层的激活时，从最近的检查点重新做一次前向计算，现算现用，用完即丢：

```
不用梯度检查点：前向缓存全部 L 层激活 → 反向直接用          显存占用 O(L)，无额外计算
用梯度检查点：  前向只缓存若干检查点激活 → 反向时重新计算所需的中间激活   显存占用降低，但多了一次局部重算
```

这是显存不够训练更深/更大模型时的常用手段：牺牲一部分训练速度（因为要多算一次前向），换取能训练本来装不进显存的更大模型。

## 8. 常见训练不稳定现象排查清单

| 现象 | 可能原因 | 排查方向 |
| --- | --- | --- |
| loss 变成 `nan`/`inf` | 学习率过大、梯度爆炸、FP16 数值溢出 | 检查学习率、加梯度裁剪、检查是否缺 loss scaling |
| loss 不下降 | 学习率过小、梯度消失、数据/标签有误 | 检查学习率、检查梯度是否流到浅层、抽样检查数据 |
| loss 前期正常、训练久了突然发散 | 学习率衰减不够、异常 batch、优化器状态累积异常 | 抽查异常样本、考虑加裁剪 |
| 训练损失降但验证损失升 | 过拟合 | 参考 [过拟合与偏差方差](01-过拟合与偏差方差.md)、加正则化 |
| 大 batch 效果不如小 batch | 学习率没随 batch size 调整 | 尝试线性/平方根缩放学习率，检查 warmup 步数 |
| 深层 Transformer 前几步就发散 | Post-LN + 学习率过大/warmup 不足 | 确认是否用 Pre-LN（见 [归一化技术](03-归一化技术.md)） |
| 显存不足（OOM） | batch size 过大、模型过深 | 梯度累积降低单步显存、梯度检查点换显存 |

## 9. 最小可运行实现

### 9.1 学习率调度曲线 + 梯度裁剪

对比 Warmup+Cosine 和 Step Decay 两种调度在训练过程中的学习率取值，并验证梯度裁剪能把梯度的全局范数压到指定阈值以内。

```python
import numpy as np


def lr_warmup_cosine(step, total_steps, warmup_steps, base_lr, min_lr=0.0):
    """Warmup 线性升到 base_lr，然后 cosine 衰减到 min_lr"""
    if step < warmup_steps:
        return base_lr * step / warmup_steps
    progress = (step - warmup_steps) / max(1, total_steps - warmup_steps)
    progress = min(progress, 1.0)
    cosine_decay = 0.5 * (1 + np.cos(np.pi * progress))
    return min_lr + (base_lr - min_lr) * cosine_decay


def lr_step_decay(step, base_lr, decay_every, decay_factor):
    """Step decay：每隔固定步数把学习率乘上一个衰减因子"""
    n_decays = step // decay_every
    return base_lr * (decay_factor ** n_decays)


total_steps, warmup_steps, base_lr = 100, 10, 1e-3

print("step   warmup+cosine     step_decay")
for step in [0, 1, 5, 10, 20, 40, 60, 80, 99]:
    wc = lr_warmup_cosine(step, total_steps, warmup_steps, base_lr)
    sd = lr_step_decay(step, base_lr, decay_every=30, decay_factor=0.1)
    print(f"{step:4d}   {wc:.6f}       {sd:.6f}")


def clip_grad_norm(grads, max_norm):
    """按全局范数裁剪：所有梯度张量整体缩放同一比例，保持方向不变"""
    total_norm = np.sqrt(sum(np.sum(g ** 2) for g in grads))
    if total_norm > max_norm:
        scale = max_norm / (total_norm + 1e-6)
        grads = [g * scale for g in grads]
    return grads, total_norm


rng = np.random.default_rng(0)
grads = [rng.normal(0, 5, (3, 3)) for _ in range(3)]  # 较大方差模拟梯度爆炸场景
clipped, orig_norm = clip_grad_norm(grads, max_norm=1.0)
clipped_norm = np.sqrt(sum(np.sum(g ** 2) for g in clipped))
print(f"\n裁剪前全局范数: {orig_norm:.4f}")
print(f"裁剪后全局范数: {clipped_norm:.4f} (应 <= max_norm=1.0)")
```

实测输出（numpy 2.4.4）：

```
step   warmup+cosine     step_decay
   0   0.000000       0.001000
   1   0.000100       0.001000
   5   0.000500       0.001000
  10   0.001000       0.001000
  20   0.000970       0.001000
  40   0.000750       0.000100
  60   0.000413       0.000010
  80   0.000117       0.000010
  99   0.000000       0.000001

裁剪前全局范数: 21.7822
裁剪后全局范数: 1.0000 (应 <= max_norm=1.0)
```

`step=0` 到 `step=10`（`warmup_steps=10`）学习率从 0 线性升到 `base_lr=0.001`，之后按 cosine 曲线平滑衰减到接近 0；Step Decay 在 `step=30/60/90` 处发生突变式衰减（每次乘 0.1）。梯度裁剪把原本范数 21.78 的梯度整体缩放到刚好 1.0，验证裁剪逻辑正确。

### 9.2 FP16 下溢与 Loss Scaling

用 `numpy.float16` 模拟训练中常见的小梯度在 FP16 下的下溢现象，并验证 loss scaling 能否缓解。

```python
import numpy as np

rng = np.random.default_rng(0)

# 构造一批典型的小梯度值，量级低于 FP16 最小可表示的 subnormal 范围（约 6e-8）
small_grads = rng.uniform(1e-8, 5e-8, 1000).astype(np.float32)

# 不做任何处理，直接转 FP16，看看有多少下溢为 0
grads_fp16_direct = small_grads.astype(np.float16)
n_underflow_direct = np.sum(grads_fp16_direct == 0)

# loss scaling：反向传播前把 loss（从而梯度）等比放大，抬到 FP16 可表示范围内
scale = 2.0 ** 20  # 约 1048576
scaled_grads = small_grads * scale
grads_fp16_scaled = scaled_grads.astype(np.float16)
n_underflow_scaled = np.sum(grads_fp16_scaled == 0)

# 更新参数前把梯度除回 scale，还原真实大小
unscaled_back = grads_fp16_scaled.astype(np.float32) / scale

print(f"float32 原始梯度量级示例: 最小值 {small_grads.min():.2e}, 最大值 {small_grads.max():.2e}")
print("（FP16 最小可表示的 subnormal 数量级约为 6e-8，正规数最小约 6e-5）")
print(f"不做 scaling，下溢为 0 的梯度个数: {n_underflow_direct} / {len(small_grads)}")
print(f"scale={scale} 后，下溢为 0 的梯度个数: {n_underflow_scaled} / {len(small_grads)}")

rel_err = np.abs(unscaled_back - small_grads) / (np.abs(small_grads) + 1e-12)
print(f"scaling 还原后与原始梯度的平均相对误差: {rel_err.mean():.4f}")
```

实测输出（numpy 2.4.4）：

```
float32 原始梯度量级示例: 最小值 1.00e-08, 最大值 5.00e-08
（FP16 最小可表示的 subnormal 数量级约为 6e-8，正规数最小约 6e-5）
不做 scaling，下溢为 0 的梯度个数: 466 / 1000
scale=1048576.0 后，下溢为 0 的梯度个数: 0 / 1000
scaling 还原后与原始梯度的平均相对误差: 0.0002
```

不做 loss scaling 时，1000 个小梯度里有 466 个（近半数）在转 FP16 后直接变成 0——这些参数这一步完全不更新，且不会报任何异常，非常隐蔽。经 `scale=2^20` 放大后下溢个数降为 0，还原后与原始梯度的平均相对误差只有 0.0002（FP16 精度本身有限带来的正常误差），验证了 loss scaling 能挽救原本被清零的梯度。

## 10. 小结

| 技巧 | 解决的问题 | 关键机制 |
| --- | --- | --- |
| Warmup | 训练初期不稳定 | 学习率从小到大线性爬升，避开随机初始化时的不可靠梯度 |
| Cosine/Step/OneCycle 调度 | 训练不同阶段需要不同的更新步长 | 前期大步探索，后期小步精细收敛 |
| 梯度裁剪 | 梯度爆炸、训练发散 | 按全局范数整体缩放，保持方向不变 |
| 梯度累积 | 显存不够支撑期望的 batch size | 多个小 batch 的梯度累加后再统一更新 |
| 混合精度（FP16/BF16） | 训练速度慢、显存占用高 | 用低精度计算，FP16 需配合 loss scaling 防下溢 |
| 梯度检查点 | 深层网络显存不足 | 不缓存全部激活，反向时按需重算，用计算换显存 |
