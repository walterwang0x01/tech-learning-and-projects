# 模型评估与度量选择

> Author: Walter Wang

> **读完你能回答的 3 个问题**
>
> 1. 为什么在正负样本比例极端的场景下，准确率很高但模型可能毫无价值？
> 2. P-R 曲线和 ROC-AUC 都能衡量分类器好坏，为什么类别极端不平衡时两者会给出截然不同的结论，该信哪个？
> 3. 离线评估分数很好，上线后业务指标却没提升甚至下降，可能是哪些环节出了问题？

## 1. 准确率陷阱：不平衡数据下的假象

准确率（accuracy）= `(TP + TN) / (TP + TN + FP + FN)`。正负样本比例悬殊时，什么都没学到的模型也能拿高分。例如风控场景欺诈交易只占 2%，一个**永远预测"不是欺诈"**的模型，准确率高达 98%。业务关心的是能否揪出那 2%，而准确率被多数"容易样本"主导，少数类预测得再差对总分影响都微乎其微。**类别越不平衡，准确率越容易失真**，第 6 节会用代码验证。

## 2. 混淆矩阵：四个格子对应四种业务结果

```
                预测为正        预测为负
实际为正      TP (真阳性)      FN (假阴性/漏报)
实际为负      FP (假阳性/误报)  TN (真阴性)
```

- **TP**：正确识别出的正类，比如真的抓到了欺诈交易。
- **FN（漏报）**：该抓的没抓到，比如欺诈被判定为正常——风控、医疗诊断场景里通常代价最高。
- **FP（误报）**：正常样本被误判为异常，比如正常用户被冻结账户——代价是体验受损、人工复核成本上升。
- **TN**：正确识别出的负类，符合预期，通常不单独作为优化目标。

评估指标的选择本质是在 FN 和 FP 之间选择"更不能接受哪种错误"，这直接决定后面精确率与召回率如何取舍。

## 3. 精确率与召回率：取舍的业务逻辑

```
Precision = TP / (TP + FP)   预测为正的样本里，有多少真的是正
Recall    = TP / (TP + FN)   实际为正的样本里，有多少被找出来了
```

两者往往此消彼长：阈值调低，召回率上升但精确率下降；阈值调高则相反。**该优先哪个，取决于 FN 和 FP 哪个代价更高**：

- **优先召回率**：医疗筛查（漏诊代价远高于误诊多做一次复查）、欺诈检测（漏放一笔大额欺诈的损失远高于误拦一笔正常交易）。
- **优先精确率**：垃圾邮件过滤（误判重要邮件为垃圾邮件代价很高）、推荐系统曝光位（推错内容直接损伤体验）。

单独看精确率或召回率都可能被极端阈值"作弊"，所以实践中通常用调和平均综合权衡。

## 4. F1 与 F-beta：加权综合精确率与召回率

```
F1 = 2 · Precision · Recall / (Precision + Recall)
```

用调和平均而不是算术平均，是因为调和平均对较小值更敏感——精确率和召回率任一个很低，F1 都会被拉低。业务上两者权重不对等时用 **F-beta**：

```
F_beta = (1 + beta²) · Precision · Recall / (beta² · Precision + Recall)
```

`beta > 1` 召回率权重更大（如 F2，业务更看重"别漏"）；`beta < 1` 精确率权重更大（如 F0.5，业务更看重"别错报"）；`beta = 1` 退化为 F1。选 `beta` 依据同样是第 3 节的业务代价分析。

## 5. P-R 曲线 vs ROC-AUC：类别极端不平衡时的关键差异

这是实践中最常被选错的一环。两者都通过扫描分类阈值把一对指标画成曲线，但分母结构完全不同，对不平衡数据的敏感度天差地别。

**ROC 曲线**：横轴假正率 `FPR = FP / (FP + TN)`，纵轴召回率 `TPR = TP / (TP + FN)`。**FPR 的分母是全部负类样本数**——负类基数很大时，即使 FP 绝对数量不小，FPR 依然很小（分母被稀释）。这会让 ROC 曲线"看起来"贴近左上角，AUC 虚高。

**P-R 曲线**：横轴召回率，纵轴精确率 `Precision = TP / (TP + FP)`。**精确率的分母是"预测为正"的样本数**，通常和正类基数同量级，不会被大量负类稀释。正类基数很小时，FP 只增加几十个，精确率就会断崖式下降，P-R 曲线会如实反映。

结论：**正负比例越悬殊，ROC-AUC 越容易"乐观地"掩盖模型对少数类预测质量差的问题，此时应优先看 P-R 曲线（或其曲线下面积 AP）**。ROC-AUC 更适合正负比例接近、业务同等关心两个类别的场景。第 6 节用具体数值直接展示这个反差。

## 6. 最小可运行实现：极端不平衡数据下的指标对比

```python
"""
极端不平衡二分类例子：
  1. 准确率陷阱——全预测多数类也能拿到很高准确率
  2. 手算混淆矩阵与精确率/召回率/F1/F-beta
  3. P-R 曲线 vs ROC-AUC 在正负比例极端时的行为差异
"""
import numpy as np

rng = np.random.default_rng(42)

n_neg, n_pos = 1000, 20  # 负类基数远大于正类
neg_scores = rng.normal(loc=0.3, scale=0.15, size=n_neg)
pos_scores = rng.normal(loc=0.6, scale=0.2, size=n_pos)  # 与负类有重叠，模拟不完美模型
y_true = np.array([0] * n_neg + [1] * n_pos)
scores = np.clip(np.concatenate([neg_scores, pos_scores]), 0, 1)

# 场景 A：永远预测负类的偷懒模型
lazy_acc = np.mean(np.zeros_like(y_true) == y_true)
print("=== 场景 A：偷懒模型 ===")
print(f"准确率: {lazy_acc:.4f}（看起来很高，但正类识别能力为 0）")

# 场景 B：阈值 0.5 的真实模型，手算混淆矩阵
y_pred = (scores >= 0.5).astype(int)
tp = np.sum((y_pred == 1) & (y_true == 1))
fp = np.sum((y_pred == 1) & (y_true == 0))
fn = np.sum((y_pred == 0) & (y_true == 1))
tn = np.sum((y_pred == 0) & (y_true == 0))
precision = tp / (tp + fp)
recall = tp / (tp + fn)
f1 = 2 * precision * recall / (precision + recall)


def f_beta(p, r, beta):
    return (1 + beta ** 2) * p * r / (beta ** 2 * p + r)


print("\n=== 场景 B：阈值 0.5 混淆矩阵 ===")
print(f"TP={tp}, FP={fp}, FN={fn}, TN={tn}")
print(f"准确率={(tp+tn)/(tp+fp+fn+tn):.4f}, 精确率={precision:.4f}, 召回率={recall:.4f}, F1={f1:.4f}")
print(f"F0.5(重精确率)={f_beta(precision, recall, 0.5):.4f}, F2(重召回率)={f_beta(precision, recall, 2):.4f}")

# P-R 曲线：扫描阈值
pr_points = []
for t in np.linspace(0.0, 1.0, 21):
    pred_t = (scores >= t).astype(int)
    tp_t = np.sum((pred_t == 1) & (y_true == 1))
    fp_t = np.sum((pred_t == 1) & (y_true == 0))
    fn_t = np.sum((pred_t == 0) & (y_true == 1))
    p_t = tp_t / (tp_t + fp_t) if (tp_t + fp_t) > 0 else 1.0
    r_t = tp_t / (tp_t + fn_t) if (tp_t + fn_t) > 0 else 0.0
    pr_points.append((t, p_t, r_t))

print("\n=== P-R 曲线采样点 ===")
for t, p_t, r_t in pr_points[::4]:
    print(f"  阈值={t:.2f}: 精确率={p_t:.4f}, 召回率={r_t:.4f}")

recalls = np.array([pt[2] for pt in pr_points])
precisions = np.array([pt[1] for pt in pr_points])
order = np.argsort(recalls)
ap = np.trapezoid(precisions[order], recalls[order])  # 梯形法近似 AP（P-R 曲线下面积）
print(f"\nP-R 曲线下面积（近似 AP）: {ap:.4f}")

# ROC-AUC：手算 P(正类分数 > 负类分数)
pos_arr, neg_arr = scores[y_true == 1], scores[y_true == 0]
comparisons = pos_arr[:, None] > neg_arr[None, :]
ties = pos_arr[:, None] == neg_arr[None, :]
auc = (comparisons.sum() + 0.5 * ties.sum()) / (len(pos_arr) * len(neg_arr))
print(f"ROC-AUC: {auc:.4f}")
print(f"\n对比：ROC-AUC={auc:.4f} vs P-R 曲线下面积={ap:.4f}")
```

实测输出（numpy 2.4.4）：

```
=== 场景 A：偷懒模型 ===
准确率: 0.9804（看起来很高，但正类识别能力为 0）

=== 场景 B：阈值 0.5 混淆矩阵 ===
TP=14, FP=90, FN=6, TN=910
准确率=0.9059, 精确率=0.1346, 召回率=0.7000, F1=0.2258
F0.5(重精确率)=0.1606, F2(重召回率)=0.3804

=== P-R 曲线采样点 ===
  阈值=0.00: 精确率=0.0196, 召回率=1.0000
  阈值=0.20: 精确率=0.0262, 召回率=1.0000
  阈值=0.40: 精确率=0.0661, 召回率=0.8000
  阈值=0.60: 精确率=0.3214, 召回率=0.4500
  阈值=0.80: 精确率=1.0000, 召回率=0.0500
  阈值=1.00: 精确率=1.0000, 召回率=0.0000

P-R 曲线下面积（近似 AP）: 0.3495
ROC-AUC: 0.9019

对比：ROC-AUC=0.9019 vs P-R 曲线下面积=0.3495
```

三组数字印证前面结论：偷懒模型准确率 0.9804，正类识别能力为 0，即第 1 节的准确率陷阱；场景 B 精确率仅 0.1346（100 次预测为正里 87 次误报），召回率 0.7（漏掉 3 成正类），F0.5 因重精确率被拖低到 0.1606，F2 因重召回率相对高（0.3804），F-beta 随权重变化方向符合预期；最关键的是 ROC-AUC=0.9019 看起来"优秀"，但 P-R 曲线下面积只有 0.3495，相差近 0.55——负类基数（1000）远大于正类基数（20），FPR 分母被稀释，ROC 对这批误报视而不见，精确率却如实记录，这正是第 5 节"类别越不平衡越该信 P-R 而非 ROC-AUC"的数值证据。

## 7. 阈值选择与业务代价矩阵

上线时要选具体判定阈值。做法是给四个格子标出业务代价（FN 代价 = 一次漏报的损失，FP 代价 = 一次误报的损失），扫描候选阈值，选总代价最小的：

```
总代价(t) = FN(t) · Cost_FN + FP(t) · Cost_FP
```

这比固定阈值 0.5 更贴近业务目标——0.5 只是数学中点，与业务代价无关。代价矩阵随业务变化（如大促期间更看重不误伤正常用户），阈值也应跟着重新校准。

## 8. 多分类的宏平均、微平均与加权平均

多分类下精确率/召回率/F1 需先对每个类别单独计算再汇总，三种方式含义不同：

- **宏平均（macro）**：对每类指标取算术平均，每类权重相等，不管样本量。适合小类别同等重要的场景。
- **微平均（micro）**：所有类别的 TP/FP/FN 先加总再算一次，等价于按样本数量加权，样本多的类别主导结果。
- **加权平均（weighted）**：按各类真实样本占比加权，介于两者之间。

选择依据是业务目标：稀有故障、稀有病种同等重要用宏平均；只关心整体表现用微平均或加权平均。

## 9. 回归度量：MSE、MAE、MAPE、R² 各自的陷阱

```
MSE  = (1/n) Σ (y_i - ŷ_i)²        大误差被平方放大，对异常值极敏感
MAE  = (1/n) Σ |y_i - ŷ_i|          对异常值更鲁棒，但 0 点不可导
MAPE = (1/n) Σ |y_i - ŷ_i| / |y_i|  百分比误差直观，但 y_i 接近 0 时会爆炸
R²   = 1 - Σ(y_i-ŷ_i)² / Σ(y_i-ȳ)²  衡量比"预测均值"好多少，非绝对精度
```

陷阱：MSE 被少数极端异常值主导，模型会牺牲大部分正常点精度去讨好这几个点；MAE 更均衡但不可导，无法直接用于需要梯度的优化目标；MAPE 在真实值接近 0 的场景（库存差异、温度差值）分母趋近 0 会数值爆炸，且对"预测过高/过低"惩罚不对称；R² 依赖目标值方差作为基准，同一模型换个方差更大的数据集 R² 会自动"变好"，不能跨数据集直接比较。

## 10. 排序与推荐度量简介：NDCG 与 MRR

```
MRR = (1/|Q|) Σ_q 1/rank_q     rank_q: 第一个相关结果在查询 q 中的排名
```

MRR 只关心"第一个正确答案排多前"，适合"只需一个好答案"的场景（问答系统）。

```
DCG@k = Σ_{i=1}^{k} rel_i / log2(i+1)
NDCG@k = DCG@k / IDCG@k    IDCG@k: 理想排序下的 DCG@k
```

NDCG 同时考虑相关性等级（`rel_i` 可多档）和位置衰减，除以理想排序归一化，使不同查询间分数可比，适合推荐列表、搜索排序等需要多个结果都相关的场景。

## 11. 离线指标与在线指标不一致的常见原因

- **分布不一致**：训练/测试是历史静态快照，线上流量随时间、渠道、用户群体持续变化（分布漂移）。
- **标签滞后或偏差**：如用"最终是否转化"做标签，但线上要在转化前预测，特征可用性和离线训练不完全对齐。
- **只优化了代理指标**：离线优化点击率，业务关心长期留存或 GMV，两者不总是正相关（标题党提升点击率但损伤信任）。
- **系统效应被忽略**：离线是静态单点预测，线上是和其他策略共同作用的结果，单模块变好不代表端到端变好。
- **A/B 实验样本量或时长不足**：线上指标本身有噪声，短期波动可能被误判为效果。

## 12. 小结

| 主题 | 关键结论 |
| --- | --- |
| 准确率 | 类别不平衡时失真，不能单独作为评估标准 |
| 精确率/召回率 | 取舍取决于 FN、FP 谁的业务代价更高 |
| F1/F-beta | beta 权重让综合指标匹配业务偏好方向 |
| P-R vs ROC-AUC | 类别越不平衡越该信 P-R（或 AP），ROC-AUC 容易虚高 |
| 阈值选择 | 应基于代价矩阵校准，而非固定 0.5 |
| 宏/微/加权平均 | 是否让小类别与大类别同等重要，决定用哪种平均 |
| 回归度量 | MSE 怕异常值，MAPE 怕分母接近 0，R² 不能跨数据集比较 |
| 离线 vs 在线 | 分布漂移、代理指标偏差、系统效应是常见不一致来源 |
