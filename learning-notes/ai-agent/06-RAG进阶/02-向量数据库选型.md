## 2. Chroma（轻量开发）

```python
import chromadb
from chromadb.utils import embedding_functions

# 创建客户端
client = chromadb.PersistentClient(path="./chroma_db")

# 使用 OpenAI Embedding
ef = embedding_functions.OpenAIEmbeddingFunction(
    api_key="sk-xxx",
    model_name="text-embedding-3-small",
)

# 创建集合
collection = client.get_or_create_collection(
    name="documents",
    embedding_function=ef,
    metadata={"hnsw:space": "cosine"},  # 距离度量
)

# 添加文档
collection.add(
    documents=["AI Agent 是自主决策的智能系统", "RAG 结合检索与生成"],
    metadatas=[{"source": "doc1"}, {"source": "doc2"}],
    ids=["id1", "id2"],
)

# 查询
results = collection.query(query_texts=["什么是Agent"], n_results=3)
print(results["documents"])
```

## 3. Qdrant（高性能生产）

```python
from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams, PointStruct, Filter, FieldCondition

client = QdrantClient(host="localhost", port=6333)

# 创建集合
client.create_collection(
    collection_name="knowledge_base",
    vectors_config=VectorParams(size=1536, distance=Distance.COSINE),
)

# 插入向量
client.upsert(
    collection_name="knowledge_base",
    points=[
        PointStruct(id=1, vector=embedding_1, payload={"text": "...", "source": "doc1"}),
        PointStruct(id=2, vector=embedding_2, payload={"text": "...", "source": "doc2"}),
    ],
)

# 带过滤的搜索
results = client.query_points(
    collection_name="knowledge_base",
    query=query_vector,
    query_filter=Filter(must=[FieldCondition(key="source", match={"value": "doc1"})]),
    limit=5,
)
```

## 4. pgvector（PostgreSQL 扩展）

```python
# 适合已有 PostgreSQL 基础设施的团队
import psycopg2

conn = psycopg2.connect("postgresql://localhost/mydb")
cur = conn.cursor()

# 启用扩展
cur.execute("CREATE EXTENSION IF NOT EXISTS vector")

# 创建表
cur.execute("""
    CREATE TABLE IF NOT EXISTS documents (
        id SERIAL PRIMARY KEY,
        content TEXT,
        metadata JSONB,
        embedding vector(1536)
    )
""")
```

## 6. 选型指南

```
├── 快速原型 / 小数据量？
│   └── Chroma（嵌入式，零配置）
├── 已有 PostgreSQL？
│   └── pgvector（无需新增组件）
├── 需要高性能 + 丰富过滤？
│   └── Qdrant（Rust 实现，性能优秀）
├── 大规模（亿级向量）？
│   └── Milvus（分布式，GPU 加速）
├── 全托管 + 零运维？
│   └── Pinecone（SaaS，自动扩展）
└── 语义搜索 + GraphQL？
    └── Weaviate（模块化，多模态）
```

## 7. 2026 年 5 月版本动态

> 🔄 更新于 2026-05-28

各家产品在过去一个月里集中发布了重要版本，以下是关键变化和升级建议。

### 7.1 Weaviate 1.37（2026-04-16 发布）

新增四项预览特性：

| 特性 | 说明 |
| ---- | ---- |
| **内置 MCP Server** | LLM 和 IDE 可以通过 MCP 协议直接访问 Weaviate Database，无需中间适配层 |
| **可扩展 Tokenizers** | 支持 accent folding（去除重音）和自定义 stopword 预设 |
| **Diversity Search (MMR)** | 最大边际相关性搜索，减少语义检索结果的重复 |
| **Query Profiling** | 每个 shard 的耗时分解，定位性能瓶颈 |

正式 GA 的功能：Server-side Batching、Object TTL、Async Replication 改进、Drop Inverted Indices、Backup Restoration Cancellation。

来源：[Weaviate 1.37 Release](https://weaviate.io/blog/weaviate-1-37-release)

### 7.2 Qdrant 1.15（2025-07 发布，1.16 准备中）

二进制量化升级：新增 **2-bit 和 1.5-bit binary quantization 存储**，比 1-bit 压缩在小维度向量（< 1000 维）上精度更高，避免昂贵的 rescoring。Text 过滤也得到性能改进。

> **升级提醒**：Qdrant 要求按 minor 版本递进升级。例如从 1.15 升到 1.17，必须先升所有节点到 1.16。

来源：[Qdrant 1.15 Smarter Quantization](https://qdrant.tech/blog/qdrant-1.15.x/)、[Qdrant Upgrades](https://qdrant.tech/documentation/upgrades/)

### 7.3 Milvus 2.6.5（2026-04 发布，关键安全修复）

修复 **CVE-2025-64513**（具体细节官方未披露），并将 Go 编译器升级到 1.24.9。**所有 Milvus 2.6.x 用户应尽快升级到 2.6.5**。Milvus v3.0 路线图目标 2026 年底，v3.1 长期开发，配套 Vector Lake（数据湖 / Loon）演进。

来源：[Milvus Release Notes](https://milvus.io/docs/release_notes.md)、[Milvus Roadmap](https://milvus.io/docs/roadmap.md)

### 7.4 pgvector 0.8.2（2026-02 发布）

修复 **CVE-2026-3172**：HNSW 并行索引构建时的缓冲区溢出，可能泄露其他关系的敏感数据或导致数据库崩溃。**在 PostgreSQL 集群中并行构建 HNSW 索引的项目必须立即升级**。

来源：[pgvector 0.8.2 PostgreSQL News](https://www.postgresql.org/about/news/pgvector-082-released-3245/)

### 7.5 选型决策树（2026-05 更新）

```
新增决策维度：
├── 需要 MCP 原生集成？
│   ├── 是 → Weaviate 1.37+（内置 MCP Server）
│   └── 否 → 维持现有选型
├── 关注向量量化精度？
│   ├── 小维度（< 1000）→ Qdrant 1.15+（2-bit/1.5-bit）
│   └── 大维度 → Weaviate（RQ）/ Milvus（IVF_PQ/SQ）
├── PostgreSQL 用户 + 安全敏感？
│   └── 立即升级 pgvector 0.8.2（CVE-2026-3172）
└── Milvus 2.6.x 用户？
    └── 立即升级到 2.6.5（CVE-2025-64513）
```

### 7.6 第三方基准测试观察

第三方测试普遍认为 Qdrant 在自托管场景下提供最佳的延迟与单位成本之比，Pinecone 在零运维全托管场景下仍然领先，Weaviate 凭借混合搜索和原生多租户在企业 RAG 中保持竞争力，Milvus 在十亿级以上向量规模下唯一可行。Pinecone 的「Serverless 自动扩展」与「按用量计费」模式被多家分析机构指出在大规模、高 QPS 场景下成本可能数倍于 Qdrant 自托管。
