## 1. Rust 异步的基本模型

```
async/await 是 Rust 的语言特性
但 Rust 不内置 Runtime
  ↓
必须选一个：Tokio / async-std / smol

生产 99% 选 Tokio
```

```rust
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    println!("Hello");
    sleep(Duration::from_secs(1)).await;
    println!("World");
}
```

## 2. Future 和 Runtime

```rust
// async fn 本质上返回一个 Future
async fn fetch(url: &str) -> String {
    // ...
    "response".to_string()
}

// 等价于
fn fetch(url: &str) -> impl Future<Output = String> {
    // ...
}
```

Future 本身不做事，需要 Runtime 去 poll 它才会执行。

## 3. Tokio 基础

```toml
# Cargo.toml
[dependencies]
tokio = { version = "1.47", features = ["full"] }
```

```rust
use tokio::task;

#[tokio::main]
async fn main() {
    // Spawn 一个任务（轻量级，类似 goroutine）
    let handle = task::spawn(async {
        println!("在另一个任务里");
        42
    });

    let result = handle.await.unwrap();
    println!("结果: {}", result);

    // 并发执行多个任务
    let (a, b) = tokio::join!(
        async { 1 },
        async { 2 },
    );

    // 竞速执行（谁先完成用谁）
    let result = tokio::select! {
        v = async_op_1() => v,
        v = async_op_2() => v,
    };
}
```

## 4. 异步 HTTP：reqwest

```rust
use reqwest::Client;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = Client::new();

    let resp = client
        .get("https://api.example.com/users")
        .header("Authorization", "Bearer xxx")
        .send()
        .await?
        .json::<Vec<User>>()
        .await?;

    for user in resp {
        println!("{}", user.name);
    }

    Ok(())
}

#[derive(serde::Deserialize)]
struct User {
    name: String,
}
```

## 5. Axum：现代 Web 框架

```toml
[dependencies]
axum = "0.9"
tokio = { version = "1.47", features = ["full"] }
tower = "0.5"
tracing = "0.1"
tracing-subscriber = "0.3"
serde = { version = "1.0", features = ["derive"] }
```

```rust
use axum::{
    extract::{Path, State},
    http::StatusCode,
    routing::{get, post},
    Json, Router,
};
use serde::{Deserialize, Serialize};
use std::sync::Arc;
use tokio::net::TcpListener;
use tokio::sync::RwLock;

#[derive(Clone)]
struct AppState {
    users: Arc<RwLock<Vec<User>>>,
}

#[derive(Clone, Deserialize, Serialize)]
struct User {
    id: u64,
    name: String,
}

async fn get_users(State(state): State<AppState>) -> Json<Vec<User>> {
    let users = state.users.read().await;
    Json(users.clone())
}

async fn get_user(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<Json<User>, StatusCode> {
    let users = state.users.read().await;
    users
        .iter()
        .find(|u| u.id == id)
        .cloned()
        .map(Json)
        .ok_or(StatusCode::NOT_FOUND)
}

async fn create_user(
    State(state): State<AppState>,
    Json(payload): Json<User>,
) -> (StatusCode, Json<User>) {
    let mut users = state.users.write().await;
    users.push(payload.clone());
    (StatusCode::CREATED, Json(payload))
}

#[tokio::main]
async fn main() {
    tracing_subscriber::fmt::init();

    let state = AppState {
        users: Arc::new(RwLock::new(vec![])),
    };

    let app = Router::new()
        .route("/users", get(get_users).post(create_user))
        .route("/users/:id", get(get_user))
        .with_state(state);

    let listener = TcpListener::bind("0.0.0.0:3000").await.unwrap();
    tracing::info!("listening on 3000");
    axum::serve(listener, app).await.unwrap();
}
```

**Axum 的优势**：
- 基于 Tower（通用中间件生态）
- 类型驱动的 Extractor
- 零成本抽象
- 和 Tokio 深度集成

## 6. 数据库：sqlx

```toml
[dependencies]
sqlx = { version = "0.8", features = ["runtime-tokio-rustls", "postgres", "macros", "uuid", "chrono"] }
```

```rust
use sqlx::postgres::PgPoolOptions;
use sqlx::{FromRow, PgPool};

#[derive(FromRow, Debug)]
struct User {
    id: i64,
    name: String,
    email: String,
}

#[tokio::main]
async fn main() -> Result<(), sqlx::Error> {
    let pool = PgPoolOptions::new()
        .max_connections(10)
        .connect("postgres://user:pass@localhost/db")
        .await?;

    // 编译期校验 SQL！
    let users: Vec<User> = sqlx::query_as!(
        User,
        r#"SELECT id, name, email FROM users WHERE active = $1"#,
        true
    )
    .fetch_all(&pool)
    .await?;

    for u in &users {
        println!("{:?}", u);
    }

    // 插入
    sqlx::query!(
        "INSERT INTO users (name, email) VALUES ($1, $2)",
        "Alice",
        "a@example.com",
    )
    .execute(&pool)
    .await?;

    Ok(())
}
```

**sqlx 的杀手锏**：`query!` 宏在编译期连接数据库验证 SQL，拼写错误和类型不匹配在编译时就被发现。

## 7. 错误处理：anyhow + thiserror

```toml
[dependencies]
anyhow = "1.0"          # 应用层错误（想都不想）
thiserror = "1.0"       # 库层错误（类型化）
```

```rust
// 库中：类型化错误
use thiserror::Error;

#[derive(Error, Debug)]
pub enum UserError {
    #[error("user {0} not found")]
    NotFound(u64),

    #[error("database error: {0}")]
    Database(#[from] sqlx::Error),
}

pub async fn find_user(pool: &PgPool, id: u64) -> Result<User, UserError> {
    sqlx::query_as!(User, "SELECT ... WHERE id = $1", id as i64)
        .fetch_optional(pool)
        .await?
        .ok_or(UserError::NotFound(id))
}

// 应用中：用 anyhow
use anyhow::{Context, Result};

async fn process() -> Result<()> {
    let config = load_config().context("loading config")?;
    let pool = connect(&config.db).await.context("connecting to db")?;
    // ...
    Ok(())
}
```

## 8. 取消与超时

```rust
use tokio::time::{timeout, Duration};

async fn may_hang() -> u32 {
    tokio::time::sleep(Duration::from_secs(10)).await;
    42
}

#[tokio::main]
async fn main() {
    match timeout(Duration::from_secs(3), may_hang()).await {
        Ok(value) => println!("completed: {}", value),
        Err(_) => println!("timeout"),
    }
}
```

Tokio 没有 Go 那样原生的 Context 传递，通常用 `CancellationToken`：

```rust
use tokio_util::sync::CancellationToken;

let token = CancellationToken::new();
let token_clone = token.clone();

tokio::spawn(async move {
    tokio::select! {
        _ = token_clone.cancelled() => println!("cancelled"),
        _ = long_work() => println!("done"),
    }
});

// 触发取消
token.cancel();
```

## 9. Arc + Mutex：共享状态

```rust
use std::sync::Arc;
use tokio::sync::Mutex;

let counter = Arc::new(Mutex::new(0));

let mut handles = vec![];
for _ in 0..10 {
    let counter = Arc::clone(&counter);
    handles.push(tokio::spawn(async move {
        let mut num = counter.lock().await;
        *num += 1;
    }));
}

for h in handles {
    h.await.unwrap();
}

println!("{}", *counter.lock().await);  // 10
```

**Arc** = 原子引用计数指针（跨线程共享）。
**tokio::sync::Mutex** 在持有锁时允许 await（标准库的 Mutex 不行）。

## 10. 常见坑

```
❌ 在 async 函数里用 std::sync::Mutex 然后 await
   → 锁被跨 await 持有，可能 deadlock
   → 改 tokio::sync::Mutex 或缩短持锁范围

❌ spawn 大量任务但不管理
   → 内存泄漏 + 任务 orphan
   → 用 JoinSet 或 structured concurrency

❌ 阻塞 CPU 密集工作
   → Runtime 被卡死
   → 用 spawn_blocking 或 rayon

❌ 一切都 async
   → 复杂度爆炸
   → 简单的纯计算不用 async

❌ 用 std::fs 在 async context
   → 阻塞线程
   → 用 tokio::fs
```
